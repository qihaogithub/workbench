# 测试与工程质量问题沉淀

记录开发工具链、编译性能、测试稳定性和验证门禁中仍有复用价值的结论。

## 1. Next.js 开发环境首页与编辑页冷编译过重

- **现象**：`pnpm dev` 首次打开首页或编辑页时长时间等待，返回首页时还会与截图补生争抢资源；Docker 生产构建正常。
- **根因**：根布局的 Toast 通过 `@workbench/ai-chat-shared` 根入口间接纳入 Streamdown/Shiki；编辑页经过 demo-ui 聚合入口读取具体符号；首页水合后立即并发补生所有缺失截图。
- **当前结论**：已将 Toast 切到轻量子路径，将编辑页预览/画布/配置依赖切到 demo-ui 具体 exports，将截图元数据读取改为接近视口时加载，并将截图补生改为延迟后串行。AI Chat 现通过宿主专用入口加载，空会话的消息富文本渲染器也延迟到出现消息后下载。第三阶段进一步清除了编辑页同步依赖链上的 demo-ui 根入口，包括画布持久化、视觉编辑、运行时配置、原型编辑和评论 API，避免 Milkdown/DocumentEditor 被根索引带入主体 chunk。当前行为规则见 [开发环境路由编译性能](../../项目文档/创作端/06-基础设施/技术/07_开发环境路由编译性能.md)。
- **待办**：继续按冷启动产物体积排查编辑页主体中的文档编辑器、知识文档弹窗和设计规范 Provider，只在用户切换到对应视图或打开弹窗时加载。
- **环境风险**：项目统一使用 Node 24 LTS；切换主版本后须重建 `better-sqlite3` 等原生扩展。Next.js 14.1.0 曾在 Node 24 下出现 Undici Request body 异常，需在后续 Next.js/Turbopack 升级中持续回归验证，不能再以已 EOL 的 Node 20 作为长期规避方案。
