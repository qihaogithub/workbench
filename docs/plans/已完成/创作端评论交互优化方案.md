# 创作端评论交互优化

> 计划文档，记录评论交互优化的目标、范围、方案与进度。

## 背景与目标

评论功能（demo-ui `packages/demo-ui/src/comment/`）已支持 pin 锚点、侧栏列表、线程弹窗、@AI 异步任务。当前存在几处交互体验断点，本次按用户确认的范围优化：

1. 状态文案不统一：侧栏显示英文 `pending/processing/...`，线程弹窗显示中文「排队中/执行中/...」。
2. `failed` 无出路：失败后无重试入口。
3. 线程弹窗固定在 pin 位置弹出，无法自由移动；靠边时可能溢出视口。
4. 回复无法指定回复对象，长线程上下文混乱。

范围确认（用户已选）：线程弹窗可拖动、状态文案统一 + failed 重试、pin 失效兜底（视口钳制）、回复可指定回复对象。**不做**已读/未读与通知。

## 方案

### 1. 状态文案统一
- 新增 demo-ui 共享常量 `AI_STATUS_LABEL`（中文），供 `CommentSidebar` 与 `CommentThreadPopover` 共用。
- `CommentSidebar.tsx:136` 英文状态改为中文标签。

### 2. failed 重试
- 后端 `comment-store.ts` 新增 `retryAiTask(projectId, threadId)`：将线程 `aiTaskStatus` 置回 `pending`，写盘 + 广播 `comment:ai-status` + 调 `enqueueAiTask` 重新入队。
- author-site 新增 API：`POST /api/projects/[projectId]/comments/[threadId]/retry-ai`。
- demo-ui `CommentApiAdapter` 增加 `retryAiTask(threadId)`；author-site 适配器实现。
- `CommentThreadPopover` 在 `failed` 状态显示「重试」按钮。

### 3. 线程弹窗可拖动
- `CommentThreadPopover` 增加拖拽把手（标题栏），拖动更新弹窗位置。
- 视口钳制：拖拽/初始定位时限制在视口内，避免溢出。

### 4. 回复可指定回复对象
- 每条回复 hover 显示「回复」按钮，点击后在回复输入框预填 `@被回复人` 并聚焦。

## 风险与待确认
