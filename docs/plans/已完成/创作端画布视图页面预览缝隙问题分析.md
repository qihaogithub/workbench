# 创作端画布视图页面预览缝隙问题分析

> 仅记录问题背景、现状和根因，不做修复。

---

## 问题背景

用户项目 `proj_1779608460372`（"底部弹窗"）包含两个页面：「手机」（375×812）和「平板」（768×1024 左右）。在编辑页画布模式下，平板页面预览的右侧和下方出现白色缝隙，内容无法填满分组的白色容器。单页预览模式正常。

---

## 问题现状

将手机和平板页面拖到一起合并为页面分组后：
- 分组容器尺寸固定为第一个页面（手机）的尺寸（375×812）
- 切换到平板页查看时，平板内容被等比缩小塞进手机尺寸的壳子里，右侧和下方空出大片白色缝隙
- 手动拖拽调整分组尺寸可以临时消除缝隙，但切换页面后缝隙又会出现
- 刷新页面重新加载后缝隙依然存在（状态已被持久化）

---

## 根因

两个独立问题叠加：

### 1. 分组容器尺寸不跟随激活页变化

**代码位置**：

- 分组创建：`packages/demo-ui/src/PreviewCanvas.tsx:2153` `handleMergeSelectedPages`，分组 `layout` 取第一个选中页面的 `firstLayout`，宽高固定为第一个页面的尺寸
- 页面切换：`packages/demo-ui/src/PreviewCanvas.tsx:1220` `handlePageGroupActivePageChange`，仅更新 `activePageId`，不调整 `group.layout.width/height`
- 状态加载：`packages/demo-ui/src/PreviewCanvas.tsx:558` `effectivePageGroups`，从持久化恢复分组状态时只过滤页面，不检查 `layout` 与 `activePageId` 的尺寸一致性
- 状态规范化：`packages/demo-ui/src/canvas-kernel.ts:131` `normalizeCanvasStateLayers`，只处理 `nodes` 和 `layers`，完全不碰 `pageGroups`

**链路**：创建分组 → layout 取手机尺寸 → 切换到平板 → layout 不变 → 平板内容被 `computePreviewScale` 等比缩小居中 → 右侧和下方出现缝隙 → 状态持久化保存了不匹配的 {activePageId: 平板, layout: 手机尺寸} → 下次加载直接复现。

### 2. 面板布局宽度溢出导致隐形滚动条

**代码位置**：

- `packages/author-site/src/app/demo/[id]/edit/page.tsx:6537` 编辑页根节点 `div`，`h-screen` 但无 `overflow-hidden`
- `packages/author-site/src/app/demo/[id]/edit/page.tsx:6700` `ResizablePanelGroup`，三个面板按百分比分配宽度（25%+50%+25%），两条拖拽手柄各 4px（`packages/author-site/src/components/ui/resizable.tsx:15` `w-1`），总宽 = 100% + 8px
- `packages/author-site/src/app/globals.css:39-46` 全局 `* { scrollbar-width: thin; }` 和 `*::-webkit-scrollbar { width: 6px; height: 6px; }`

**链路**：面板百分比 + 手柄固定宽度超出屏幕 → 超出部分被 `flex-1 overflow-hidden` 裁剪，但根节点无 `overflow-hidden` → body/html 出现 6px 宽滚动条 → 预览区实际可用宽度减少 6px → 右侧缝隙。

## 后续方向

- 修复 1：分组切换页面时同步调整 `group.layout.width/height` 为当前页 `previewSize`
- 修复 2：状态加载时在 `effectivePageGroups` 中规范化为激活页尺寸
- 修复 3：根节点加 `overflow-hidden` 消除手柄宽度溢出的隐形滚动条
