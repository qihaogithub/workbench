# 创作端 Markdown 编辑器 Crepe 迁移实施计划

## 背景

共享 `DocumentEditor` 当前以 Milkdown Kit 组合插件并自行维护斜杠菜单、选区工具条、块手柄和局部样式。标准 Markdown 能力可用，但交互完整度、排版主题和复杂块操作与 Milkdown 官方 Crepe 演示存在明显差距。

## 目标

- 所有 `DocumentEditor` 消费入口统一迁移到 Crepe，不保留旧实现开关。
- 保持现有 `value`、`onChange`、`readOnly`、`placeholder`、`uploadHandler`、`referenceCandidates`、`className` 接口和 Markdown 存储协议。
- 使用 Crepe 的标准块编辑、选区工具条、链接、图片、表格、代码块、列表、光标和占位能力。
- 使用项目 CSS tokens 构建自适应宿主主题，同时适配暗色工作台和浅色弹窗。
- 通过 Crepe `BlockEdit.buildMenu` 扩展配置引用、视频和附件入口。
- 不启用 LaTeX 和 Crepe AI；可编辑状态启用 Crepe 原生 TopBar，只读状态隐藏。

## 范围

- `packages/demo-ui` 中的共享编辑器实现、样式、测试与依赖。
- 所有现有 `DocumentEditor` 消费方自动获得新实现，不改各入口的数据保存流程。
- 更新配置与预览模块的共享组件技术文档。

## 方案

`DocumentEditor` 继续作为 React 受控组件边界，内部改为管理单一 Crepe 实例。编辑器创建时注册监听、上传适配和块菜单扩展；外部值变化使用 Crepe/Milkdown 实例同步，读写状态通过 Crepe API 切换。组件卸载时销毁实例，避免事件监听和编辑器状态泄漏。

项目扩展菜单与标准 Markdown 菜单共存：图片使用 Crepe ImageBlock 的上传配置；视频和附件通过隐藏文件输入触发上传，再向当前选择位置插入 Markdown；配置引用按候选项生成可搜索菜单项并插入现有 `@[label](key)` 语法。上传失败保留明确错误反馈，失败时不写入半成品节点。

主题只导入 Crepe 公共结构样式，不直接使用固定明暗主题；编辑器外层按官方 Frame 的色阶关系，从工作台背景/前景 token 推导完整 Crepe 变量。正文、TopBar、浮层和交互状态形成稳定层级，表格与节点选中保留 Crepe 组件级规则，小尺寸宿主允许内容铺满，并遵守 `prefers-reduced-motion`。

- 在创作端文档入口执行：输入与撤销、`/` 菜单键盘选择、文本选区格式、链接编辑、表格/代码块、图片/视频/附件上传、配置引用、只读切换和外部值回填。

## 风险与待确认事项

- Crepe 的公共样式选择器可能随小版本变化；自适应主题集中在独立样式文件，降低升级影响。
- 编辑器消费入口尺寸差异大；主题已覆盖窄容器响应式，部署/重启新 author-site 后仍建议补一次全屏文档、弹窗备注和使用端人工视觉回归。
- 当前工作区已有与旧 Milkdown 迁移相关的未提交改动；本任务在其现状上继续演进，不触碰无关改动。
