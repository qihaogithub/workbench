## 根因假设

**后端已完全正常，问题在前端显示/刷新机制：**

1. **`WorkspaceFileTree` 不自动刷新** — 组件仅挂载时 fetch 一次根目录（`useEffect` deps `[sessionId, showKnowledge]`），上传附件后不会重新请求
2. **文件面板 doc/code 双视图** — `fileView` 默认 `"doc"`，`WorkspaceFileTree`（code 视图）在 `fileView === "code"` 时才挂载。用户需切换到 code 视图才能看到文件树
3. **浏览器缓存** — 即使硬刷新，可能因浏览器缓存或前端 bundle 未更新导致显示旧状态
4. **上传后无刷新触发** — `chat-input.tsx` 上传附件后，没有通知 `WorkspaceFileTree` 重新 fetch 的机制

## 复现步骤

1. 打开项目编辑页（如 `http://localhost:3200/demo/proj_1785858256243_p2zs4y/edit`）
2. 在 AI 对话输入框使用回形针按钮上传一个非图片文件（如 `.md`/`.txt`/`.pdf`）
3. 等待 AI 处理完成
4. 切换到左侧文件栏（点击"文件"标签）
5. 在文件栏内点击"code"视图（如果默认显示 doc 视图）
6. 观察是否出现"聊天文件"目录

**如果仍不显示：**
- 硬刷新页面（Cmd+Shift+R）
- 再次切换到文件栏 code 视图
- 检查浏览器开发者工具 Network 标签，确认 `/api/sessions/{sessionId}/workspace/files?path=` 请求返回的 children 中是否包含"聊天文件"

## 风险与遗留问题

- **旧附件**：迁移前在 `data/ai-attachments/{sessionId}/` 下的附件不会被迁移到新路径，且不再被读取。如果项目中有旧 session 绑定的附件，需评估是否需要保留或迁移。
- **内联图片**：粘贴/拖拽图片走的不是附件上传路径（直接 base64 内联），不会出现在"聊天文件"中。这是预期行为，但需确保用户知晓。
- **GC 机制**：`OPS/automations/` 下已有附件 GC runbook（`daily-attachment-gc.md`），当前为 `report-only` 级别，后续需评估是否启用清理。
