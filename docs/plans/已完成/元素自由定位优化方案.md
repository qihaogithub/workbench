### 第二轮修复（2025-07-31）

验证结果同上不变。针对第一轮实施后发现的 3 个问题修复：

| 问题 | 根因 | 修复 |
|------|------|------|
| 预览区元素无法拖拽 | `data-pos-key` 属性未在页面 DOM 中设置 | `positionEditScript` 在 `enter()` 时扫描容器内 `position: absolute` 元素，按 style.left/style.top 与当前 positions 值匹配，自动注入 `data-pos-key` |

## 背景

`$demo.positionable` 允许用户在 Schema 中声明可定位子组件列表，通过配置面板中的缩略画布拖拽或输入坐标来调整元素在容器中的 X/Y 位置。当前实现的核心流程：

1. Schema 声明 `$demo.positionable`（items / defaults / size）—— 自 config.ts 重构后，Agent 在 `config.ts` 中使用 `$positionable` 顶层 key 声明（格式与 `$demo.positionable` 一致），由 `packages/shared/src/config-compiler.ts` 1:1 透传编译为 `$demo.positionable`，运行时消费者路径不变
2. `__positions` 以隐藏 prop 注入组件代码，组件代码需在 DOM 上添加 `data-pos-key` 属性
3. 配置面板渲染 280×200px 缩略画布，等比缩放容器，在画布上拖拽方块
4. 元素尺寸通过 postMessage 协议从 iframe 收集（`COLLECT_POSITIONABLE_SIZES` → `POSITIONABLE_SIZES_RESULT`）
5. 坐标变更写入 `formData.__positions`

## 当前问题

### 1. 缩略画布与真实预览脱节

- 用户在 280×200px 的迷你画布上拖拽缩放后的方块，无法看到实际渲染效果
- 小尺寸元素在缩放后几乎不可见（例如 40×40px 元素缩放后仅 ~14×14px），难以精确操作
- 网格线基于 100px 间距，与元素实际尺寸无关联

### 2. 鼠标事件边界问题

- 使用 `onMouseDown` / `onMouseMove` / `onMouseUp`（`ConfigForm.tsx` 513-540 行）
- 鼠标拖拽到画布外时丢失 `mousemove`，依赖 `onMouseLeave` 兜底结束拖拽
- 不支持触摸设备（平板/手机）

### 3. `data-pos-key` + postMessage 尺寸收集协议脆弱

- 组件代码必须手动添加 `data-pos-key` 属性，增加创作端用户的心智负担
- 尺寸收集依赖 500ms 图片加载超时兜底（`iframe-template.ts` 2099-2119 行），时序不确定
- 仅在父窗口主动发送 `COLLECT_POSITIONABLE_SIZES` 时才回传，不是实时推送
- 找不到元素或尺寸为 0 时回退到无尺寸的标签方块

### 4. 每次拖拽触发 React re-render

- 每个 `mousemove` 调用 `onPositionsChange({ ...positions, [key]: { x, y } })`（533 行）
- 导致整个 `PositionControl` 组件在每次鼠标移动时重新渲染，画布 60fps 拖拽下产生大量不必要的渲染开销

### 5. 缩放比例失真

- 容器尺寸通过 `positionable.size` → `previewSize` → 800×600 回退链计算
- 缩略画布固定最大 280×200，极端长宽比（如移动端 375×812）下画布非常窄小
- 缩放后的方块位置与实际 DOM 渲染位置可能有亚像素误差

## 优化方案

### 核心思路

废弃缩略画布，向 iframe 注入 `positionEditScript`（类比 `visualEditScript` / `commentModeScript`），用户在预览区**直接拖拽元素本身**来调整位置。

- **无手柄**：不额外渲染拖拽手柄 DOM
- **无边框**：不给元素加选中边框
- **无蒙层**：不添加全局半透明遮罩

视觉提示仅通过 cursor 变化来实现。

#### 为什么不在 iframe 外部叠加

外部叠加层需要完整的 scale/offset 矩阵坐标转换（`computePreviewScale` 3 个分支）、手动跟踪 scrollX/Y 滚动偏移、监听 `ResizablePanelGroup` 容器 resize 重算位置，且与现有 `CommentLayer`（z-20）和 `visualContextMenu`（z-30）存在层级冲突。iframe 内部脚本消除了所有这些问题。

### 用户流程

```
配置面板 "编辑位置" 按钮
→ PreviewPanel 发送 ENTER_POSITION_EDIT { items, positions } 到 iframe
→ positionEditScript 激活：
    - 所有 [data-pos-key] 元素的 cursor 变为 grab
    - 预览顶部显示模式状态栏：[ 位置编辑中 ] [✓ 置灰非可拖拽元素 ] [完成]
    - 默认开启"置灰非可拖拽元素"：非 data-pos-key 元素 opacity 降至 0.3
→ 用户 pointerdown 到可拖拽元素：
    - setPointerCapture 接管指针
    - cursor 变为 grabbing
    - 临时禁用子元素 pointer-events（防止误触内部 button/input/link）
    - pointermove → 操作元素 style.transform 做本地视觉反馈（不触发 config 更新）
    - pointerup → 恢复 cursor 和子元素 pointer-events，postMessage POSITION_CHANGE { key, x, y }
→ 父窗口收到 POSITION_CHANGE → 更新 __positions → UPDATE_CONFIG → 预览重新渲染到最终位置
→ 用户点 "完成" → 发送 EXIT_POSITION_EDIT → 移除 cursor 样式、模式状态栏、置灰样式
```

### 交互设计

#### 光标提示（主要视觉反馈）

| 状态 | cursor |
|------|--------|
| 编辑模式激活，鼠标在可拖拽元素上 | `grab` |
| 正在拖拽 | `grabbing` |
| 编辑模式激活，鼠标在不可拖拽区域 | 默认箭头 |

不需要手柄、边框或蒙层。用户凭 cursor 变化判断哪些元素可拖拽，无需额外视觉干扰。

#### 模式状态栏

位于预览区顶部，半透明浮层，提供：

- **"位置编辑中"** 状态文字
- **"置灰非可拖拽元素" toggle**（默认开启）：开启后，所有非 `[data-pos-key]` 元素 `opacity: 0.3`，帮助用户聚焦可拖拽元素。用户可随时关闭。
- **"完成" 按钮**：退出位置编辑模式

#### 已评估并拒绝的方案

| 方案 | 结论 | 原因 |
|------|------|------|
| 拖拽手柄 | 拒绝 | 增加视觉噪音，额外 DOM 开销 |
| 选中边框 | 拒绝 | 与 visualEditScript 的选中框冲突且视觉干扰 |
| 蒙层 + 元素浮于蒙层之上 | 拒绝 | CSS stacking context 硬性限制：元素可能被父级 `z-index`/`opacity`/`transform`/`filter` 锁在 stacking context 内，无法跨层级提升到文档级蒙层上方。不是实现技巧问题，是 CSS 规范约束。置灰模式（降低非目标元素透明度）无此问题，因为不需要改变 z-index 关系 |
| hover 高亮 | 拒绝 | 拖拽对齐其他元素时有视觉干扰 |

#### 兼容性说明

- **与评论模式不冲突**：评论和配置是两个独立 tab，用户无法同时操作。评论模式激活时不会进入位置编辑，反之亦然。
- **保留坐标输入框**：`PositionControl` 中继续保留 X/Y 数值输入，作为精确编辑入口，同时显示当前坐标。

### 实现要点

1. **新增 `positionEditScript`**：在 `iframe-template.ts` 中注入为 IIFE 字符串，类似于 `commentModeScript` 的注入方式。脚本维护闭包内的编辑态状态（items 列表、当前 positions、dim 开关状态）。

2. **拖拽策略：本地 transform + dragEnd 提交**：
   - 拖拽过程中仅操作元素的 `style.transform`，不触发任何 React 状态更新，保证 60fps 流畅拖拽
   - `pointerup` 时计算最终位置，发送单次 `POSITION_CHANGE` 消息
   - 父窗口更新 `__positions` 后发送 `UPDATE_CONFIG`，React 重新渲染到最终位置
   - 这避免了每帧 config 更新导致 React 卸载/重建 `[data-pos-key]` 元素、打断拖拽状态的问题

3. **消息协议扩展**：

   | 方向 | 类型 | 载荷 |
   |------|------|------|
   | 父→子 | `ENTER_POSITION_EDIT` | `{ items: string[], positions: Record<string, {x,y}> }` |
   | 父→子 | `EXIT_POSITION_EDIT` | 无 |
   | 子→父 | `POSITION_CHANGE` | `{ key: string, x: number, y: number }` |

4. **拖拽时子元素交互屏蔽**：`pointerdown` 时临时设置子元素 `style.pointerEvents = 'none'`，`pointerup` 时恢复。防止拖拽目标元素内部的可点击子元素抢走事件。

5. **多元素重叠的命中处理**：`pointerdown` 时用 `document.elementsFromPoint()` 取最上层 `[data-pos-key]` 元素，不穿透到下层。

6. **拖拽约束**：限制元素边界不能移出容器（`getBoundingClientRect` 计算），delta 叠加到当前 `style.transform` 时做 clamp。

7. **置灰模式实现**：通过注入 CSS rule 实现，不依赖 JS 逐元素操作：
   ```css
   body.position-editing.position-dimming :not([data-pos-key]),
   body.position-editing.position-dimming :not([data-pos-key]) * {
     opacity: 0.3;
   }
   ```
   toggle 切换时仅增删 body 上的 CSS class。

8. **模式状态栏 UI**：`fixed` 定位浮层，z-index 与 comment overlay 同级（`2147483646`），避免被页面内容遮盖。

9. **双向同步**：用户在配置面板通过坐标输入框修改位置时，通过 `UPDATE_CONFIG` 更新 iframe 内渲染，元素自然移动到新位置，不需额外同步手柄（因为无手柄）。

### 收益

- **所见即所得**：100% 准确的视觉反馈，用户在真实预览中直接拖拽，所见即所得
- **不再需要缩略画布和缩放计算**：移除 `PositionControl` 中的缩略画布渲染逻辑和 scale factor 计算
- **不再需要尺寸收集**：新方案中元素尺寸自然可见，无需 `COLLECT_POSITIONABLE_SIZES` → `POSITIONABLE_SIZES_RESULT` 协议（坐标输入框的 max 约束可通过 iframe 内 `getBoundingClientRect` 获取）
- **触摸设备支持**：Pointer Events + `setPointerCapture` 天然支持触摸、笔和鼠标
- **无拖拽边界丢失**：`setPointerCapture` 确保指针事件跟到 iframe 外也不会丢失
- **流畅拖拽**：拖拽中仅操作 `style.transform`，不触发 React re-render
- **代码量约 200-300 行**：复用已验证的脚本注入模式
