## 目标

在创作端项目编辑页「文档」视图（`DocumentView`）中，新增「设计规范」文件夹，支持多份设计规范文档的录入与维护：

- 目录区新增「设计规范」可折叠文件夹，默认空；`+` 新建一份设计规范文档。
- 选中某份设计规范文档后，右侧编辑区切换为 demo 的三区布局：中栏为规范卡片列表（条目为主体），右栏为配置项素材池（绑定素材）。
- 完整复刻 demo 交互：卡片展开/折叠、重命名、删除、通用 Crepe Markdown 编辑、从配置项池拖拽绑定、配置项表格（缩略图+名称+格式+尺寸）、值 swatch 只读投影、搜索/绑定过滤、悬停放大与图片全屏、卡片排序。
- 本次不做 AI 集成（不注入 system prompt），仅前端录入/维护。

## 数据模型

```
workspace/design-spec/
├── manifest.json                 ← 目录索引（列表/排序）
│    { version: 1, items: [{ id, title, createdAt, updatedAt }] }
└── spec-{id}.json                ← 单份设计规范文档
     {
       id: string,
       title: string,             // 规范文档名
       createdAt: string,
       updatedAt: string,
       entries: [                 // 卡片条目（同远期规划数据模型）
         {
           id: string,
           title: string,         // 条目名，如"主按钮"
           markdown: string,      // 富文本说明，可选
           refs: [                // 引用的配置项
             { scope: "project"|"page", pageId?: string, fieldKey: string }
           ]
         }
       ]
     }
```

**核心不变量**（沿用远期规划）：只存“条目结构 + 说明文字 + 对配置项的引用”，不存配置值。值实时从 `project.config.schema.json` / 页面 `config.schema.json` 投影，规范永不过期。

**引用稳定性**：页面级配置项按 `pageId + fieldKey` 引用；页面删除后引用悬空 → 卡片中显示“已失效引用”灰条，不阻断，由设计者清理。

## 配置项素材池聚合

从项目级 + 各页面级 schema 生成配置项列表，供右栏素材池使用。输入：`project.config.schema.json` 内容 + 各页面 `demos/{pageId}/config.schema.json` 内容。复用 `@workbench/demo-ui` 的 `parseSchemaToFields` / `getDefaultValues`。

每个配置项结构：

```ts
interface ConfigPoolItem {
  id: string;                       // `${scope}:${pageId?}:${fieldKey}`，用于绑定去重
  scope: "project" | "page";
  pageId?: string;
  pageName?: string;
  key: string;                      // fieldKey
  title: string;
  kind: "color" | "text" | "image" | "number" | "motion";
  value?: unknown;                  // schema default
  category?: string;                // schema ui:options.category
  format?: string;                  // 图片从 default 扩展名推断
  size?: { w?, h?, wMin?, wAny?, hMin?, hAny? };  // 图片尺寸约束，demo 为 mock
  pages?: string[];                 // 项目级配置项受影响的页面标题，用于拆分展示
}
```

kind 映射：`format==="color"` 或 `type` 含 color → color；`type`/`uiWidget` 为 image/imageList → image；`type` number/integer → number；`uiWidget` 或 `key` 含 motion/animation → motion；其余 → text。

**素材池分组（按页面，非按类型）**：右栏配置项列表按**受影响页面**折叠分组（每个页面一个折叠列表，默认展开），不再按配置类型分组。项目级配置项通过 `pages` 字段拆分到每个受影响页面下展示；页面级配置项归入其所在页面。分组顺序按受影响页面顺序（项目级项拆分后不设独立"项目级"分组）。

### API 契约

- `GET /api/design-specs?workingDir=&sessionId=` → `{ success, data: DesignSpecMeta[] }`
- `POST /api/design-specs?workingDir=&sessionId=` body `{ title }` → `{ success, data: DesignSpecDoc }`
- `GET /api/design-specs/[docId]?workingDir=&sessionId=` → `{ success, data: DesignSpecDoc }`
- `PUT /api/design-specs/[docId]?workingDir=&sessionId=` body `{ doc }` → `{ success }`
- `DELETE /api/design-specs/[docId]?workingDir=&sessionId=` → `{ success }`
- `GET /api/design-specs/config-pool?workingDir=&sessionId=` → `{ success, data: ConfigPoolItem[] }`

live workspace 分支复用 `getLiveWorkspaceRouteContext` + `commitWorkspaceMutation`（与知识库 `knowledge` API 一致）；非 live 走直接 fs。

## 交互（复刻 demo）

Demo 页面为三栏布局（对照创作端项目编辑页）。**实现时仅复刻中、右两栏**（设计规范编辑区 + 配置项素材池）；左栏为 AI 对话区，属既有编辑页布局，本次不新增逻辑。

- **目录区**：新增「设计规范」文件夹（可折叠，`FolderOpen`，e.g. cyan 图标），悬停 `+` 弹窗输入文档名新建；子项为各设计规范文档，点击选中。
- **中栏（设计规范编辑区）**：
  - 无外层标题卡片；条目卡片直接铺满，右下角悬浮圆形 `＋` 新建条目。
  - 每条目一张卡片：标题（可重命名）、展开/折叠、删除。
  - 展开后：已绑定配置项表格（缩略图 + 名称 + 格式 + 尺寸） + 通用 Crepe Markdown 说明编辑区。
- **右栏（配置项素材池）**：
  - 顶部面板头 + 搜索框 + 分类过滤 chips（全部/图片/动效/色值/文字/数值）+ 绑定过滤段（全部/已绑定/未绑定，默认「未绑定」）。
  - 按受影响页面折叠分组（默认展开），项目级配置拆分到各页面；分组头可点击折叠/展开并显示各项数。
  - 每项：swatch（颜色块/文字/图片缩略）、名称、类型、已绑定标签；**无悬浮 `＋` 按钮**（拖拽即可绑定）。

**拖拽交互（区分三种落点）**：
- 配置项拖到**已有卡片** → 绑定到该条目。
- 配置项拖到**中栏空白区** → 自动新建条目并绑定该配置项。
- **卡片拖到另一卡片** → 排序（移到目标之后）；卡片 `draggable`，与配置项拖拽用不同 dataTransfer 键区分。

**配置项绑定表格**：每行 = 缩略图（图片显示默认值缩略图，其余类型固定图标，悬停放大第一列图 + 所在页面示意） + 名称 + 格式 + 尺寸。尺寸格式：`W=xxx H=xxx` / `W≥xxx H=xxx` / `W=不限 H=xxx`。删除按钮为垃圾桶图标，悬浮该行时出现，绝对定位不占列宽。

**图片交互**：
- 素材池 & 卡片表格缩略图的配置项图片，悬停放大气泡（不含名称）。
- 点击打开全屏蒙层，**并排展示两张图**——左侧配置项默认图、右侧所在页面示意图；滚轮**整体缩放**、拖拽整体平移、点击或 Esc 关闭，两张图不显示名称。

## 风险与待确认

- 图片「尺寸/格式」列在真实 schema 中无法可靠推导（demo 为 mock）：格式可从 default 扩展名推断，尺寸约束（`W≥xxx`/`W=不限`）需 schema 提供或留空，首版以推断格式 + 留空尺寸为主。
- 项目级配置「受影响页面」拆分依赖 `pages` 字段，真实 schema 无此信息，需实现时定义推导规则（如扫描各页面引用该 fieldKey 的 usage）或默认归入全部页面，待确认。
- 设计规范在 live workspace 的写入走 mutation authority，需保持与知识库一致，避免被 AI 工具旁路。
- 远期：抽离纯数据读写到 `project-core` 供 CLI 复用；AI 集成（读注入 + 写工具）后续迭代。
