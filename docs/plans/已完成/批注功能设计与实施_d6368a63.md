# 评论功能设计与实施

## Summary

在创作端（author-site）和浏览端（viewer-site）添加类 Figma 评论功能。用户在页面内容区域点击即可添加评论，系统自动捕获点击位置下方元素的信息作为上下文（位置参考，非语义绑定）。支持线程回复、@提及（标记对象 + 筛选）、匿名评论、解决/重新打开。@AI 时异步触发 Agent 处理并自动回复。实时同步采用 REST + WebSocket。数据两端共享可见。

---

## 核心设计决策

### 评论定位策略

**产品原则：评论只能在页面内容上添加（单页面模式和画布模式均如此），不能放在画布空白区域。因此每条评论必然落在某个元素之上，系统总是捕获该元素信息。但元素信息只是位置上下文，不代表评论语义上"针对"该元素——是元素相关还是页面相关，由阅读者（人或 AI）自行判断。**

交互流程：
1. 用户开启评论模式
2. 点击页面内容任意位置 → 系统捕获点击位置下方元素的 domPath + 快照
3. 弹出评论输入框 → 提交
4. pin 显示在点击位置

技术实现（利用现有 iframe 运行时 `VisualNodeInfo`，`packages/demo-ui/src/iframe-types.ts`）：
- 点击时通过 iframe postMessage 获取点击坐标下方最内层元素的 `VisualNodeInfo`（domPath、tagName、rect、sourceLocation 等）
- 存储 `pin: { xRatio, yRatio }` (0~1 归一化坐标) 作为 pin 视觉定位
- 存储 `anchor` 元素信息作为上下文参考
- 查看时向 iframe 发送 `LOCATE_ELEMENT` 按 domPath 重新查询位置；失败则用 pin 回退

### 实时同步：REST + WebSocket 通知

- **写入主路径**：REST API（author-site route handlers）
- **通知层**：agent-service 新增轻量 WebSocket 频道 `/ws/comments`
  - 客户端连接后发送 `{ type: "subscribe", projectId }` 订阅
  - REST API 写入成功后，通过内部 HTTP 调用 agent-service 的 `/internal/comments/notify` 触发广播
  - 广播事件：`comment:created`、`comment:replied`、`comment:resolved`、`comment:deleted`
  - 客户端收到事件后 SWR mutate 刷新本地数据
- 无需 Yjs，纯 JSON 事件广播，Agent 也能消费

### Agent 友好设计

**核心原则：Agent 读 comments.json 获得评论意图和位置元素上下文，按需深入获取元素当前状态。**

- 每条评论自动携带锚点元素快照（`CommentElementSnapshot`）：
  - `outerHtml`、`computedStyle`、`className`、`sourceLocation`、`editCapabilities`
  - 快照是创建时的参考信息，可能过期；Agent 应结合当前代码判断
- 新增 `inspect_element` 工具：Agent 可按 domPath 或源码位置主动获取元素当前状态
- 评论存储为纯 JSON 文件（`data/projects/<projectId>/comments.json`），Agent 文件工具可直接读取
- 在 `packages/agent-service/src/backends/pi-tools/` 新增评论工具：
  - `read_comments`：按 projectId + 可选 pageId 读取评论，输出格式化结构化文本
  - `inspect_element`：按 domPath / sourceLocation 获取元素当前状态（读源码 + 解析结构）
  - `reply_comment`：向指定线程添加回复
  - `resolve_comment`：标记线程已解决/重新打开
- Agent 回复的 author 标记为 `{ id: "agent", name: "AI 助手", isAnonymous: false, isAgent: true }`

**`read_comments` 工具输出示例：**
```
[评论 #a3f2] 页面: 首页 (page-1) | 状态: 未解决
  用户(张三): 把这个按钮改为红色
  位置元素: <button class="cta-primary">立即购买</button>
  源码位置: demos/page-1/index.tsx:42
  ---

[评论 #b7c1] 页面: 首页 (page-1) | 状态: 未解决
  匿名: 整体配色太暗，能不能明亮一些
  位置元素: <section class="hero-banner">...</section>
  源码位置: demos/page-1/index.tsx:18
```

### @提及机制

**产品定位：@不是推送通知，而是标记“这条是留给谁的” + 支持筛选。@AI 则同时将评论变为异步任务。**

**创作端（author-site）：**
- 评论/回复时可选择 @用户 或 @AI
- 默认不 @ 任何人 → AI 可读但不会被激活
- 评论即任务：创作端用户可以批量留多条评论各 @AI，然后继续做其他事，Agent 在后台统一处理

**浏览端（viewer-site）：**
- 只能 @人，不能 @AI
- 可 @人员 = 浏览过该项目的已登录用户，按最近浏览时间排序

**UI 表现：**
- 评论内容中 @名称高亮显示
- 评论列表支持筛选：“全部” / “@我的” / “未解决”
- @AI 评论显示任务状态徽标（排队中/执行中/已完成/失败）
- 无站内通知中心，无离线推送

### @AI 执行模型：项目级任务队列

**核心设计：评论即异步任务。多条 @AI 评论进入项目级队列，单个 Agent 会话批量消费，逐条回复。**

与对话框的互补关系：
- 对话框：同步、一问一答、探索性讨论
- 评论 @AI：异步、批量、明确指令、每条可追踪状态

执行流程：
1. 用户创建评论并 @AI → REST API 检测 mentions 含 `{ type: "agent" }`
2. 评论 aiTaskStatus 置为 `"pending"`，加入项目任务队列
3. 调用 agent-service `POST /internal/comments/ai-task` 通知有新任务入队
4. agent-service 检查该项目是否已有活跃 Agent 会话：
   - 无 → 启动新会话，提示词包含该项目所有 pending 评论列表
   - 有 → 将新评论追加到当前会话上下文（Agent 继续处理）
5. Agent 统一规划：看到所有待处理评论 → 按页面/文件分组 → 顺序执行避免冲突
6. 每完成一条：`reply_comment` 回复结果 + 更新 aiTaskStatus="done" + WS 广播
7. 失败的评论：aiTaskStatus="failed" + 回复失败原因
8. 队列清空后会话结束

优势：
- 全局视角：Agent 知道“还有 3 个任务”，可合并相关修改、避免冲突
- 用户无需等待：留完评论继续工作，回复实时出现在评论线程中
- 可追踪：每条评论有独立状态（pending/processing/done/failed）

**项目访问者追踪：**
- 新增 `data/projects/<projectId>/visitors.json`：`{ visitors: [{ userId, name, lastVisitedAt }] }`
- viewer-site 已登录用户打开项目时，调用 `POST /api/projects/[pid]/visit` 记录/更新访问时间
- 浏览端 @候选人列表从 visitors.json 读取，按 lastVisitedAt 降序

### 匿名评论

- API 不强制鉴权；未登录用户提供 `displayName`（可选，默认"匿名用户"）
- 匿名用户分配临时 `anonymousId`（UUID，存 localStorage）
- 登录用户通过现有 JWT / X-Auth-Token 鉴权
- 匿名用户不能 @人（无身份），但可以创建普通评论

### 数据存储

- 文件路径：`data/projects/<projectId>/comments.json`
- 与现有项目数据同目录，格式为 `{ threads: CommentThread[] }`
- 不依赖 SQLite，保持文件系统一致性，Agent 文件工具可直接读写

## 数据模型

```typescript
// packages/shared/src/comment.ts

export interface CommentAuthor {
  id: string;           // userId | anonymousId | "agent"
  name: string;
  isAnonymous: boolean;
  isAgent?: boolean;
}

export interface CommentMention {
  type: "user" | "agent";
  id: string;           // userId 或 "agent"
  name: string;
}

export interface CommentReply {
  id: string;
  content: string;
  author: CommentAuthor;
  mentions?: CommentMention[];
  createdAt: number;
}

export interface CommentElementSnapshot {
  className?: string;              // CSS 类名
  outerHtml?: string;              // outerHTML 前 300 字符
  computedStyle?: Record<string, string>; // 关键计算样式
  attrs?: Record<string, string>;  // 属性（src, href, role 等）
  sourceLocation?: {               // 源码定位（高保真页可用）
    file: string;                  // e.g. "demos/page-1/index.tsx"
    line?: number;
    column?: number;
  };
  editCapabilities?: string[];     // ['style','text','image','link','structure']
}

export interface CommentAnchor {
  domPath: string;        // 点击位置下方元素的 CSS 选择器路径
  tagName: string;
  componentName?: string;
  textSnippet?: string;   // 元素文本前 80 字符
  snapshot?: CommentElementSnapshot; // 创建时元素快照（参考信息，可能过期）
}

export interface CommentThread {
  id: string;
  projectId: string;
  pageId: string;
  anchor: CommentAnchor;   // 必有：评论位置下方元素（位置上下文）
  pin: { xRatio: number; yRatio: number };  // 必有：pin 视觉定位
  content: string;
  author: CommentAuthor;
  mentions?: CommentMention[];
  aiTaskStatus?: "pending" | "processing" | "done" | "failed";
  createdAt: number;
  updatedAt: number;
  resolved: boolean;
  replies: CommentReply[];
}

// WebSocket 事件
export type CommentWsEvent =
  | { type: "comment:created"; thread: CommentThread }
  | { type: "comment:replied"; threadId: string; reply: CommentReply }
  | { type: "comment:resolved"; threadId: string; resolved: boolean }
  | { type: "comment:deleted"; threadId: string };
```

### 1. `@workbench/shared` — 类型定义

- 新增 `packages/shared/src/comment.ts`

### 2. `author-site` — REST API + 存储

新增路由 `packages/author-site/src/app/api/projects/[projectId]/comments/`：

| 路由 | 方法 | 功能 |
|------|------|------|
| `.../comments` | GET | 列出评论（可选 `?pageId=&resolved=` 过滤） |
| `.../comments` | POST | 创建评论线程 |
| `.../comments/[threadId]` | PATCH | resolve/reopen/编辑 |
| `.../comments/[threadId]` | DELETE | 删除线程 |
| `.../comments/[threadId]/replies` | POST | 添加回复 |
| `.../comments/[threadId]/replies/[replyId]` | DELETE | 删除回复 |
| `.../visit` | POST | 记录已登录用户访问（更新 visitors.json） |
| `.../visitors` | GET | 获取访问者列表（@候选人，按最近浏览排序） |

新增 `packages/author-site/src/lib/comment-store.ts`：
- 读写 `data/projects/<projectId>/comments.json`
- 使用 `fs-utils.ts` 已有的 `PROJECTS_DIR` 路径体系
- 写入后调用 agent-service 内部通知接口触发 WS 广播

鉴权：
- GET 公开
- 写入操作：有 token 解析 userId；无 token 要求 `anonymousId` + `displayName`
- 删除/编辑：作者本人或管理员

### 3. `agent-service` — WebSocket 通知频道 + Agent 工具

**WebSocket 频道**（`packages/agent-service/src/routes/comments-ws.ts`）：
- 路径：`/ws/comments`
- 协议：客户端发 `{ type: "subscribe", projectId }` / `{ type: "unsubscribe", projectId }`
- 服务端维护 `Map<projectId, Set<WebSocket>>` 订阅表
- 广播接口：`POST /internal/comments/notify`（body: `{ projectId, event: CommentWsEvent }`），仅接受内部调用（localhost / 内部 token）

**Agent 工具**（`packages/agent-service/src/backends/pi-tools/comment-tools.ts`）：
- `read_comments`：参数 `{ projectId, pageId?, resolved? }` → 读取 comments.json 返回格式化列表
- `inspect_element`：参数 `{ projectId, pageId, domPath? | sourceFile+line? }` → 读取源码获取元素当前状态
- `reply_comment`：参数 `{ projectId, threadId, content }` → 追加回复 + 触发 WS 通知
- `resolve_comment`：参数 `{ projectId, threadId, resolved }` → 更新状态 + 触发 WS 通知

**AI 任务队列接口**（`POST /internal/comments/ai-task`）：
- 由 author-site REST API 在检测到 @AI 提及后调用
- Body: `{ projectId, threadId }`
- 处理流程（队列制）：
  1. 立即返回 202 Accepted（不阻塞 HTTP 响应）
  2. 检查该项目是否已有活跃 Agent 会话（内存中维护 `Map<projectId, CommentTaskSession>`）：
     - 无 → 读取该项目所有 aiTaskStatus="pending" 的评论，启动新 Agent 会话
     - 有 → 将新评论追加到当前会话上下文
  3. Agent 会话提示词包含：所有待处理评论列表（内容 + 锚点元素 + 源码位置）+ 工作指令
  4. Agent 统一规划、顺序执行，每完成一条：
     - `reply_comment` 回复结果
     - 更新 aiTaskStatus = "done" / "failed" + WS 广播
  5. 队列清空后会话结束，释放项目锁
- 并发安全：项目级锁保证同一项目同时只有一个评论任务 Agent 会话

## 风险与待确认

- **domPath 稳定性**：页面代码变更后 domPath 可能失效。回退：pin 归一化坐标 + textSnippet 模糊匹配。
- **画布模式 pin 定位**：画布有缩放/平移，pin 需跟随 CanvasPageItem 的 transform。需在 CanvasViewport 层注入 overlay。
- **发布可见性**：评论独立于发布版本，始终读取最新 comments.json。
- **并发写入**：文件系统 JSON 在当前用户量下可接受；后续可迁移 SQLite。
- **agent-service 接口安全**：`/internal/comments/notify` 和 `/internal/comments/ai-task` 需限制为 localhost 或内部 token 调用。
- **AI 任务超时**：Agent 会话可能耗时较长，需设置单条评论超时（如 120s）并在失败时更新 aiTaskStatus + 回复错误信息，然后继续处理队列中下一条评论。
- **队列会话中断恢复**：agent-service 重启后，内存队列丢失。启动时应扫描各项目 comments.json 中 aiTaskStatus="pending"/"processing" 的评论，重新入队处理（processing 超过 5 分钟视为失败，重置为 pending）。
