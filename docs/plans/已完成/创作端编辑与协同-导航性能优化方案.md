# 创作端导航性能优化方案

> 日期：2026-08-07
> 状态：方案制定
> 目标：降低「首页 → 编辑页 → 首页」导航耗时，重点是首屏感知与退出阻塞

---

## 一、背景与现象

开发模式下「首页 → 项目编辑页」与「编辑页 → 首页」导航明显卡顿。单看代码无法定位单一根因，已逐项复核并确认 5 个叠加因素（详见第三节）。

本方案只做性能与导航体验优化，不改变编辑页功能、保存流程和会话模型。

## 二、目标与范围

### 目标

- 首页 → 编辑页：点击后尽快出现页面（loading 反馈 + 客户端导航预取）。
- 编辑页 → 首页：无未保存变更时退出不应等待串行 flush 链路。
- 首页：减少返回时重复的截图 meta 请求风暴与 ensure 生成触发。
- 降低 middleware 对所有请求的 JWT 校验开销。

### 范围（涉及文件）

- `packages/author-site/src/components/demo/demo-card.tsx`
- `packages/author-site/src/components/demo/home-page.tsx`
- `packages/author-site/src/app/page.tsx`
- `packages/author-site/src/app/demo/[id]/edit/page.tsx`
- `packages/author-site/src/app/api/sessions/route.ts`
- `packages/author-site/src/middleware.ts`
- `packages/author-site/src/lib/agent-providers.ts`
- `packages/author-site/next.config.mjs`（如需）

## 三、根因分析（已复核）

### 3.1 首页卡片使用原生 `<a>` 而非 `next/link`

`demo-card.tsx:390` 的卡片链接是原生 `<a href>`，不是 `<Link>`：

- 每次点击触发完整页面导航（MPA），不会走 Next.js 客户端导航预取。
- 编辑页路由依赖 `app/loading.tsx`（根目录）提供反馈，但**`/demo/[id]/edit` 没有自己的 `loading.tsx`**，全页导航期间无 loading 反馈，dev 下等待按需编译明显。

### 3.2 编辑页为巨型客户端路由，且关键依赖为静态导入

`page.tsx`（8476 行）静态导入：

- `getAgentClient`（AgentClient 实例）
- `useCollabDocument`（yjs + HocuspocusProvider 静态引入）
- `ai-elements` barrel（re-export @workbench/ai-chat-shared）
- `@/components/demo` legacy barrel（re-export ~50 个 demo-ui 符号，包括 编译产物）

本身已有 19 个 `next/dynamic`，但上述静态导入决定了 dev 首次编译图巨大。`next.config.mjs` 的 `transpilePackages` 含 11 个 workspace 包 + shiki，dev 按需编译首帧慢。

### 3.3 返回首页被串行 flush 链路阻塞

`handleBackClick`（page.tsx:5616）→ `flushBeforeExit`（5548）：

- 若 `hasPendingWorkspaceFlush`，走 `syncWorkspaceToProject`（5267）：**3 次串行 fetch**（persist-active-page → collab-flush → persist-workspace）。
- 全部完成后才 `router.push("/")`。
- 即使无未保存内容，`flushBeforeExit` 仍会 `await flushCanvasState()` 与 `flushSyncWorkspaceRef.current()`，存在不必要等待。
- 浏览器返回键不经过 `handleBackClick`，无阻塞但仍是整页 reload。

### 3.4 首页返回时截图请求风暴

`home-page.tsx`：

- 卡片 `ScreenshotCover`（demo-card.tsx:218）对每个页面发起 `/api/screenshots/file/{projectId}/{pageId}?meta=1`，实测 11 个项目、约 58 个页面 → 每页 1 个 meta 请求，全部代理到 screenshot-service（默认 `:4202`，`getScreenshotProxyTimeoutMs()` 默认 30s）。
- `useEffect`（home-page.tsx:266）对 `!d.thumbnail` 的项目 POST `/api/screenshots/ensure`，**每次返回首页重新挂载都会再次触发**（`ensureTriggeredRef` 仅在单次挂载内防重）。

### 3.5 middleware matcher 过宽

`middleware.ts` 的 matcher 仅排除 `_next/static|_next/image|favicon.ico`，所有页面与 API 请求都跑 `verifyToken`（jose JWT）。受保护路由实际只有 `/demo`、`/cli`、`/api/sessions`。

### 3.6 会话创建同步等待 agent-service 推送

`POST /api/sessions`（route.ts:70）在创建会话后同步 `await`：

- `pushSessionModelConfigToAgent`
- `pushSessionExternalAuthToAgent`

两个推送都 fetch agent-service（`getServerAgentServiceUrl()` 默认 `http://localhost:4201`），**无超时**。agent-service 未启动时，fetch 挂起会阻塞 `loadDemo`（page.tsx:3485）后续 `GET /api/sessions/{id}/files` 的整条链路（`await Promise.all` 或串行）。

## 四、修复方案（按优先级）

### P0：导航链路（点击→出内容）

1. **卡片改 `<Link>`**：`demo-card.tsx` 用 `next/link` 替换原生 `<a>`，并给 `loading.tsx` 提供客户端导航。同时首页进入编辑页会走客户端导航，减少整页 reload 与 middleware 重复执行。
2. **增加编辑页 `loading.tsx`**：`/demo/[id]/edit/loading.tsx`，复用根 `app/loading.tsx` 的样式或简化版，解决全页导航期间无反馈。

### P1：返回首页不被 flush 阻塞

3. **`flushBeforeExit` 短路**：`handleBackClick` 在无 `hasPendingWorkspaceFlush`、无未保存 canvas 变更时，跳过 flush 直接 `router.push("/")`。
4. **flush 链路不阻塞导航**：有变更时改为「后台 flush + 立即导航」或加时间预算（如 2s），避免 3 次串行 fetch 完成后才跳转。

### P2：会话创建链路

5. **agent-service 推送移出关键路径**：`POST /api/sessions` 的 model-config / external-auth 推送改为 `fire-and-forget`（`void` + catch），或用 `AbortSignal.timeout` 包裹；agent-service 不可用时不能阻塞会话创建。检查 `agent-providers.ts` 的 fetch 是否已有超时，无则补。
6. **核对端口常量**：`runtime-config.ts` 中 `DEFAULT_AGENT_SERVICE_URL=4201` 与 `AGENT_SERVICE_PORT=3201`（浏览器侧）是否一致，避免 agent-service 已起但前端连错端口。

### P3：首页请求风暴

7. **截图 meta 请求**：给 `/api/screenshots/file/...?meta=1` 增加 SWR 缓存或前端记忆化，避免返回首页时重复请求；考虑批量 meta 接口。
8. **ensure 触发收敛**：`home-page.tsx` 的 ensure 只在真正缺封面且非本次会话已触发时执行，避免每次返回首页都重新 POST。

### P4：middleware 收窄

9. **收窄 matcher**：仅对 `/demo`、`/cli`、`/api/sessions`、`/api/admin` 等受保护路径执行 `verifyToken`，减少无关请求的 JWT 开销。

## 六、验证方式

- `pnpm check:author`（类型 + 测试）。
- 手测：首页点击进入编辑页出现 loading → 编辑页加载完成 → 返回首页无明显等待。
- 有量化脚本 `scripts/development/measure-edit-page-load.mjs`，可测冷/热导航时长、loading 时长、返回首页耗时，用于 P0/P1 前后对比。
- agent-service 未启动时验证 `POST /api/sessions` 不阻塞。

## 七、风险与待确认事项

- 编辑页首次 dev 编译时间长是根本因素之一，但不在本方案范围（不改依赖结构）；loading 反馈可大幅改善感知，真实绝对耗时改善有限。
- `flushBeforeExit` 后台化需保证 flush 仍在 `beforeunload`/组件卸载前完成，不能丢数据；建议先做「无变更短路」，再做「后台化」。
- 浏览器返回键（非 `handleBackClick`）无法拦截 flush，属既有行为，本次不处理。
- 需确认 agent-service 推送是否依赖会话创建结果顺序（若依赖，fire-and-forget 需调整为创建成功后触发）。
