# 编译与预览管线-图片路径渲染问题沉淀

> 覆盖：编译时路径重写、创作端预览/截图、浏览端发布内容的图片加载问题。

---

## [2026-08-05] 高保真页面预览/截图中相对路径图片无法加载——workspace 端点鉴权阻断

### 现象

项目 `proj_1779608460378`（广场页面）页面截图中，通过相对路径引用的图片全部显示为 broken image（alt 文本），而通过远程 HTTP URL 引用的图片正常渲染。创作端浏览器预览功能正常（用户有登录态），但截图服务生成的缩略图大面积缺图。

### 影响范围

- **受影响项目**：使用 `../../assets/images/xxx.png` 相对路径引用图片的 TSX 页面（仅 2 个项目：`proj_1779608460378`、`proj_1784874964275_p0k4ho`）
- **受影响场景**：所有需要截图服务渲染的场景（项目列表缩略图、截图导出等）
- **不受影响场景**：创作端浏览器预览（用户已登录）、浏览端发布内容（有独立的图片处理管线）

### 根因

**两层问题叠加**：

**问题 1（编译阶段）**：`rewrite-local-paths.ts` 将 TSX 中的相对图片路径重写为 workspace 端点 URL：

```
../../assets/images/xxx.png
  → /api/sessions/{sessionId}/workspace/assets/images/xxx.png
```

**问题 2（渲染阶段）**：Puppeteer 截图时，浏览器请求上述 URL 被 middleware 鉴权阻断：

```
Puppeteer 无 auth_token cookie
  → middleware.ts:91-99 返回 401 "未登录"
  → 图片加载失败
```

完整调用链：

```
TSX 源码: src="../../assets/images/xxx.png"
  ↓ compile API   (rewrite-local-paths.ts)
/api/sessions/{id}/workspace/assets/images/xxx.png
  ↓ <base href="http://localhost:4200/">
Puppeteer 浏览器请求 → http://localhost:4200/api/sessions/{id}/workspace/...
  ↓ middleware.ts:12  PROTECTED_API_ROUTES = ["/api/sessions"]
  ↓ middleware.ts:91-99  无 cookie → 401 JSON
图片 401 → 显示 alt 文本
```

**关键发现**：`/api/images/{imageId}` 端点不在鉴权保护列表中，可公开访问。项目 `images.json` 中每张图片都已有对应的 `/api/images/{imageId}` 公开 URL。

### 修复

**编译阶段 fix**（`rewrite-local-paths.ts` + `/api/compile/route.ts`）：

1. 新增 `resolveRewriteTarget` 函数，接受 `imageManifest?: Map<string, string>` 参数
2. 编译时读 `images.json`，构建 `filename → /api/images/{imageId}` 映射表
3. 重写时优先查映射表，命中则用公开 image store URL，未命中 fallback 到 workspace URL
4. 不改变函数签名兼容性（`imageManifest` 为可选参数）

改动文件：
- `packages/author-site/src/lib/rewrite-local-paths.ts` — 提取 `resolveRewriteTarget`，接受 `imageManifest` 参数
- `packages/author-site/src/app/api/compile/route.ts` — 引入 `getProjectImages`，编译时构建映射表传入

### 补充发现：已有冗余路径处理

`/api/screenshots/ensure` 端点已有独立的图片路径处理（`ensure-image-resolver.ts`），在截图请求发出前先将代码中的相对路径替换为 `/api/images/` 公开 URL。本次修复在编译层面做了相同的事情，未来可考虑收敛到一处。

### 浏览端不更新的原因

浏览端（viewer-site）渲染的是**发布快照**（`data/published/`），不是实时 workspace。发布管线（`image-processor.ts` + `path-replacer.ts`）在发布时将图片复制到 `data/published/proj_xxx/assets/images/`，路径重写为 `/data/proj_xxx/assets/images/hash.png` 绝对路径，作为静态文件服务，不经过 middleware 鉴权。因此浏览端本身不受此问题影响，但如果工作区变更需要反映到浏览端，必须**重新发布**。

另外，浏览端 dev 模式默认 `DATA_BASE=http://localhost:3200`（Docker 端口），本地 dev 需要手动设置 `NEXT_PUBLIC_DATA_BASE=http://localhost:4200` 指向 author-site。

## [2026-08-05] 浏览端项目封面发布后不更新——截图 URL 无缓存破坏参数

### 现象

页面修改并发布后，创作端项目封面立即更新（走 `/api/screenshots/file/{id}?meta=1` 带 hash 的 URL），但浏览端项目卡片封面仍显示旧图。受影响项目为无手动封面（`project.thumbnail` 未设置）、走 `ScreenshotCover` 分支的项目。

### 根因

浏览端 `ViewerApp.tsx` 的 `PageScreenshotCell` 使用发布快照中的固定 `screenshotPath`（`screenshots/demo_xxx.png`）作为静态文件 URL：

```
创作端: /api/screenshots/file/{projectId}/{pageId}?meta=1 → 返回带 hash 的 URL → 无缓存
浏览端: DATA_BASE/data/{projectId}/screenshots/demo_xxx.png → 固定URL
        ↓ data route Cache-Control: public, must-revalidate, max-age=3600
        → 浏览器缓存 1 小时 → 发布后 URL 不变 → 显示旧图
```

即：服务端发布快照已更新，但浏览端浏览器缓存了旧截图（同 URL），封面不刷新。

### 修复

为浏览端截图静态 URL 添加 `publishedVersion` 作为缓存破坏参数（`?v={publishedVersion}`），版本变化即可避开浏览器缓存。`publishedVersion` 从 `ProjectCover` 经 `ScreenshotCover` 传递到 `PageScreenshotCell`。

改动文件：`packages/viewer-site/src/components/ViewerApp.tsx`（三处组件传参）。
