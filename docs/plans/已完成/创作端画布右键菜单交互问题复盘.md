# 创作端画布右键菜单交互问题复盘

## 问题现象

`SketchEditorCanvas` 画布右键菜单交互问题：
1. 气泡内按钮点击无响应 ✅ **已修复**（第一轮 Portal 渲染）
2. 气泡外左键点击无法关闭 ❌ **未解决**，点击时光标穿透到画布显示为抓握手型（`cursor-grab`）

## 排查过程

### 阶段一：确认测试与生产环境差异

sketch-react 的 151 个单元测试（含右键菜单测试）全部通过，但生产环境交互完全失效。测试使用 `fireEvent.click` 直接触发，不模拟完整 pointerdown→pointerup→click 序列，无法覆盖真实事件流中的 stacking context 和 overflow 裁剪问题。

### 阶段二：Playground 验证

`sketch-playground`（隔离环境）中菜单交互正常。说明问题不在组件本身，而在创作端宿主环境。

### 阶段三：发现问题分层

**第一层：按钮不可点击** — 菜单以 `absolute z-30` 渲染在画布容器内，该容器在创作端被多层 `overflow-hidden` 祖先嵌套（ResizablePanel + 包裹层 + CommentLayer 区域），且 Stage div 的 CSS `transform` 创建独立 stacking context。菜单被祖先 `overflow-hidden` 裁剪，部分按钮不可见/不可交互。

**第二层：外部点击不能关闭** — 创作端祖先元素可能拦截 `pointerdown` 事件流（`stopPropagation`），导致 document 级 `pointerdown` 监听收不到事件，画布容器的 `onPointerDown` 也无法触发。

## 修复方案（两轮迭代）

### 第一轮：Portal 渲染（解决按钮不可点击）

- 将菜单改为 `createPortal(..., document.body)` + `position: fixed`
- 彻底脱离画布容器的 `overflow-hidden` 祖先链和 stacking context
- 定位改用视口坐标（`event.clientX/clientY`），不受祖先 transform/offset 影响
- `useLayoutEffect` 按菜单实测尺寸做视口边缘 clamping
- **效果**：按钮可点击，但外部点击仍不能关闭

### 第二轮：Backdrop 遮罩（解决外部点击不能关闭）

- 在菜单同 portal 内追加 `fixed inset-0 z-[9998]` 透明遮罩
- `onPointerDown` → `setContextMenu(null)` 关闭菜单
- 遮罩在菜单之下（`z-9999` > `z-9998`）、所有宿主叠加层之上
- 气泡外任意位置点击均命中遮罩，不再依赖 document 监听能否收到事件
- **效果**：外部点击关闭正常

## 架构经验

### 浮动 UI 渲染规则

Sketch-react 中需要脱离容器定位的浮动 UI（右键菜单、悬浮工具栏、命令面板、快捷键帮助等），必须使用 `createPortal` + `position: fixed` 渲染，避免被祖先 `overflow`、`transform`、`z-index` 影响。

### 外部点击关闭的正确模式

Portal 浮动 UI 的外部点击关闭应采用 **backdrop** 而非 document 事件监听：
- Backdrop 不依赖事件能否冒泡到 document（祖先可能 stopPropagation）
- Backdrop 天然与 portal 同生命周期，无需 useEffect 管理注册/清理
- Backdrop 覆盖整个视口，确保任意位置点击均生效

### z-index 层级策略

| 层级 | 用途 | 值 |
| --- | --- | --- |
| 宿主内容 | 画布、工具栏等 | 低于 portal |
| Backdrop 遮罩 | 浮动 UI 外部点击关闭 | `style={{ zIndex: 9998 }}` |
| 浮动 UI 本体 | 右键菜单、popover 等 | `style={{ zIndex: 9999 }}` |
| 全局模态/对话框 | 最高优先级 | 待定（需高于 9999） |

> 注意：跨包 portal 元素应使用 inline style 设置 z-index，而非 Tailwind 任意值类名（如 `z-[9998]`），因为消费者 Tailwind 可能不扫描该包的源文件。

## 修复历程

### 第三轮：修复 Tailwind z-index 流失效（2025-07-31）

**现象**：第二轮修复后菜单仍无法通过点击菜单外关闭，点击时鼠标变成缩放手势。

**排查与修复**：
- 发现 `z-[9998]`/`z-[9999]` 是 Tailwind 任意值类名，但 `packages/sketch-react/src/` 不在创作端 Tailwind `content` 扫描路径中，这些 CSS 类从未生成
- 将 backdrop/菜单的 z-index 改为 inline style（`style={{ zIndex: 9998 }}` / `style={{ zIndex: 9999 }}`）
- 为 backdrop 添加 `cursor-default` 防止画布光标穿透
- 在 `onContextMenu` 中先调用 `releasePointerCapture()` 释放可能残留的捕获
- **效果**：问题依然存在，外部点击仍无法关闭菜单，inline style 并非根因

**验证**：`pnpm check:sketch-react` 通过（151 测试 + typecheck），但单元测试无法覆盖真实渲染环境。

### 第四轮：深入排查（未解决，记录待续）

> **已解决（2026-08-06）**：按推荐方案 A 落地修复。在 Stage `onPointerDown` 顶部增加主键守卫，`typeof event.button === "number" && event.button !== 0` 时 `event.preventDefault(); return;`，右键不再触发 capture/拖拽/框选，Stage 打开菜单时不会持有 pointer capture，backdrop 的 `onPointerDown` 能正常关闭菜单、菜单项可点击。详见 `docs/plans/进行中/创作端编辑与协同问题沉淀.md`「草图画布右键菜单打开后整页无法点击」。

**排查范围**：审查了从 sketch-react → demo-ui → author-site 的完整组件嵌套链、CSS stacking context、pointer capture 生命周期和事件流。

**关键发现**：

1. **Tailwind 编译范围缺陷**（已修复）：
   - `packages/sketch-react/src/` 不在 author-site `tailwind.config.ts` 的 content 路径中
   - 任意值类名（`z-[9998]`、`z-[9999]`）不会生成 CSS，回退到 `z-index: auto`
   - 但这并非根因——改用 inline style 后问题依旧

2. **Pointer Capture 时序嫌疑**：
   - 右键按下时，Stage div 的 `onPointerDown` 无条件调用 `capturePointer(event)`（不检查 `event.button`，对左/右键一视同仁）
   - 关键代码路径：
     - 选中节点：`capturePointer` → `setActiveDragStart`（index.tsx:6726-6727）
     - 点击空白区域：`capturePointer` → `setActiveMarquee` + `setActiveDragStart`（index.tsx:6740-6742）
   - `pointerup` 中 `releasePointerCapture()` 应释放捕获（index.tsx:6531），但事件顺序为 `pointerdown → pointerup → contextmenu`
   - 如果 `pointerup` 和 `contextmenu` 之间存在 React 批量更新窗口，捕获状态可能未及时清除

3. **Portal 渲染与事件目标**：
   - Backdrop 和菜单通过 `createPortal` 渲染到 `document.body` 末尾
   - Backdrop 为 `position: fixed; inset: 0; z-index: 9998`，理论上覆盖所有宿主内容
   - 但如果 Stage 持有 pointer capture，所有 pointer 事件（包括对 backdrop 的点击）都会被重定向到 Stage
   - 表现为：用户点击 backdrop 区域，但指针事件落到 Stage，光标显示为 canvas 的 `cursor-grab`（被用户描述为"缩放鼠标"）

4. **光标线索**：
   - 当 `isSpacePanning` 为 true 时，画布容器 cursor 为 `cursor-grab`（握拳手型）
   - 用户描述的"缩放鼠标"很可能是 `cursor-grab` 手型光标的视觉误判
   - 光标穿透到画布说明点击事件最终落到了画布上，而非 backdrop

5. **测试盲区**：
   - 151 个单元测试全部通过，但使用 `fireEvent.click` 直接触发事件
   - 无法模拟：真实 pointerdown/pointerup 序列、pointer capture、浏览器 stacking context、CSS overflow 裁剪

**未验证假设**（需要在浏览器 DevTools 中确认）：
- 打开右键菜单后，检查 Elements 面板中 backdrop div 是否存在、是否具有正确的 `z-index: 9998` 和 `position: fixed`
- 打开右键菜单后，检查 Stage 元素是否持有 pointer capture（`document.pointerLockElement` 或检查 pointer events 目标）
- 在 backdrop 的 `onPointerDown` 中添加 `console.log` 验证是否收到事件
- 检查是否有其他元素（如 shadcn/ui dialog overlay）渲染在 backdrop 之上

**后续修复方向建议**：
1. **方案 A（推荐）**：在 Stage 的 `onPointerDown` 中检查 `event.button`，右键（button=2）直接跳过 capture/drag/marquee 逻辑，只保留 `event.preventDefault()`
2. **方案 B**：使用 `window` 级 `pointerdown` 监听（`{ capture: true }`），在事件到达任何元素之前拦截
3. **方案 C**：改用 `onMouseDown` + `onMouseUp` 替代 `onPointerDown`（绕过 pointer capture API 的影响范围）
