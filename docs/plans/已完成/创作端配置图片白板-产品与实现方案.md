# 创作端配置图片白板：产品与实现方案

> 状态：一期及嵌套对象数组图片支持已完成，待灰度与性能基线
> 创建日期：2026-08-28
> 适用范围：创作端配置面板、图片资产、草图绘图 SDK、协同草稿

## 一、背景

当前配置系统中的图片配置主要通过上传或选择已有图片完成。流程图、线框图、标注图和简单插画等素材需要用户先在外部工具绘制，再回到项目上传；后续修改时也无法恢复原始绘图内容。

项目已有 `@workbench/sketch-core` / `@workbench/sketch-react`，具备场景协议、节点编辑、图片处理、撤销重做和 PNG/SVG 导出能力。本方案拟将其封装为配置图片字段可打开的独立白板，不新增页面运行时，也不改变当前页面画布。

本方案不把白板 scene 当作普通图片资产的附属元数据，也不复用页面草图 scene 的存储与协同链路。白板是创作端私有编辑能力；它最终只向页面配置回填一个已本地化的 PNG 引用。

## 二、目标与非目标

### 目标

- 图片配置字段可直接打开类似 Excalidraw 的绘图白板。
- 绘图结果默认导出 PNG，并回填当前图片配置。
- 回填后可再次打开并编辑原始 scene。
- 覆盖标准单图字段、`imageList` 当前项和对象数组内的图片字段。
- 白板的 scene、视口、草稿和保存链路与页面画布隔离。
- 回填成功时，配置值、白板版本、绑定关系和 PNG 引用属于同一 committed revision。

### 非目标

- 不引入 Excalidraw 作为核心编辑器。
- 不把白板设计成新的页面 runtime。
- 不自动改写代码中的任意图片 URL 或普通字符串。
- 第一阶段不把 SVG 作为配置回填格式。
- 不支持 `oneOf`/变体、视频 `poster`、共享/页面跨作用域复用和 Excalidraw 文件兼容；这些能力在稳定目标绑定协议后另行评估。
- 不把白板 scene 放进 HTML sandbox canonical 文件、execution ticket 或页面 runtime。

## 三、方案决策

### 产品形态

白板以配置字段内的弹窗工作台提供。关闭/取消不改变配置；“回填图片”才提交图片值。

- 对已有白板来源图片，入口为“继续编辑绘图”，恢复其已提交的 scene 与编辑视口。
- 对普通上传图、外链图或历史图片，入口为“用白板重新创作”：以原图作为可删除的背景图创建新白板；在用户回填前不修改原字段。
- 图片列表入口位于每个图片项，明确显示“替换当前项”；列表工具栏可提供“追加白板图片”。删除、排序期间不保留悬空目标。
- 视频能力二期仅对白板开放 `poster` 子字段，绝不把入口表述为编辑视频内容。

### 技术路线

复用 `SketchSceneDocument` 和 sketch-react 受控编辑器，新增 `WhiteboardDialog`、`WhiteboardHost`、一等 `WhiteboardDocument` 资源和 `WhiteboardBinding`。采用 Schema 驱动、fail-closed 的图片字段识别器。

`@workbench/demo-ui` 只负责展示入口并向宿主传出稳定的 `ImageConfigTarget`；它不得直接持有项目、工作区、权限、Authority revision 或协同 IO。author-site 通过 `WhiteboardLauncher` capability 承接这些能力，避免共享表单组件耦合创作端存储。

### 数据与提交合同

配置值继续保持现有图片字符串或数组结构；PNG 作为项目图片资产登记。图片资产按内容可去重、可复用，因此不承担字段所有权。

| 对象 | 职责 | 关键字段 |
| :-- | :-- | :-- |
| `WhiteboardDocument` | 可编辑、版本化的白板内容 | `id`、`version`、已校验的 `scene`、`editorView` |
| `WhiteboardBinding` | 稳定地把一个配置目标关联到白板产物 | `id`、owner（page/project）、稳定 target pointer/数组项 ID、`whiteboardId`、`sceneRevision`、`outputAssetHash` |
| 图片资产 | PNG 内容与来源审计 | content hash、尺寸、MIME、来源类别；不记录字段归属 |

`SketchSceneDocument` 不保存缩放/平移状态，因此 `WhiteboardDocument` 使用版本化 envelope：`scene` 继续按 Sketch 协议校验，`editorView` 单独校验且不混入 scene。

白板 scene 不能按普通 `assets/` 文本文件落地。实现前必须定义一等 `whiteboard-document` 资源类型：受管路径、大小上限、JSON 校验、Authority/Yjs adapter、读取 API、版本与脱敏诊断。它不复用页面 `sketch.scene.json` 的资源语义。

“回填图片”必须走专用 `WhiteboardCommit` command，而非普通表单 `onChange`：

```text
私有草稿 → 导出 PNG → 临时产物/校验 → WhiteboardCommit
  → scene + binding + config-values + 项目资产引用一次提交
  → Authority receipt / revision 投影 → 预览刷新
```

提交失败时，原配置和已发布预览不变，私有草稿与临时产物保留可重试；临时产物在超时后由受控清理任务回收。

## 五、数据流程草图

```text
图片字段 → ImageConfigTarget → WhiteboardLauncher / Dialog
  → WhiteboardDocument 私有草稿（scene + editorView）
  → PNG 导出与本地化输入校验 → 临时产物
  → WhiteboardCommit（scene + binding + 资产引用 + config-values）
  → Authority receipt / revision 投影 → 现有预览刷新
```

草稿保存与配置回填分离。回填失败、权限拒绝或冲突时保留草稿，不覆盖原配置。

### 草稿与回填状态机

`未修改 → 本地已修改 → 草稿已同步 → 导出/上传中 → 回填提交中 → 已回填`

任一阶段可进入 `提交失败` 或 `冲突待处理`。Esc、关闭按钮、遮罩关闭和路由离开在存在未同步修改时都要求确认；关闭后焦点返回原字段入口。冲突不得静默覆盖，用户可选择刷新远端版本、另存为副本或放弃本地稿。

## 六、验证方式

- 识别器：标准单图与 `imageList` 当前项的路径和目标定位；不支持字段不展示入口且不改变原值。
- 编辑器：绘制、文本、撤销重做、导出、二次编辑、焦点陷阱/归还与快捷键作用域。
- 持久化：刷新恢复、权限拒绝、Authority receipt、页面复制、延迟 GC 和未引用保护。
- 回填：预览刷新；尺寸超限、上传失败、权限拒绝或冲突均不改配置；成功结果属于同一 committed revision。
- 协同：两人同时回填同一目标不能静默覆盖，冲突拥有刷新、另存副本、放弃本地稿的恢复路径。
- 输入安全：一期仅允许 data URL 或已本地化项目资产进入 scene；远程图片必须先经受控本地化，导出前检查 canvas taint。
- 隔离性：白板操作不改变页面画布 scene、视口、HTML sandbox canonical 文件或协同资源。
- 性能：在约定浏览器与测试设备上，记录首开耗时、200 节点拖拽输入响应、指定画布尺寸 PNG 导出耗时及失败降级阈值。

## 七、风险与待确认事项

- `WhiteboardDocument` 的资源目录、最大 JSON 大小、Yjs adapter、Authority operation 和读取 API 需要先完成跨包契约设计。
- 现有图片资产登记与临时产物“提升为正式引用”的边界需要在实现前确认，避免回填失败留下孤儿资产。
- PNG 导出是否需要 worker，取决于指定画布尺寸与已本地化图片的实测耗时；应先记录基线再决定。
- 白板复制、配置字段删除、运行值覆盖、历史/发布版本对 binding 可达性和延迟 GC 的保护规则需要统一。
- Excalidraw 文件导入/导出、嵌套/变体字段和视频 `poster` 不属于第一阶段；如后续需要，应以稳定 binding pointer 协议为前提单独设计适配层。
