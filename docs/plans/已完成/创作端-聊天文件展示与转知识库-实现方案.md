# 创作端 — 聊天文件展示与转知识库 实现方案

## 背景

两个关联问题：

1. **「我发的是什么」复述爆炸**：用户本轮只发 1 个文件，Agent 却复述 10 个历史附件（同一文档 5 份、test.md 3 份）。根因是附件按项目级累积、上传无内容去重、prompt 全量注入历史附件且语义误导。
2. **聊天文件在文件栏不显示 / 无法转知识库**：后端已能列出「聊天文件」，但前端不刷新、默认 doc 视图不挂载文件树、点击聊天文件报「不支持子目录浏览」，且没有「转知识库」能力。

## 目标

- 根治附件「复述爆炸」：按内容去重 + prompt 分层。
- 让聊天文件在**文档视图**与**代码视图**都可见、可查看内容。
- 支持把聊天文件**剪切**转为知识库文件（原聊天附件删除）。

## 范围

- `packages/agent-service/`：附件存储去重、上传附件 prompt 分层。
- `packages/author-site/`：附件读取能力、文件树刷新、文档视图「对话文件」分组、查看/转知识库/删除。
- `packages/ai-chat-shared/`：上传成功后触发文件树刷新事件。

## 关键决策

- **附件作用域**：保持项目级（`data/projects/{projectId}/.ai-attachments/`），不改存储作用域，通过内容去重控制膨胀。
- **转知识库 = 剪切**：读附件 `text.txt` → `POST /api/knowledge` 创建知识文件 → 删除原聊天附件。
- **文件读取**：author-site 新增读取附件内容接口（附件在 workspace 之外，现有 `[...filePath]` 路由无法读取）。

## 方案

### Part 1 — 附件去重与 prompt 分层（agent-service）

**B. 持久层按内容去重** — `packages/agent-service/src/utils/uploaded-file-attachments.ts`
- `saveUploadedFileAttachment` 写入前按 `sha256(input.buffer)` 查重（遍历 manifest 的 `sha256`）。
- 命中则复用既有 attachmentId，返回已有元数据，不新建副本目录。

**A. prompt 分层** — `packages/agent-service/src/backends/pi-agent.ts` 的 `formatUploadedFilesForPrompt`
- 拆分「本轮上传」与「历史附件」两段。
- 历史附件按内容去重后只出紧凑条目，不再重复列副本。
- 添加指令：用户问「我发了什么/复述一遍」时，以【本轮上传】为准作答。
- 对历史附件数量裁剪，防止无限膨胀。

### Part 2 — 聊天文件展示 + 转知识库（author-site + ai-chat-shared）

**2c. 附件读取能力（共用基础）**
- 新建 `packages/author-site/src/lib/ai-attachments.ts`：按项目读取附件清单 + 读取附件 `text.txt`/manifest。
- 新增 API `app/api/sessions/[sessionId]/attachments/route.ts`：返回附件清单与内容。

**2a. 代码视图（WorkspaceFileTree）**
- 新增 `chat-attachments-updated` 刷新事件：`chat-input.tsx` 上传成功后 `dispatch`，`WorkspaceFileTree` 监听后重新 fetch 根目录。
- 修复点击聊天文件报「聊天附件不支持子目录浏览」：改为走新增读取接口查看内容。

**2b. 文档视图（KnowledgePanel）**
- 「项目知识库」下方新增「对话文件」分组，复用附件清单接口。
- 每项：查看内容、剪切转知识库、删除附件。

## 风险与待确认

- 剪切转知识库会删除原附件；已发送消息中保留的附件元数据（attachmentId）对应的文件将不再可读，属预期行为。
- 去重后同一文件多次上传复用同一 attachmentId，`readUploadedFile` 仍可读既有内容。
