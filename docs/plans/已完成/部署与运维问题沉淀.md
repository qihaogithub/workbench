## agent-service 全局 backendProviders 配置在容器重建后丢失，导致评论 @AI 任务失败

- **状态**：已修复（2026-08-10）
- **现象**：Docker 部署下，评论 @AI 后立即显示「AI 失败」，评论被标记 `aiTaskStatus=failed`，回复为「处理失败：AI 未能在本轮完成处理，请重试」。
- **根因**：agent-service 的全局 `backendProviders` 配置是**内存态**，只在 author-site 启动时一次性推送（`POST /internal/backend-providers`）。当 agent-service 容器重建（或 author-site 与 agent-service 不同步启动，如 agent-service 在 author-site 启动后 4 分钟才起来）时，新实例的全局配置为空。评论 @AI 是服务端发起的 Agent 任务，AgentConfig 不带 `backendProviders`，模型解析回退到环境变量 `PI_AGENT_PROVIDER=deepseek`，而该供应商在全局配置中无 API Key → `Error: No API key for provider: deepseek`，毫秒级失败。
- **关键证据**：agent-service 日志 `No API key for provider: deepseek`；`GET /internal/backend-providers` 返回 `providers: []`；手动推送真实配置后评论 @AI 立即正常（状态 `done`，AI 正常回复）。
- **修复摘要**：`packages/author-site/src/lib/backend-providers-sync.ts` 在启动同步后启动周期性核验（约 15s），当检测到 DB 有配置而 agent-service 全局配置缺失时自动重新推送（`_verifyTick`），保证 agent-service 重建后服务器发起任务仍能解析到带 Key 的供应商。
- **验证状态**：新增 2 个单测（配置缺失时重推、配置一致时不重推）；`check:author` 全量 1048 用例通过。
- **后续事项**：需重建 author-site 容器使修复生效；若再次出现评论 @AI 失败，先查 `GET /internal/backend-providers` 是否为空，再查 agent-service 是否在 author-site 启动后才重建。
- **相关文件**：`packages/author-site/src/lib/backend-providers-sync.ts`、`packages/agent-service/src/routes/comment-ai-task.ts`、`packages/agent-service/src/backends/managers/model-manager.ts`。
