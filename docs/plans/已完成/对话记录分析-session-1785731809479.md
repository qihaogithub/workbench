## 关键代码事实（已核实源码）

### 1. 项目级配置注入机制：注入 ≠ 消费

- 配置面板修改：`edit/page.tsx` `handleProjectConfigPanelChange`（3777-3809 行）将新值合并进**所有页面**的 `configDataMap`，并持久化 `project.config.values.json`、失效全部页面截图。
- 编辑器加载：`allDefaults[pageId] = { ...getSafeMergedDefaults(schema, projectConfigSchema), ...loadedProjectConfigValues, ...demo.configValues }`（3553-3564 行）。
- 即：项目级字段运行时注入到每个页面组件的 props，但**页面代码必须自己解构消费**才会显示。这是预期设计，不是配置"只对手机生效"。

### 2. 平板页原代码（修复前）确实未消费 `miniBanners`

- 只解构 `bigBannerForeground`；横滑"领课卡片"区硬编码 6 张本地图 `pad-course-card-1~5.png` + 重复第 1 张，与项目级配置无任何连接。
- AI 的诊断结论正确。

### 3. 引用元素 label/context 恒为空（前端代码 bug，本次会话最大痛点）

链路：`edit/page.tsx` `handleAddToChat`（5809-5818 行）→ `setChatElement({ id, label: getNodeLabel(...), context: buildVisualSelectionPrompt(...) })` → `chat-input.tsx` useEffect 自动 `insertTag`（334-345 行）→ 提交时拼串（405-414 行）`[引用${type}: ${label}]\n${context}`。

bug 位置：`ai-chat-shared/src/chat/inline-tag-input.tsx`

- `insertTag`（189-261 行）只给 chip DOM 写 `data-tag-id`，label/context 仅存内存 `tagsMapRef`；
- `extractSegments`（60-98 行）却只从 DOM `dataset.tagLabel` / `dataset.tagContext` 读取，永远得到 `""`；
- `getValue()`（271-276 行）基于 extractSegments → 提交消息中标签 label/context 恒为空。

证据：`.messages.json` 中 `user-1785741227300-91w4gr` 原文即 `'[引用元素: ]'`（后面跟着空行 + 正文），与拼串模板完全吻合。

后果：用户点击"添加到对话"后，AI 收到的是无任何元素信息（无 label、无 DOM 路径、无文本）的空引用，无法定位用户所指区域，只能靠 requestUserChoice 追问。

### 4. 截图 dependency_import 故障：两处缓存不一致（平台侧候选根因）

链路：screenshot-service `screenshots.ts`（717-747 行）→ `compileCache.get(code, cacheScope)` 命中时**跳过** author-site `/api/compile`，直接用缓存的 `moduleUrl` 生成 iframe（`generateIframeHtml({ compiledCodeUrl: moduleUrl, ... })`）→ iframe 内 `import(moduleUrl)` → 404 时报 `dependency_import: Failed to fetch dynamically imported module`。

author-site 侧：`lib/preview-module-store.ts`

- 模块按 hash 全局文件存储（`data/preview-modules/{hash}.js`），`MODULE_TTL_MS = 30 分钟`、`MAX_MODULES = 200`；
- `pruneFileCache()`（22-41 行）在**每次新模块注册时**删除超过 30 分钟未改动或超出 200 个的文件；
- `readPreviewModule` 内存 miss 时读磁盘，文件不存在返回 null → 路由 404（`app/api/preview-modules/[hash]/route.ts`）。

不一致点：screenshot-service 编译缓存是内存 LRU（200 条、无 TTL），命中后不再触发 author-site 重新注册；而 author-site 的模块文件会被任何其他会话的新注册 prune 掉。截图时命中旧缓存 + 模块文件已被 prune → 404。

证据：两次失败截图引用的模块 hash（`7aff8d16…`、`784f8648…`）在 `data/preview-modules/` 中均不存在；工作区创建于 14:36，截图失败于 15:12-15:14，模块注册早于截图 30 分钟以上，与 TTL prune 时间吻合。

### 5. 排查手段受限

- bash 在本工作区只读（`live Workspace bash is read-only` / `WORKSPACE_AUTHORITY_REQUIRED`），AI 无法用命令验证；
- `getConsoleLogs` 无日志可读（`No console logs available`）；
- AI 首读 `workspace/project.config.schema.json` 失败（项目级配置实际在工作区根目录），需要 listFiles 才发现，属预设路径与实布局偏差。
