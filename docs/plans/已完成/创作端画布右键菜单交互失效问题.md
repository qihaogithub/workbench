# 创作端画布右键菜单交互失效问题

## 结论

已修复。根因是右键菜单以 `absolute z-30` 渲染在 `SketchEditorCanvas` 容器内部，该容器在创作端被多层 `overflow-hidden` 祖先（ResizablePanel、`overflow-hidden` 包裹层、CommentLayer 区域）嵌套，且 Stage div 的 CSS `transform` 创建独立 stacking context。菜单被祖先 `overflow-hidden` 裁剪、或被祖先 stacking context 干扰，导致气泡外左键无法关闭、气泡内按钮无法点击。

## 修复方案

将画布右键菜单改为 `createPortal(..., document.body)` + `position: fixed` 渲染：

- 菜单挂载到 `document.body`，彻底脱离画布容器的 `overflow-hidden` 祖先链和 stacking context，不再被裁剪或遮挡。
- 定位改用视口坐标（`event.clientX/clientY`），不受祖先 `transform`/`offset` 影响。
- `useLayoutEffect` 在首次绘制前按菜单实测尺寸做视口边缘 clamping，避免菜单超出屏幕。
- `z-[9999]` 保证菜单在所有叠加层之上。
- 在菜单同 portal 内追加 `fixed inset-0 z-[9998]` 透明遮罩（backdrop），`onPointerDown` 关闭菜单。遮罩在菜单之下、所有宿主叠加层之上，气泡外任意位置点击均命中遮罩并关闭菜单，不依赖 document 监听能否收到事件（创作端祖先可能 stopPropagation 拦截 pointerdown，导致 document 监听失效）。
- 菜单 `onPointerDown` 的 `stopPropagation()` 阻止内部点击冒泡到遮罩与 document，避免误关闭。

此方案与 demo-ui `CanvasPageItem` 的 `createPortal` + 遮罩模式一致，是 doc 待确认事项 5 的落地。

- `pnpm --filter @workbench/sketch-react typecheck` 通过。
- `pnpm --filter @workbench/sketch-react test`：151 个用例全部通过。
- sketch-playground 真实浏览器验证：右键打开菜单（`position: fixed`、`parent: BODY`、`z-index: 9999`、backdrop `z-9998`）、点击「删除」按钮生效并关闭菜单、气泡外左键（画布背景、工具栏区域）关闭菜单，均正常。
