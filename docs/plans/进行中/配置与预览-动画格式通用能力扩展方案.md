# 配置与预览-动画格式通用能力扩展方案

> 日期：2026-08-05
> 状态：设计评审
> 目标：把 SVGA 的"预览运行时内置动画能力"模式推广为通用能力，一次性支持 Lottie / Rive / Spine 三种动画格式，供创作端 AI 在 `high-fidelity-react` 页面中通过 `@preview/sdk` 组件调用，沿用现有配置面板与素材上传链路，不改产品 UI。

---

## 一、背景

当前系统已支持 SVGA 动画预览：`proj_1782718596686_wmv9yu` 项目中，页面通过 `@preview/sdk` 的 `SvgaPlayer` 组件 + 配置面板上传 `.svga` 文件实现动画效果。SVGA 链路是"运行时登记 → vendor 构建 → 编译期解析 → iframe import map → 素材上传 → agent 编排"六段式，天然可扩展。

用户明确要求：**Lottie、Rive、Spine 三种格式一次全部接入**，做成通用能力，支持 agent 通过写页面代码 + config.schema.json 的方式调用。决策约束：

- Lottie 素材先支持 `.json`（lottie-web），`.lottie` zip 格式留后续。
- 配置面板沿用现有做法：agent 在 schema 里声明 `mediaType` enum + `accept` 字段，走通用 `FileUploadWidget`，不改产品 UI。

## 二、目标

1. 三种动画格式在创作端编辑态预览、发布态 iframe、使用端（viewer）均可渲染。
2. `@preview/sdk` 新增 `LottiePlayer` / `RivePlayer` / `SpinePlayer` 三个受控组件，替换现有 Lottie 占位组件。
3. agent 通过 `react-high-fidelity` skill + L5 运行契约知道可用能力，能独立编写页面代码与配置 schema。
4. 素材上传、发布资源本地化、项目资产清单、截图服务全链路支持新扩展名。

## 三、范围

### 在范围内

- `@workbench/preview-contract`：依赖白名单、L5 authoring rules。
- `@workbench/author-site`：SDK data-URI 兜底源码、runtime manifest、素材上传/服务 route、screenshot 关联。
- `@workbench/demo-ui` 与 `@workbench/shared`：两个 iframe-template 的 import map。
- `scripts/build-preview-runtime.mjs`：vendor 构建、wasm 复制、SDK 源码、manifest 版本。
- `@workbench/project-core`、`@workbench/project-cli`：资产扩展名白名单。
- `@workbench/agent-service`：预装 skill 文档。
- 项目文档：`docs/项目文档/创作端/04-配置与预览/` 相关技术文档。

### 不在范围（本期）

- `.lottie` zip 素材格式（dotlottie-web）——留后续。
- 产品层新增通用"动画"表单控件——沿用 FileUploadWidget。
- prototype-html-css 原型页的动画播放能力——本期只保证素材可上传与 URL 可用，不新增原型页运行时。
- 修改发布资源本地化机制本身（只扩扩展名白名单）。

## 四、现状：SVGA 完整链路（新格式的复刻模板）

```
① 运行时登记    preview-contract/src/rules.ts PREVIEW_DEPENDENCY_POLICY
                svgaplayerweb@2.3.1 { version, kind: "internal" }
② vendor 构建   scripts/build-preview-runtime.mjs
                esbuild → public/preview-runtime/vendor/svgaplayerweb.js
                同时生成 SDK 源码 preview-sdk.js（含 SvgaPlayer 组件），
                复制到 author-site 与 viewer-site 两端 public/，
                写入 manifest.json
③ 编译期解析    author-site/src/lib/compiler.ts compileCode()
                import { SvgaPlayer } from '@preview/sdk'
                → 本地 vendor URL / data-URI 虚拟模块
                （preview-dependency-policy.ts createPreviewSdkSource() 兜底）
④ iframe map    shared/src/demo/iframe-template.ts 与 demo-ui/src/iframe-template.ts
                DEFAULT_RUNTIME_IMPORTS + buildRuntimeImports() 的 CDN 分支
                svgaplayerweb → /preview-runtime/vendor/svgaplayerweb.js
                               → https://esm.sh/svgaplayerweb@2.3.1
⑤ 素材上传      app/api/sessions/[sessionId]/assets/upload/route.ts
                ALLOWED_EXTENSIONS + .svga 放行 octet-stream；
                schema ui:options.accept=".svga"；页面 <SvgaPlayer src=.../>
⑥ agent 编排    generatePreviewAuthoringRules() + react-high-fidelity/SKILL.md
```

关键事实：

- iframe sandbox 为 `allow-scripts allow-same-origin`，无 CSP 阻止 wasm —— Rive/Spine 的 wasm 运行时可行。
- 现有 SDK 源码存在 `Lottie` 占位组件（仅渲染"动画"文字），本次替换为真实实现。
- `build:preview-runtime` 已挂进 author-site 与 viewer-site 的 `build` 脚本，重生成 vendor 属于构建流程一环。
- SDK 源码有三处事实源，需保持同步：`scripts/build-preview-runtime.mjs` 的 `sdkSource`、`author-site/src/lib/preview-dependency-policy.ts` 的 `createPreviewSdkSource`、以及构建产物 `public/preview-runtime/vendor/preview-sdk.js`（由脚本重生成，勿手改）。

## 五、方案设计

### A. 运行时依赖接入（三格式统一骨架）

| 步骤 | 文件 | 改动 |
|------|------|------|
| A1 白名单登记 | `packages/preview-contract/src/rules.ts` | `PREVIEW_DEPENDENCY_POLICY` 新增：`lottie-web@5.13.0`、`@rive-app/canvas@2.38.1`、`@esotericsoftware/spine-webgl@4.2.112`（kind 均为 `internal`） |
| A2 vendor 构建 | `scripts/build-preview-runtime.mjs` | 新增三个 esbuild entry；把 `rive.wasm`（来自 `@rive-app/canvas`）与 `spine-*.wasm`（来自 `@esotericsoftware/spine-webgl`）复制进 vendor 目录；`PREVIEW_RUNTIME_MANIFEST_VERSION` bump；`packages` 清单补三项 |
| A3 runtime manifest | `packages/author-site/src/lib/preview-runtime-manifest.ts` | `DEFAULT_PREVIEW_RUNTIME_IMPORTS` 补三映射：`lottie-web`、`@rive-app/canvas`、`@esotericsoftware/spine-webgl` |
| A4 iframe import map | `packages/shared/src/demo/iframe-template.ts`、`packages/demo-ui/src/iframe-template.ts` | 两个文件的 `DEFAULT_RUNTIME_IMPORTS` 与 `buildRuntimeImports()` CDN 分支补三项。CDN 分支 URL：`esm.sh/lottie-web@5.13.0`、`esm.sh/@rive-app/canvas@2.38.1`、spine-webgl CDN 分支暂不提供（wasm 兼容性不可靠，见风险 R3），CDN 模式下 Spine 不可用
| A5 重生成 vendor | 根目录 | `pnpm build:preview-runtime` 重生成 author/viewer 两端 vendor + manifest |

### B. @preview/sdk 新增组件

SDK 源码两处同步维护：`scripts/build-preview-runtime.mjs` 的 `sdkSource` + `author-site/src/lib/preview-dependency-policy.ts` 的 `createPreviewSdkSource()`（data-URI 兜底，运行时按 resolver 计算 import URL）。

新增组件设计：

| 组件 | 素材 | 实现要点 |
|------|------|----------|
| `LottiePlayer({ src, loop=0, autoplay=true, renderer='svg', fallback, onError, className, style })` | `.json` | `lottie.loadAnimation({ path: src, container, renderer, loop, autoplay })`；卸载时 `destroy()`；替换现有占位 `Lottie` |
| `RivePlayer({ src, fit='cover', alignment='center', autoplay=true, fallback, onError, ... })` | `.riv` | `@rive-app/canvas` 高精度 API `new Rive({ src, canvas, fit, alignment, autoplay })`；`locateFile` 指向同源 `/preview-runtime/vendor/rive.wasm`；canvas 尺寸随容器自适应（ResizeObserver）；卸载 `cleanup()`/`delete()` |
| `SpinePlayer({ skeleton, atlas, texture, animation, loop=true, ... })` | `.json`/`.skel` + `.atlas` + `.png` | `@esotericsoftware/spine-webgl`：`loadTextureAtlas` + `loadSkeletonData` + 手写 WebGL 渲染循环（或封装官方 spine-canvas/webgl 示例）；`locateFile` 指向同源 `/preview-runtime/vendor/spine-*.wasm` |

组件统一约束：无 `src` 或加载失败时返回 `fallback` 占位而非空；遵循 `return null` 风险规则（`generatePreviewAuthoringRules` 禁止 return null）。

### C. 素材上传与分发链路

| 步骤 | 文件 | 改动 |
|------|------|------|
| C1 上传白名单 | `app/api/sessions/[sessionId]/assets/upload/route.ts` | `ALLOWED_EXTENSIONS` 补 `.lottie`、`.riv`、`.json`、`.skel`、`.atlas`、`.zip`；MIME 判断：`.json` 放行 `application/json`，其余放行 `application/octet-stream`（沿用 `.svga` 分支模式） |
| C2 文件服务 mime | `app/api/sessions/[sessionId]/assets/[filename]/route.ts`、`app/api/sessions/[sessionId]/workspace/[...path]/route.ts`、`app/data/[...path]/route.ts` | mime map 补 `.json`→application/json，`.lottie/.riv/.skel/.atlas/.zip`→application/octet-stream（`data/[...path]` 的 `.json` 已有） |
| C3 Spine zip bundle（唯一新基础设施） | `app/api/sessions/[sessionId]/assets/upload/route.ts` | 当扩展名为 `.zip` 时：服务端解压到 session workspace `assets/animations/{stamp}/`，**返回 `{ baseUrl, files: { skeleton, atlas, texture } }` 结构**（解压后自动扫描 `.skel`/`.json`/`.atlas`/`.png` 文件并报告具体文件名），agent 把该结构传给 `SpinePlayer` 的 `skeleton`/`atlas`/`texture` props。解压依赖新增一个最小 zip 库（如 `yauzl` / `adm-zip`），并做路径穿越防护（拒绝 `../`、绝对路径） |
| C4 扩展名白名单扩散 | `packages/project-core/src/service.ts`（约 6935/7029/7068 三处正则）、`packages/project-cli/src/index.ts`（约 1020） | 补 `.lottie/.riv/.skel/.atlas/.zip`；`.png` 已在内。注意 zip 解压后的目录也应被 `walkFiles` 资产收集覆盖（对 `assets/animations/` 下多文件均需命中正则） |
| C5 原型页/本地路径正则 | `packages/shared/src/demo/prototype-preview.ts`（IMAGE_EXT_RE）、`author-site/src/lib/rewrite-local-paths.ts`（IMAGE_EXT_RE） | 补 `.lottie/.riv/.skel/.atlas`；`prototype-preview.ts` 已有 `.svga`，`rewrite-local-paths.ts` 顺手补上 `.svga`（修正既有不一致）。⚠️ **`.json` 不加入**：会误伤普通 json 引用；Lottie `.json` 一律走上传返回的绝对 URL（与 SVGA 一致） |

配置 schema 模板（agent 沿用 SVGA 模式，示意）：

```jsonc
{
  "mediaType": { "type": "string", "enum": ["image", "lottie", "rive", "spine"], "default": "image" },
  "lottieSrc": { "type": "string", "format": "file",
    "ui:options": { "accept": ".json", "visibleWhen": { "field": "mediaType", "equals": "lottie" } } },
  "riveSrc":   { "type": "string", "format": "file",
    "ui:options": { "accept": ".riv",  "visibleWhen": { "field": "mediaType", "equals": "rive" } } },
  "spineSrc":  { "type": "string", "format": "file",
    "ui:options": { "accept": ".zip",  "visibleWhen": { "field": "mediaType", "equals": "spine" } } }
}
```

## 七·五、E3 验证发现并修复的 bug

### J1：Rive 无法播放（根因：`RivePlayer` 构造器取错）

- **现象**：上传 `.riv` 素材后 Rive 卡片一直显示 fallback（`Rive 加载中...`），canvas 停留在默认 300×150 不渲染。
- **根因**：`scripts/build-preview-runtime.mjs` 的 `RivePlayer` 里 `var R = mod.default || mod; new R(...)`。而 `@rive-app/canvas` 的构建入口是 `import * as rive; export default rive;`，即 `default` 是**命名空间对象**（内含 `Rive`/`Fit`/`Alignment` 属性），不是构造器。`new (命名空间对象)` 抛 `R is not a constructor`，被 catch 置 `failed=true` → 显示 fallback。
- **修复**：改用 `var ns = mod.default || mod; var R = ns.Rive || ns;`，用 `ns.Rive` 实例化，`Fit`/`Alignment` 从 `ns`（命名空间对象）取。重新 `pnpm build:preview-runtime` 后 author-site 与 viewer-site 两端 vendor 均含修复。
- **验证**：直接在 shell 中 `import('@rive-app/canvas')` 后 `new ns.Rive({src, canvas, autoplay, locateFile})` 成功，`inst.contents` 有值（素材加载成功）。
- **注意**：Spine 走 `export * from "@esotericsoftware/spine-webgl"`（命名导出），`SpinePlayer` 用 `mod.AssetManager` 正确，无此问题。

### J2：Spine 素材 URL 构造错误（根因：sessionId 用错）

- **现象**：`.zip` 上传解压成功后，返回的 `skeleton/atlas/texture` URL 里的 sessionId 是**项目 ID**（`proj_xxx`）而非会话 ID（`session-xxx`）。
- **根因**：`app/api/sessions/[sessionId]/assets/upload/route.ts` 的 `extractZipToWorkspace` 用 `path.basename(path.dirname(workspacePath))` 推导 sessionId，而 workspacePath 形如 `/app/data/workspaces/projects/proj_xxx/live-xxx/`，`dirname` 后取 basename 得到的是 `proj_xxx`。该 ID 作为 session 访问时 `getSessionMeta` 找不到 `.session.json` → 素材 404。
- **修复**：改为把路由参数 `sessionId` 显式传入 `extractZipToWorkspace`，URL 使用真实 sessionId。
- **验证**：`pnpm --filter @workbench/author-site typecheck` 通过。

### J3：Spine zip 解压错配三元组导致预览无法播放（根因：贪心取"最后一个"）

- **现象**：上传官方 spineboy 示例 zip（`proj_1785742777589_ncs6r6` 的 Spine 卡片）后预览一直显示 fallback，无法播放。诊断日志报 `preview.error: Couldn't load image: .../assets/animations/{stamp}/mouth-grind.png`。
- **根因**：`extractZipToWorkspace` 把 zip 内每个类型的**最后一个**文件分别取为 `skeleton/atlas/texture`。而该 zip 内含多套导出（`spineboy-ess`/`spineboy-pro` 的 `.skel`+`.json`、三套 atlas+纹理）外加 `images/` 拆包纹理切片。最终拼出 `spineboy-pro.skel + spineboy-run.atlas + mouth-grind.png`（最后一个 `.png` 是拆包切片），三者互不属于一套，渲染必然失败。
- **修复**：抽出纯函数模块 `assets/upload/extract-spine-package.ts`，新增 `selectSpinePackage`：解析 `.atlas` 首行取引用纹理名，必须存在于已解压文件才可用；按骨架与图集的前缀匹配度（共同前缀 > 图集为骨架名前缀 > 更短图集名 > 骨架 .skel 优先 > 文件名更长）选出自洽三元组。对 spineboy 示例正确选中 `spineboy-pro.skel + spineboy-pma.atlas + spineboy-pma.png`（完整动效 + 正确预乘图集）。
- **验证**：`pnpm check:author` 通过（1012 tests，含新增 5 条 `assets/upload/select-spine.test.ts`）。
- **注意**：已上传坏包的会话需**重新上传** zip 才会走新逻辑；历史存量坏包不会自动修复。

## 八、风险与待确认事项

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| R1 | **Spine 许可证（必须确认）**：Spine runtime 为专有许可（非 MIT/OSI），整合进商业产品对外分发需 Spine 商业授权 | 若未授权，Spine 能力不能交付 | 实现可先做，但交付前必须与团队/法务确认许可证，否则从发布中剔除 Spine 或改为服务端渲染降级 |

| R3 | CDN 回退模式（`PREVIEW_RUNTIME_SOURCE=cdn`）下 wasm 获取 | `@rive-app/canvas` wasm 可从 unpkg 固定版本取；spine-webgl 的 esm.sh wasm 兼容性不确定 | CDN 诊断模式只保证 JS 可用，wasm 统一回退到 unpkg 固定版本；CDN 模式非默认路径 |
| R4 | Spine 运行时与 Spine Editor 版本强绑定（4.2 vs 4.3 素材不兼容） | 素材打不开 | 固定运行时版本 4.2.112，并在 SKILL 文档明确版本匹配约定 |
| R5 | SDK 源码两处手写维护易漏同步 | data-URI 兜底与 vendor 行为不一致 | 本次实现后评估是否把 SDK 源码提取为共享生成模块，避免再次分叉 |
| R6 | 依赖体积：三个 runtime（含 wasm）使 vendor 约增 2MB+ | 发布包变大、首屏变慢 | 三个 Player 组件内使用动态 `import()` 按需加载对应 runtime（如 `const mod = await import("lottie-web")`），不预加载到 SDK 顶层。`@preview/sdk` vendor 文件本身不含这三个库的 bundle，依赖通过 import map 在首次渲染 Player 时解析为独立 vendor 文件 |
| R7 | `.zip` 解压安全 | 路径穿越/超大压缩包 | 解压时拒绝 `../`、绝对路径、符号链接；限制解压体积与文件数；只接受白名单扩展名文件 |
| R8 | `.json` 上传与普通 json 配置的语义边界 | 上传 route 放行 `.json` 后可能被误用于非动画场景 | 靠 `accept` 约束 + 配置字段语义控制；通用图片/资产正则不含 `.json`，避免全局副作用 |
