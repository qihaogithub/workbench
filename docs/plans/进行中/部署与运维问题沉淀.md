## 测试环境编辑页同步与模型列表不可用

- 现象：测试环境编辑页右上角同步状态长期为“连接中”，AI 对话左下角“选择模型”列表为空；`agent-service` 健康检查超时并接近满 CPU。
- 根因：旧版 `WorkspaceMutationAuthority` 在 `getCommittedEventsSince`、`getProjectionAcks` 和 `getState` 的只读请求中复用写事务路径。每次编辑页约 2 秒轮询都会在 lease 内对约 311 MiB 的 live Workspace 做完整资源哈希，多个请求互相排队，阻塞 Agent WebSocket 和模型响应。远端 `/models` 已能返回 6 个模型，说明模型供应商配置不是首要故障。
- 修复：只读路径优先读取持久化 Authority state 与增量记录；仅在发现 prepared/reconcile-prepared 恢复工件时进入串行 lease，并保留 mutation、snapshot、health 的全量漂移检查。新增回归测试验证活动 lease 下 catch-up 读取不会再次读取业务资源。
- 验证状态：`workspace-mutation-authority.test.ts` 33/33、`check:workspace-authority`、`check:workspace-deploy-compose`、部署前置契约测试 6/6、部署脚本 `bash -n` 均通过。agent-service 全量测试仍有仓库既有失败（模型 mock、图片预览断言、端口权限等），与本次 Authority 只读路径无关。
- 部署状态：本地修复尚未部署到测试机。远端部署前 Authority 门禁发现 26 个未注册 live Workspace 与 69 个 external drift（共 95 项），脚本按设计停止且未自动 adopt/restore；需要用户明确授权一次 test-only 门禁旁路后才能重建并替换 agent-service/author-site 镜像。
- 后续事项：获得授权后只同步代码并远程构建目标服务，不覆盖 `data/`；部署后复核 agent 健康、编辑页同步状态、模型列表和浏览器 WebSocket，再决定是否处理剩余 Authority 项。
