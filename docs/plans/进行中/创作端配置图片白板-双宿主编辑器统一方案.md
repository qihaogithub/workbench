# 创作端配置图片白板：双宿主编辑器统一方案

> 状态：已实施，待持续回归
> 创建日期：2026-08-29
> 适用范围：Whiteboard Studio、author-site 配置图片白板、`@workbench/sketch-react`
> 关联设计：[配置图片白板实现设计](../../项目文档/创作端/04-配置与预览/技术/14_配置图片白板实现设计.md)

## 一、目标与边界

本方案只解决一件事：**白板本身只有一套编辑体验和实现**。Whiteboard Studio 与创作端配置图片对话框可以有不同的页面外壳、尺寸和提交动作，但进入画布后必须使用同一个编辑器工作区、同一个 action registry、同一套快捷键与同一套面板入口。

不在本方案中引入或预留第三方编辑器，也不为尚不存在的多引擎需求增加 adapter、Host 或版本化引擎 envelope。当前编辑器就是 `sketch-core` / `sketch-react`；业务层与编辑器的边界保持在“scene 草稿 + PNG 导出”即可。

### 非目标

- 不让 Studio 复刻创作端的项目标题、权限提示、关闭确认或“回填图片”按钮。
- 不把项目、会话、权限、配置 API 引入 `sketch-react` 或 Studio。
- 不把编辑器视口、选区和撤销栈保存到图片配置值。
- 不重构创作端编辑页已有的 `SketchEditorEngineHost`；它不属于配置图片白板的双宿主范围。

## 二、现状与问题

- Studio 当前自行组合 `SketchEditorCanvas` 与底部浮动 `SketchEditorToolbar`。
- `WhiteboardDialog` 当前使用 `SketchPageEditor`；后者额外渲染固定工具栏和固定属性面板。
- `SketchEditorCanvas` 本身已拥有选区快捷工具条、属性/图层/导出入口、命令面板、视口和键盘作用域。

因此同一份 scene 在两个入口会落入不同的 UI 组合。继续分别组合 Canvas、工具栏或面板，会让功能、快捷键和视觉在迭代时继续漂移。

## 三、目标架构

```text
Whiteboard Studio（独立开发外壳） ─┐
                                  ├→ SketchEditorSurface（唯一白板工作区）
WhiteboardDialog（业务与提交外壳） ─┘
                                      ├─ SketchEditorCanvas（含选区工具条、面板入口、视口、快捷键）
                                      └─ 浮动主工具栏

WhiteboardDialog
  ├─ scene 私有草稿、加载、关闭保护、PNG 导出
  └─ WhiteboardCommit（配置回填）
```

### 3.1 `SketchEditorSurface`

在 `packages/sketch-react` 提取唯一的可编辑白板工作区。它内部创建 controller，并以固定结构组合 `SketchEditorCanvas` 与底部浮动主工具栏；两个宿主均直接使用它。

```ts
interface SketchEditorSurfaceProps {
  scene: SketchSceneDocument;
  configData?: Record<string, unknown>;
  fillContainer?: boolean;
  className?: string;
  onSceneChange?: (scene: SketchSceneDocument) => void;
  onSelectionChange?: (selection: SketchEditorSelection) => void;
}
```

约束：

- 不提供 `studio` / `embedded` 等会改变编辑器结构的布局预设；宿主差异留在 Surface 外层。
- Canvas 内已有的选区工具条、属性/图层/导出入口继续由 Canvas 独占管理；Surface 不复制或二次挂载这些面板。
- 两个宿主都使用同一份浮动主工具栏；不得在某一宿主改为固定工具栏或固定属性面板。
- 只读展示使用现有预览组件，不复用可编辑 Surface，也不创建编辑 controller。

### 3.2 宿主职责

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `SketchEditorSurface` | 绘制、选择、撤销重做、快捷键、画布视口、工具栏与 Canvas 内面板 | 网络 IO、项目写入、配置回填 |
| Whiteboard Studio | 独立开发入口、fixtures、性能与交互验证 | 项目、登录、白板读取/提交 API |
| `WhiteboardDialog` | document 读取、本地草稿、脏稿关闭保护、PNG 导出、原子提交与错误恢复 | 重新组合编辑器 UI、管理编辑器内部监听 |

`WhiteboardDialog` 可以直接依赖 `SketchEditorSurface` 和 `renderSketchSceneToPngBlob`；在只有一个原生编辑器时，额外的通用 Host 只会增加一层没有业务价值的转发。

## 五、验证方式

### 组件与契约测试

- `SketchEditorSurface` 的同一 action 输入产生与现有 Canvas/controller 相同的 scene patch。
- Surface 在两个宿主中只挂载一份主工具栏、一个键盘作用域和一套 Canvas 内面板入口。
- 对同一 scene，Studio 和 Dialog 的绘制、选择、文本编辑、撤销重做、缩放及 PNG 导出结果一致。
- Dialog 的取消、Escape、遮罩关闭、冲突、导出失败和提交失败均不改变原配置图片。

### 浏览器回归

- Studio：空白画布、底部工具栏、绘制、选中、缩放、按需打开属性/图层/导出入口。
- author-site：相同编辑行为，加上对话框尺寸、脏稿确认、PNG 回填和二次打开恢复。
- 使用同一份 fixture scene 对两个入口做截图与关键交互比对；允许外壳不同，不允许编辑器结构不同。

## 六、验收结论

完成后应满足：

1. Studio 与 `WhiteboardDialog` 都只渲染 `SketchEditorSurface`，没有各自维护的 Canvas/工具栏/面板组合。
2. 两个入口的白板操作语义、快捷键、面板入口和导出行为一致；差异只存在于编辑器外壳。
3. `sketch-react` 不依赖创作端业务，`WhiteboardDialog` 不重新实现编辑器 UI。
4. 新增白板能力时先修改 `SketchEditorSurface` 并在 Studio 验证，再以 Dialog 覆盖宿主尺寸和回填契约。
