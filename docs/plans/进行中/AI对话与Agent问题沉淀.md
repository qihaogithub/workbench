# AI 对话与 Agent 问题沉淀

## 计划审批超时后消息永久排队（2026-08-31）

- 现象：计划审批等待期间 AI 因无进展超时后，审批工具仍显示运行中；用户输入“继续”会停留在“等待发送”。
- 根因：计划审批工具未消费 Pi Agent 的取消信号，待审批 Promise 会继续等待自身超时；编辑页随后只重置受控流状态，没有释放 `useChatStream` 的内部运行锁。
- 修复摘要：确认工具将取消信号传入权限管理器并以统一终结路径清理等待资源；前端把审批超时、工具终态、运行锁和 FIFO 出队统一收尾，宿主 stale-state reset 同步释放 Hook 状态。
- 验证状态：覆盖审批超时后历史工具状态结束与后续“继续”可发送的前端回归；后端确认取消与审批单测见本次变更。
- 后续事项：无。

## 测试环境模型下拉为空（2026-08-29）

- 现象：创作端编辑页 AI 对话区的模型下拉容器可打开，但没有任何模型选项。
- 根因：某个登录用户历史保存的个人模型 API Key 无法按当前环境密钥解密，`GET /api/models/config` 因此整体返回 500。前端转入构建期兜底配置后启用了空的精确白名单，将 agent-service 已返回的可用模型全部过滤。
- 修复摘要：模型配置 API 隔离不可读的个人配置并继续返回全局模型配置；下拉 viewport 保持自然高度并限制最大高度，避免模型项到达后被压缩。
- 验证状态：测试环境 `author-site` 已重建并健康；使用已登录浏览器重新打开项目后，下拉实际渲染 `deepseek-v4-flash-vision-exp` 与 `Qwen3.8-27B` 两项（各 32px）。路由回归测试、`check:ai-chat-shared` 与 author-site 类型检查通过。
- 后续事项：该用户如需继续使用个人供应商，需在个人模型设置中重新保存 API Key；旧密文无法在新密钥下恢复。

## 图片附件上传被浏览器拦截（2026-08-12）

- 现象：创作端 Docker 编辑页添加图片后提示“附件上传失败：无法连接 AI 服务”。
- 影响范围：浏览器直连 `agent-service` 的图片与 multipart 附件上传；普通同源页面请求不受影响。
- 根因：两项 CORS 配置同时缺失。服务未允许 `X-API-Key` 预检头；更关键的是 Docker Compose 复用了根 `.env` 的 `CORS_ORIGINS`，把容器 `3200/3300` 的实际来源覆盖成 `pnpm dev` 使用的 `4200/4300`，预检没有返回 `Access-Control-Allow-Origin`，浏览器未发送上传 POST。
- 修复摘要：agent-service CORS 允许 `X-API-Key`；Docker 改用 `DOCKER_CORS_ORIGINS` 并在容器内映射为 `CORS_ORIGINS`，从根 `.env` 开发端口配置隔离。
- 验证状态：已重建 agent-service、author-site 和 screenshot-service 容器；`http://localhost:3200` 的预检返回允许来源和 `X-API-Key`；隔离浏览器在项目 `proj_1779608460372` 上传图片并发送到 AI 对话成功，消息进入“AI 正在处理”。
- 相关事实：长期配置说明见 [使用端部署与 CORS 配置](../../项目文档/使用端/03-部署与嵌入/技术/01_部署与CORS配置.md) 与 [Docker 部署方案](../../项目文档/创作端/06-基础设施/技术/03_Docker部署方案.md)。
