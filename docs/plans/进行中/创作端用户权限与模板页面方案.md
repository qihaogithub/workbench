# 创作端用户权限与模板页面方案

## 1. 背景与目标

创作端当前已有登录用户和管理员后台，但项目操作主要依赖固定 actor，用户角色尚未形成统一的业务权限模型。模板目前是项目级类型，页面没有独立的模板页标记，无法表达“模板项目中部分页面可继续编辑、部分页面受保护”的场景。

本方案新增管理员与编辑者两级用户权限，并把模板保护细化到页面级：管理员在项目编辑页的“项目设置”中管理模板项目和模板页；编辑者拥有完整创作能力，但模板页不开放可视化编辑。AI 编辑暂不增加审核或额外风险控制，编辑者仍可通过 AI 修改模板页。

## 2. 角色规则

### 2.1 角色范围

- 角色采用全局用户级权限，不新增工作空间成员表、邀请流程或项目成员 ACL。
- 所有登录用户默认可以访问现有项目和工作空间。
- 用户角色只有 `admin`（管理员）和 `editor`（编辑者）。
- 编辑者对应现有项目服务中的普通可写 actor；管理员对应管理员 actor。

### 2.2 角色初始化与调整

- 空数据库中，第一个注册用户自动成为管理员。
- 已有用户迁移时，按 `created_at` 最早的用户回填为管理员，其余用户回填为编辑者。
- 管理员通过现有管理后台的用户管理功能修改用户角色。
- 现有 `ADMIN_SECRET` 管理后台入口继续保留，作为管理后台访问和应急管理凭证。
- 首期不增加“不能移除最后一个管理员”等额外治理规则。

## 3. 模板项目与模板页面语义

### 3.1 页面标记

在 `DemoPageMeta` 增加持久化页面标记，例如：

```ts
isTemplatePage: boolean
```

默认值为 `false`。页面模板标记是独立属性，不实时从项目 `projectType` 推导。

### 3.2 项目设置为模板

管理员将普通项目设置为模板时，项目类型变更和项目内所有现有页面变为模板页必须在同一事务中完成。

### 3.3 新建页面默认值

- 模板项目中新建页面：`isTemplatePage = true`。
- 普通项目中新建页面：`isTemplatePage = false`。

### 3.4 管理员手动调整

管理员可以在任意项目中修改页面模板标记：

- 模板项目中的模板页可以改回普通页。
- 普通项目中的普通页可以改为模板页。
- 支持单页修改和批量修改。
- 项目取消模板时保留页面现有标记，不自动清除模板页状态。

### 3.5 权限边界

- 设置/取消项目模板身份：仅管理员。
- 修改页面模板标记：仅管理员。
- 编辑者不能通过页面 API、项目 API 或 CLI 绕过上述限制。

## 4. 能力矩阵

| 能力 | 管理员 | 编辑者 |
| --- | --- | --- |
| 查看项目和页面 | 是 | 是 |
| 创建、删除、重命名、移动、排序页面 | 是 | 是 |
| 编辑代码和 Schema | 是 | 是，包括模板页 |
| 发布项目 | 是 | 是 |
| 通过 AI 修改页面 | 是 | 是，包括模板页 |
| 设置/取消模板项目 | 是 | 否 |
| 设置/取消模板页面 | 是 | 否 |
| 普通页面可视化编辑 | 是 | 是 |
| 模板页面可视化编辑 | 是 | 否 |
| 管理用户角色 | 是 | 否 |

“模板页面不可编辑”仅指编辑者的可视化编辑能力，不扩大为页面只读权限。

## 5. 技术实现建议

### 5.1 用户与认证

- `users` 表新增 `role` 字段，并提供幂等迁移和历史用户回填。
- JWT payload 与 `/api/auth/me` 返回当前用户角色。
- 提供统一的当前用户解析、角色校验和 actor 构造辅助函数。
- 所有项目、页面、工作区、资源、发布和恢复 API 使用当前登录用户 actor，不能继续默认使用固定管理员 actor。

### 5.2 Project Core 与接口

- 扩展共享类型中的页面元数据、用户信息和相关请求/响应类型。
- `project-core` 的 actor 映射规则：管理员为 `admin`，编辑者为普通可写角色。
- 设置模板项目时，项目类型和所有页面 `isTemplatePage` 一起提交。
- 新增页面模板标记单页/批量更新接口，校验页面属于目标项目。
- 项目列表、页面详情、编辑初始化响应返回页面模板标记和当前用户能力。
- 服务层对模板项目设置、模板页设置和可视化写入执行最终权限校验。

### 5.3 编辑页

编辑页按以下规则计算可视化能力：

```text
canUseVisualEditor = currentUser.role === "admin" || !activePage.isTemplatePage
```

编辑者打开模板页时，隐藏或禁用可视化模式、图层选择、属性面板提交、可视化补丁和可视化配置项创建；仍保留预览、代码/Schema 编辑、页面结构操作、发布和 AI 对话。

前端限制只负责用户体验，所有可视化提交接口必须在服务端再次检查角色和页面标记，并返回稳定的 `FORBIDDEN` 错误。

### 5.4 项目设置

- 用户管理增加角色展示和角色修改。
- 编辑页顶部提供“项目设置”入口，统一管理项目封面和模板设置。
- 所有登录用户可更新本项目封面；服务端必须验证登录态和项目访问范围。
- 模板设置仅管理员可见，支持项目模板身份切换、项目页面列表和模板页批量管理。
- 管理后台只保留全局配置和用户管理，不再提供模板项目或模板页入口。

## 6. AI 编辑策略

- 编辑者可以通过 AI 修改模板页。
- 不新增管理员审核、审批队列或额外风险控制流程。
- AI 请求必须携带当前用户身份，不能为了实现 AI 写入而固定使用管理员 actor。
- AI 与可视化编辑的权限边界独立：模板页只禁止编辑者可视化写入。

## 7. 测试与验收标准

### 用户角色

- 空库首个用户为管理员。
- 历史用户按最早注册时间回填管理员，其余为编辑者。
- JWT 和 `/api/auth/me` 正确返回角色。
- 编辑者无法调用用户角色修改接口。

### 模板项目与页面

- 设置模板项目后，所有已有页面自动变为模板页。
- 模板项目新增页面默认为模板页。
- 普通项目新增页面默认为普通页。
- 管理员可将模板页改为普通页，也可将普通页改为模板页。
- 批量修改拒绝不存在或不属于当前项目的页面。
- 模板项目转为普通项目时，页面模板标记保持原值。

### 编辑权限

- 编辑者在普通页可正常使用全部可视化能力。
- 编辑者在模板页看不到或无法启用可视化编辑。
- 绕过前端直接提交模板页可视化写入时，服务端返回 `FORBIDDEN`。
- 管理员可在任意页面使用可视化编辑。
- 编辑者仍可通过 AI、代码编辑、配置编辑和发布修改模板页。

## 9. 范围与默认假设

- 本方案定义并落实权限和模板页面行为；实施入口以项目编辑页“项目设置”为准。
- 不新增工作空间成员/邀请体系。
- 不改变现有项目访问范围：所有登录用户仍可访问现有项目。
- 页面模板标记独立于项目模板身份。
- 不增加 AI 审核、审批和专门风险控制。
- 项目当前未上线，允许直接调整数据结构和接口，不设计旧格式兼容分支。
