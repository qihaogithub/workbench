## 1. 背景

在页面 `闯关活动页-进行中_ec853d` 中，用户要求把硬编码的“领课广告”调整为内容模块列表末尾的可选图片模块。Agent 修改 `index.tsx` 与 `config.schema.json` 后，用户反馈广告没有显示、配置项也未出现，并一度认为预览区为空。

本次排查的目标不是为单次页面补丁增加兼容分支，而是厘清以下边界并修复可复用的契约缺口：

1. 页面 Schema 默认值、已保存运行值和预览 props 的优先级；
2. HTML 导入、创作端页面扫描和 Agent 页面/可见性工具对 `pageId` 的校验一致性；
3. Workspace Authority 备份不变量失效时的恢复、诊断与用户反馈；
4. 预览“空白”是否有可复现的运行时根因，避免将工具侧误判当作 UI 根因。

## 3. 已证实的证据

### 3.1 运行值覆盖默认值，广告模块不会自动出现

目标页的组件使用非空 `modules` props 时直接渲染该数组，否则才回退到 `DEFAULT_MODULES`：

```ts
const list = modules && modules.length > 0 ? modules : DEFAULT_MODULES;
```

本次排查初始状态是 Agent 只写入 `DEFAULT_MODULES` 和 `config.schema.json.properties.modules.default`，未同步运行值；修复后源项目工作区和 live Workspace 的 `config.values.json` 均为 11 个模块，前 10 项顺序保持不变，末项为唯一广告图片模块。源项目运行值使用已资产化的 `/api/images/img_RmY_REJpq2nrtg`，live Workspace 使用当前页面默认图片 URL，均按“已保存运行值优先”参与预览和配置面板投影。

创作端加载 Authority 快照时也明确按“Schema 默认值 → 页面运行值”覆盖：存在 `config.values.json` 时，页面运行值是权威快照，不能以旧状态或新的默认数组覆盖它。

### 3.2 中文 `pageId` 被 Agent 工具静默漏掉

目标页已经存在于 `workspace-tree.json`，并声明 `runtimeType: "high-fidelity-react"`；创作端 `listDemoPages` 直接按页面树和该运行时入口校验，因此会保留该页。

但 Agent 的 `listPages` 和可见性工具的 `parseTree` 都调用：

```ts
/^[A-Za-z0-9_-]+$/.test(pageId)
```

所以历史上的 `闯关活动页-进行中_ec853d` 被过滤。现在列表、可见性、HTML 导入、上传和页面级路由均复用共享单路径段校验，非法页面改为输出结构化诊断，不再静默遗漏。

### 3.3 Authority 发生过真实的备份不变量故障

同一编辑会话的 Authority journal 记录了提交成功的页面源码/Schema 写入，也记录了包含历史 `prototype.*` 文件的 mutation 因 `WORKSPACE_AUTHORITY_BACKUP_MISSING` 回滚；编辑端诊断记录随后出现 `autosave.sync_failed`、`FILE_WRITE_ERROR` 和 HTTP 503。

当前 Authority state 所有 resource hash 都能找到且校验通过对应 backup，因此只能确认“故障曾经发生并已恢复”，不能从现有证据断言是备份清理、迁移、并发还是外部文件操作导致首次缺失。

### 3.4 预览空白尚未形成可归因证据

同一会话中目标页多次记录 `compile_done`、`render_committed`、`iframe_loaded`，没有捕获到该页的 preview runtime error。`captureScreenshot` 则因当前机器没有 Chromium executable 失败；现在截图服务通过深度健康检查门控 Agent 工具，诊断 SQLite 之外始终保留有界 JSONL 镜像，并提供受控重建入口。

因此“预览空白由中文 ID、`description` 或遗留 prototype 文件导致”的说法均不成立。若要修复真实 UI 空白，必须在截图与浏览器控制台可用后复现并采集完整 trace。

## 4. 目标与非目标

### 4.1 目标

- 页面 ID 在导入、页面创建、页面扫描、Agent 工具、可见性、上传和 Authority 操作中采用同一个安全契约。
- Agent 编辑现有页面的配置数组时，明确区分定义默认值与当前运行值，并能一次事务完成必要更新。
- Authority 不再在可恢复的备份缺失条件下反复触发 autosave 503；不可恢复时提供可定位的错误和健康状态。
- Agent 没有获得视觉/运行时验证时，不得把文件写入描述为“预览已验证完成”。

### 4.2 非目标

- 不把未复现的预览空白归咎于某个页面文件或进行重建、重注册、重命名等破坏性操作。
- 不删除迁移遗留的 `prototype.*` 文件；它们不是本问题的证据或修复对象。
- 不让 Schema 默认值无条件覆盖用户保存的配置值。
- 不在业务页面中添加特殊兼容分支。

## 5. 技术方案

### 5.1 建立唯一的 Unicode 安全页面 ID 契约

采用已有白板治理方向：页面 ID 可以是 Unicode 单路径段，但必须拒绝空值、`.` / `..`、`/`、`\\`、控制字符和孤立代理项。不要再让不同模块各自维护 ASCII 正则或仅靠 `basename` 检查。

1. 在共享层定义并导出唯一的 `isSafeWorkspacePathSegment`（或等价命名）与错误码；
2. `html-import`、Agent `listPages/createPage/deletePage`、`visibility-tools`、素材上传和所有页面级路由都改为使用它；
3. 过滤不合法页面时返回结构化诊断（页面 ID、调用方、拒绝原因），不得静默省略；
4. 为现有中文页面补齐端到端测试：导入/扫描、Agent 列表、可见性检查、配置上传和预览快照都应能定位到同一页面。

这比强制改为 ASCII 技术 ID 更符合已存在的中文页面及既有 Unicode 治理方向，同时仍保持文件路径安全边界。

### 5.2 明确“默认值”和“当前运行值”的 Agent 写入协议

对“向现有可排序模块数组追加默认内容”的请求，Agent 必须执行以下顺序：

1. 读取 Schema、`config.values.json` 和页面组件实际 fallback 逻辑；
2. 更新 Schema：新增/保留可选模块变体与新页面默认值；
3. 若当前 values 中存在该数组：按稳定 discriminator 判断广告项是否已存在，未存在则在末尾追加，不重写用户既有排序或其他字段；
4. 在同一受管 mutation 中提交源码、Schema 和 values；
5. 从 Authority receipt 重新读取完整页面快照，断言 values 模块数、末项类型/图片和预览 props 一致；
6. 以 Authority receipt、刷新后的完整 props、`render_committed` 和无 runtime error 作为功能完成条件；截图只在服务健康且任务确实需要视觉判断时追加，不能成为普通配置修改的必选条件。

该协议是 Agent 工作流约束，不应通过“Schema default 自动合并进非空数组”改变用户数据语义。

### 5.3 强化 Workspace Authority 备份恢复与故障边界

保留备份缺失时的 fail-closed 原则，但使其在 mutation 前可检测、在可安全重建时可恢复、在不可恢复时可诊断：

1. 在 mutation 预检阶段校验 state 中每个 resource hash 的 backup；缺失时记录 resource path/hash 与触发操作；
2. 若当前工作区内容与 state hash 完全一致，可从当前已验证内容重建缺失的 content-addressed backup，并记录 `backup_rehydrated` 诊断事件；
3. 若当前内容不能证明与 state 一致，拒绝写入并返回带 resource path/hash 的 `WORKSPACE_AUTHORITY_BACKUP_MISSING`，禁止进入可能无法回滚的写阶段；
4. 核查任何备份清理/保留任务不得删除仍被当前 state、prepared mutation 或 receipt 引用的 hash；
5. 前端收到该错误后停止无意义的防抖重试，展示“页面暂存异常，可重试/刷新”的明确状态，并在健康恢复后允许继续保存。

### 5.4 将截图改为按健康状态暴露的可选能力

- 截图服务启动时明确配置 Chromium executable 或 channel，并在健康检查中暴露浏览器可用状态；
- Agent 服务在创建会话和 `activateCapabilities` 时读取带短 TTL 的截图健康状态。仅当服务可达且浏览器可启动时，才把 `captureScreenshot` 加入工具注册、workspace/image capability 返回值和相关 Skill 的可用能力说明；不健康时不向模型暴露该工具，也不布置截图任务；
- 将“功能验证”和“视觉验证”分离：前者使用 receipt、配置快照、编译/渲染 trace 和控制台错误完成；后者仅用于视觉布局、响应式、像素/截图对比等明确需要视觉判断的任务；
- 截图服务在会话期间转为不健康时，撤销后续截图调用资格并返回结构化 capability-state，而不是让 Agent 重复调用必然失败的工具；对于用户明确要求视觉验收的任务，Agent 应报告视觉证据暂不可用，而非把它伪装成通用失败；
- 修复/重建诊断 SQLite 前保留 JSONL fallback，但诊断结果必须标注 `eventGapDetected`，不得拿不完整事件流做强因果判断；
- 预览 trace 至少记录 active page、页面 runtime type、配置快照 hash、编译错误、模块加载错误、`render_committed` 与 iframe 生命周期；
- Agent 的完成话术由功能验证和可选视觉验证分别驱动：前者足以说明功能修改完成，后者只补充用户可见的视觉证据。

## 8. 风险与待确认事项

- Unicode 路径段需覆盖 Windows/macOS/Linux 文件系统、URL 编码、路由参数和所有现有正则；仅替换 Agent 工具会再次形成漂移。
- `config.values.json` 是用户状态。自动追加只适用于用户明确要求“在当前页面增加该模块”的操作，不能把每次 Schema 变更都升级为 values 重写。
- 当前备份已经完整，历史缺失来源没有证据；已保留 fail-closed，并只允许在 root hash 与 state 完全一致时重建缺失 backup。
- 诊断 SQLite 曾报告损坏和事件缺口；JSONL 镜像/重建只用于恢复可查询性，不用于推断未记录操作。
