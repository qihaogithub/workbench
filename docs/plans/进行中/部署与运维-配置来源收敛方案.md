# 配置来源收敛实施记录

## 背景

当前仓库在端口、服务 URL、数据目录、环境变量加载、模型配置和工具链配置上存在多处声明。部分差异属于 local/Docker 或全局/用户/session 的合理分层，部分已经形成真实漂移。

## 目标

- 为非敏感运行配置建立明确的单一来源。
- 保留合理的环境与运行时覆盖层级。
- 删除已确认的重复、冲突和未接通配置。
- 用自动检查阻止配置再次漂移。
- 不覆盖当前工作树中的无关改动，不读取或改写运行数据。

## 范围

- `@workbench/runtime-config` 配置包。
- local/Docker 端口、服务 URL、dotenv、`DATA_DIR` 和环境模板。
- E2E 配置入口。
- 全局/用户/session 模型配置与绘图配置。
- 协议常量和 TypeScript、Vitest、Tailwind、ESLint、PostCSS 基线。
- 配置漂移检查及相关项目文档。

## 方案

采用独立配置包承载可共享的非敏感配置、解析器和契约；各服务只在启动边界读取环境；Docker 和浏览器构建保持独立 profile；动态模型配置保留业务优先级但统一持久化结构。无法直接消费配置包的脚本和声明式配置由漂移检查约束。
