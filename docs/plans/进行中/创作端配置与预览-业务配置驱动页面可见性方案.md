# 创作端配置与预览：配置驱动页面可见性方案

> 状态：方案设计中
> 创建日期：2026-09-02
> 适用范围：创作端配置栏、AI 创作能力、预览运行时、画布页面状态、发布与浏览端

## 一、背景

当前产品已经形成了相对清晰的两个创作入口：

- **编辑栏**：用于修改页面本身，属于页面开发能力，负责页面结构、组件、布局和样式的创造与调整。
- **配置栏**：用于定义页面在被使用时呈现什么内容、具备什么能力，属于消费配置能力。

现有配置栏已经支持 Schema 驱动的表单、页面级配置、项目级共享配置、资源上传、默认值管理和预览联动。配置值能够在创作端预览中即时生效，并随发布快照进入浏览端。

新的业务需求是：配置栏中的某个配置项，不仅影响当前页面中的一部分内容，还可能影响项目中其他页面的显示、隐藏或可用状态。例如：

> 开启“会员中心”后，首页显示会员入口，同时启用会员权益、账单和积分页面；关闭后，首页入口隐藏，相关页面在浏览端不再出现。

这类需求本质上是“配置驱动的页面与区域状态”，不是普通的组件显隐，也不是页面结构编辑。若把关联页面、触发行为和规则条件都直接做成用户可维护的配置功能，会增加理解和维护成本，也会让配置栏逐渐演变成复杂的流程编排工具。

本方案的方向是：**保留一个统一配置栏，支持资源配置和业务配置；任意明确允许的配置项都可以由 AI 在创作阶段生成页面关联和联动规则，系统负责校验、预览和执行；浏览端以已发布配置和规则为基础消费页面，资源配置仅可按策略产生页面内区域的会话级覆盖。**

## 二、目标

### 2.1 产品目标

1. 在不新增第二个配置栏的前提下，让现有配置栏能够承载业务配置。
2. 让资源配置和业务配置使用同一套表单能力，降低用户学习成本和实现成本。
3. 让资源配置和业务配置都支持项目级与页面级作用域。
4. 支持一个项目级配置项影响多个页面或页面区域的显示与可用状态。
5. 让复杂关联关系和联动行为由 AI 创作能力完成，不要求普通用户维护规则图或表达式。
6. 让创作端、预览端、发布产物和浏览端对配置结果保持一致。
7. 保证业务配置和联动规则只能在创作端修改；浏览端资源配置仍可按字段权限修改，但其会话级覆盖不得改变页面导航、直接访问结果或页面可用状态。
8. 页面被配置规则停用时不删除内容，保留编辑、恢复、撤销和版本回滚能力。

### 2.2 工程与治理目标

1. 复用现有 Schema、ConfigForm、FieldRenderer、配置值持久化和预览投影能力。
2. 将配置值、页面关联关系和联动行为分离建模，避免把复杂关系塞进普通字段值。
3. 让 AI 生成的规则具备可验证、可追踪、可回滚的提交边界。
4. 发布前能够发现缺失目标、无效页面引用、冲突规则和无法执行的联动规则。
5. 通过 Agent Skill 明确告诉 Agent 如何识别配置作用域、修改 Schema、同步页面代码并建立联动规则。
6. 让 Agent 遵循现有的 `readPreinstalledSkill`、页面生命周期、运行时和权限约束，不依赖模型临时猜测文件结构。

## 三、非目标

本阶段不做以下事项：

- 不新增独立的“业务配置栏”或“页面关系配置栏”。
- 不在编辑栏中增加业务配置开关。
- 不提供普通用户拖拽配置页面关系、编写条件表达式或搭建动作流程的工作台。
- 不允许浏览端修改业务配置或页面联动关系；资源配置仍按既有消费权限开放。
- 不因关闭配置项而物理删除页面、源码、配置值或资源。
- 不把所有页面内容自动抽取为配置字段。
- 不允许浏览端执行未经校验的任意 AI 生成脚本。
- 不把页面可见性或可用状态当作鉴权、数据访问控制或功能授权机制。
- 阶段一不允许浏览端资源配置会话覆盖改变页面导航、直接访问结果或页面可用状态。

## 四、现状

### 4.1 产品现状

- 编辑栏和配置栏已经形成不同的产品职责：前者负责页面开发，后者负责消费配置。
- 配置栏当前同时承载页面级配置和项目级共享配置，但主要关注字段值编辑；资源配置和业务配置在作用域上应遵循同一套层级模型。
- 配置字段已经支持文本、数字、布尔、枚举、图片、视频、音频、数组和对象等类型。
- 用户可以在创作端编辑配置值，预览区会根据配置值刷新页面。
- 画布和单页预览都可以查看页面及其配置状态。

### 4.2 技术现状

- `ConfigForm` / `FieldRenderer` 根据 Schema 生成表单，创作端和使用端复用同一套字段控件。
- 项目级配置定义与运行值已分离，项目级运行值可以写入发布事实。
- AI 编辑可以原子化更新页面代码、Schema 和相关配置默认值。
- 预览运行时按项目级默认值、页面级默认值和运行值合并后注入组件。
- Agent 当前通过 `page-lifecycle`、`react-high-fidelity`、`page-runtime-conversion` 等预装 Skill 学习页面创建、Schema 配置、React Props 和运行时转换规则；Skill 由 `readPreinstalledSkill` 按需加载。
- 当前 System Prompt 已明确“只有用户明确要求时才新增或删除配置字段”、项目级字段不写入页面 `DemoProps`、原型页需要同步 HTML 绑定等约束。
- 当前配置协议主要表达“字段是什么、字段值是什么、字段如何渲染”，尚未形成统一的“任意配置项影响哪些页面及如何联动”的创作协议。
- 当前页面状态、导航可见性、直接访问旧链接和发布前跨页面依赖校验缺少统一业务规则入口。

### 4.3 现有问题

1. 如果把页面显隐开关放在属性编辑器里，用户会误以为它只是当前页面的视觉属性。
2. 如果为业务配置单独创建一套配置栏，会造成两个入口、两套表单和两套保存心智。
3. 如果把关联页面和联动行为全部暴露成表单，配置栏会出现页面关系、条件、动作等复杂概念。
4. 如果只让 AI 修改页面代码而不保留宿主层关系信息，系统无法可靠处理页面导航、直接访问、发布校验和影响范围。
5. 如果浏览端继续暴露影响页面结构的配置编辑能力，线上用户可能改变项目页面结构或绕过发布流程。

## 五、核心概念与边界

### 5.1 两种配置类型，共用一套表单

| 配置类型 | 解决的问题 | 典型例子 | 项目级作用域 | 页面级作用域 | 是否可作为联动来源 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 资源配置 | 消费时使用什么内容或资源 | 图片、文案、数据源、商品列表 | 多个页面共享的品牌素材、数据源 | 当前页面或区域专用内容 | 可以，需显式声明 |
| 业务配置 | 消费时启用什么产品能力 | 是否启用会员中心、是否开启订单功能 | 可驱动多个页面或区域 | 默认只驱动当前页面及其区域 | 可以，通常适合跨页面 |

两者可以共用字段类型、表单控件、校验、默认值、保存和预览联动机制。差异不在“表单怎么填”，而在字段的产品语义；是否能够影响页面状态，由独立的联动能力和权限规则决定。

### 5.2 配置作用域与联动范围

项目级和页面级是配置项的作用域，而不是两套配置栏：

| 作用域 | 适用场景 | 默认生效范围 | 跨页面联动 |
| :--- | :--- | :--- | :--- |
| 项目级 | 多个页面共享的资源或产品能力 | 整个项目；页面级配置可补充当前页面独有值 | 允许，由 AI 建立受控规则 |
| 页面级 | 当前页面独有的资源或局部业务状态 | 当前页面及其页面区域 | 不允许；若需影响其他页面、画布、导航或默认入口，AI 必须创建或提升为项目级配置 |

项目级配置继续使用现有项目级 Schema 与运行值语义；页面级配置继续使用页面 Schema 与运行值语义。业务配置和资源配置都遵循同一套项目级/页面级合并顺序，不另设一套业务配置覆盖机制。项目级和页面级字段不得使用相同配置 key 表达不同含义，避免合并和覆盖歧义。配置项是否作为联动来源、可影响哪些目标以及谁可以修改，均由联动规则和权限元数据单独决定。

### 5.3 联动能力与配置分类解耦

关联关系和联动行为是配置系统的通用能力，不是业务配置的专属能力：

- 资源配置和业务配置都可以作为联动规则来源；
- 只有用户明确提出或 AI 明确生成的规则，配置项才参与联动，不根据字段类型自动推断；
- 资源值为空、资源加载失败或网络异常，不应在没有显式规则时自动改变页面结构；
- 业务配置来源的页面结构联动在浏览端必须锁定来源值；
- 浏览端资源配置会话覆盖在阶段一只能驱动目标页面内已声明区域的展示，不能改变页面导航、直接访问结果或页面可用状态；
- 资源配置需要驱动跨页面结构时，必须使用已发布值；是否在后续阶段开放会话级跨页面联动，需另行设计权限、体验和兼容策略；
- 配置分类用于产品解释、分组和默认权限，不作为联动能力的硬性准入条件。

### 5.4 三类数据分离

配置驱动联动需要拆成三类数据：

1. **配置定义**：名称、类型、默认值、说明、分类和作用域等，继续由项目级或页面级 Schema 表达。
2. **配置运行值**：当前项目或工作区实际使用的值，继续由项目级或页面级配置值文件保存。
3. **消费联动规则**：配置值变化后影响哪些页面/区域，以及目标状态如何变化。该规则由 AI 在创作阶段生成，属于受控的创作资产，不作为普通配置表单暴露。

配置定义和运行值面向创作者；消费联动规则主要面向 AI、运行时和诊断系统。资源配置和业务配置都可以成为规则来源，但不是所有字段都默认具备联动能力。

### 5.5 显示、可用与编辑状态分离

- **显示状态**：页面或区域是否出现在浏览端导航和正常视图中。
- **可用状态**：页面是否可以被访问或使用；可显示为不可用提示，也可以被隐藏。
- **编辑状态**：创作端是否仍然保留页面和区域供编辑。

默认规则是：配置值触发停用后，浏览端按规则隐藏或禁用目标，但创作端始终保留页面内容并标记控制来源。

页面状态规则只负责浏览体验和路由解析，**不构成鉴权或数据访问控制**。即使页面在浏览端被隐藏或不可用，服务端 API、资源与业务动作仍必须各自执行既有的身份与权限校验。

## 六、总体方案

### 6.1 信息架构

继续使用一个配置栏，在配置栏中对配置项进行分类：

```text
配置栏
├─ 项目级配置
│  ├─ 资源配置
│  └─ 业务配置
└─ 页面级配置
   ├─ 资源配置
   └─ 业务配置
```

“联动规则摘要”只作为只读说明或诊断信息，不提供拖拽关联、条件编辑和动作编排入口。配置栏可以提供项目级/页面级筛选或分组，但不拆成两个独立面板。

资源配置和业务配置均可显示“已被联动规则使用”的只读标记；该标记表示字段的消费关系，不改变字段所属分类，也不把联动规则变成用户可编辑的配置项。

### 6.2 配置栏交互

项目级和页面级资源/业务配置在日常使用上保持一致：

- 使用相同的字段控件和布局；
- 使用相同的字段校验和默认值机制；
- 修改后进入同一套保存队列；
- 修改后驱动预览刷新；
- 支持恢复默认和撤销。
- 项目级字段展示项目范围；页面级字段展示当前页面范围。

配置字段可以显示少量只读上下文，例如：

> 已由 AI 配置页面联动规则

如果需要帮助用户理解影响范围，可以展示“影响 3 个页面”的摘要或查看入口，但不展示关系编辑器。

### 6.3 编辑栏交互

编辑栏不增加配置驱动联动控件。

被配置联动规则控制的页面或区域，在编辑栏、画布和单页预览中显示只读状态：

> 由配置「启用会员中心」控制
> 当前状态：已停用
> [查看配置]

点击“查看配置”后跳转到同一个配置栏，而不是打开第二个配置面板。

### 6.4 AI 创作流程

用户可以使用自然语言描述跨页面业务需求，例如：

> 增加一个“启用会员中心”的业务配置。打开时显示首页会员入口，并启用会员权益、账单和积分页面；关闭时隐藏这些内容。

AI 按以下步骤执行：

1. 识别或创建配置字段，并判断其属于资源配置还是业务配置；
2. 判断配置应属于项目级还是页面级；
3. 识别目标页面和目标区域；
4. 判断是否需要联动，以及联动是否超出当前配置作用域；
5. 生成页面代码对配置值的消费逻辑；
6. 生成宿主可识别的页面状态联动规则；
7. 执行规则校验和页面引用校验；
8. 在草稿预览中展示配置变化的结果；
9. 向用户展示代码变更、配置变更和影响摘要；
10. 用户确认后提交创作端草稿；
11. 发布仍由创作者显式发起。

如果用户要求一个页面级配置影响其他页面，AI 应优先解释作用域冲突，并建议创建或提升为项目级配置，而不是隐式扩大页面级配置的作用范围。若资源配置被用于页面结构联动，AI 应明确提示该结构只由已发布值驱动；浏览端会话覆盖在阶段一仅影响该页面内已声明区域的展示，不能改变导航或直接访问结果。

AI 可以使用代码实现局部区域的灵活逻辑，但跨页面可见性、导航和直接访问策略必须同时登记为受控规则，不能只依赖运行时扫描任意代码。

### 6.5 Agent Skill 与编辑协议

配置驱动联动不是只增加一个表单字段，还需要让 Agent 知道“什么时候改什么、改到哪里、改完如何验证”。建议新增一个专用预装 Skill：

> Skill 名称建议：`config-driven-behavior`

该 Skill 由 `packages/agent-service/src/preinstalled-skills/config-driven-behavior/SKILL.md` 提供，沿用现有预装 Skill 机制：任务匹配时，Agent 必须先调用 `readPreinstalledSkill({ name: 'config-driven-behavior' })` 读取完整规则，再执行编辑。

#### Skill 触发范围

以下需求应触发 `config-driven-behavior`：

- 增加或修改业务配置或资源配置；
- 开关打开/关闭后改变页面或区域显示；
- 一个配置影响多个页面；
- 页面启用、停用、不可用或导航可见性变化；
- 将已有页面行为改造成由配置值驱动。

单纯修改不参与联动的资源配置值、单页文案或样式，不必加载该 Skill，继续沿用现有配置和页面编辑规则。

#### Agent 必须遵循的编辑步骤

1. **判断用户意图**：区分“修改已有配置值”“新增配置字段”“修改配置消费逻辑”和“建立跨页面联动”四类任务。
2. **识别配置语义**：判断配置是资源配置还是业务配置；分类用于说明字段含义，不决定其是否具备联动能力。
3. **确认作用域**：判断配置是项目级还是页面级。跨页面联动默认必须使用项目级配置；页面级配置默认只作用于当前页面及其区域。
4. **读取真实上下文**：先通过页面清单获得稳定 page ID，再读取项目级 Schema、目标页面 Schema 和对应运行时源码；不得根据页面名称或猜测路径直接编辑。
5. **遵守配置字段边界**：只有用户明确提出配置诉求时才能新增或删除字段；项目级字段写入项目 Schema，页面级字段写入目标页面 Schema；不得出现同名字段。
6. **同步页面消费代码**：React 页按照 `react-high-fidelity` 规则维护 Props 和运行时消费；原型页按照 `page-lifecycle` 规则补齐 `{{fieldKey}}` 或 `data-bind-*` 绑定；复合配置按需触发 `page-runtime-conversion`。
7. **建立联动规则**：任意配置项需要影响页面或区域时，除页面局部代码外，还必须生成宿主可识别的联动规则；规则使用稳定 page ID/区域 ID，不使用标题和 DOM 文本作为唯一标识。
8. **先计划再执行高影响修改**：跨页面、跨模块或涉及发布权限的任务属于高影响任务，按现有 Agent 计划审批机制先提交计划，用户确认后再写入。
9. **原子提交**：Schema、页面源码、联动规则和必要的配置值变更必须在同一草稿提交边界内完成；live Workspace 必须走受管工具和 Workspace Mutation Authority，不能使用 bash 绕过写入链路。
10. **验证并回报**：执行 Schema 校验、规则引用校验和预览验证；确认保存 receipt 或等价持久化结果后，才能向用户报告完成，并说明作用域、受影响页面和未解决风险。

#### Skill 中必须写清楚的禁止事项

- 不得把配置驱动联动开关放回编辑栏属性中；
- 不得为跨页面关系创建普通用户拖拽配置器；
- 不得把页面级配置隐式扩大为项目级；
- 不得因为生成页面而自动增加资源配置或业务配置字段；
- 不得删除被停用页面或覆盖其原有资源；
- 不得只修改页面代码却声称已经完成跨页面联动；
- 不得在浏览端 Agent 中调用写文件、编辑配置或修改联动规则的能力。

#### 现有 Skill 和 Prompt 的配套更新

新增 `config-driven-behavior` 后，还需要同步维护现有 Agent 教学入口：

| 位置 | 更新内容 |
| :--- | :--- |
| `page-lifecycle` | 增加项目级/页面级配置边界、跨页面配置必须提升为项目级的说明 |
| `react-high-fidelity` | 增加项目级资源/业务配置的消费示例，强调项目级字段不进入 `DemoProps` |
| `page-runtime-conversion` | 转换页面运行时保留配置字段和消费逻辑，不丢失联动绑定 |
| `system-prompt.md` | 在按需 Skill 列表中登记 `config-driven-behavior`，并写入触发条件和强制读取指令 |
| 动态 Agent 上下文 | 提供项目级/页面级 Schema、稳定页面 ID、当前规则摘要和配置作用域，避免 Agent 只看到当前页面 |
| `viewer-readonly` Prompt/工具集 | 浏览端 Agent 仍保持只读，不修改业务配置或联动规则；浏览端配置 UI 可修改资源值，但阶段一只触发页面内允许区域的联动计算 |

Skill 不是权限边界的替代品。文件路径校验、浏览端 Agent 只读、用户确认、Authority receipt 和发布门禁仍由工具层和服务端强制执行。业务配置和联动规则不得在浏览端修改；资源配置可以按既有消费权限修改，但阶段一仅允许其会话值重算目标页面内允许覆盖的区域状态。

### 6.6 联动规则的内部表达

联动规则不是用户表单，而是 AI 生成、系统校验的内部规则资产。其表达至少需要包含：

- 来源配置项标识及其项目级/页面级作用域；
- 条件和值的判断方式；
- 目标页面或区域的稳定标识；
- 目标状态：显示、隐藏、可用、不可用；
- 可选的兜底页面或提示策略；
- 规则版本和生成来源。

阶段一采用受限声明式规则，不执行任意表达式或脚本。最小模型固定为：

- 来源仅限项目级配置字段；条件仅支持布尔 `truthy` 与标量 `equals`；
- 目标为稳定 `pageId` 或目标页面显式声明的 `regionId`；区域 ID 必须由源码/运行时协议声明并可在构建时校验，不能从 DOM 文本、CSS 选择器或 AI 猜测推导；
- 效果仅支持 `hidden` 与 `disabled`；规则计算是纯函数 `resolveVisibility(publishedSnapshot, allowedSessionOverrides)`；
- 同一目标、同一状态维度存在相反效果时拒绝发布；没有优先级、后写覆盖或运行时猜测；
- 条件不得读取其他规则的计算结果或页面状态。因此阶段一不存在规则循环；多字段组合、状态依赖和“全部/任一”条件留到阶段三。

AI 可以通过代码或工具调用生成规则，但浏览端只执行编译后、已发布、通过校验的规则。

### 6.7 规则资产与原子提交

联动规则必须是工作区的一等受管资源，阶段一固定使用项目根目录 `project.visibility-rules.json`。该资源必须：

- 纳入 Workspace resource registry、Agent 文件/工具权限、Mutation Authority 和协同持久化白名单；
- 与 Schema、页面源码和配置值一起进入同一 Authority mutation；任何一项校验、写入或 projection 失败都不得形成部分提交；
- 进入不可变发布快照，随快照记录内容哈希、规则版本、生成来源和 mutation receipt；发布回滚必须同时恢复规则；
- 由创作端草稿预览与浏览端共用同一个规则解析器/测试夹具，禁止两端各自实现解释逻辑。

### 6.8 预览与画布行为

预览必须同时支持配置值和联动规则的草稿态：

- 切换参与联动的配置项后，预览即时更新当前页面区域；
- 画布中的受控页面保持可见，但置灰并标记“已停用”；
- 画布页面卡片显示控制来源和当前状态；
- 用户可以切换或修改参与联动的配置值，查看页面组的整体状态变化；
- 规则错误时，预览展示可理解的错误摘要，不显示空白画布；
- 创作端页面内容不会因为停用而被删除。

### 6.9 发布与浏览端行为

发布时，页面代码、Schema、配置运行值和联动规则必须作为同一份发布事实提交。

浏览端行为：

- 以已发布的配置值和联动规则作为默认事实；
- 业务配置不在浏览端配置栏中展示；
- 不提供修改业务配置或联动规则的接口；
- 资源配置仍可以由浏览端按既有消费权限修改；
- 浏览端资源配置修改只影响当前消费会话，并且阶段一只重新计算目标页面内允许会话覆盖的区域状态；
- 导航、页面列表和页面直接访问都使用同一套解析结果；
- 被隐藏页面的旧链接进入统一兜底页或友好不可用提示；
- 浏览端资源配置修改默认只影响当前消费会话，不回写项目级业务配置、联动规则或发布快照。

## 七、权限与状态

### 7.1 权限边界

| 操作 | 创作端 | 预览 | 浏览端 |
| :--- | :---: | :---: | :---: |
| 修改资源配置值 | 允许 | 草稿态允许 | 允许，按现有资源配置策略执行；阶段一只影响本会话内允许覆盖的页面区域 |
| 修改项目级/页面级业务配置值 | 允许 | 草稿态允许 | 不允许 |
| 创建或修改页面联动规则 | 由 AI 创作能力完成 | 只读预览 | 不允许 |
| 查看受控页面状态 | 允许 | 允许 | 只显示最终结果 |
| 发布配置与联动规则 | 显式发布 | 不适用 | 不允许 |

### 7.2 页面状态建议

| 状态 | 创作端 | 浏览端 |
| :--- | :--- | :--- |
| 已启用 | 正常编辑和预览 | 正常显示、可访问 |
| 已停用 | 保留页面，置灰并标记来源 | 隐藏或不可用 |
| 依赖缺失 | 显示错误，允许 AI 修复 | 禁止发布或进入安全兜底 |
| 规则冲突 | 显示诊断信息 | 禁止发布 |
| 已发布旧版本 | 草稿可继续修改 | 继续使用最近一次已发布快照 |

## 八、校验与安全策略

### 8.1 AI 生成前后校验

- 配置项必须存在且类型匹配；
- 页面和区域必须使用稳定 ID，不能依赖易变的显示名称；
- 目标页面必须存在；
- 页面级规则只能引用本页显式声明的区域，不能影响其他页面、画布、导航或默认入口；
- 阶段一条件不得读取页面状态或其他规则结果；
- 同一配置项对同一目标不能产生互相冲突的动作；
- 隐藏关键入口时必须有明确兜底策略；
- AI 不能把浏览端配置权限写入页面代码；
- 规则变更与页面代码、Schema 变更必须在同一草稿提交中保持一致。

### 8.2 发布前检查

发布门禁至少检查：

1. 配置字段定义和运行值是否通过 Schema 验证；
2. 联动规则引用的页面和区域是否存在；
3. 是否存在孤立规则、冲突规则、越出配置作用域的目标或不支持的条件/效果；
4. 被隐藏页面是否仍被导航、页面链接或默认入口引用；
5. 浏览端是否能使用同一份已发布配置重现创作端预览结果；
6. 规则错误是否会导致空白页面、不可恢复导航或越权访问。

## 九、数据与接口建议

本方案不要求立即确定具体文件名，但建议保持以下职责分离：

| 数据 | 主要内容 | 作用域 | 是否由普通配置表单直接编辑 | 浏览端行为 |
| :--- | :--- | :--- | :---: | :--- |
| 配置 Schema | 字段、类型、默认值、校验、展示元数据和作用域 | 项目级或页面级 | 部分可编辑 | 不修改 |
| 配置运行值 | 当前项目或页面实际使用的字段值 | 项目级或页面级 | 是 | 资源配置允许临时修改；业务配置不允许 |
| 消费联动规则 | 项目级配置与页面/区域状态的受限声明式关联 | `project.visibility-rules.json`，阶段一仅项目级来源 | 否，由 AI 管理 | 不修改；仅使用已发布值计算跨页面状态 |
| 发布快照 | 代码、Schema、运行值和规则的不可变版本 | 项目级发布事实 | 否 | 只读消费 |

联动规则以 `project.visibility-rules.json` 作为唯一工作区真值；发布清单只引用其不可变快照副本。规则必须具备版本、哈希、来源和原子提交信息，避免代码已经更新而规则尚未落盘，或规则已更新而页面仍使用旧逻辑。

## 十、典型用户流程

### 10.1 创建配置并建立联动

1. 用户在 AI 对话中提出“开启会员中心后展示相关页面”。
2. AI 识别需要一个项目级配置（本例为布尔型业务配置），并复用现有表单字段能力。
3. AI 找到首页会员入口及三个关联页面。
4. AI 生成局部渲染代码和跨页面联动规则。
5. 创作端在项目级业务配置分组中展示配置字段、预览结果和影响摘要。
6. 用户在配置栏切换开关，预览实时展示两种状态。
7. 用户确认 AI 变更并保存草稿。

### 10.2 停用并恢复

1. 用户在配置栏修改参与联动的配置项。
2. 系统提示将影响的页面数量和区域数量。
3. 预览和画布同步显示停用状态。
4. 关联页面内容仍保留在页面树和画布中。
5. 用户恢复配置值，页面恢复；或通过撤销/版本恢复回到此前状态。

### 10.3 浏览端消费

1. 创作者发布包含配置值和联动规则的版本。
2. 浏览端读取发布快照。
3. 浏览端根据已发布配置值和联动规则计算导航、页面和区域状态；资源配置临时覆盖只参与该页面允许覆盖的区域计算。
4. 用户只能使用最终页面，不能修改影响页面结构的配置或联动关系。

## 十二、验收标准

### 产品验收

- [ ] 产品中只有一个配置栏，资源配置和业务配置可在同一入口使用。
- [ ] 资源配置和业务配置均支持项目级与页面级，且用户能清楚区分作用域。
- [ ] 编辑栏不出现配置驱动联动开关，也不提供页面关系编辑器。
- [ ] 用户可以通过同一套表单控件修改资源配置和业务配置值。
- [ ] 任意被明确声明为联动来源的配置变更后，关联页面和区域按规则隐藏或变为不可用。
- [ ] 创作端仍保留被停用页面的内容和编辑能力。
- [ ] 页面、画布、单页预览和发布浏览结果的状态一致。
- [ ] 浏览端不展示业务配置，不能修改业务配置或联动关系；资源配置会话覆盖仅改变允许覆盖的页面区域，不会改变页面导航、直接访问结果或页面可用状态。
- [ ] AI 能够根据自然语言完成配置项和页面联动的创建、预览与提交。
- [ ] Agent 在匹配配置驱动联动任务时先读取 `config-driven-behavior` Skill，并按项目级/页面级规则选择编辑路径。
- [ ] Agent 能分别正确处理项目级配置、页面级配置、资源配置、业务配置、仅修改配置值和需要同步页面代码的任务。
- [ ] Agent 对跨页面修改先给出计划和影响范围，未经确认不提交高影响变更。
- [ ] Agent 不会因普通页面生成、样式修改或资源替换而隐式新增资源配置或业务配置字段。
- [ ] Agent 在页面代码修改成功但联动规则未提交时，不得向用户报告“跨页面联动已完成”。

### 质量验收

- [ ] 缺失页面、非法区域 ID、作用域越界、冲突动作和死链能够在发布前被发现。
- [ ] 代码、配置值和联动规则不会出现部分提交或版本错配。
- [ ] AI 生成失败时保留可诊断草稿，不破坏原有已发布版本。
- [ ] 关闭和恢复配置支持撤销、重做和版本回滚。
- [ ] 规则不允许携带创作端会话、管理权限或未授权宿主动作进入浏览端。

## 十三、风险与待确认事项

1. **代码逻辑与规则清单可能重复**：需要明确哪些局部逻辑由页面代码负责，哪些跨页面能力必须登记为宿主规则。
2. **区域标识稳定性**：页面重命名不会破坏 `pageId`，但 `regionId` 必须由页面源码显式声明并可校验；不得使用 DOM 文本或 CSS 选择器作为规则目标。
3. **会话覆盖扩张**：资源配置的会话覆盖若未来需要改变跨页面结构，必须单独设计权限、预期提示和直接访问语义；阶段一禁止该能力。
4. **运行时个性化**：如果未来按用户角色计算配置，需要区分项目级配置和用户运行时上下文，不能开放浏览端写入项目配置；页面状态规则也不能替代服务端鉴权。
5. **复杂规则可解释性**：规则越灵活，越需要 AI 提供影响摘要、状态解释和修复入口。
6. **作用域冲突**：项目级与页面级出现同名字段或同一业务语义重复声明时，需要明确拒绝、继承或覆盖规则。
7. **Skill 漂移**：配置规则、文件路径和工具能力变化后，`config-driven-behavior` 与现有页面 Skill、System Prompt 可能不一致，需要把 Skill 测试纳入 Agent 版本发布门禁。
8. **发布回滚边界**：回滚必须同时恢复代码、Schema、配置运行值和联动规则，不能只回滚页面源码。

## 十四、结论

本需求不应被实现为第二个配置栏，也不应把页面关联和联动行为暴露为普通表单功能。

推荐的最终产品边界是：

> **编辑栏负责创造页面；配置栏负责定义页面如何被使用；AI 负责在创作阶段建立配置项与页面之间的关系；系统负责校验和执行；浏览端以已发布结果为基础消费页面，资源配置仅可按既有策略产生页面内区域的会话级覆盖。**

资源配置和业务配置继续共享一个配置栏和一套表单引擎。两类配置均可成为联动规则的来源，但是否允许联动、联动范围和浏览端可变性由独立规则和权限元数据控制。复杂关系由 AI 创作能力和受控联动规则承载，从而在保持用户界面简单的同时，为跨页面业务场景保留足够的扩展空间。
