# 评论批注：钉钉提及与工作通知方案

## 背景

现有评论支持页面、文档、配置项和 `@AI`，普通用户候选人仅来自项目访问记录，且没有钉钉工作通知。本任务将普通用户提及收敛为当前项目的创作端钉钉参与者，并把新提及异步发送到钉钉个人工作通知。

## 目标与范围

- 创作端所有现有评论/回复入口均可搜索并 @ 当前项目参与者。
- 浏览端保持免登录，匿名评论/回复也可 @ 参与者并自动通知，但必须经过持久化限流。
- 通知统一跳到浏览端；当前发布版本无法定位目标时发送无链接消息。
- 不增加浏览端登录，不增加浏览端配置项或文档评论写入口，不扫描完整企业通讯录。

## 方案

- SQLite 保存项目参与者、通知 outbox、发送尝试和匿名限流事件；评论数据继续以项目 `comments.json` 为真值。
- 普通用户提及只提交项目级随机参与者 ID，服务端重新解析并保存姓名快照。
- 评论先落库，再以每位收件人一条 outbox 记录发送；编辑只为新增提及建任务。
- 评论 API/WS 只公开通知汇总，不暴露钉钉 userId、taskId、IP 或原始错误。
- 匿名候选搜索仅对已发布项目开放，通知按 IP、匿名身份、项目和收件人多维限流。

## 风险与待确认事项

- 生产环境必须配置可信客户端 IP 转发、公开 HTTPS Viewer 地址，以及与 AppKey/AppSecret 同应用同企业的 AgentId。
- 钉钉异步接口返回 taskId 只代表任务已提交，不等于已读。
