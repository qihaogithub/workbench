# 创作端配置与预览问题沉淀

## Spine 原子上传被资源策略拒绝

- 现象：`.zip` 与 `.zip.flutter` 均可完成解析和 staging，但 Authority 在提交素材与页面配置引用前返回 `WORKSPACE_INVALID_OPERATION`。
- 根因：Authority 使用的旧资源白名单未登记页面级 `demos/<pageId>/config.values.json`，且仓库同时维护 shared contracts 与 project-core 两套已漂移的受管资源策略。
- 修复：project-core Workspace Resource Registry 成为唯一资源策略；页面配置运行值登记为 JSON 对象资源；Authority 新增串行区内合并字段的 `patch_config_values`，使素材文件、manifest 与 `spineAsset` 引用保持单事务提交。上传 receipt 标记配置已提交，前端不再重复保存，并会合并上传期间的待保存配置。
- 失败边界：提交前拒绝会回收本次 staging；诊断包含 operation 类型和资源路径；失败不会更新本地配置或产生悬空资产引用。
- 验证状态：Registry、Authority、上传路由和配置 UI 定向测试已通过；真实浏览器上传、刷新持久化和音频事件验收待完成。
- 长期约束：禁止在 shared contracts 或业务路由复制 Workspace 资源白名单；新增受管资源必须先登记 project-core Registry 并覆盖 Registry 与 Authority 测试。

## Spine 上传成功但预览仍显示无素材

- 现象：上传、Authority 提交和配置持久化均成功，页面却继续显示 Spine 素材不可用占位。
- 根因：编译器 SDK 已切换为原子 `src` 接口，但 author/viewer 的预构建 `preview-sdk.js` 仍包含旧 `skeleton/atlas/texture` 接口；iframe 执行旧静态包后将新配置判定为空。
- 修复：preview runtime 构建从编译器 SDK 源码提取唯一实现，同时生成 author 与 viewer 产物；产物契约测试锁定 `src`、4.2/4.3 runtime 映射和音频能力，并拒绝旧三文件接口。播放器以 manifest 版本选择 runtime，骨架请求失败时进入可诊断错误状态。
- 验证状态：两端 runtime 已重新生成，产物语法、原子接口、4.2 映射和包级类型检查通过；真实页面播放、刷新恢复和事件音频由人工浏览器验收。

## 合并后白板路由残留冲突标记导致创作端编译阻断

- 现象：合并后打开创作端编辑页，Next.js 报 `Merge conflict marker encountered`，白板无法加载。
- 根因：合并完成后恢复 stash 时，白板读取与提交路由仍保留 `Updated upstream` / `Stashed changes` 标记；两侧同时包含 V2/客户端 PNG 与 V3/服务端 PNG 两套提交契约，不能通过删除标记或整体选择一侧解决。
- 修复：统一为 V3 完整 scene、服务端渲染 PNG、`whiteboard-image-target` 目标校验和原子事务回填；读取继续兼容 V1/V2，客户端 `pngBase64` 被拒绝；相关项目文档同步收口。
- 验证状态：author-site 类型检查通过，白板相关定向测试通过；完整 author 测试仍有与本次白板无关的既有失败，Studio 与 Dialog 白板浏览器回归已完成。
- 长期约束：合并或恢复 stash 后，先扫描源代码冲突标记并运行 author-site typecheck，再进入浏览器验收；禁止以 ours/theirs 整体覆盖白板提交路由。

## 白板双宿主工具入口统一 profile

- 当前结论：Whiteboard Studio 与创作端 `WhiteboardDialog` 必须使用 `@workbench/sketch-react` 唯一的 `whiteboard` profile，共享选择、抓手、矩形、圆形、画笔分组/橡皮、文本和图片入口；`SketchPageEditor` 不接入。
- 边界：profile 只限制入口和工具激活，不过滤已有 scene 节点；菱形、线条、箭头、便签、路径等隐藏入口节点继续读取、编辑、渲染、提交和回填；`html-css-v2` bridge 白名单独立维护。
- 验证状态：profile 契约、双端 Dialog/Studio 工具回归和隐藏节点保留测试通过；后续新增白板入口只修改 profile 并先在 Studio 验证。
