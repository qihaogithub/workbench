# 创作端配置与预览问题沉淀

## Spine 原子上传被资源策略拒绝

- 现象：`.zip` 与 `.zip.flutter` 均可完成解析和 staging，但 Authority 在提交素材与页面配置引用前返回 `WORKSPACE_INVALID_OPERATION`。
- 根因：Authority 使用的旧资源白名单未登记页面级 `demos/<pageId>/config.values.json`，且仓库同时维护 shared contracts 与 project-core 两套已漂移的受管资源策略。
- 修复：project-core Workspace Resource Registry 成为唯一资源策略；页面配置运行值登记为 JSON 对象资源；Authority 新增串行区内合并字段的 `patch_config_values`，使素材文件、manifest 与 `spineAsset` 引用保持单事务提交。上传 receipt 标记配置已提交，前端不再重复保存，并会合并上传期间的待保存配置。
- 失败边界：提交前拒绝会回收本次 staging；诊断包含 operation 类型和资源路径；失败不会更新本地配置或产生悬空资产引用。
- 验证状态：Registry、Authority、上传路由和配置 UI 定向测试已通过；真实浏览器上传、刷新持久化和音频事件验收待完成。
- 长期约束：禁止在 shared contracts 或业务路由复制 Workspace 资源白名单；新增受管资源必须先登记 project-core Registry 并覆盖 Registry 与 Authority 测试。

## Spine 上传成功但预览仍显示无素材

- 现象：上传、Authority 提交和配置持久化均成功，页面却继续显示 Spine 素材不可用占位。
- 根因：编译器 SDK 已切换为原子 `src` 接口，但 author/viewer 的预构建 `preview-sdk.js` 仍包含旧 `skeleton/atlas/texture` 接口；iframe 执行旧静态包后将新配置判定为空。
- 修复：preview runtime 构建从编译器 SDK 源码提取唯一实现，同时生成 author 与 viewer 产物；产物契约测试锁定 `src`、4.2/4.3 runtime 映射和音频能力，并拒绝旧三文件接口。播放器以 manifest 版本选择 runtime，骨架请求失败时进入可诊断错误状态。
- 验证状态：两端 runtime 已重新生成，产物语法、原子接口、4.2 映射和包级类型检查通过；真实页面播放、刷新恢复和事件音频由人工浏览器验收。

## 设计规范条目反向拖拽排序

- 现象：设计规范卡片从下方向上拖到另一张卡片时，尤其是相邻卡片，松手后顺序恢复不变。
- 根因：拖拽源移除后仍按目标原始索引 `to + 1` 插入，导致向上拖动时源条目被重新放回目标之后的原位置。
- 修复：排序迁移到 dnd-kit，优先按鼠标当前位置与目标卡片中线显式计算 `before/after`（键盘拖拽回退到拖拽卡片中心），目标卡片使用浅色高亮作为落点反馈；源在目标上方时落到目标之后，源在目标下方时落到目标之前，覆盖相邻与跨项移动。
- 验证状态：设计规范排序单元测试覆盖上下方向、相邻场景和中线判定；排序与配置项拖入已分离，author-site 定向测试通过。

## 测试环境编辑页无响应（author-site native 崩溃）

- 现象：`10.130.33.131:3200` 编辑页间歇性无响应；`author-site` 容器自动重启，健康检查在重启间隙短暂正常。
- 根因：Node 24 运行时加载 `better-sqlite3@12.11.1` 的 legacy `node::ObjectWrap` 原生扩展，进程退出清理阶段触发 `RemoveEnvironmentCleanupHook` 断言并 abort；不是 OOM 或单个项目页面代码导致。
- 修复：`author-site`、`project-core`、`knowledge-service` 与 `OPS/CLI` 统一升级到 `better-sqlite3@13.0.3`（Node-API），更新 `pnpm-lock.yaml`，并新增 `test:better-sqlite3-runtime` 门禁和 open/prepare/close 回归测试。
- 验证状态：Node 24 本地原生模块重复建库、写入、关闭通过；project-core 类型检查与 190 个测试通过。author-site 类型检查通过；其余 Jest 失败为仓库既有缺失模块/界面断言问题，与此次依赖升级无关。
- 部署状态：已在测试机远程重建并替换 `author-site`；容器内确认为 `better-sqlite3@13.0.3`，健康检查、四个 HTTP 端点和目标编辑页路由均通过，`RestartCount=0`、`OOMKilled=false`。

## 白板 V3 远程图片与 AI action 阻塞项

- 现象：远程图片下载在超限前一次性读入内存；重定向存在 DNS 校验与实际连接的时间差；AI 修改默认 V3 白板时仍使用旧 bridge 校验。
- 修复：图片响应改为逐块读取，累计超过 10 MiB 立即中止；重定向和 DNS 解析共享总超时，并通过自定义 `lookup` 将 socket 固定到已校验的公网 IP（HTTPS 保留原域名作为 Host/SNI）；`applyWhiteboardActions` 改用原生 V3 文档校验器和 canonicalizer，保留 `scene.metadata/assets/bindings`。
- 验证状态：白板核心、agent-service 白板 action、author-site 图片资产与类型检查通过；完整 author/agent 测试仍有仓库既有失败，白板 E2E 受 PR 分支工具栏断言缺失阻断，与本轮三个安全/数据完整性修复无关。
- 后续事项：画布最大尺寸、浏览器 Blob/整请求体大小限制列入下一轮安全加固。
