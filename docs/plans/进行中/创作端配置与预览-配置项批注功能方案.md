# 创作端配置与预览：配置项批注功能方案

## 背景

创作端右侧配置栏原先把配置项名称直接作为配置定义编辑入口。业务方在引用页面、模板页面或只拥有普通编辑权限时，往往不能修改字段定义和值，但仍需要把业务要求准确地留在对应字段上。将批注建模为评论线程，可以复用回复、编辑、解决、删除和实时同步能力，同时不污染配置 Schema、运行值或历史 `$demo.note`。

## 目标

- 在项目级和页面级配置项上创建、查看和维护 Markdown 批注线程。
- 恢复配置项名称直接点击编辑，并在名称后以内联 Tag 提供规范与批注入口。
- 对引用页面、模板页面普通编辑者实施只批注不可配置写入的权限矩阵，并由服务端做最终校验。
- 保持页面评论、设计规范、页面配置要求和 `$demo.note` 数据边界不变；viewer 读取项目级批注线程并只读展示。

## 范围

本期覆盖 author-site 作者编辑页右侧配置栏、demo-ui 表单与评论面板、shared 评论领域模型、评论 REST/WS 数据流、配置写入 API 与协同持久化边界。viewer 端提供配置项批注 Tag 和只读气泡；主批注与回复均使用安全 Markdown 展示，提及仍沿用结构化 `mentions`，不扩展 AI 目标识别。

## 方案

### 1. 评论目标与存储

新增 `kind: "config"` 目标，使用 `scope + pageId + fieldKey` 表示字段身份，名称只作为展示快照。项目级评论不携带 `pageId`，页面级评论必须携带当前页面 ID；评论写入当前项目 comments store。字段删除或改名不删除线程，展示时标记字段已不存在。

配置目标不使用页面锚点、画布 pin 或文档锚点。GET 查询使用显式 `configScope/pageId/fieldKey/resolved` 参数，POST 对 scope、pageId、fieldKey 和互斥锚点做严格校验，WS 继续传输完整 `CommentThread.target`。

### 2. 配置栏交互

`FieldRenderer` 按权限将标题渲染为直接编辑按钮或普通文本：创作端具备定义编辑权限时，点击、Enter 或 Space 直接打开配置项编辑 Dialog；标题悬浮或聚焦不打开菜单。规范 Tag 与批注 Tag 紧跟标题排列，批注文案固定为“批注”，无线程时弱化、有任意线程（含已解决）时以琥珀色高亮，不显示数量。

表单通过 `ConfigItemCapabilities` 同时接收定义编辑、值编辑、批注能力和禁用原因，并通过布尔 `hasConfigComment` resolver 判断批注 Tag 状态；所有文本、数字、颜色、图片、文件、数组、开关等控件都使用 `canEditValue` 真正禁用。嵌套对象数组继续透传能力、resolver 和字段路径。

### 3. 批注面板

新增配置项评论面板，按精确目标展示已有线程并创建新线程。线程列表独立滚动，创作端新增批注编辑区固定在浮窗底部并采用紧凑自动增高编辑器，浏览端隐藏该编辑区。主批注和回复默认只读 Markdown，点击图标后才进入编辑；主批注使用 800ms 防抖自动保存，失焦/关闭前 flush，空正文恢复最近已保存内容；新增批注失焦或 Cmd/Ctrl+Enter 提交，不显示保存按钮；回复通过发送/确认图标显式提交。渲染复用安全 Markdown/媒体清洗链路，`CommentMarkdownEditor` 隐藏固定 TopBar 但保留选区浮动 Toolbar，并沿用评论权限、提及、解决/恢复、编辑、删除和 WS 更新。

### 4. 作者页能力与权限

作者编辑页一次加载项目评论，再按当前页面筛选页面线程并按配置目标分发到字段。普通页面且具备编辑权限时项目级、页面级配置均可编辑和批注；引用页面两者均只批注；模板页 admin 可编辑和批注，普通 editor/creator 只批注。画布模式使用实际 `configPanelDetailPageId` 计算能力。页面评论未处理数量只统计 `kind: "page"`。

前端能力判断只负责交互；配置 schema、配置值、可视化配置和白板回写入口统一在服务端检查上下文页面。引用页面一律返回 `CONFIG_READONLY`，模板页普通编辑者的配置写入同样返回明确 403；正常页面和 admin 保持原有写入能力。

## 风险与待确认事项

- 项目级配置的作者页 HTTP 写入带 `contextPageId`；协同 `project-schema` 会话保持项目级单一房间，因此作者页在引用/模板普通编辑者上下文中关闭该协同入口，通用工作区文件入口同样按当前页面禁用编辑。若未来开放任意客户端直连项目 Schema 协同，需要把页面上下文纳入会话级写权限校验，但不能把它加入房间身份导致同一项目配置分裂成多个协同房间。
- 字段名称快照只用于展示，字段改名不会迁移评论；产品验收需确认“配置项已不存在”的文案和定位方式。
- 配置项主批注与回复共用 Markdown 编辑器和安全渲染链路，回复仍不自动保存，必须显式发送以避免误发半成品。
- viewer 端通过只读控制器消费项目级配置项批注线程；发布数据仍沿用现有评论格式和权限接口。
