# 创作端配置与预览：视频配置项上传后 UI 优化方案

> 状态：P0 已实现
> 更新日期：2026-08-31

## 1. 背景与范围

当前配置面板的视频字段使用 `format: "video"`，值结构为 `{ url: string, poster?: string }`。上传链路已支持 MP4/WebM、单文件 200MB 上限、容器校验、可选封面和结构化错误提示。

本方案只优化配置项的已上传状态和预览入口；上传前区域沿用现状，不改变富文本编辑器的视频上传链路，也不引入转码服务。截图仅作为现状参考，不构成额外产品指令。

## 2. 现状问题

1. 上传后卡片直接嵌入原生视频控件，视觉信息密度高，配置面板被播放器控制条占用。
2. 上传后没有统一的封面/占位展示规则；未配置封面时容易出现黑色空块，无法表达“点击可预览”。
3. 操作文字靠近、层级弱；删除不需要二次确认，但应明确“删除后恢复默认值”的结果。
4. 封面是与视频并列的文字操作，没有形成“封面用于卡片展示，点击卡片打开预览”的清晰心智模型。

## 3. 设计目标与非目标

### 目标

- 保持上传前区域和现有上传链路不变。
- 让已上传视频成为一个“封面/默认占位 + 点击弹窗预览”的轻量媒体卡片。
- 让替换、添加封面和删除操作清晰可达；删除时按默认值规则恢复。
- 保持现有 session 上传、200MB 限制和服务端校验不变。
- 支持键盘操作、屏幕阅读器播报和深色主题下的清晰对比。

### 非目标

- 上传前布局、文案和拖拽交互不在本轮调整。
- 首期不做视频转码、压缩、云端抽帧或多版本 CDN。
- 不把富文本视频上传改造成视频配置项。
- 不在卡片中展示文件名、格式、状态、时长、分辨率和大小。
- 不在普通配置面板暴露内部 `videoPreviewStyle` 选项。

## 4. 推荐信息架构

```text
视频配置项
└─ 素材
   └─ 已上传：封面/默认占位 + 点击弹窗预览 + 替换/封面/移除
```

### 4.1 上传前与上传中

- 本轮不调整上传前的占位区域、文案、尺寸和拖拽行为。
- 上传中状态沿用现有实现；若后续改动，必须保持本方案的已上传卡片契约不变。

### 4.2 已上传卡片

- 展示区保持 16:9 卡片比例；有 `poster` 时展示封面，没有 `poster` 时展示统一默认占位（视频图标/中性图形），不读取首帧替代封面。
- 卡片整体可点击，点击后打开弹窗预览；卡片本身不嵌入可播放的原生控制条。
- 弹窗内使用 `<video controls>` 播放当前 `url`，带有关闭按钮和清晰的弹窗标题；关闭弹窗后回到配置面板原位置。
- 卡片底部只保留操作按钮：`替换视频`、`更换封面`/`添加封面`、`移除`。不展示文件名、格式、状态、时长、分辨率和大小。
- 默认占位也保留点击能力，避免用户误以为视频未上传。

### 4.3 删除与默认值

- 点击 `移除` 后立即执行，不弹二次确认。
- 若字段配置了默认值，移除后调用 `onChange(defaultValue)`，恢复默认视频（包括默认封面）。
- 若没有默认值，移除后清空当前视频，沿用现有空值策略。
- 默认值判定不能只支持字符串：视频字段的 `defaultValue` 应允许与 `VideoValue` 相同的对象结构。

### 4.4 封面交互

- 没有封面时显示默认占位和 `添加封面` 操作；有封面时显示封面和 `更换封面`。
- 封面上传成功后立即替换卡片展示，不改变视频 URL。
- 本轮不增加“使用首帧”或封面裁剪能力。

## 5. 状态与交互流程

```text
空状态
  └─ 选择/拖拽 → 校验中 → 上传中 → 已上传卡片
                                  ├─ 有封面 → 展示封面
                                  └─ 无封面 → 展示默认占位
已上传
  ├─ 点击卡片 → 预览弹窗 → 关闭回到配置面板
  ├─ 替换视频 → 上传中（旧卡片仍保留）→ 成功替换 / 失败恢复旧视频
  ├─ 添加/更换封面 → 上传中 → 回显封面
  └─ 移除 → 有默认值则恢复默认，否则清空
```

关键交互规则：

- 卡片点击只打开预览弹窗，不在卡片内播放视频。
- 替换失败不能清空原视频；只有新视频上传成功后才提交 `onChange`。
- 上传成功但响应缺少非空 URL 时，保留当前值并就地提示错误。
- 错误消息靠近问题位置显示，并使用 `role="alert"` 或 `aria-live="polite"` 播报。
- 上传按钮、替换、封面和移除在 `disabled`/上传中状态下均不可重复触发；移除不弹确认框。

## 6. 视觉规范

- 复用现有暗色主题 token：`--background`、`--card`、`--muted`、`--border`、`--foreground`、`--muted-foreground`、`--primary`、`--destructive`，不新增同义硬编码颜色。
- 卡片圆角 12px，预览区与操作区间距 12–16px；不使用大面积阴影。
- 正文 14px，字段标题 16px；中文统一使用现有系统无衬线字体（可选 Noto Sans SC）。上传前文案本轮不调整。
- 关键文字与背景保持至少 4.5:1 对比度；危险操作除红色外同时使用文字和图标表达含义。
- 交互状态提供 150–300ms 的颜色/边框过渡；尊重 `prefers-reduced-motion`。
- 图标统一使用 Lucide（Video、Play、RefreshCw、Image、Trash2、X），按钮最小点击区域 36px；卡片和弹窗关闭按钮都保留可见焦点态。

## 7. 接口与数据建议

### P0：不改上传协议即可完成

- 继续调用现有 `/api/sessions/:sessionId/assets/upload`。
- 继续执行服务端 MP4/WebM 容器校验与 200MB 上限。
- 上传成功后继续使用当前响应里的 URL；卡片只依赖 `url` 和可选 `poster` 决定展示内容。
- 预览弹窗直接播放 `url`，不要求上传接口新增元数据字段。
- 删除时由组件根据 `defaultValue` 决定恢复默认或清空，不改变发布资源本地化规则。

## 8. 分阶段实施

- 保持空状态不变，只重做已上传卡片：封面/默认占位、点击打开预览弹窗、按钮组、就地错误、替换保留旧值。

## 9. 验收标准

- 上传前区域保持现有行为。
- 上传成功后卡片只展示封面或默认占位；点击卡片可打开弹窗播放视频。
- 弹窗内具备原生播放控制和可见关闭入口，关闭后回到配置面板。
- 卡片内能完成替换视频、添加/更换封面和移除。
- 替换失败时原视频、封面和配置值保持不变。
- 移除不弹二次确认；有默认值恢复默认视频，无默认值清空。
- 卡片不展示文件名、格式、状态、时长、分辨率和大小。
- 401、404、413、容器无效、网络失败均显示可理解的就地错误和下一步操作。
- 键盘可完成选择、播放、替换、封面和移除；焦点环清晰，错误可被屏幕阅读器播报。
- 发布与重新打开流程仍只依赖项目本地化资源，不产生会话 URL 泄漏。
- 相关文档同步更新：配置系统需求、表单生成器技术文档、使用端只读配置说明。

## 10. 本轮已确认决策

1. 上传前 UI 保持不变。
2. 上传后不在卡片内播放；点击卡片后用弹窗预览。
3. 有封面展示封面，无封面展示默认占位；不展示文件元数据。
4. 删除不二次确认；有默认值恢复默认值，无默认值清空当前值。
