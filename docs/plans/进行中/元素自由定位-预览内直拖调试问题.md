# 元素自由定位 — 预览内直拖调试问题

> 关联计划文档：`docs/plans/进行中/元素自由定位优化方案.md`（记录完整方案设计和实施历史）
>
> 状态：✅ 根因已定（2026-07-31），待用户在生产环境验证

## 根因分析（第六轮，2026-07-31）

### 核心缺陷

**`getContainer()` 返回 `root.firstElementChild` 作为坐标参考系，但该元素并非绝对定位元素的坐标原点。**

React 组件渲染在 `#root` 内，绝对定位元素的 `left`/`top` 值是相对于**最近 `position: relative/absolute/fixed` 祖先**，而不是相对于 `#root.firstElementChild`。如果该祖先与 `#root.firstElementChild` 之间有 padding/margin 偏移，`getBoundingClientRect()` 计算出的位置就会与 `positions` 值不匹配，导致 `injectPosKey` 完全失败。

### 证据链

1. **诊断日志空白**：`data/editor-diagnostics/` 中没有任何 `[pos-edit]` 前缀的 console 日志，说明 `injectPosKey` 从未成功执行或从未到达
2. **零匹配 → 零副作用**：`injectPosKey` 失败 → 无 `[data-pos-key]` 注入 → `setGrabCursors(true)` 找不到目标元素（无光标变化）→ `applyElementDimming()` 虽有执行但无可见效果（因为 `getComputedStyle` 的 `opacity` 未正确应用）
3. **Round 4 vs Round 5 回归**：Round 4 使用 `parseInt(getComputedStyle(el).left)` 直接匹配 CSS 值（WORKED），Round 5 改用 bounding rect 相对 `firstElementChild` 后完全失效

### 修复内容（`packages/demo-ui/src/iframe-template.ts`）

1. **`getContainer()` 改为返回 `#root`**：`#root` 是固定挂载点，无 padding/margin，是稳定的坐标参考系
2. **添加 computed style fallback**：bounding rect 匹配失败时，回退到 `parseInt(getComputedStyle(el).left)` 匹配（恢复 Round 4 已验证工作的逻辑）
3. **添加 try-catch + 日志**：在消息接收端和 `enter()` 入口添加诊断日志，捕获任何 JS 错误
4. **`applyPosition` 自动受益**：该函数也使用 `getContainer()`，现在使用 `#root` 作为参考系，与 `injectPosKey` 一致

## 核心判断

**`injectPosKey` 必定失败**——步骤 1 无光标变化 + 步骤 3 无拖拽能力 → `[data-pos-key]` 未被注入到任何 DOM 元素。

步骤 1 "预览区正常显示" 是新的关键线索：`setDimCSS(true)` 调了 `applyElementDimming()` 但没有让页面变暗。这说明要么 `setDimCSS(true)` **根本没执行到**，要么所有元素（包括 `#root`）都因某种条件被跳过了。

## 第五轮修改汇总

### `iframe-template.ts`

1. **`injectPosKey` 改用 bounding rect 匹配**：
   - 原先用 `parseInt(getComputedStyle(el).left)` —— 受 `offsetParent` 层次影响，`position: relative` 祖先会导致值不匹配
   - 现在用 `Math.round(el.getBoundingClientRect().left - container.getBoundingClientRect().left)`
   - 容差从 ±2px 放宽到 ±3px
   - **添加详细诊断日志**：扫描了多少 absolute 元素、匹配了哪些 key、未匹配的 key、以及所有 absolute 元素的实际 rect 值

2. **CSS 置灰规则移除 → JS 逐元素置灰**：
   - 删除了 `<style>` 中的 `body.position-editing-dimming :not([data-pos-key]) *` 规则
   - `applyElementDimming()`：遍历 `body.querySelectorAll('*')`，对不含 `data-pos-key` 且不含 `[data-pos-key]` 后代且 `id !== 'root'` 的元素设置 `opacity: 0.3 !important`
   - `clearElementDimming()`：移除 `.pos-dimmed` 的 inline opacity
   - 目的：防止 `#root` 被置灰（即使 `injectPosKey` 失败也不该全白）

### `PreviewPanel.tsx`

3. **退出流程效果顺序重组**：
   - 合并 ENTER/EXIT/退出后 UPDATE_CONFIG 为一个 effect，**声明在 configData effect 之前**
   - 退出时消息到达顺序：`EXIT_POSITION_EDIT`（清理 dimming）→ `UPDATE_CONFIG`（React 重渲染）
   - 添加 `skipConfigUpdateOnExitRef` 防止 configData effect 重复发送 UPDATE_CONFIG

## 第七轮修复（2026-07-31，拖拽闪跳）

### 根因

**`pointerup` 中过早清除 `transform` 导致元素在 `APPLY_POSITIONS` 到达前跳回原始 DOM 位置。**

拖拽释放时序：
1. 通过 `transform` 拖到新位置
2. `pointerup` → `dragTarget.style.transform = ''` → **元素跳回原位**（闪跳）
3. 发 `POSITION_CHANGE` → React 重渲染 → 发 `APPLY_POSITIONS` → 元素再次移动到新位置

### 修复内容（`iframe-template.ts`）

1. **`pointerup` 不再清除 `transform`**：移除 `dragTarget.style.transform = ''`，保留视觉位置直到 `APPLY_POSITIONS` 到达。
2. **`pointermove` 累加而非替换 transform**：解析旧 transform 偏移量 `dragAccumTx/Ty`，`transform = translate(dragAccumTx + offsetX, ...)`，而非覆盖。
3. **`pointerup` 直接用 `getBoundingClientRect()` 读最终位置**：废弃 `dragOrigLeft + match[1]` 双重计数公式，改用 `finalRect.left - containerRect.left`。
4. **`applyPosition` 先清 transform 再读 rect**：将 `el.style.transform = ''` 移到 `el.getBoundingClientRect()` 之前，确保读取 DOM 原始位置。同一同步帧内完成无闪烁。

## 第八轮修复（2026-07-31，退出/进入/诊断）

### 修复内容（`iframe-template.ts`）

1. **`exit()` 增强**：新增 `clearAllTransforms()` 清除所有位置元素的 transform；重置 `containerEl`、`dragTarget`、`dragAccumTx/Ty`。
2. **`applyPosition` 增加容差**：`Math.round(offset)` < 1px 时不应用 transform，防止子像素偏差导致位移。
3. **`enter()` 防止重复进入**：检测到 `editing` 已为 true 时先调用 `exit()` 再重新进入。
4. **全链路诊断日志**：`enter()`、`exit()`、`ENTER_POSITION_EDIT`、`EXIT_POSITION_EDIT`、`APPLY_POSITIONS`、`applyPosition` 均添加 `[pos-edit]` 前缀日志，便于在 iframe 控制台追踪完整消息流。

### 待验证问题与排查方向

**问题 A：点击编辑后无法拖动，需要改一下坐标才能拖动**

最可能根因：`injectPosKey` 的 bounding box 匹配失败（元素嵌套在 `position: relative` 容器中导致 `rect.left` ≠ `positions.x`），且 computed style fallback 也失败（如果组件用 `right`/`bottom` 而非 `left`/`top` 定位）。

排查步骤：
1. 打开 iframe 控制台，查看 `[pos-edit] enter called` 后的 `injectPosKey` 日志
2. 关注 `boundingBoxMatched` 和 `still unmatched after fallback` 计数
3. 如果 0/3 匹配，查看 "absolute element" 日志中的 `rect` 值和 computed style 值
4. 对比 `positions` 中的 `x`/`y` 与元素实际的 `computedStyle.left`/`top`

**问题 B：进入可拖动模式后元素位移**

可能根因：`applyPosition` 因 DOM 位置与 config 位置不匹配而施加了 transform 偏移。

排查步骤：
1. 查看 `[pos-edit] applyPosition:` 日志中的 `target` vs `current` 和 `offset`
2. 如果 offset ≠ 0，说明 config 位置与 DOM 位置不一致

**问题 C：点击完成后预览区不恢复**

可能根因：`EXIT_POSITION_EDIT` 未被接收，或 `exit()` 执行时出错。

排查步骤：
1. 查看是否有 `[pos-edit] received EXIT_POSITION_EDIT` 日志
2. 查看是否有 `[pos-edit] exit complete` 日志
3. 如果都没有，说明消息未到达 iframe，检查 PreviewPanel 的发送逻辑

## 后续事项
