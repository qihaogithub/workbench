## 条目：浏览端图片资源不显示与单页面模式缺失（proj_1784874964275_p0k4ho）

### 现象

打开项目 `proj_1784874964275_p0k4ho` 的浏览端时，发现以下异常：

1. **画布预览中部分图片资源不显示**：页面内配置的默认图片（如 `imageUrl`、`videoBg`、`progressBgTop` 等）在浏览端预览区加载失败。
2. **配置栏图片默认图不显示**：右侧配置面板中，图片类型字段的默认缩略图无法加载；同一项目在创作端配置栏可正常显示。
3. **无法切换单页面模式**：浏览端仅显示画布模式，顶部没有「单页/画布」切换按钮。用户反馈其他多页面项目可以切换。

### 影响范围

- **包**：`packages/viewer-site`
- **文件**：`packages/viewer-site/src/components/ViewerApp.tsx`
- **触发条件**：
  - 浏览端打开包含图片路径默认值的单页面项目；
  - 图片路径为相对路径（如 `../../assets/images/xxx.png`）且路径中包含字母 `s`（如 `assets`、`images`）。

### 根因分析

#### 根因 1：图片路径解析正则错误

`ViewerApp.tsx` 中的 `resolvePublishedConfigAssetUrls` 负责将 schema 默认值中的相对图片路径解析为可访问的 API URL。其内部使用的正则表达式存在书写错误：

```typescript
// 错误（原代码）
const IMAGE_EXT_RE = /\.(png|jpe?g|gif|webp|svg|bmp|ico)(\?[^'")\\s]*)?$/i;
//                                              ^^^^^
//                                              这里 \\s 在正则字面量中表示"反斜杠 + 字母 s"
```

在 JavaScript 正则字面量中，`\\` 表示匹配一个反斜杠字符，`\s` 才表示匹配空白字符。原代码写成 `\\s`，导致字符类 `[^'")\\s]` 的含义变成：
> 不匹配 `'`, `"`, `)`, `\`, 以及**字母 `s`**。

因此，任何包含字母 `s` 的路径（如 `assets`、`images`）都会被正则拒绝匹配，相对图片路径不会被解析为 API URL，直接以原始值（如 `../../assets/images/xxx.png`）传入 iframe 预览。iframe 的 base URL 为 `/api/preview-runtime/shell` 或 `data:` URL，相对路径解析后无法指向正确的图片资源，导致加载失败。

**对比**：创作端 `preview-config-utils.ts` 中使用了正确的 `\s`（`\s` 在字符串正则中），路径可正常解析。

#### 根因 2：单页面项目隐藏模式切换按钮

`ViewerApp.tsx` 第 1251 行控制「单页/画布」切换按钮的显示：

```tsx
{project.demoPages.length > 1 && (
  <div className="flex items-center gap-2 ...">
    {/* 单页 / 画布 切换按钮 */}
  </div>
)}
```

该项目 `demoPages.length === 1`，因此切换按钮被隐藏。这是代码设计，但导致单页面项目用户无法切换到单页面模式，与多页面项目的行为不一致。

### 修复摘要

#### 修复 1：修正正则表达式

**文件**：`packages/viewer-site/src/components/ViewerApp.tsx`

将 `\\s` 改为 `\s`：

```typescript
// 修正后
const IMAGE_EXT_RE = /\.(png|jpe?g|gif|webp|svg|bmp|ico)(\?[^'")\s]*)?$/i;
```

#### 修复 2：允许单页面项目显示模式切换

**文件**：`packages/viewer-site/src/components/ViewerApp.tsx`

将切换按钮的显示条件从 `> 1` 放宽为 `>= 1`：

```tsx
{project.demoPages.length >= 1 && (
  <div className="flex items-center gap-2 ...">
    {/* 单页 / 画布 切换按钮 */}
  </div>
)}
```

> 备注：左侧页面目录栏的显示条件（`previewMode !== "canvas" && (project.demoPages.length > 1 || isLoggedIn)`）保持不变。单页面项目切换到单页模式后，未登录用户不显示目录栏（只有一个页面，无切换需求），已登录用户仍可看到目录栏进行页面管理。

## 条目：浏览端滚动条未隐藏与预览撑满容器（proj_1784874964275_p0k4ho / proj_1783585261167_7h7prw）

### 现象

1. **浏览端滚动条依然在**：项目 `proj_1784874964275_p0k4ho` 在浏览端单页预览中，iframe 内部出现滚动条；同一项目在创作端预览区无滚动条。
2. **浏览端预览撑满预览区**：项目 `proj_1783585261167_7h7prw` 在创作端单页模式下显示为手机尺寸，但在浏览端几乎撑满整个预览容器。

### 影响范围

- **包**：`packages/demo-ui`、`packages/viewer-site`
- **文件**：
  - `packages/demo-ui/src/preview-scale.ts`
  - `packages/demo-ui/src/IframePreviewFrame.tsx`

### 根因分析

#### 根因 1：旧项目发布的 `iframe.html` 缺少 Shell 模板滚动条样式

创作端使用动态生成的 Shell（`/api/preview-runtime/shell` 或 `data:text/html`），总是加载最新的 `packages/demo-ui/src/iframe-template.ts`，其中已包含 `html, body { overflow: hidden }` 与美化滚动条样式。

浏览端在有 `iframeHtmlPath` 时直接使用 `IframePreviewFrame` 加载静态发布的 `iframe.html`。旧项目是在 Shell 模板样式更新前发布的，其 `iframe.html` 不包含 `overflow: hidden`，导致 iframe 内部内容溢出时出现滚动条。

#### 根因 2：`computePreviewScale` 在 `fillContainer=false` 时允许放大超过设计尺寸

`preview-scale.ts` 中 `fillContainer=false` 分支的 `scale = displayWidth / designWidth` 未做上限限制。当浏览端预览容器很大（viewer-site 单页预览区几乎占满整个屏幕）时，`displayWidth` 远大于 `designWidth`，`scale > 1`，预览被放大到接近容器尺寸，失去"手机尺寸"效果。创作端容器通常较小，放大不明显，因此观感正常。

### 修复摘要

#### 修复 1：`preview-scale.ts` 限制 `fillContainer=false` 时 `scale <= 1`

**文件**：`packages/demo-ui/src/preview-scale.ts`

```typescript
// 修改前
const scale = displayWidth / designWidth;
// 修改后
const scale = Math.min(1, displayWidth / designWidth);
```

确保 `fillContainer=false` 时预览不会放大超过设计尺寸。大容器下保持设计尺寸，小容器下仍按现有逻辑缩小适应。

#### 修复 2：`IframePreviewFrame.tsx` 注入兼容性兜底样式

**文件**：`packages/demo-ui/src/IframePreviewFrame.tsx`

在 `handleLoad` 中向 iframe document 注入与最新 Shell 模板一致的默认样式：

```typescript
const doc = iframeRef.current?.contentDocument;
if (doc && doc.head) {
  const style = doc.createElement("style");
  style.textContent = `
    html, body { overflow: hidden; }
    ::-webkit-scrollbar { width: 4px; height: 4px; }
    ::-webkit-scrollbar-track { background: transparent; }
    ::-webkit-scrollbar-thumb { background: rgba(0, 0, 0, 0.2); border-radius: 2px; }
    ::-webkit-scrollbar-thumb:hover { background: rgba(0, 0, 0, 0.35); }
    * { scrollbar-width: thin; scrollbar-color: rgba(0, 0, 0, 0.2) transparent; }
  `;
  doc.head.appendChild(style);
}
```

新项目已包含相同样式，注入冗余但不产生副作用；旧项目因此获得缺失的默认滚动条控制。注入不使用 `!important`，Agent 页面代码仍可通过更具体的选择器或内联样式覆盖。
