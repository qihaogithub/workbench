# 创作端编辑页结构优化方案

> 目标：让 Agent 修改单一功能时只需读 1-2 个文件，而非在当前 7911 行的 page.tsx 中大海捞针。

## 问题诊断

`page.tsx` 对 Agent 不友好的根因不是"太大"，而是**信息没有按功能领域隔离**。当前结构：

```
page.tsx (7911 行)
├── 区域 A: 22 个纯工具函数 (229-660)
├── 区域 B: 约 80 个 useState + 30 个 useCallback + 10 个 useEffect (647-5947)
├── 区域 C: 加载态 JSX (5948-5958)
├── 区域 D: 主渲染 JSX (6077-7909)
```

一个 Agent 想修改"AI 对话的自动修复逻辑"，需要：
1. 在 ~5000 行状态区里找到 `handlePreviewError` 所在位置（行 2033-2201）
2. 在 ~5000 行状态区里找到 `triggerAutoSend` 的状态定义（行 1631-1633）
3. 在 ~5000 行状态区里找到 `aiMessages` 的状态定义（行 1601）
4. 在 ~1833 行 JSX 里找到 `AIChat` 的 props 传递（行 6263-6477）
5. 理解这些状态之间的隐式依赖关系

**核心问题：相关代码跨越了数千行，Agent 无法通过读一个文件理解一个功能。**

## 目标

| 场景 | 现在 | 优化后 |
|------|------|--------|
| 修改 AI 对话逻辑 | 扫描 5000 行状态区 + 1833 行 JSX | 读 `hooks/useAiChatBridge.ts` + `panels/AIChatTab.tsx` |
| 修改页面预览/截图 | 同上 | 读 `hooks/usePreviewState.ts` + `components/EditPreviewPanel.tsx` |
| 理解页面保存/刷新机制 | 在状态区搜索各种 flush useEffect | 读 `hooks/useWorkspaceLifecycle.ts` |
| 修改版本历史 Tab | 在 JSX 末尾 ~167 行内联 | 读 `panels/HistoryPanel.tsx` |
| 修改某个 Dialog | 在 JSX 末尾嵌套查找 | 读 `dialogs/XxxDialog.tsx` |

## 方案

将 `page.tsx:229-660` 提取到 `edit/utils.ts`。纯函数无副作用，所有引用变量都是参数传入，零风险。

#### 步骤 2：4 个内联 Dialog → `dialogs/` 目录

### 阶段二：状态按功能域聚合（核心改动）

### 最终 page.tsx 结构

```tsx
export default function DemoEditPage({ params }: DemoEditPageProps) {

      <EditPageHeader {...headerProps} />
      <MainLayout>
        <SidebarTabs ... />

```

**page.tsx 缩减到约 300 行**，成为纯粹的结构性代码。任何功能改动都能通过对口 hook 文件名直接定位。

## 设计约束

1. **hook 返回值使用对象而非元组**。每个 hook 返回 `{ state, handlers, computed }` 结构化对象，Agent 可以通过 IDE 自动补全发现可用字段，不需要依赖文档。

2. **hook 之间通过显式参数传递依赖**。不引入 Context、Redux 或任何隐式状态共享。每个 hook 的输入参数列表即其依赖声明，Agent 无需搜索文件就能理解模块边界。

3. **一个文件一个领域**。如果 hook 超过 500 行，进一步拆分——但只在确实需要时。优先保证领域聚合清晰。

4. **不引入新依赖**。只用 React hooks（`useState`, `useCallback`, `useEffect`, `useMemo`, `useRef`），不新增状态管理库。

## 风险

1. **阶段二的重构风险**：将 ~5300 行状态体拆分为 4 个 hook 需要精确提取闭包依赖。每个 hook 独立开发、独立验证：先确定接口 → 复制/移动代码 → `pnpm check:author` → 下一个。

2. **hook 间循环依赖**：`useAiChatBridge` 依赖 `applyDemoSnapshot`（来自 `usePageContentState`），`useWorkspaceLifecycle` 依赖 `markWorkspaceChanged`（被多个 hook 调用）。需在接口设计中明确数据流向，确保依赖是单向的（hook 层之间不互相调用，由 page.tsx 作为唯一编排点）。

3. **测试覆盖**：现有测试主要覆盖 hooks（`useVisualEditState`, `useVersionControl`, `useCommandHistory`, `useWorkspaceAuthorityState`），page.tsx 本身无直接测试。重构后每个新 hook 应该是可独立测试的函数，建议阶段二中为新增 hook 补充测试。

4. **Git 历史断层**：大范围代码移动会使 `git blame` 失效。建议阶段二的每个步骤在同一 commit 中完成（提取 hook + 修改 page.tsx 调用方式），并注明"extract hook from page.tsx, no behavior change"。
