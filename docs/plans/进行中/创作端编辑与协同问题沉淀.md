## [2026-08-03] 配置项修改后预览不生效 —— 分组 schema 值形状断裂（系统回归，非 AI 错误）

### 现象

AI 生成的高保真 React 页面（分组式 `config.schema.json`，如「标题与描述 / 样式与颜色 / 选择与富文本 / 模块列表 / 定位与条件」等分组），在配置面板修改任意字段后，画布/单页预览与截图均无任何变化。AI 校验链路（schema 校验、代码-配置一致性校验、截图）全部通过，页面初始渲染正常。

### 当前结论（根因已确认，真实代码复现）

全链路存在**形状不一致**：运行时 props 注入为**扁平**（flat），配置面板变更发出为**嵌套**（nested），合并与注入环节均不做转换。

| 环节 | 形状 | 代码位置 |
|------|------|---------|
| 初始注入 | **扁平** `{ bgColor, accentColor, ... }` | `demo-ui/src/validator.ts:20` `getDefaultValues` 调用 `flattenSchema` → iframe `React.createElement(Component, configData)`（`iframe-template.ts:2430`） |
| 配置面板变更发出 | **嵌套** `{ "样式与颜色": { bgColor: "#ff0000" } }` | `demo-ui/src/ConfigForm.tsx:362-377` `handleFieldChange` 对分组字段拼 `{ [父组名]: { 字段: 新值 } }` |
| 页面合并 | 浅合并（`{ ...prev, ...data }`），不摊平 | `edit/page.tsx:3723-3760` `handlePageConfigPanelChange` |
| 向 iframe 注入 | 原样透传 | `sendUpdateConfig` → iframe `UPDATE_CONFIG` handler |

**结果**：合并后 configData 同时包含过期扁平默认值（如 `bgColor: "#f0f4ff"`）和嵌套用户新值（如 `"样式与颜色": { bgColor: "#ff0000" }`）。组件读取 `props.bgColor` → 永远拿到过期值。嵌套用户修改被"藏"在 `props["样式与颜色"]` 中，无代码路径读取。`config.values.json` 持久化混合形状 → 重开页面同样不生效；截图链路复用同一 configData，同样不反映修改。

回归引入点：commit `4edfce6d`（2026-08-02「配置面板 schema.json 重构」）。重构前 ConfigForm 对任意字段一律扁平发出 `onChange({ [key]: value })`，与注入形状一致，配置修改正常；重构后分组字段改为嵌套发出，但注入/合并/持久化/截图等链路均未同步。

### 为什么 AI 页面"全中"

- AI 遵循 `page-lifecycle` skill 模板，天然产出分组式 schema，几乎所有字段都在分组内 → 全部走嵌套路径 → 全部失效。
- 手写无分组（顶层扁平）的 schema 不受影响 → 表现为"只有 AI 页面改不动"。
- Schema 契约校验（`shared/src/validator.ts`）强制 AI 声明**扁平** `DemoProps` —— 这意味着即使 AI 知道嵌套格式，写出正确的页面也不会生效，因为组件只能用扁平 key 读取 props。

### 受影响字段类型复查结果

| 字段类型 | 受此问题影响 | 说明 |
|---------|------------|------|
| 分组内 `string/number/integer/boolean` | **是** | 核心受影响 |
| 分组内 `color/image/text` | **是** | 同上 |
| 分组内 `enum/多选` | **是** | 同上 |
| 分组内 `cascade` | **是** | 同上 |
| 分组内 `richtext` | **是** | 同上 |
| 分组内 `imageList`（`array`+`items.string`） | **是** | 同上 |
| 分组内 `array`+`oneOf`（模块数组） | **是** | `ArrayFieldGroup` → `ConfigForm.handleFieldChange("modules", array)` → 嵌套发出 |
| 分组内 `position` 字段（面板坐标输入） | **是** | `flattenSchema`/`computeFlattenPathMap` 把 position 字段摊平到父组下 → 走嵌套路径 |
| 分组内 `position` 字段（拖拽） | **否** | `handlePositionChange` → `setNestedValue` 写扁平 `{ badgePosition: {x,y} }`（绕过 ConfigForm） |
| 顶层非分组字段 | **否** | `computeFlattenPathMap` 不映射 → 扁平发出 |

### 修复方案

需同时修改三个位置：

#### 1. ConfigForm `handleFieldChange` — 恢复扁平发出

**文件**：`packages/demo-ui/src/ConfigForm.tsx:352-380`

将 `handleFieldChange` 中 `parentKey` 嵌套发出逻辑删除，一律扁平发出 `onChange({ [key]: value ?? null })`。`flattenPathMap` / `computeFlattenPathMap` 保留不动（`flattenInitialData` 仍需用于面板显示向后兼容）。

#### 2. 新增 `flattenNestedDelta` 工具函数

**文件**：`packages/author-site/src/app/demo/[id]/edit/page.tsx`（当前位置附近的辅助函数区）

```ts
function getGroupKeys(schema: string): Set<string> {
  try {
    const parsed = JSON.parse(schema);
    const props = parsed.properties;
    if (!props || typeof props !== 'object' || Array.isArray(props)) return new Set();
    const groups = new Set<string>();
    for (const [key, prop] of Object.entries(props)) {
      const p = prop as any;
      // 与 flattenSchema / computeFlattenPathMap 保持一致的判定逻辑
      if (p?.type === 'object' && p?.properties && !p.$demo?.positionable) {
        groups.add(key);
      }
    }
    return groups;
  } catch {
    return new Set();
  }
}

function flattenNestedDelta(data: Record<string, unknown>, schema: string): Record<string, unknown> {
  const groupKeys = getGroupKeys(schema);
  const result: Record<string, unknown> = {};
  // 先展开旧格式嵌套分组
  for (const groupKey of groupKeys) {
    const groupVal = data[groupKey];
    if (groupVal && typeof groupVal === 'object' && !Array.isArray(groupVal)) {
      Object.assign(result, groupVal as Record<string, unknown>);
    }
  }
  // 再覆盖扁平键（扁平值优先级更高，保证最新修改不被旧嵌套覆盖）
  Object.assign(result, data);
  for (const groupKey of groupKeys) {
    delete result[groupKey];
  }
  return result;
}
```

#### 3. `handlePageConfigPanelChange` — 合并前摊平

**文件**：`packages/author-site/src/app/demo/[id]/edit/page.tsx:3723-3760`

```ts
const handlePageConfigPanelChange = useCallback(
  (pageId: string, data: Record<string, unknown>) => {
    invalidatePageScreenshot(pageId);
    const schema = pageSchemaMapRef.current[pageId];
    const dataClean = schema ? flattenNestedDelta(data, schema) : data;
    const prevClean = schema ? flattenNestedDelta(configDataMapRef.current[pageId] ?? {}, schema) : (configDataMapRef.current[pageId] ?? {});
    const nextPageConfig = { ...prevClean, ...dataClean };
    persistPageConfigValues(pageId, nextPageConfig);
    setConfigDataMap((prev) => ({ ...prev, [pageId]: nextPageConfig }));
    // schedule screenshot（原逻辑移到此处，使用 nextPageConfig）
  },
  [demoPages, pageCodes, persistPageConfigValues],
);
```

同时将原 `setConfigDataMap` 内的独立 `nextPageConfig` 和截图调度移到外层统一使用 `nextPageConfig`。

#### 4. 初始加载合并时摊平（建议，非必须）

**文件**：`packages/author-site/src/app/demo/[id]/edit/page.tsx:3553-3564`

在 `allDefaults[pageId] = { ...getSafeMergedDefaults(...), ...projectConfigValues, ...demo.configValues }` 后调用 `flattenNestedDelta(allDefaults[pageId], demo.schema)`，避免初始 configDataMap 携带混合形状。
