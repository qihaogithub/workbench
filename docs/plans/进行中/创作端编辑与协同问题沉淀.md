## 当前条目：共享 Markdown 菜单与跨文档一致性

### 现象

- 最初为菜单透明、偏移、分组全部展开；第一轮修复后，用户仍反馈只有某个文档看起来生效。

### 当前结论

- 各文档入口都复用 `DocumentEditor`，未发现项目 ID 特判或仅针对单篇文档注入样式。旧 TopBar 标题下拉和手柄菜单是不同实现，第一轮只覆盖后者。
- 原手柄打开即插入临时空段，关闭尝试清理；斜杠没有独立锚点，普通事务会重置菜单分组。上述副作用均应由共享控制器解决，不能改文档数据兜底。
- 原定位在应用尺寸限制前就判断是否放得下，且把正文高度当视口；短流式文档与长文档都会出现不同于正常样本的结果。
- 本机本轮实际返回的编译 chunk 仍包含旧实现，开发服务有 `EMFILE` 监听错误。重启后已加载新模块；Webpack 诊断启动期间又触发内存阈值重启。环境证据与应用根因分开，不把刷新/重启作为产品修复方案。
