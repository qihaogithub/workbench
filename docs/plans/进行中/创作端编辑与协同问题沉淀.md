# 创作端编辑与协同问题沉淀

## 当前条目：文档块手柄菜单浮层

### 现象

- 块手柄菜单背景透明，正文会从菜单内容之间穿出。
- 菜单位置偶尔远离被点击的手柄。
- 原菜单顶部看起来像导航，但实际同时渲染所有分组，导致内容重复、过长且层级不清。

### 当前结论

- 坐标由 Milkdown `SlashProvider` 和本地浮层定位器同时写入，存在定位权竞争。
- 菜单挂载在编辑器 overlay root，但碰撞计算使用全屏 root，无法表达当前编辑器的可用边界。
- 手柄点击后需要临时空段来承载 ProseMirror 命令；若把光标矩形当作唯一锚点，更新时序会让菜单脱离原手柄。

### 修复状态

- [x] 由本地 `DocumentOverlayPositioner` 作为唯一坐标写入者，移除块菜单对 `SlashProvider` 的定位依赖。
- [x] 保存被点击块的元素作为锚点，临时空段仅作为命令上下文，关闭时清理仍为空的临时段。
- [x] 将碰撞边界绑定到当前编辑器，菜单具备不透明背景、描边和阴影。
- [x] 增加统一最大高度，导航固定，当前分组内容在菜单内部滚动。
- [x] 将顶部导航实现为真正的 Tab：一次只展示一个分组；H4-H6 与上传能力放入“更多”；配置项引用与项目/页面/文档引用保持独立分组。
- [x] 补充菜单、主题、定位器和配置分组测试。
