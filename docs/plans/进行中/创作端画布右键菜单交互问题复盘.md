# 创作端画布右键菜单交互问题复盘

## 问题现象

`SketchEditorCanvas` 画布右键菜单两个交互失效：
1. 气泡内按钮点击无响应
2. 气泡外左键点击无法关闭

## 排查过程

### 阶段一：确认测试与生产环境差异

sketch-react 的 151 个单元测试（含右键菜单测试）全部通过，但生产环境交互完全失效。测试使用 `fireEvent.click` 直接触发，不模拟完整 pointerdown→pointerup→click 序列，无法覆盖真实事件流中的 stacking context 和 overflow 裁剪问题。

### 阶段二：Playground 验证

`sketch-playground`（隔离环境）中菜单交互正常。说明问题不在组件本身，而在创作端宿主环境。

### 阶段三：发现问题分层

**第一层：按钮不可点击** — 菜单以 `absolute z-30` 渲染在画布容器内，该容器在创作端被多层 `overflow-hidden` 祖先嵌套（ResizablePanel + 包裹层 + CommentLayer 区域），且 Stage div 的 CSS `transform` 创建独立 stacking context。菜单被祖先 `overflow-hidden` 裁剪，部分按钮不可见/不可交互。

**第二层：外部点击不能关闭** — 创作端祖先元素可能拦截 `pointerdown` 事件流（`stopPropagation`），导致 document 级 `pointerdown` 监听收不到事件，画布容器的 `onPointerDown` 也无法触发。

## 修复方案（两轮迭代）

### 第一轮：Portal 渲染（解决按钮不可点击）

- 将菜单改为 `createPortal(..., document.body)` + `position: fixed`
- 彻底脱离画布容器的 `overflow-hidden` 祖先链和 stacking context
- 定位改用视口坐标（`event.clientX/clientY`），不受祖先 transform/offset 影响
- `useLayoutEffect` 按菜单实测尺寸做视口边缘 clamping
- **效果**：按钮可点击，但外部点击仍不能关闭

### 第二轮：Backdrop 遮罩（解决外部点击不能关闭）

- 在菜单同 portal 内追加 `fixed inset-0 z-[9998]` 透明遮罩
- `onPointerDown` → `setContextMenu(null)` 关闭菜单
- 遮罩在菜单之下（`z-9999` > `z-9998`）、所有宿主叠加层之上
- 气泡外任意位置点击均命中遮罩，不再依赖 document 监听能否收到事件
- **效果**：外部点击关闭正常

## 架构经验

### 浮动 UI 渲染规则

Sketch-react 中需要脱离容器定位的浮动 UI（右键菜单、悬浮工具栏、命令面板、快捷键帮助等），必须使用 `createPortal` + `position: fixed` 渲染，避免被祖先 `overflow`、`transform`、`z-index` 影响。

### 外部点击关闭的正确模式

Portal 浮动 UI 的外部点击关闭应采用 **backdrop** 而非 document 事件监听：
- Backdrop 不依赖事件能否冒泡到 document（祖先可能 stopPropagation）
- Backdrop 天然与 portal 同生命周期，无需 useEffect 管理注册/清理
- Backdrop 覆盖整个视口，确保任意位置点击均生效

### z-index 层级策略

| 层级 | 用途 | 值 |
| --- | --- | --- |
| 宿主内容 | 画布、工具栏等 | 低于 portal |
| Backdrop 遮罩 | 浮动 UI 外部点击关闭 | `style={{ zIndex: 9998 }}` |
| 浮动 UI 本体 | 右键菜单、popover 等 | `style={{ zIndex: 9999 }}` |
| 全局模态/对话框 | 最高优先级 | 待定（需高于 9999） |

> 注意：跨包 portal 元素应使用 inline style 设置 z-index，而非 Tailwind 任意值类名（如 `z-[9998]`），因为消费者 Tailwind 可能不扫描该包的源文件。

## 待追踪事项

1. **图层面板右键菜单**：`SketchLayerPanel` 使用相同 `absolute z-30` 模式，但位于侧边栏（非多层 `overflow-hidden` 嵌套），尚未收到类似问题反馈。若出现，应采用相同 portal + backdrop 模式修复。
2. **悬浮工具栏**：`SketchFloatingToolbar` 使用 `absolute z-30` 渲染，同样存在在创作端被裁剪的风险。当前定位于画布内选中节点上方，容器高度不足时可能被裁剪。需评估是否也需要 portal 迁移。
3. **命令面板与快捷键帮助**：`SketchCommandPalette`、`SketchShortcutHelp` 使用 `absolute z-20` 渲染，在创作端是否有类似问题待确认。
4. **创作端 sketch 编辑页**：当前 `NEXT_PUBLIC_SKETCH_SCENE_AUTHORING_ENABLED` 未开启，无法在 Docker 创作端直接验证。开启后需全面回归所有浮动 UI 交互。
5. **测试覆盖**：当前单元测试使用 `fireEvent.click`，无法覆盖事件流、stacking context、overflow 等真实渲染环境问题。考虑补充 Playwright E2E 测试覆盖右键菜单完整交互。

## 修复历程

### 第三轮：修复 Tailwind z-index 流失效（2025-07-31）

**现象**：第二轮修复后菜单仍可通过点击菜单外关闭，点击时鼠标变成缩放光标。

**根因**：backdrop 使用的 `z-[9998]` 和菜单使用的 `z-[9999]` 是 Tailwind 任意值类名，但 `packages/sketch-react/src/` 不在创作端 Tailwind `content` 扫描路径中，导致这些 CSS 类从未生成。backdrop 和菜单实际回退到 `z-index: auto`，指针事件穿透到下层画布。

**修复**：
- 将 backdrop 和菜单的 z-index 从 Tailwind 任意值类名改为 inline style（`style={{ zIndex: 9998 }}` / `style={{ zIndex: 9999 }}`），不再依赖 Tailwind 编译
- backlog 添加 `cursor-default`，防止画布 `cursor-grab` 穿透显示
- `onContextMenu` 中先调用 `releasePointerCapture()` 释放可能残留的指针捕获，再打开菜单

**验证**：`pnpm check:sketch-react` 通过（151 测试 + typecheck）。

**关键教训**：跨包的 Tailwind 任意值类名（`z-[*]`、`w-[*]` 等）在消费者编译时可能丢失，跨包渲染到 portal 的元素应使用 inline style 设置关键定位属性。
