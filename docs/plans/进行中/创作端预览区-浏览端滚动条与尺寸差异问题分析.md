## 二、根因分析（三轮排查）

### 2.1 问题1：浏览端滚动条

#### 根因A：sandbox 缺少 allow-same-origin（第二轮发现）

`IframePreviewFrame` 默认 `sandbox="allow-scripts"`（无 `allow-same-origin`），而 `PreviewPanel` 用 `"allow-scripts allow-same-origin"`。没有 `allow-same-origin` 时 iframe 获得唯一 opaque origin，`contentDocument` 返回 `null`，样式注入静默失败。

**修复**：将 `IframePreviewFrame` 默认 sandbox 改为 `"allow-scripts allow-same-origin"`。

#### 根因B：overflow:hidden 阻止了滚动（第三轮发现）

sandbox 修复后样式注入生效，但注入的是 `html, body { overflow: hidden; }`，这会**阻止内容滚动**。旧项目发布的 `iframe.html` 内容可能比预览区高，需要滚动。用户反馈"滚动条虽然隐藏了，但也不能滚动了"。

**修复**：注入样式改为仅隐藏滚动条，不改变 overflow 行为：
```css
::-webkit-scrollbar { display: none; }
html, body { scrollbar-width: none; -ms-overflow-style: none; }
```

### 2.2 问题2：浏览端预览撑满容器

#### 根因A：wrapper 尺寸未随 scale 一起限制（第二轮发现）

`computePreviewScale` 在 `fillContainer=false` 时，`scale` 被限制为 `Math.min(1, ...)`，但 wrapper 仍用 `displayWidth × displayHeight`（容器适配尺寸）。大容器下 wrapper 为 401×868 而非 375×812。

**修复**：wrapper 尺寸改为 `designWidth * scale × designHeight * scale`，大容器下 wrapper 被限制为设计尺寸。

#### 根因B：prototype 页面 previewSize 未从 prototypeMeta 提取（第三轮发现）

项目 `proj_1783585261167_7h7prw` 的页面是 `prototype-html-css` 类型，`previewSize=None`，但 `prototypeMeta.previewSize={width:375, height:812}`。

创作端 `activePreviewSize` 有四个 fallback 来源：
```typescript
sizeFromSchema ?? pagePreviewSizeMap[id] ?? sizeFromPrototypeMeta ?? previewSize
```

浏览端只有两个：
```typescript
previewSize ?? activePage.previewSize  // 都为 undefined
```

`PrototypePagePreview` 在 `previewSize=undefined` 时不缩放，直接 `h-full w-full` 撑满容器。

**修复**：将 `getPrototypePreviewSize` 移至 `demo-ui` 共享包，浏览端 `PrototypePagePreview` 渲染时增加 prototypeMeta fallback：
```typescript
previewSize={previewSize ?? activePage.previewSize ?? getPrototypePreviewSize(activePage.prototypeMeta)}
```

## 四、关于预览区共享组件的评估

当前创作端与浏览端预览逻辑存在三处差异：

| 差异点 | 创作端 | 浏览端 | 影响 |
|--------|--------|--------|------|
| React 页面渲染 | `PreviewPanel` + `code`（动态编译 + 动态 Shell） | `IframePreviewFrame` + 静态 `iframe.html`，fallback 到 `PreviewPanel` + `compiledJsUrl` | Shell 样式可能过期 |
| previewSize 来源 | 4 个 fallback（schema → pageMap → prototypeMeta → global） | 3 个 fallback（schema → page.previewSize → prototypeMeta） | 已对齐（pageMap 是创作端手动覆盖，浏览端不需要） |
| 额外功能 | 可视化编辑、图层树、属性抽屉 | 无 | 不适合直接共享 |

**结论**：预览区不适合直接做成一个共享组件，因为创作端有大量交互功能（可视化编辑、图层树等）是浏览端不需要的。但可以做以下渐进改进：

1. **已做**：将 `getPrototypePreviewSize` 移至 `demo-ui`，统一 previewSize 提取逻辑。
2. **建议**：将 previewSize 完整推导逻辑（schema → page.previewSize → prototypeMeta）提取为 `demo-ui` 中的共享函数 `resolvePreviewSize`，两端复用。
3. **长期**：考虑将单页预览的**组件选择 + 尺寸计算 + 容器渲染**提取为 `demo-ui` 中的 `SinglePagePreviewStage` 组件，创作端在此基础上叠加交互层。但这需要评估改动范围和收益。
