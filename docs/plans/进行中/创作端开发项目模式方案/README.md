## 当前状态

方案设计阶段。创作端当前有两种项目类型：**演示项目**（代码在平台内，快速原型预览与配置）和**开发项目**（代码在外部 Git 仓库，平台接入预览 + AI 代理修改真实业务代码）。本方案聚焦开发项目的设计与实现。创作端不拥有、不编译、不管理开发项目的代码，而是作为透明代理层连接项目 dev server，Codex 自动分析源码发现所有页面和状态变体。

## 背景与动机

### 现状痛点

- 开发者使用 Codex IDE 编码活动页面
- 同事对页面有修改意见时口头或文字通知开发者
- 开发者理解意见 → 手动修改 → 给同事确认 → 反复迭代
- 开发者成为瓶颈，沟通成本高、响应慢

### 目标

1. **开发者零负担启动**：在 Codex IDE 中一句话即可生成开发项目链接，或 PM 在创作端自行创建
2. **画布预览**：自动发现项目所有页面 × 所有状态变体（含弹窗、loading、空状态等），画布网格展示
3. **页面标注**：同事（PM / 设计师）在预览区直接标注修改点，结构化数据随 AI 对话传递
4. **AI 对话**：Pi Agent 仅做"翻译官"——理解需求、追问澄清、确认后组装 Task
5. **Codex 执行**：agent-service 通过 `codex exec --json` 执行实际代码修改
6. **任务队列**：串行排队、状态查看、HMR 自动刷新预览

### 核心原则

```
本模式是 AI 驱动的异步委托执行，而非多人实时协同编辑。

PM 提交修改指令 → Pi Agent 确认需求 → Codex 执行代码修改 → HMR 实时刷新预览
（等待时间通常几十秒到数分钟）

与 Figma 式多人实时编辑不同：修改需要经过 AI 确认和执行环节，但结果立即可见。
适用于"PM 看到业务页面想改 UI 细节，不想等开发者排期"的场景。

开发者仍是代码所有者——涉及功能逻辑的修改自动留存，由开发者手动处理。
```

```
【Session 创建】→ spawn dev server → Session 立即可用（2-3s）
        │
        ├──▶ 实时代理预览（始终走 dev server，不再区分浏览/编辑模式）
        │
        └──▶ npm run build（后台异步并行）→ 截图（渐进就绪）
        
【Codex 分析项目源码】→ 自动发现页面、路由、状态分支（全委托 Codex，与 dev server 并行）
        ↓
【画布导航就绪】→ 截图渐进加载，单页模式实时 iframe
        ↓
【Pi Agent = 需求翻译】→ 确保需求明确，组装 Task
        ↓
【Codex CLI = 执行】→ 接收精准指令，直接改代码 → HMR 热更新
        ↓
【编辑完成】→ 自动 npm run build（后台，不阻塞）→ 新快照加入版本链
        ↓
【版本链持久化】→ 任意历史版本可静态回看，当前版本实时代理
```
