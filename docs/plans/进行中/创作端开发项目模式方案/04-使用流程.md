# 04 - 使用流程

## 开发者侧（通过 Codex IDE MCP）

```
开发者在 Codex IDE 中说：
  "给这个项目创建 review session"
  
→ Codex 检测当前项目路径
→ 通过 MCP review_start 工具调用 agent-service
→ agent-service: spawn dev server + 注册代理路由 + 后台 build
→ 立即返回 review URL（2-3s）

输出：
✅ Review Session 已创建
🔗 链接: http://author-site:3200/review/sess_abc123
⏳ 正在后台分析页面、生成截图...
💡 链接可分享给团队成员，多人可同时标注和对话
```

## 创作端主动创建

```
1. 打开创作端首页项目列表 → 点击「新建开发项目」→ 对话框弹出
2. 在「新建开发项目」对话框中 → 从已有项目中选择，或手动输入项目路径
3. 点击「创建开发项目」
4. agent-service spawn dev server → Session 立即可用
5. 自动跳转到画布页面 → 开始浏览、标注和 AI 对话
   （后台并行：npm run build + 截图 + Codex CLI 分析 Manifest → 渐进就绪）
```

## 协作者侧

```
1. 打开链接 → 画布显示所有页面 × 所有状态（截图渐进加载，未就绪时显示占位符）
2. 浏览画布，发现需要修改的地方

   **方式一：可视化编辑（推荐用于样式修改）**
   3a. 在右侧「编辑」Tab 中直接调颜色、字号、圆角等属性 → 预览即时生效
   3b. 满意后点击「应用这些修改」或 AI Chat 中说"应用修改"
   3c. Pi Agent 将编辑状态序列化为 Task → 提交到队列

   **方式二：标注 + AI 对话（推荐用于复杂修改）**
   3d. 点击页面上的元素 → 弹出标注气泡 → 输入修改意见
   3e. 或在 AI Chat 中描述需求（可引用当前选中的页面）

4. Pi Agent 确认需求 → 提交 Task → 排队执行
5. Codex 执行 → dev server HMR → iframe 自动更新
6. 标注自动标记为已解决
7. 编辑完成后自动 build → 版本链追加新快照 → 历史版本随时回看
```

## 修改不满意时的回退

```
协作者发现 Codex 修改结果不符合预期：

1. 在 AI Chat 中直接描述回退需求，例如：
   "把提交按钮改回原来的样式"
   "撤销上一次对抽奖页面的修改，恢复到改动前的样子"
2. Pi Agent 将其识别为新的修改任务，提交到队列
3. Codex 执行回退 → HMR 实时刷新 → 确认结果

本质与提交新任务流程完全一致。
极端情况下开发者可随时通过 git 手动恢复。
```
