# AI 对话与 Agent - 数据驱动模型路由方案

> 状态：远期规划 · 暂不实施
> 关联模块：`packages/agent-service/`、`packages/ai-chat-shared/`、模型管理后台

## 背景

当前 Pi Agent 已支持运行时模型选择、上下文压缩、一次溢出恢复和基础请求重试，但没有记录足以比较模型表现的真实使用量、成本与分阶段耗时。自定义 OpenAI 兼容供应商的模型成本当前统一为 0，成功运行也不会向控制面回传完整 token 使用量。

在缺少这些数据时，按任务自动切换模型会把模型偏好固化为猜测，既难验证收益，也可能降低复杂任务的成功率。因此本方案只沉淀未来实施边界，不进入当前开发排期。

## 目标

在可解释、可回退且不牺牲任务成功率的前提下，为不同任务选择性价比更高的模型或模型档位。

衡量指标：

- 任务成功率与修改后验证通过率；
- 单次运行的输入、输出、缓存 token 与估算成本；
- 首 token、工具调用、压缩、重试和总耗时；
- 超时、限流、上下文溢出、重试及人工重试率；
- 用户切换模型或重试后的最终完成率。

## 非目标

- 不在没有观测基线前自动替用户切换模型；
- 不依据用户内容中的敏感信息推断模型选择；
- 不把模型路由作为权限或安全策略的替代品；
- 不要求所有供应商先提供精确价格才能开始采集使用量。

## 分阶段方案

### 阶段 1：统一观测（前置条件）

为每次运行记录并返回：

1. 路由前后模型标识、供应商、模型配置版本和工具能力版本；
2. 供应商返回的 usage；没有 usage 时标记为估算值，不能伪装为精确值；
3. 排队、初始化、首 token、各工具、重试、上下文压缩、完成的耗时；
4. 最终结果、错误分类、Mutation receipt 与适用验证器的结果。

按 `traceId` 聚合到运行日志和诊断系统，并限制日志只保存聚合指标，避免写入提示词正文或密钥。

### 阶段 2：离线评估与建议模式

建立覆盖只读问答、局部页面修改、多文件修改、图片任务、联网读取、超长上下文和失败恢复的固定场景集。先以“建议模型”方式展示或记录候选路由，不自动生效。

候选模型必须同时满足成功率下限和延迟/成本收益；只比较同一能力档位内支持相同输入与工具要求的模型。评估维度至少包括成功、验证通过、工具调用次数、token、成本、总耗时、人工重试和安全拒绝是否正确。

### 阶段 3：受控自动路由

仅对高置信、低风险任务启用，例如短文本只读问答或明确的图片理解请求。复杂修改、多文件任务、需要联网/子 Agent 的任务默认保留用户选择或稳定的主模型。

路由决策需要输出原因码，例如 `short_readonly`、`vision_required`、`large_context`、`provider_degraded`；用户可见当前模型并可一键切回默认模型。任何失败自动回退最多一次，且不得在已产生工具副作用后整轮重放。

## 路由信号与约束

可使用的信号：显式模型选择、是否带图片、输入长度、已知上下文预算、工具能力档位、供应商健康状态和历史聚合指标。

不可直接使用原始用户内容作为长期画像；不以模型“价格低”覆盖显式用户选择；没有供应商 usage 或健康指标时，只允许静态默认路由，不做动态降级。

## 验收条件

- 可按模型、能力档位和任务类型查询成功率、p50/p95 耗时与单位任务成本；
- 路由决策可追溯到配置版本和原因码；
- 自动路由的任务成功率不低于默认模型基线，且验证通过率不下降；
- 路由错误可在一个明确的边界内回退，不产生重复写入或无限重试；
- 评估场景和关键路由规则有自动化回归。

## 当前前置缺口

- 成功运行尚未统一回传 provider usage、成本与阶段耗时；
- 自定义模型的成本元数据为零值；
- 缺少用于模型横向比较的场景集与验证断言；
- 需要先完成工具副作用后的整轮重试收敛，才能安全引入自动回退。
