## 部署拓扑

```
┌──────────────────────────────────────────────────────────────┐
│                    同一台局域网服务器                           │
│                                                              │
│  ┌─────────────────────┐    ┌──────────────────────────────┐ │
│  │    Codex 项目目录     │    │      创作端 + agent-service    │ │
│  │                     │    │                              │ │
│  │  ~/projects/        │◄──►│  author-site :3200           │ │
│  │    activity-2026/   │    │  agent-service :3201         │ │
│  │    summer-promo/    │    │                              │ │
│  │    ...              │    │  agent-service 直接 spawn    │ │
│  │                     │    │  项目目录下的 dev server       │ │
│  └─────────────────────┘    └──────────────────────────────┘ │
│                                                              │
│  开发者 Codex IDE（同一服务器或局域网内）                        │
│   └─ 通过 MCP 调用 agent-service 创建 Session                  │
│                                                              │
│  PM / 设计师浏览器（同一局域网内）                               │
│   └─ 打开 review URL → 标注 → AI 对话                          │
└──────────────────────────────────────────────────────────────┘
```

> **关键前提**：开发项目代码与创作端部署在同一台局域网服务器上，agent-service 通过文件系统直接访问项目目录，spawn dev server 和 codex exec 子进程。开发者通过 Codex IDE（MCP）创建 Session，PM 通过创作端 UI 访问已有 Session。

## 关键架构决策

1. **Session 独立于项目体系**：不修改 `project-core`，不扩展 `ProjectConfig`
2. **始终走代理层**：不再区分浏览/编辑模式，简化架构
3. **全委托 Codex**：Manifest 分析和代码执行都交给 Codex CLI，agent-service 不做 AST 分析
4. **构建后台异步**：不阻塞 Session 创建，渐进就绪
5. **多人协作**：链接可分享，标注和消息各自携带操作者标识
6. **回退即新任务**：对修改结果不满意时，直接在 AI Chat 中描述期望的回退目标，Pi Agent 将其作为新任务提交给 Codex 执行。不引入专门的 git 操作或回滚功能，保持架构简洁——所有项目仓库均已有 git 管理，极端情况下开发者随时可手动处理
7. **需求分级执行**：纯 UI 修改（颜色、尺寸、文案、布局）由 Codex 直接执行；功能逻辑修改留存为待处理任务，由开发者手动处理
8. **高复用骨架 + 独立页面组装**：Codex 项目页面与创作端编辑页共享 `ResizablePanelGroup` 三栏布局、`AIChat`、`PreviewCanvas`/`PreviewPanel`、`VisualPropertyPanel`（编辑 Tab 复用但落点改为本地预览）、Tabs 框架等核心组件（复用度约 70%）。仅替换右侧栏配置 Tab 为任务 Tab、左侧页面树数据源切换为 Manifest、预览渲染方式改为代理模式。两个页面各自独立路由（`/review/[sessionId]` vs `/demo/[id]/edit`），避免在已有 7000+ 行的编辑页中叠加条件分支
