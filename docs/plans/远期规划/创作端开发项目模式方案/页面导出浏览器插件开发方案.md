# 高保真网页工程导出浏览器插件开发方案

> 创建日期：2026-08-20
> 最近校正：2026-08-20
> 状态：内部实现已完成到 P2 主链路；加载未打包扩展的公开夹具、真实 `activeTab` 手势、外部 source map 恢复、50MB 取消重试与 Service Worker 回收 E2E 已通过，author-site 登录态、Save As 系统对话框与许可评审待完成
> 目标平台：Chrome / Edge（Manifest V3），Firefox 适配后置
> 定位：基于 SingleFile 技术捕获当前浏览器标签及其真实状态，在尽量保留 HTML、CSS、JavaScript、事件属性、iframe 和资源的前提下，导出 Agent 可阅读、可修改、可预览的网页工程

## 一、方向与边界

插件的第一目标是高还原度和 Agent 可编辑性，不是满足创作端 `prototype-html-css` 的静态安全限制。因此：

- 不主动移除 script、内联事件属性、iframe/embed/object、form action、`javascript:` URL 或 CSS `@import`。
- 不以 `prototypeGate` 作为插件产物验收标准。
- 不生成 `prototype.html/prototype.css` 作为主产物。
- 插件产物不得直接导入现有原型页运行时，因为现有原型页明确禁止脚本和 iframe。
- 如需进入创作端原型评审，必须由独立的“静态原型派生器”从高保真工程生成降级副本；不得反向修改或覆盖高保真原件。

校正后的关系：

```text
浏览器当前标签
      │
      ▼
SingleFile 高保真采集
      │
      ▼
Editable Snapshot Bundle v1
  ├─ faithful/  原样执行基线
  ├─ workspace/ Agent 可读可编辑工程
  ├─ sources/   可获得的 source map 源文件
  └─ reports/   依赖、缺失资源和还原度报告
      │
      ├── 本地隔离预览 / Agent 修改
      │
      └── 可选：静态原型派生器 → Import Bundle → 创作端原型页
```

## 二、目标与非目标

### 2.1 目标

- 复用用户当前浏览器登录态和已经准备好的页面状态。
- 尽量完整保存当前 DOM、CSS、脚本、内联事件、iframe 描述和页面资源。
- 将单文件快照拆解为结构清晰的多文件网页工程，便于 Agent 定位和编辑。
- 同时保留未经可读性改写的忠实基线，方便对照、回退和视觉比较。
- 生成依赖图、资源来源、脚本顺序、iframe 层级和缺失项报告。
- 提供安全隔离的本地预览方式，验证 Agent 修改后的结果。

### 2.2 非目标

- 不承诺恢复 React/Vue/Svelte 组件、TypeScript、原始 CSS Modules 类名或构建配置。
- 不反编译压缩后的第三方库，也不伪造不存在的 source map。
- 不承诺恢复 JavaScript 堆、闭包、WebSocket、Service Worker、IndexedDB、内存路由状态等不可序列化运行时。
- 不保证所有交互能够离线工作；脚本重放可能因后端 API、同源策略或初始化时序发生变化。
- 不直接写入创作端项目数据。

### 2.3 “高还原度”的验收含义

高还原度分层评估：

| 层级 | 目标 |
|---|---|
| 视觉 | 约定 viewport 下截图、字体、图片、布局和可见状态接近原页面 |
| 结构 | DOM 层级、属性、ARIA、表单状态、Shadow DOM/iframe 描述尽量保留 |
| 资源 | CSS、脚本、图片、字体和媒体来源可追踪，能本地化的尽量本地化 |
| 交互 | 内联事件和脚本保留；能否离线重放按页面逐项报告，不作普遍保证 |
| 可编辑 | Agent 能从 manifest、依赖图和格式化文件定位修改点并验证效果 |

## 三、SingleFile 技术路线与许可

### 3.1 技术路线

SingleFile 官方提供 `singlefile.getPageData(options)`，可返回完整页面内容、标题和文件名。插件采用“薄插件 + SingleFile Core/MV3 capture adapter”：

- 使用 SingleFile hooks 捕获 DOM、frame、Shadow DOM、样式和资源。
- 配置为保留脚本与页面结构，不启用原型页净化选项。
- 不 fork 完整 SingleFile 产品 UI，仅复用采集核心和 MV3 大文件通信模式。
- SingleFile 输出首先写入 `faithful/snapshot.html`；可读工程从该基线派生。

官方资料：

- [SingleFile 主仓库](https://github.com/gildas-lormeau/SingleFile)
- [SingleFile Manifest V3 实现](https://github.com/gildas-lormeau/SingleFile-MV3)
- [SingleFile 扩展集成 API](https://github.com/gildas-lormeau/SingleFile/wiki/How-to-integrate-the-API-of-SingleFile-into-an-extension)
- [自定义环境集成说明](https://github.com/gildas-lormeau/SingleFile/wiki/How-to-integrate-SingleFile-library-code-in-%22custom%22-environments%3F)

### 3.2 许可门禁

SingleFile 与 SingleFile MV3 使用 AGPL-3.0-or-later。直接嵌入、修改或分发其代码会带来相应开源义务。开发开始前必须完成以下二选一决策：

1. 插件及相关网络交互源代码按 AGPL 兼容方式发布；或
2. 与 SingleFile 作者确认并取得适合当前分发方式的商业许可。

许可结论明确前，仅允许内部技术原型，不发布商店版本，不对外分发安装包。

## 四、产物协议：Editable Snapshot Bundle v1

插件默认下载 ZIP：

```text
editable-snapshot-<host>-<route>-<timestamp>.zip
  bundle.json
  README.md
  AGENT.md
  faithful/
    snapshot.html
    screenshot.png
  workspace/
    index.html
    styles/
      page.css
      inline-001.css
    scripts/
      first-party/
        inline-001.js
        app-<hash>.js
      vendor/
        vendor-<hash>.js
    frames/
      frame-001/
        index.html
        frame.json
    assets/
      images/<content-hash>.<ext>
      fonts/<content-hash>.<ext>
      media/<content-hash>.<ext>
  sources/
    <source-map 中可恢复的原始路径>
  reports/
    capture-report.json
    dependency-graph.json
    readability-report.json
    fidelity-report.json
    security-report.json
```

### 4.1 双层产物

**faithful 层**：

- 保存 SingleFile 捕获结果，除必要元数据外不做结构重写。
- 作为视觉和行为基线，Agent 修改不得覆盖此目录。
- 用于判断 workspace 拆分或格式化是否改变页面。

**workspace 层**：

- 将 HTML、CSS、脚本、iframe 和资产拆成可导航文件。
- 保持脚本相对顺序、模块类型、async/defer、crossorigin、integrity 等执行属性。
- 通过稳定格式化提高阅读性，不做可能改变语义的重构。
- Agent 默认在此目录修改。

### 4.2 bundle.json

至少包含：

- contractVersion、captureId、URL、标题、时间、viewport。
- sourceProjectKey、routeKey、页面状态备注。
- faithful/workspace 入口文件。
- HTML、CSS、script、frame、asset 清单与内容哈希。
- 资源原始 URL、本地路径、第一方/第三方分类和下载状态。
- 脚本执行顺序及 module/async/defer 等属性。
- source map 来源和恢复结果。
- missingResources、crossOriginResources、runtimeDependencies。
- `executableContent: true` 安全标记。

### 4.3 AGENT.md

随包生成的 Agent 入口应说明：

- 页面目标、入口文件和目录结构。
- 哪些文件参与实际预览，哪些只是格式化阅读副本。
- 第一方与第三方代码边界。
- 不应直接修改 faithful 和 vendor 的规则。
- 本地预览、截图比较和还原度验证命令。
- 已知缺失资源、后端 API 和跨域限制。

## 五、用户流程

1. 用户打开目标页面并完成登录。
2. 用户展开菜单、滚动加载并调整到希望保留的状态。
3. 点击插件，确认 routeKey、页面名称、viewport 和捕获范围。
4. 插件申请当前标签权限及必要的可选跨域资源权限。
5. SingleFile 捕获忠实快照。
6. 插件拆分并格式化 workspace，生成依赖图和可读性报告。
7. 插件分别预览 faithful 与 workspace，生成截图差异。
8. 用户查看缺失资源、交互风险和敏感信息提示。
9. 下载 Editable Snapshot Bundle。
10. Agent 解压后先读 AGENT.md，再修改 workspace 并运行隔离预览。

批量标签页放到 P2，必须由用户显式选择；禁止静默读取全部标签或浏览历史。

## 六、插件架构

```text
Popup / Side Panel
  配置、进度、资源授权、还原度报告
          │
          ▼
MV3 Service Worker
  任务状态机、权限、下载、storage
          │
          ├── Capture Adapter
          │     SingleFile hooks / getPageData / frame capture
          │
          └── Offscreen Bundle Worker
                HTML/CSS/JS parser
                资源提取与 source map 恢复
                依赖图、格式化、ZIP、报告
                         │
                         ▼
              Editable Snapshot Bundle v1
```

### 6.1 模块职责

| 模块 | 职责 |
|---|---|
| `capture-adapter` | 封装 SingleFile 注入、选项、frame/Shadow DOM 捕获和结果分块 |
| `task-orchestrator` | 管理权限、状态、取消、超时和 service worker 重启恢复 |
| `snapshot-parser` | 解析捕获 HTML，建立节点、样式、脚本、frame 和资源索引 |
| `workspace-builder` | 生成可读工程并维持执行顺序和引用关系 |
| `source-map-recovery` | 在可用且获授权时提取真实原始源码，不做反编译 |
| `dependency-graph` | 标注第一方/第三方、入口、动态依赖和外部 API |
| `fidelity-checker` | faithful/workspace 截图和资源差异检查 |
| `security-scanner` | 标识可执行内容、凭证、个人信息和危险外链，不擅自删除 |
| `bundle-builder` | 生成 bundle、校验内容哈希并下载 ZIP |

### 6.2 任务状态机

```text
idle
  → requesting_permission
  → preparing_page
  → capturing
  → parsing
  → building_workspace
  → recovering_sources
  → checking_fidelity
  → packaging
  → ready

任一阶段 → failed / cancelled
```

状态写入 `chrome.storage.session`。大体积页面用 port 分块传输并带 sequence/checksum，不通过单条 runtime message 传完整 HTML。中间数据使用 offscreen document 内存或 IndexedDB，完成和取消后清理。

## 七、捕获与可读性规则

### 7.1 SingleFile 捕获 profile

默认“Editable Fidelity”配置意图：

| 能力 | 默认 | 说明 |
|---|---|---|
| `compressHTML` | false | 保留格式化和阅读空间 |
| scripts | 保留 | 不为 prototypeGate 删除 |
| inline event attributes | 保留 | 保持原始 HTML 行为描述 |
| iframe/frame | 保留描述；能捕获则保存嵌套快照 | 跨域 frame 可能只能保留 URL |
| hidden elements | 保留 | 避免丢失交互状态和未展开结构 |
| unused styles/fonts | 保留 | 高还原优先；后续只生成分析，不自动删除 |
| CSS imports | 保留并记录解析结果 | workspace 可镜像为本地文件，但 faithful 不改 |
| deferred images | 保存 | 覆盖懒加载资源 |
| canvas/Shadow DOM | 启用 SingleFile 对应捕获能力 | 报告不可还原部分 |

具体字段名以锁定版本的 SingleFile API 为准，禁止用 CLI 参数名猜测 Core API。版本升级必须跑契约测试。

### 7.2 HTML

- 忠实保留 script、noscript、事件属性、iframe/embed/object、form 和业务 `data-*`。
- workspace 使用 HTML parser 和稳定 pretty printer，不用正则拆结构。
- 不改变节点顺序，不擅自补语义标签，不移动脚本位置。
- pre、code、textarea、SVG、MathML、template 和自定义元素采用保守序列化。
- 记录运行时生成节点与原始文档来源无法区分的事实，不伪造来源。

### 7.3 CSS

- faithful 保留 SingleFile 捕获 CSS。
- workspace 通过 CSS AST 格式化，保留 import、layer、media、supports、container、keyframes 和自定义属性。
- 不排序声明、不重命名 class、不激进合并规则。
- CSS parse error 时保留原始文件并标记，不能用猜测性修复覆盖。
- 可以生成“可能未使用规则”报告，但默认不删除。

### 7.4 JavaScript

- 可执行 workspace 默认引用原始字节脚本，确保格式化不影响运行。
- 同时生成格式化阅读副本；Agent 明确选择后才能让预览切换到编辑版脚本。
- inline script 按 DOM 顺序编号，拆出后在原位置用等价 script 引用保持顺序。
- 保留 type/module/nomodule/async/defer/crossorigin/integrity/referrerpolicy。
- 第一方/第三方按 URL origin、source map 路径和启发式规则分类；分类不确定时标记 unknown。
- 有 source map 时恢复真实 sources；没有 source map 时只格式化 bundle，不声称恢复源码。
- `addEventListener` 注册的监听器依赖脚本重放，不能从 DOM 通用序列化；闭包监听器不承诺恢复。

### 7.5 iframe

- 保留 iframe 元素、sandbox、allow、src/srcdoc、name 和尺寸。
- 同源 frame 尝试生成独立嵌套 workspace，并在父页面保持引用。
- 跨域 frame 在取得可选权限且技术允许时捕获；否则保留 URL、截图和缺失原因。
- 不把 iframe 内容平铺进父 DOM，避免破坏隔离和选择器作用域。

### 7.6 资产

- 原始 URL、响应类型、内容哈希和本地路径全部进入依赖清单。
- 使用内容哈希命名，避免跨页面冲突并支持去重。
- 图片、字体、音视频、worker 和 wasm 分目录保存。
- Blob URL 尽量在页面上下文读取；失败时记录创建者和引用节点。
- 第三方资源默认保留，不因“可读性”删除。

## 八、可编辑预览与安全

### 8.1 本地预览

高保真 bundle 包含可执行脚本，不能像普通文档一样信任。预览必须使用独立本地 runner：

- 使用临时 origin 提供 workspace 文件，禁止直接写入开发项目服务。
- 默认阻断非 allowlist 的写请求、下载、弹窗和顶层导航。
- 网络模式分为 offline、read-only proxy 和 original-network，默认 offline。
- original-network 模式必须提示可能向真实后端发送请求。
- faithful 与 workspace 使用相同 viewport 截图比较。

### 8.2 最小权限

初始权限：

- `activeTab`
- `scripting`
- `downloads`
- `storage`
- `offscreen`

跨域资源使用 `optional_host_permissions` 按需申请。P0 不申请 cookies、history 或永久 `<all_urls>`；若捕获能力确实依赖更高权限，需单独记录用途和用户可见影响。

### 8.3 敏感信息

- 不读取或导出 Cookie、localStorage、sessionStorage、IndexedDB 数据库内容。
- DOM、脚本和网络 URL 中已经存在的 token/个人信息可能进入 bundle，下载前必须扫描和提示。
- security report 只报告，不为提高安全性静默删除脚本或业务内容。
- bundle.json 必须标记 `executableContent: true`。
- 不上传第三方服务；P0 全程本地处理。

## 十一、测试与验收

### 11.1 契约测试

- script、inline event、iframe 和 form action 不会被净化器删除。
- 脚本顺序、类型和 async/defer 等属性保持。
- HTML/CSS/JS 格式化前后 parser round-trip 通过。
- 多页面、iframe 和同名资源不发生覆盖。
- source map 只输出真实存在的 sources。

### 11.2 扩展 E2E

- 公开页和已登录 author-site 页面。
- 页面展开状态、表单当前值、Shadow DOM、canvas 和懒加载资源。
- 同源与跨域 iframe。
- 第一方 module、第三方 bundle、inline script 和 inline event。
- service worker 回收、任务取消和大文件传输。

### 11.3 还原度验收

- faithful 截图与原标签在约定 viewport 下达到阈值。
- workspace 截图与 faithful 达到更严格阈值。
- 资源、console error、failed request 和 CSP 差异进入报告。
- 核心导航和交互按页面场景清单验证，不使用“一切交互正常”的模糊结论。

### 11.4 Agent 可编辑性验收

- Agent 只读 AGENT.md 和 dependency graph 能定位主要入口。
- 第一方和第三方代码边界明确。
- 修改标题、样式和一个第一方交互后可重新预览。
- 没有 source map 的压缩 bundle 被明确标注为 formatted bundle，而非原始源码。

### 11.5 安全与许可验收

- manifest 权限通过最小权限审查。
- bundle 不包含 Cookie 或浏览器 storage dump。
- 本地 runner 默认不向真实后端发写请求。
- AGPL/商业许可结论、第三方 notice 和源码提供方式完成评审。

## 十二、主要风险

| 风险 | 应对 |
|---|---|
| 运行态 DOM 与脚本初始化输入不一致 | faithful/workspace 双基线；交互按场景验证，不承诺通用重放 |
| addEventListener/闭包无法序列化 | 依赖原脚本重放；报告不可恢复监听器，不伪造代码 |
| 第三方脚本巨大且不可读 | 原字节用于执行，格式化副本用于阅读，vendor 默认不要求 Agent 修改 |
| iframe 跨域不可捕获 | 保留 URL/属性/截图，按需申请权限并报告缺口 |
| source map 不存在 | 只格式化 bundle，不声称恢复源码 |
| 可执行 bundle 有安全风险 | executable 标记、隔离 runner、默认离线、写请求阻断 |
| SingleFile AGPL 不符合分发策略 | 许可作为 P0 门禁，必要时商业许可或更换引擎 |
| MV3 worker 被回收 | session 状态、offscreen 处理、分块传输和显式恢复 |

## 十三、最终决策

浏览器插件的主产物确定为高保真、可执行、Agent 可读的 Editable Snapshot Bundle，不再以创作端原型页限制为采集标准。

现有页面快照导入工具继续负责静态原型评审。需要创作端评审时，由独立派生器从 editable snapshot 生成静态 Import Bundle；原始脚本、事件、iframe 和其他可执行内容始终保留在高保真 bundle 中。
