# 07 - 风险与远期规划

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Codex 分析源码不完整，遗漏页面/状态 | 画布上缺少某些状态 | 协作者发现遗漏可反馈；后续支持开发者手动补充 manifest |
| `npm run build` 失败（后台异步） | 画布截图暂时缺失，历史版本无法生成 | 不影响实时预览和标注；前台显示"截图生成中"，build 失败提示但不阻断流程 |
| dev server 启动失败 | 无法实时预览 | Session 创建返回错误提示；可降级为仅分析源码生成 manifest |
| Codex 做出不符合预期的修改 | 页面被改坏 | ✅ 已缓解：不满意时直接在 AI Chat 中描述回退需求，作为新任务由 Codex 反向修改；涉及功能逻辑的需求自动留存给开发者处理；所有项目仓库均有 git 管理兜底 |
| 标注脚本与目标页面 JS 冲突 | 标注功能异常 | ✅ 低风险：iframe 本身提供隔离边界（`sandbox="allow-scripts allow-same-origin"`），标注脚本挂载到独立命名空间 `window.__REVIEW_ANNOTATION__` 下；现有 `iframe-template.ts` 已有相同模式的成熟实践 |
| 多人同时标注同一元素 | 标注重叠，视觉混乱 | ✅ 低影响：标注各自携带 `author`，不同用户标注用不同颜色区分；按时间排序展示；现有可视化编辑已有类似多标注覆盖层处理经验 |
| Manifest JSON 格式不稳定（LLM 输出） | 画布内容不完整 | JSON Schema 校验 + 重试 + 降级为仅路由列表 |
| 代理层资源路径重写遗漏 | 部分资源加载失败 | `@fastify/http-proxy` 处理通用路径重写；少量静态资源路径需手动处理 |
| 目标页面 CSP 阻止注入脚本 | 标注脚本被阻止，标注不可用 | 代理层的 `onResponse` 可移除/修改 CSP 响应头（`Content-Security-Policy`），添加 `'unsafe-inline'` 或完全移除 CSP 头 |
| Session 空闲超时误杀 dev server | 协作者长时间查看历史版本或编辑标注时 WS 断开 | 编辑 Tab 操作和页面切换维持 WS 心跳；历史版本浏览使用静态 serve 不依赖 dev server |
| 编辑 Tab diff 序列化不准确 | 编辑状态的序列化结果不能准确表达用户修改意图 | 序列化时同时记录选择器 + 具体属性变更 + 元素截图，为 Codex 提供足够上下文 |

> 安全性：内网工具，不建额外鉴权层。review URL 中的 `sessionId` 即访问凭证（与现有分享链接模式一致）。dev server 由 agent-service 自管子进程管理，不暴露外部端口。

## 远期扩展

- 开发者手动编辑 manifest（添加/删除/重排页面和状态）→ **Phase 2**
- Session 持久化和历史 Session 回看
- 任务执行 diff 预览 → **远期**
- 审核模式（修改需管理员审批后执行）
- `codex remote-control` 模式升级（长连接 + 更丰富的会话管理）
