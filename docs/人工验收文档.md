# OneFlow 人工验收操作文档（通用版）

> 目标：面向不需要研发经验的验收人员，提供从启动、登录、创建项目到编辑、发布和浏览端检查的操作清单。
>
> 文档版本：2026-09-01
> 适用对象：在自己开发分支上验收的产品、设计、运营和开发人员
> 使用范围：在各自电脑和代码分支上执行，不绑定具体用户名、目录、分支或测试数据。
> 验收原则：本文是操作指南，不代表当前版本已通过验收；请记录每一步的实际结果。

## 一、使用说明

1. **先确认代码分支**：验收当前要提交或合并的分支，不要默认使用别人的分支。
2. **启动服务**：确认页面能打开，再开始业务验收。
3. **完成必测主流程**：从创建到发布，再到浏览端查看。
4. **再做页面专项验收**：检查按钮、弹窗、空状态、错误提示和返回路径。
5. 遇到“应该看到”或“预期结果”时，立即对照页面检查，不要只看页面能否打开。
6. 每一步记录实际结果和判定（通过、不通过、未验证或不适用）；发现问题时附上截图或录屏、页面地址、操作步骤、测试账号和时间。
7. 文中标记说明如下：
   1. **【必测】**：主流程必须完成，任何一步不通过都不能直接判定整体验收通过。
   2. **【专项】**：按本次范围检查独立功能和管理功能。
   3. **【条件】**：只有在功能开关、外部账号、AI 模型或对应测试数据准备好时执行；未准备好时记录“未验证”，不要直接记录为通过。
   4. **【异常】**：专门验证输入错误、网络异常、空数据或取消操作。

### 1.2 名词说明

| 词语 | 简单解释 |
| --- | --- |
| 项目根目录 | OneFlow 代码最外层的文件夹，里面能看到 `package.json`、`packages/` 和 `scripts/`。 |
| 创作端 | 用来注册、创建项目、编辑和发布的页面。 |
| 浏览端 | 用来查看已发布项目的页面，一般不要求登录。 |
| 服务 | 支撑网页运行的后台程序；服务未启动时，网页可能打不开或一直加载。 |
| 配置 | 决定页面或项目如何显示、运行的设置，例如页面尺寸、颜色或默认值。 |
| 预览 | 在正式发布前查看当前编辑结果。预览内容不一定已经对外可见。 |
| 发布 | 把当前编辑内容变成浏览端可以看到的版本。 |
| 自动保存 | 系统会在修改后自动保存内容，看到“已自动保存”后再刷新页面。 |
| 命名版本 | 你主动保存的一份可识别的历史版本，之后可以查看或恢复。 |
| 白板草稿 | 在配置图片白板里正在编辑、但还没有替换当前配置图片的内容。 |
| 回填图片 | 把白板内容生成一张图片，并替换当前配置图片；回填成功前，原图片不应改变。 |
| 白板 Studio | 独立的白板工作台，只用于检查绘图工具，不连接项目数据，也不负责保存项目图片。 |
| 未验证 | 本次没有条件或没有时间检查，不等于通过，也不等于失败。 |

## 二、验收范围和页面地图

1. **主流程【必测】**：
   1. 启动服务。
   2. 注册或登录创作端。
   3. 进入项目首页。
   4. 新建一个空白项目。
   5. 新建页面并打开编辑页。
   6. 预览页面并修改配置。
   7. 检查自动保存和刷新后数据是否还在。
   8. 保存命名版本并恢复一次历史版本。
   9. 发布项目。
   10. 从分享链接或浏览端打开项目。
   11. 在浏览端检查页面、配置、画布和文档展示。
   12. 撤销发布，再确认浏览端是否不再展示。
2. **创作端页面清单**：

   | 页面 | 地址示例 | 主要验收内容 |
   | --- | --- | --- |
   | 登录 | `/login` | 登录成功、失败提示、跳转 |
   | 注册 | `/register` | 用户名、密码、重复注册、自动登录 |
   | 忘记密码 | `/forgot-password` | 提示联系管理员，不误导为自助找回 |
   | 项目首页 | `/` | 项目列表、搜索、分类、模板、项目操作 |
   | 项目编辑 | `/demo/{项目ID}/edit` | 页面树、代码、AI、配置、预览、保存 |
   | 配置图片白板 | 从项目编辑页的图片配置入口打开 | 绘图、多选/组合、颜色与文字样式、代码导入/导出、回填、重新打开 |
   | 项目内预览 | `/viewer/{项目ID}` 或 `/viewer/{项目ID}/{页面ID}` | 单页、画布、文档、配置、评论 |
   | 嵌入页 | `/embed/{项目ID}` | 嵌入代码、预览、发布条件 |
   | 反馈 | `/feedback` | 查看、筛选、提交、处理反馈 |
   | 设置 | 从项目首页右上角“设置”进入 | 密码、AI 模型、外部账号、退出 |
   | 管理后台 | `/admin?secret=管理员密钥` | 模型、供应商、用户管理 |
   | Figma 插件 | `/figma-plugin` | 页面能否打开，授权功能按条件验收 |
   | CLI 使用页 | `/cli` | 命令行工具的说明和入口能否打开 |
   | 意见/愿望页 | `/wish` | 页面加载和提交入口 |
   | 探索页 | `/explore` | 页面加载、跳转和空状态 |
   | 预览自检页 | `/demo-test` | 仅用于开发自检，非主业务流程 |

3. **独立服务页面**：
   1. 独立浏览端：`http://localhost:4300`。
   2. 白板 Studio：`http://localhost:3400`，用于检查白板编辑器本身；纳入本次范围时再验收。
   3. 手绘页面如纳入范围，请按其专项说明验收，不要用白板 Studio 代替。
   4. 创作端内的 `/viewer/...` 与独立浏览端不是同一入口，均需验证。

## 三、验收前准备

1. 准备一个**普通测试账号**：
   1. 用户名建议使用 `acceptance_日期_姓名`，总长度 3～20 个字符。
   2. 用户名只使用英文字母、数字和下划线。
   3. 密码至少 6 个字符。
   4. 不要把真实客户数据、真实密码或生产密钥放入测试项目。
2. 准备第二个普通测试账号，用于两个人同时打开同一个项目，检查协作效果。
3. 如需验收管理员功能，提前向项目负责人获取管理员入口和临时管理员密钥；不要把密钥写进截图、工单或本文档。
4. 另建测试项目用于删除、恢复和异常操作，避免误删重要项目。
5. 准备以下测试文件：
   1. 一张正常的 JPG、PNG 或 WebP 图片，大小不超过 5MB，用于上传封面和图片配置。
   2. 一个超过 5MB 的图片，用于检查大小限制。
   3. 一个非图片文件，用于检查错误提示。
   4. 一个正常的 HTML 文件、一个空 HTML 文件和一个内容不完整的 HTML 文件，用于导入页面。
   5. 一份 Markdown 文档，用于知识文档和文档模式。
   6. 一份文本、JSON、CSV、PDF 或 DOCX 文件，用于 AI 附件；本期不测试 XLSX。
6. 如需验收 AI，先配置模型、接口地址和密钥；未配置时记录“未验证”或“服务不可用提示”，不要判为普通页面缺陷。
7. 如本次范围包含配置图片白板，提前确认：
   1. 至少有一个可编辑页面，包含标准单图配置项（图片字段）；如要检查图片列表，再准备一个包含多张字符串图片的图片列表配置项。
   2. 准备一张图片配置测试图，先完成一次白板回填，再重新打开同一字段检查画稿是否恢复；如要检查多选、对齐和分布，再准备至少三个可编辑图形。
   3. 本期只检查标准单图和图片列表的当前项；嵌套对象、变体字段、视频封面等不在范围内。
8. 建议使用以下测试窗口：
   1. 浏览器 A：普通账号 1。
   2. 浏览器 B 的无痕窗口：普通账号 2，或未登录用户。
   3. 管理员验收时，使用单独窗口，避免管理员登录状态影响普通用户验收。

## 四、启动方式

启动成功后，从第五章开始验收业务功能。

本手册使用**本地开发模式**：创作端 `4200`、独立浏览端 `4300`、白板 Studio `3400`。

### 4.1 确认代码分支和项目根目录

1. 用代码编辑器打开要验收的 OneFlow 代码，并确认当前分支正确。
2. 在**项目根目录**打开终端。
3. 项目根目录应该能看到以下内容：
   1. `package.json`
   2. `packages/`
   3. `scripts/`
4. 不要在只有 `.next` 缓存、某个 `packages/` 子目录或其他临时文件的文件夹中启动。
5. 如果终端已经位于仓库内的任意子目录，可以用下面的命令查看项目根目录：

   ```bash
   git rev-parse --show-toplevel
   ```

   如果命令报错，说明当前终端不在 OneFlow 仓库内，请回到第 2 步。
6. 记录当前分支和本地修改状态：

   ```bash
   git branch --show-current
   git status --short
   ```

   如果 `git status --short` 有输出，表示存在未提交修改；可以继续验收，但要在记录中说明。

### 4.2 本地开发模式

1. 检查 Node.js 版本：

   ```bash
   node -v
   ```

   项目要求 Node.js 24.x（低于 25）。如果已是 24.x，继续执行；否则先参阅本节启动步骤后的“Node 版本异常补充”，切换完成后再回来。
2. 检查 pnpm：

   ```bash
   corepack pnpm -v
   ```

   项目使用 pnpm 8.15.0。第一次使用 Corepack 时，按终端提示完成启用即可。
3. 如果项目根目录没有 `.env`，把 `.env.example` 复制为 `.env`，再填写项目负责人提供的本地配置。不要把真实生产密钥复制到本地测试环境。
4. 安装依赖：

   ```bash
   corepack pnpm install
   ```

5. 启动完整本地服务：

   ```bash
   corepack pnpm dev
   ```

   这个命令会启动创作端、AI/项目服务、截图服务、浏览端、知识服务和白板 Studio。第一次启动可能需要等待页面编译；终端持续出现服务日志是正常现象。

   > **Node 版本异常补充（仅特定环境需要，不是每个人都需要执行）**
   >
   > 如果前面的 `node -v` 已经显示 24.x，请跳过这一段。只有当本机显示 22.x 或其他非 24.x，或者启动时报 `better-sqlite3` 原生模块版本不匹配时，才需要执行以下处理：
   >
   > 1. 如果刚才启动失败，回到运行服务的终端按 `Ctrl + C`。
   > 2. 优先使用 nvm 切换到项目要求的版本：
   >
   >    ```bash
   >    nvm use 24
   >    node -v
   >    ```
   >
   > 3. 如果当前终端没有加载 nvm，或者本机没有使用 nvm 管理 Node，可将本机 Node 24 的 `bin` 目录临时放到 `PATH` 最前面，再刷新 shell 的命令缓存：
   >
   >    ```bash
   >    export PATH="/path/to/node-v24/bin:$PATH"
   >    hash -r
   >    node -v
   >    ```
   >
   >    将 `/path/to/node-v24/bin` 替换为本机实际的 Node 24 安装目录；确认最终输出为 24.x。
   > 4. 切换完成后，回到上面的启动步骤，再执行 `corepack pnpm dev`。

6. 本地开发模式地址如下：

   | 服务 | 地址 | 用途 |
   | --- | --- | --- |
   | 创作端 | `http://localhost:4200` | 注册、登录、项目、编辑和管理 |
   | AI/项目服务 | `http://localhost:4201` | AI、项目数据和同步 |
   | 截图服务 | `http://localhost:4202` | 封面、缩略图和截图 |
   | 独立浏览端 | `http://localhost:4300` | 未登录浏览、项目展示 |
   | 知识服务 | `http://localhost:4203` | 知识文档服务，验收时不直接打开 |
   | 白板 Studio | `http://localhost:3400` | 独立白板编辑器，按条件验收 |
7. 打开 `http://localhost:4200/login` 和 `http://localhost:4300`，确认登录页和浏览端首页能显示。
8. 如果页面显示旧内容、一直转圈或编译报错，停止当前服务后执行修复启动：

   ```bash
   corepack pnpm dev:repair
   ```

   `dev:repair` 会清理本地页面缓存后重新启动；它只是启动异常时的修复命令，不是另一种验收启动方式。
9. 停止本地服务：回到运行服务的终端窗口，按 `Ctrl + C`。

### 4.3 启动问题排查

| 看到的情况 | 先做什么 | 验收记录怎么写 |
| --- | --- | --- |
| 浏览器提示无法连接 | 确认完整本地服务已经启动，并访问 `4200`、`4300` 或 `3400` | 记录地址和错误截图 |
| 登录后又回到登录页 | 确认使用本地 HTTP 配置，例如 `USE_SECURE_COOKIE=false` | 记录登录前后的地址 |
| 项目首页能打开，但浏览端没有项目 | 确认项目已发布，且两个页面使用同一组端口 | 记录创作端和浏览端地址 |
| AI 一直等待或连接失败 | 检查模型、接口地址和密钥是否已配置；未配置就记录“未验证” | 不要重复点击，记录等待时长和提示 |
| 封面或缩略图为空 | 确认截图服务已启动，并等待首次生成完成 | 记录项目名称、等待时间和页面提示 |
| 页面显示旧内容 | 停止服务后使用 `corepack pnpm dev:repair` | 记录修复前后的表现 |
| Node 原生模块版本不匹配 | 参阅本节启动步骤后的“Node 版本异常补充”，仅特定环境需要 | 记录 Node 版本和错误提示 |
| 端口被占用 | 先确认占用者属于本项目，再处理；不要随意结束系统进程 | 记录端口和处理结果 |

## 五、主流程：注册到浏览端【必测】

### 5.1 注册、登录和退出

1. 在浏览器打开创作端登录页：`http://localhost:4200/login`。
2. 点击“注册”或直接打开 `/register`。
3. 不填写任何内容直接提交，确认页面对必填项有清楚提示，且不会提交成功。
4. 输入过短用户名，例如 2 个字符，提交后确认提示用户名长度不符合要求。
5. 输入包含空格、中文或特殊符号的用户名，确认页面提示格式不符合要求。
6. 输入少于 6 个字符的密码，确认页面提示密码太短。
7. 输入符合要求的测试用户名和密码，提交注册。
8. 注册成功后确认：
   1. 自动进入项目首页，或出现明确的成功提示和进入首页按钮。
   2. 页面右上角能看到当前用户名或用户入口。
   3. 刷新页面后仍处于登录状态。
9. 退出登录，再用刚注册的账号登录。
10. 输入错误密码，确认提示能说明登录失败，但不要泄露“用户名是否存在”等额外信息。
11. 在用户名首尾加入空格后登录，确认系统能正常处理首尾空格，或给出明确提示。
12. 未登录时直接打开一个真实的需要登录页面，例如 `/demo/{项目ID}/edit`，确认会回到登录页；登录后确认能回到原页面或首页。
13. 已登录状态下再次打开 `/login`、`/register`，确认不会重复进入注册或登录表单，而是回到项目首页或给出合理跳转。
14. 打开 `/forgot-password`，确认页面明确说明需要联系管理员，不显示不存在的自助找回流程。
15. 点击退出登录，确认：
   1. 当前窗口回到登录页或公开页面。
   2. 刷新后仍未登录。
   3. 另一个浏览器窗口中的登录状态不应被无故退出。

### 5.2 项目首页：搜索、分类和新建项目

1. 登录后进入项目首页，检查页面是否完整加载：
   1. 顶部品牌和当前用户入口显示正常。
   2. 能看到“Figma 插件”“浏览端”“CLI”“反馈”“设置”等入口；入口因功能开关隐藏时，记录为版本差异。
   3. 左侧有“全部项目”和分类区域。
   4. 页面有“全部”和“模板”等筛选入口。
2. 在没有任何项目时检查空状态：
   1. 页面不会无限转圈。
   2. 有清楚的“新建项目”或“空白项目”入口。
   3. 页面没有显示其他用户或不属于当前账号的项目。
3. 点击“空白项目”，检查创建弹窗：
   1. 项目名称为空时不能提交，或有清晰提示。
   2. 选择已有分类后可以提交。
   3. 输入名称并按回车，确认回车行为与点击确认按钮一致。
   4. 关闭后重新打开，检查未保存内容的处理是否符合约定。
4. 创建名称为“人工验收主流程”的空白项目。
5. 创建成功后确认：
   1. 自动进入项目编辑页，或回到项目首页并能找到新项目。
   2. 不应自动出现示例页面。
   3. 项目名称、分类和更新时间正确。
6. 回到项目首页，检查列表：
   1. 新项目显示在预期位置。
   2. 卡片可以看到项目名称、分类、更新时间和封面占位图或缩略图。
   3. 点击卡片主体能进入编辑页。
   4. 点击卡片上的菜单时不会误进入编辑页。
7. 使用搜索框搜索完整项目名称，再搜索其中一部分，确认能找到对应项目。
8. 搜索一个不存在的名称，确认有明确的“没有找到”或空状态。
9. 清空搜索条件，确认项目列表恢复。
10. 点击分类和子分类，确认项目筛选结果只显示当前分类下的项目。
11. 创建一个自定义分类：
    1. 选择“自定义分类”。
    2. 输入例如 `APP资源位/弹窗` 的层级分类。
    3. 检查分类树层级正确。
    4. 输入空层级、连续斜杠或只有空格，确认不能保存或有明确提示。
12. 点击“模板”筛选，确认只显示模板项目；再切回“全部”，确认普通项目重新显示。

### 5.3 项目卡片的操作菜单

1. 在项目卡片上打开更多菜单，逐项检查以下操作是否存在且名称易懂：
   1. “分享”。
   2. “修改名称”。
   3. “修改分类”。
   4. “修改封面”。
   5. 普通项目显示“设为模板”。
   6. 模板项目显示“转为普通项目”。
   7. “复制当前项目”。
   8. “删除”。
2. 选择“修改名称”，输入新名称并保存，确认列表卡片和编辑页标题都更新。
3. 选择“修改分类”，切换已有分类并保存，确认筛选和卡片信息同步更新。
4. 选择“修改封面”：
   1. 上传正常 JPG、PNG 或 WebP，确认上传成功并显示新封面。
   2. 上传超过 5MB 的图片，确认拒绝并说明原因。
   3. 上传非图片文件，确认拒绝并说明支持的格式。
   4. 关闭弹窗后重新打开，确认已保存的封面仍在。
   5. 选择删除封面或恢复默认缩略图，确认操作前有清楚提示，操作后卡片显示默认封面。
5. 选择“设为模板”：
   1. 检查模板弹窗需要填写分类、名称和描述。
   2. 缺少必填内容时不能保存。
   3. 保存后项目变成模板，但项目 ID 和已有内容不应改变。
   4. 模板仍可以编辑和发布。
6. 对模板执行“转为普通项目”，确认模板标识消失，普通项目操作重新出现。
7. 选择“复制当前项目”：
   1. 输入新项目名称和分类。
   2. 提交后出现一个独立的新项目。
   3. 修改复制后的项目，不应影响原项目。
   4. 复制项目按约定保留原项目的页面、配置和资源。
8. 选择“删除”：
   1. 先取消删除，确认项目仍然存在。
   2. 再次删除，按要求输入项目名称或确认文字。
   3. 确认删除后，列表移除该项目且不会自动跳到错误页面。
   4. 刷新列表，确认项目没有重新出现。
   5. 如果产品支持恢复，记录恢复入口；如果不支持，不要尝试删除重要项目。

### 5.4 编辑页首次进入和基础状态

1. 从项目卡片进入“人工验收主流程”的编辑页。
2. 检查首次进入状态：
   1. 加载中有明确反馈，页面不会静止不动。
   2. 加载成功后能看到编辑页面主要区域。
   3. 加载失败时有原因和重试入口。
3. 检查编辑页顶部：
   1. 项目名称正确。
   2. 当前页面和模式清楚。
   3. 能看到保存状态，例如同步中、已自动保存、离线或保存失败。
   4. 能找到分享、发布、历史版本或相关入口。
4. 检查编辑页主要区域：
   1. 左侧页面树或“页面”区域。
   2. 中间预览区域。
   3. 右侧配置、评论或属性区域。
   4. “代码”“AI 对话”等工作区域；如按标签切换，逐个切换检查。
5. 不修改内容，先刷新页面，确认项目仍能打开，且不会自动生成重复页面或会话。
6. 新建第二个浏览器窗口打开同一个项目，确认能看到正确的项目内容；有协作提示或当前用户信息时，一并记录。

### 5.5 页面列表：新建、切换、复制、移动、删除

1. 点击编辑页左侧的“页面”标签，确认标题或区域名称清楚。
2. 如果是空白项目，确认页面列表有明确的“暂无页面”空状态，并能看到“添加”入口。
3. 点击“添加”，逐项检查可见选项：
   1. “添加页面”。
   2. “添加文件夹”。
   3. “从 Figma 导入”。
   4. “添加手绘页面”仅在相关功能开关打开时出现；未打开时不应因为缺少该项而阻塞普通页面验收。
4. 点击“添加页面”，输入页面名称“首页”，保存后确认：
   1. 页面出现在列表中。
   2. 新页面自动成为当前页面，或有明确的选中状态。
   3. 中间预览区域不再显示无页面空状态。
5. 再添加“详情页”，确认两个页面都存在。
6. 点击“首页”和“详情页”来回切换，确认：
   1. 当前页面有清楚的高亮或“当前”标识。
   2. 页面内容随选择变化。
   3. 切换过程中有加载提示，但不会长期卡住。
7. 在单页预览中检查上一页、下一页按钮：
   1. 第一页点击上一页不会越界或报错。
   2. 最后一页点击下一页不会越界或报错。
   3. 方向键可以切换页面。
   4. 在输入框中输入文字时，方向键不会误切换页面。
8. 双击页面名称，输入新名称后回车，确认名称更新；按取消或点击页面外时，确认不会保存不完整名称。
9. 打开页面菜单，逐项检查：
   1. “重命名”。
   2. “移动到”。
   3. “复制页面”。
   4. 如果开启转换功能，检查“AI 转高保真页”或“AI 转 HTML/CSS 原型”。
   5. “删除页面”。
10. 复制“首页”，确认出现独立副本；修改副本后，原“首页”不受影响。
11. 将页面移动到其他文件夹，再移回根目录，确认位置和页面内容都正确。
12. 删除一个测试页面：
    1. 先取消确认，确认页面仍在。
    2. 再次删除并确认，确认页面从列表消失。
    3. 如果该页面是当前页面，确认系统自动切到合理的其他页面或显示空状态。
13. 点击“添加文件夹”，创建“营销页面”文件夹。
14. 在文件夹中创建子文件夹，确认展开、收起、选中和页面移动都正常。
15. 尝试超过产品允许的文件夹层级，确认系统给出清楚提示，不会让页面消失。
16. 尝试把文件夹拖入自己或自己的子文件夹，确认系统阻止循环移动。
17. 在文件夹菜单中检查：
    1. “重命名”。
    2. “新建子文件夹”。
    3. “删除文件夹（页面移至上级）”。
    4. “删除文件夹及内容”。
18. 使用“删除文件夹（页面移至上级）”，确认文件夹删除但页面保留。
19. 对只包含测试内容的文件夹使用“删除文件夹及内容”：
    1. 先取消，确认文件夹和内容仍在。
    2. 再确认删除，确认弹窗明确说明操作不可撤销。
    3. 完成后刷新，确认文件夹和内容都已按预期删除。
20. 拖动页面调整顺序，刷新后确认顺序仍然保留；如拖动不适用，使用页面菜单中的移动操作完成同等检查。

### 5.6 从 HTML 导入页面【专项】

1. 在“页面”区域点击“添加”，进入 HTML 导入入口；界面可能显示“从 Figma 导入”或“导入 HTML”。
2. 检查弹窗标题、说明和关闭按钮。
3. 选择一个正常 HTML 文件，确认文件进入待导入列表。
4. 一次选择多个 HTML 文件，确认可以批量处理。
5. 选择一个非 HTML 文件，确认它被跳过或提示不支持，不影响其他正常文件。
6. 选择空 HTML 文件和内容不完整的 HTML 文件，确认每个文件有单独的成功或失败结果。
7. 导入完成后确认：
   1. 页面名称与文件名一致。
   2. 页面出现在页面树中。
   3. 可以打开并预览。
   4. 页面宽高或设计尺寸按产品要求保留。
   5. 同名且大小相同的文件重复导入时不会无限生成重复页面，或有清楚的重复提示。
8. 在导入过程中关闭弹窗，确认系统不会留下不完整的导入状态。

### 5.7 预览模式和页面大小

1. 在编辑页打开单页预览，确认页面内容可见，页面内按钮、动效和可点击区域按页面设计工作。
2. 检查预览尺寸入口，按当前页面实际显示的选项逐项检查：
   1. 手机竖屏，约 375×667。
   2. 手机横屏，约 667×375。
   3. 平板竖屏，约 768×1024。
   4. 平板横屏，约 1024×768。
   5. 桌面 100%。
   6. 自定义尺寸。
3. 每次切换尺寸后确认：
   1. 预览区域居中或按页面设计排列。
   2. 页面内容不会被错误裁切或跑到屏幕外。
   3. 重新进入页面后尺寸仍然保留。
4. 点击手动刷新，确认有“刷新中”反馈，最终进入成功、失败、取消或超时状态，不应一直转圈。
5. 有页面时，检查预览模式：
   1. “单页”：只看当前页面。
   2. “画布”：同时查看多个页面或对象。
   3. “文档”：查看知识文档或 Markdown 内容；只有存在文档时才重点验收。
6. 在单页模式右上角打开页面选择器，确认：
   1. 页面和文档分组清楚。
   2. 当前页面有明显标识。
   3. 上一页和下一页按钮与页面树选中结果一致。
   4. 从页面切到文档时，右侧不再显示页面配置编辑项。
7. 在没有任何页面的项目中确认显示“暂无页面”等清楚空状态，不应停在加载中。

### 5.8 配置面板：查看、修改、校验和恢复

1. 选择一个有配置的页面；空白项目没有配置时，使用项目提供的演示页面，没有可用配置则记录“未验证”。
2. 打开右侧配置区域，确认：
   1. 页面配置和项目共享配置的范围容易理解。
   2. 共享配置如果影响多个页面，有“影响 N 个页面”等说明。
   3. 没有配置时不显示空白的无意义面板。
   4. 配置名称、说明和当前值清楚。
3. 逐项检查当前页面实际存在的控件：
   1. 文本输入：修改文字后预览实时变化。
   2. 数字或滑块：输入最小值、最大值和小数，确认范围限制清楚。
   3. 开关：打开和关闭后状态与预览一致。
   4. 下拉选择：选择不同选项后预览变化，非法选项不可保存。
   5. 颜色：输入或选择颜色后预览正确。
   6. 图片或图片列表：上传、替换、删除和顺序调整正常。
   7. 富文本或代码：按页面说明编辑，不能把输入内容误当成普通文本。
4. 清空必填项后尝试保存，确认有明确提示并阻止保存。
5. 输入超出长度、超出范围、格式错误或不在选项内的值，确认错误提示靠近问题位置，且不会保存错误值。
6. 修改配置后确认预览在合理时间内更新，不需要手工刷新才能看到变化。
7. 如果配置支持“保存字段”或“保存并应用”，分别点击并确认：
   1. 只保存字段时，不会误修改其他配置。
   2. 保存并应用时，预览和当前页面结果都更新。
8. 检查“更多”菜单：
   1. 编辑状态下可以看到“添加配置项”。
   2. 可以看到“恢复默认”或同等入口。
   3. 浏览端不应出现添加配置项的入口。
9. 对有默认值的配置执行恢复默认：
   1. 先修改值。
   2. 点击恢复默认。
   3. 确认有清楚的变化或确认提示。
   4. 刷新页面后仍是恢复后的默认值。
10. 对支持排序的配置，使用上下箭头和拖动调整顺序，确认预览和刷新后的顺序一致。
11. 对支持位置调整的配置，拖动标记点或修改 X/Y 数值，确认位置变化、边界限制和恢复默认正常。
12. 对图片上传执行以下检查：
    1. 正常图片可以上传。
    2. 超过大小限制的图片被拒绝。
    3. 宽高不符合要求的图片出现警告，并提供“取消上传”和“继续上传”。
    4. 选择取消后旧图片保留。
    5. 选择继续后新图片按约定保存。
13. 如果页面有设计说明或设计规范入口，确认创作端可以进入文档模式，浏览端只能查看，空描述不会显示空卡片。

### 5.8.1 配置图片白板【条件】

> 白板只用于创作端的图片配置项。绘制、样式和代码导入都先保存在本地草稿中，只有“回填图片”成功后才会替换当前配置图片；取消、关闭或提交失败都不应半途改掉原图片。
>
> 配置图片白板和 Whiteboard Studio 共享同一套编辑器交互，但当前白板入口只开放“选择、抓手、矩形、圆形、文本、图片”六种创建工具；完整草图页面中的菱形、线条、箭头、画笔、便签和橡皮不属于本节白板工具范围。

1. 确认本次是否满足白板验收条件：
   1. 当前页面处于可编辑状态，并且配置中有标准单图字段（图片字段）；图片列表按本节第 13 步检查。
   2. 未满足以上条件时记录“条件不满足，未验证”，不要判为缺陷。
2. 打开右侧配置面板，找到一张图片配置项。将鼠标移到图片上，确认能看到“白板绘图”入口；普通上传入口仍然存在，不能被白板替代。
3. 点击“白板绘图”，检查白板弹窗：
   1. 标题是“配置图片白板”。
   2. 说明明确，例如“仅在‘回填图片’成功后更新当前配置”。
   3. 首次载入时有“正在载入白板…”等提示，完成后不应一直转圈。
   4. 底部能看到“尚未修改”“取消”“回填图片”和“代码导入/导出”等操作。
4. 在空白白板中检查底部工具栏：
   1. 可以使用“选择”“抓手”“矩形”“圆形”“文本”“图片”；当前白板入口不应出现菱形、线条、箭头、画笔、便签或橡皮等未开放工具。
   2. 用“矩形”或“圆形”拖出一个图形，确认图形显示在画布上；切回“选择”后可以移动、缩放、旋转或删除。
   3. 用“文本”点击画布，输入“白板验收文字”。纯文本中按回车是换行，点击画布其他位置提交；按 `Esc` 取消编辑。
   4. 确认可以抓动画布、放大、缩小、重置视图和缩放到选区；底部工具栏还可以撤销和重做，并能打开命令面板和快捷键帮助。
   5. 悬停工具按钮稍等可以看到提示，提示不会遮住主要操作。
   6. 在空白处拖动可以进行矩形框选，不会误创建图形；移动对象时会出现对齐参考线并自动吸附，不显示间距线或“网格”“边缘”“中心线”等文字。
   7. 按住 `Alt/Option` 拖动对象可以复制；按住 `Cmd/Ctrl` 拖动时可以暂时关闭吸附和参考线。
5. 检查选中对象后的悬浮工具栏、多选和组合：
   1. 没有内置文字的图形以图标显示填充、描边、层级和更多操作，悬停后再通过提示识别；填充是色块，描边是当前颜色的空心方框。
   2. 在描边颜色菜单中选择“无颜色”后，描边指示应变为浅灰色空心方框并带斜杠；填充和描边菜单都支持常用色、自定义颜色和“无颜色”。
   3. 点击“层级”可以执行置顶、上移一层、下移一层和置底；点击“更多”可以看到删除、剪切、复制、复制样式、粘贴样式和“位置与大小”。点击菜单外部或按 `Esc` 能关闭菜单。
   4. 选中对象后放大画布，确认选区边框会随画布缩放，而旋转和缩放控制点不会明显变大、变小或跑位。
   5. 创建两个图形，切换“选择”，先点击第一个，再按住 `Shift` 点击第二个。确认进入多选，悬浮工具栏显示“边框、颜色、对齐方式、组合、图层、更多”等图标按钮，不显示大段文字按钮。
   6. 在多选状态打开“边框”和“颜色”，确认仍使用同一套 10 列×6 行的常用色板（当前 60 种颜色），颜色不重复，并提供“其他颜色”；不同对象的颜色不一致时有“当前选区颜色不同”提示。
   7. 在多选状态打开“对齐方式”，确认有左对齐、水平居中、右对齐、顶对齐、垂直居中和底对齐六项；选择一项后对象按对应边缘或中心对齐，按 `Esc` 或点击菜单外部可以关闭。
   8. 创建第三个图形，在三个对象均选中的情况下打开“更多”，确认能看到“水平分布”和“垂直分布”；执行后对象间距按对应方向均匀分布。
   9. 同时选中一个图形和一个纯文本，打开“颜色”或“边框”并选择颜色，确认只修改支持该属性的图形，纯文本的文字颜色不会被误改。
   10. 点击“组合”，确认工具栏切换为“解组”，选区覆盖组合内容但不出现组级缩放或旋转控制点；点击“解组”后，原对象恢复为独立选择。
   11. 选中组合后拖动其中任一可见子对象，确认组合内可编辑对象一起移动且相对位置不变；组合中被锁定或隐藏的对象不应被拖动改变。
   12. 组合后普通点击组内子对象仍保持组选中；第一次双击进入组内子对象选择但不立即打开文字编辑，第二次双击带文字对象才进入文字编辑；在组内按 `Esc` 返回组选中状态。
   13. 组合状态下打开“图层”执行置顶、上移一层、下移一层或置底，确认整个组合按一个层级单元移动，组内相对顺序不变。
   14. 如果组合中同时包含图形和纯文本，确认工具栏不会提供批量填充或边框入口，但仍保留“解组”“图层”和“更多”。
   15. 在编辑模式右键对象，确认可以打开对象菜单，右键不会误启动拖动；点击菜单外部可以关闭，预览或只读状态不应打开该菜单。
6. 检查文字编辑和文字工具栏：
   1. 双击矩形，输入“图形文字”，按回车提交；再次双击仍可编辑。形状编辑框应为透明背景并隐藏滚动条。
   2. 选中带文字的图形或纯文本，确认能看到文字颜色、字号、加粗、斜体、下划线、对齐、层级和更多操作；图形还应保留填充和描边入口。
   3. 打开字号、文字颜色和对齐菜单，选择一个字号、颜色和居中对齐，确认文本能更新；文字颜色菜单使用与其他颜色入口相同的常用色板和“其他颜色”，但不提供“无颜色”。
   4. 把浏览器窗口缩窄，或让文字工具栏靠近左右边缘，重新打开上述菜单。确认菜单完整可见、可以点击，且不会被工具栏的横向滚动裁掉。
   5. 在文字编辑框中只选中部分文字，再修改颜色、加粗或下划线，确认只影响选中的文字；没有选区时修改整段文字。
7. 检查图片对象和图片来源：
   1. 使用“图片”工具点击或拖动画布，选择一张测试图片，确认图片能载入并可以选择、移动、缩放和删除。
   2. 双击图片，确认出现图片裁剪/适配工具，可以切换“裁切填满”“完整显示”和“拉伸填满”；图片仍保持在原对象范围内。
   3. 当前配置已有项目图片（本地上传或系统已管理的图片）时，重新打开白板，确认原图作为初始背景或素材载入。删除背景只影响草稿；未回填前关闭白板，原图应保持不变。
8. 检查代码导入/导出功能。无需编写代码，直接复制下面的最小示例：

   HTML：

   ```html
   <main data-sketch-canvas="v1" data-width="240" data-height="120"><div data-sketch-id="box" data-sketch-kind="rect"></div></main>
   ```

   CSS：

   ```css
   [data-sketch-id="box"] { left: 20px; top: 20px; width: 160px; height: 80px; background: #e2e8f0; }
   ```

   1. 点击“代码导入/导出”，确认出现“白板 HTML 代码”和“白板 CSS 代码”输入框。
   2. 粘贴上面的 HTML 和 CSS，点击“导入到白板”，确认画布出现矩形，底部状态变成“有未回填的本地修改”。
   3. 点击“复制代码”，再粘贴到文本编辑器或其他可输入位置，确认 HTML 和 CSS 内容完整；验收以实际粘贴结果为准，页面不一定显示“复制成功”提示。
   4. 输入空内容、缺少画布标记或包含脚本/不支持节点的代码作为反例，确认有易于理解的错误提示，且原白板草稿不会被清空或直接提交。
   5. 确认这里的代码只是白板内容的受限导入/导出，不会执行脚本，也不会把它当成项目页面代码运行。
9. 检查关闭和取消：
   1. 白板没有修改时点击“取消”，确认弹窗直接关闭，原图片和配置值不变。
   2. 先画一个图形或导入代码，再点击“取消”、右上角关闭、按 `Esc`，或点击遮罩外部，确认出现“放弃未回填的修改？”提示。
   3. 点击“继续编辑”，确认白板草稿还在，提示消失。
   4. 再次触发提示并点击“放弃并关闭”，确认弹窗关闭，原配置图片仍然不变，草稿没有被误写入。
10. 检查成功回填：
   1. 画出一个矩形和一段文字，点击“回填图片”。
   2. 回填期间按钮显示处理中状态，例如“正在回填…”；重复点击不会造成多次提交。
   3. 成功后白板弹窗关闭，当前配置图片变成新的白板图片，右侧预览也显示新结果。
   4. 确认新图片可以正常显示，没有破图、空白或只显示临时链接的情况。
11. 检查再次编辑和持久化：
   1. 在同一个图片配置项再次点击“白板绘图”，确认刚才的图形和文字仍然存在，不是重新打开空白白板。
   2. 检查画布缩放或位置是否恢复，主要内容仍可见。
   3. 再关闭编辑页、重新进入项目并刷新，确认图片配置和白板画稿都仍然存在。
   4. 确认白板操作没有改变页面画布、代码文件或其他配置项。
12. 检查回填失败和异常提示【条件】：如能在可恢复的测试项目中安全制造网络中断、权限拒绝或提交失败，执行一次：
    1. 确认提示说明失败原因，并提供重试或刷新最新版本的方式。
    2. 确认白板弹窗和本地草稿仍然保留，可以继续编辑或重试。
    3. 确认原配置图片和已发布预览没有被半途替换。
    4. 如果无法安全制造失败，不要为了测试破坏网络；记录“未验证”即可。
13. 检查图片列表：
    1. 找到包含多张图片的图片列表，确认每项的操作入口都能看到“白板绘图”。
    2. 对第二张图片打开白板并回填，确认只替换第二张，第一张和其他图片不变。
    3. 白板打开期间，在另一个窗口对同一列表进行排序、删除或替换，再回到白板提交，确认系统拒绝可能覆盖错误项的提交，并提示刷新或重试；不得无提示地写入错误位置。
14. 检查范围和权限边界：
    1. 在浏览端、项目内只读预览或只读配置中，确认没有“白板绘图”“回填图片”或代码导入入口。
    2. 对文件、视频、普通字符串、嵌套对象、变体字段和视频封面，不因没有白板入口判定为缺陷；这些不在本期标准单图和图片列表当前项的范围内。
    3. 浏览端只能看到回填后的最终图片，不应看到白板编辑器、白板代码、草稿或内部 AI 操作记录。

### 5.9 可视化选择和属性调整【条件】

1. 在编辑模式点击顶部“选择”或可视化编辑入口。
2. 点击预览中的文字、图片、按钮和容器，确认被选中时有清楚边框或提示。
3. 打开左侧视觉层级抽屉，检查：
   1. 层级与页面内容对应。
   2. 点击层级可以定位到预览元素。
   3. 键盘可以在层级之间移动。
4. 打开右侧属性面板，按当前页面实际提供的分组检查：
   1. 位置。
   2. 布局。
   3. 外观。
   4. 图片。
   5. 文字。
   6. 背景、边框、链接、阴影、模糊。
5. 点击属性名称或“添加配置”入口，确认能把属性变成可配置项，并且名称、说明和默认值清楚。
6. 修改一个属性后点击取消，确认预览恢复修改前的状态。
7. 修改一个属性后点击发送给 AI，确认页面显示正在处理、成功或失败的明确状态。
8. 如果页面没有可选择元素，确认有友好的提示，而不是空白面板。

### 5.10 画布模式【条件】

1. 切换到“画布”模式，确认首次进入会自动把页面放入可见范围。
2. 使用画布拖动、放大、缩小、适应屏幕和重置视图，确认操作不会让内容永久消失。
3. 离开画布再回来，确认视图位置仍然保留。
4. 点击画布中的页面，确认：
   1. 被选中页面有边框。
   2. 右侧预览显示当前页面真实内容。
   3. 页面树、画布选择和预览当前页面一致。
5. 移动和调整页面大小，确认拖动范围合理，刷新后位置仍然保留。
6. 使用自动排列，确认页面不重叠或跑出画布范围。
7. 通过拖入、工具或粘贴方式添加以下对象（以当前页面支持的入口为准）：
   1. Markdown 文档。
   2. 图片。
   3. 文本对象。
8. 检查文本对象：
   1. 新建后不会强制出现不需要的默认文字。
   2. 不会强制出现白色背景遮挡画布。
   3. 文本可以编辑、移动和删除。
9. 合并文档或页面为组，确认这只是画布上的视觉组织，不会改变页面树中的真实页面数据。
10. 检查右侧标签：
    1. 有配置时应能看到“配置”和“评论”。
    2. 没有配置时至少能看到评论，不应出现无法操作的空标签。
11. 添加或查看画布评论，确认评论对象、内容和位置对应正确。

### 5.11 文档模式和知识文档【条件】

1. 在编辑页打开文档模式或知识库入口。
2. 确认左侧文档列表可以看到已有文档，文档名称清楚。
3. 打开一份 Markdown 文档，确认标题、段落、列表、链接和图片显示正常。
4. 编辑文档并保存，关闭后重新打开，确认内容仍在。
5. 在画布中打开同一份文档，确认画布文档和文档模式使用同一份内容。
6. 折叠、展开或移动文档对象，确认不会改变文档正文。
7. 删除文档前取消一次，确认文档仍在；再对测试文档确认删除，刷新后不再出现。
8. 确认 AI 可以读取知识文档（如果 AI 已配置），但不能未经确认写入、删除知识文档。
9. 发布项目后，确认用户文档可以在浏览端查看；AI 的内部记忆或聊天记录不应被当成用户文档发布。

### 5.12 代码、文件和聊天附件区域

1. 打开“代码”标签或代码文件区域，确认项目文件能够加载。
2. 点击一个代码文件，确认内容能查看，编辑权限按当前角色设计生效。
3. 修改一处简单内容并等待保存状态变成已保存，刷新页面后确认内容仍在。
4. 检查文件树的展开、折叠和当前文件高亮。
5. 打开“聊天文件”或其他附件区域，确认 AI 聊天中上传的附件能看到名称、大小和类型。
6. 打开一个文本附件，确认可以查看但不会写入项目源文件。
7. 打开图片附件，确认可以预览原图或看到明确的图片处理入口。
8. 使用“转为知识文件”后，确认附件进入知识文档区域；使用删除后，确认附件从聊天文件区消失。
9. 上传不支持的附件，确认页面说明“不支持的文件类型”或其他明确原因；不要只显示无反应。

### 5.13 AI 对话【条件】

1. 确认 AI 服务和模型已配置，打开编辑页的“AI 对话”标签。
2. 检查初始状态：
   1. 没有历史消息时显示清楚的空状态和输入框。
   2. 当前模型名称可见，模型选择器可以打开。
   3. 添加附件的入口能看到“添加图片”和“添加附件”等选项。
3. 输入一个简单问题并发送，确认：
   1. 消息出现在对话中。
   2. 回复可以逐步出现，或页面有明确的处理中状态。
   3. 最终状态不应停留在“处理中”。
4. 继续追问同一问题，确认 AI 能使用当前对话上下文。
5. 新建一个对话，确认：
   1. 只是新建 AI 对话，不会清空代码、页面、配置或当前工作区。
   2. 新对话能单独查看消息。
6. 切换历史对话，确认只切换消息和上下文，不会把页面切回旧版本。
7. 对历史对话检查：
   1. 时间、消息数量和标题信息清楚。
   2. 过期对话显示不可用原因。
   3. 删除对话前有确认或可撤销提示。
8. 发送消息后，在 AI 回复期间再发送第二条，确认：
   1. 第二条进入等待队列或有清楚说明。
   2. 可以取消尚未执行的消息。
   3. 执行顺序不会错乱。
9. 如果出现选择题或操作计划卡片，逐项检查：
   1. 选项文字完整。
   2. 可以确认、修改、取消或选择其他方案。
   3. 新问题不会误执行上一张还未确认的卡片。
10. 对可能删除内容、覆盖页面或修改大量文件的操作，确认 AI 会先要求确认，而不是直接执行。
11. 上传测试附件：
    1. 图片：确认显示文件名和大小；多模态模型不可用时，应显示可理解的图片描述或能力限制提示。
    2. 文本、Markdown、JSON、CSV、PDF、DOCX：确认可以添加并在消息中显示。
    3. XLSX：确认页面提示不支持，或该格式不在支持列表中。
    4. 过大的文件和不支持的文件类型应明确报错。
12. 用 AI 对测试页面提出一个简单、可见且容易撤销的修改，例如增加一段页面文字或一个配置项。
13. 确认 AI 只有在以下全部完成后才显示成功：
    1. 文件已实际修改。
    2. 修改已写入当前工作区。
    3. 预览可以读到新内容。
    4. 刷新或另一个浏览器窗口能看到新内容。
14. 如果 AI 返回失败或超时，确认提示说明原因，并有重试入口；不能显示“成功”但页面没有变化。
15. 如果浏览端已开启 AI，进入 AI 并确认：
    1. 只允许提问和查看。
    2. 不出现修改、删除、发布或配置写入按钮。
    3. 询问“请帮我改页面”时，会明确说明浏览端只支持查看，不能修改。
16. 白板 AI 工具目前不属于普通白板验收项。只有项目负责人明确说明 AI 草稿交接、撤销/确认和“回填图片”闭环已完成，并提供可操作入口时才检查；不要自行打开 `PI_AGENT_WHITEBOARD_TOOLS_ENABLED=true`。具备完整联调条件时，确认 AI 建议先以草稿或待确认方式出现，不能绕过“回填图片”直接修改配置；否则记录“未验证”。

### 5.14 自动保存、刷新和协作【必测；协作按条件】

1. 在测试项目中依次修改以下内容，每次修改后等待保存状态变化：
   1. 页面名称。
   2. 页面顺序。
   3. 页面配置。
   4. 代码或页面内容。
   5. 画布位置或大小。
   6. 知识文档内容。
2. 每次修改都检查顶部状态是否从同步中变为已自动保存；如果失败或离线，提示必须清楚。
3. 等待页面明确显示已经保存后刷新浏览器，确认所有修改仍在。
4. 关闭编辑页再重新进入，确认打开的是最后一次已同步的内容。
5. 在修改后马上离开页面：
   1. 如果还有同步风险，应看到离开提示。
   2. 如果已经同步完成，不应仅因为没有创建命名版本而反复拦截离开。
   3. 选择取消离开，确认仍留在编辑页。
   4. 选择确认离开，重新进入后确认已保存内容没有丢失。
6. 检查网络异常【条件】：
   1. 确认测试项目可恢复后，临时停止 AI/项目服务或断开网络。
   2. 修改一处测试内容，确认页面显示离线或保存失败，不应伪装成已保存。
   3. 恢复服务或网络，确认可以重试并最终保存。
7. 两个浏览器窗口同时打开同一项目同一页面：
   1. 窗口 A 修改文字，窗口 B 等待片刻，确认可以看到最新内容或收到同步提示。
   2. 窗口 B 修改另一处内容，确认窗口 A 不会无提示地覆盖掉对方内容。
   3. 观察在线用户或协作者提示，加入和离开状态应合理变化。
   4. 如果产生冲突，提示应能让普通用户理解，并提供保留、重试或刷新等处理方式。
8. 确认旧的自动保存或 AI 结果不会把较新的内容覆盖掉。

### 5.15 历史版本、命名版本和恢复

1. 打开历史版本入口，确认列表按最新时间排列。
2. 检查历史记录是否能区分：
   1. 自动保存。
   2. 命名版本。
   3. 发布版本。
   4. 恢复版本。
3. 点击保存命名版本，输入“人工验收版本一”，确认保存后列表出现该记录。
4. 继续修改页面，再保存“人工验收版本二”。
5. 打开“人工验收版本一”的预览，确认：
   1. 页面内容是版本一，而不是最新内容。
   2. 可以查看页面或代码信息。
   3. 预览页有“页面版本预览”等只读提示。
   4. 关闭预览后不会误恢复版本。
6. 选择恢复版本一，先取消确认，确认当前内容不变。
7. 再次选择恢复并确认，确认：
   1. 当前工作区切换为版本一内容。
   2. 系统新增一条“恢复”记录，而不是删除历史记录。
   3. 版本二仍然可以在历史列表中找到。
   4. 刷新页面后恢复结果仍在。
8. 历史记录较多时，检查列表展示、滚动和最新记录；超过默认上限 50 条时，确认处理符合说明。

### 5.16 发布、分享和撤销发布【必测】

1. 发布前确认最近一次修改已同步完成。
2. 点击“发布”，确认页面展示发布中的状态，不要连续点击。
3. 发布成功后确认：
   1. 有明确的成功提示或发布状态。
   2. 生成或更新发布版本。
   3. 分享弹窗中的浏览链接可以正常打开。
   4. 没有修改时，发布按钮显示“已发布”或不可重复发布。
4. 打开“分享”弹窗，检查两个标签：
   1. “编辑链接”：只能给有编辑权限的人使用。
   2. “浏览链接”：给普通浏览者使用。
5. 在未发布的测试项目中打开分享弹窗，确认浏览链接不可用，并提示需要先发布。
6. 点击复制链接，分别在当前浏览器和新的无痕窗口粘贴，确认链接完整且能打开。
7. 打开浏览链接，确认未登录用户可以查看已发布内容。
8. 回到创作端修改一个配置，再发布一次，确认浏览端展示的是新发布结果，而不是旧缓存。
9. 打开发布菜单，选择“撤销发布”或同等入口：
   1. 取消撤销，确认项目仍可浏览。
   2. 确认撤销后，创作端显示未发布状态。
   3. 独立浏览端项目列表移除该项目，或打开旧链接时显示不可用；按产品约定执行。
10. 撤销发布后重新发布一次，确认项目可以重新出现在浏览端，且原来的编辑数据没有丢失。

### 5.17 独立浏览端：未登录浏览、项目详情和配置【必测】

1. 打开独立浏览端：`http://localhost:4300`。
2. 未登录访问首页，确认不强制跳到登录页。
3. 检查浏览端首页：
   1. 只显示已发布项目。
   2. 项目卡片有封面、名称和更新时间等基本信息。
   3. 未发布项目不应出现在列表中。
   4. 没有项目时有清楚空状态。
   5. 加载失败时有错误提示和重试入口。
4. 使用搜索框搜索项目名称的一部分，确认能找到项目；搜索不存在内容时确认有无结果提示。
5. 切换排序：
   1. 最新在前。
   2. 最旧在前。
   3. 按名称排序；中文名称顺序要稳定。
6. 点击项目卡片进入详情页，确认：
   1. 左侧或顶部有返回项目列表入口。
   2. 项目名称正确。
   3. 登录状态和登录入口显示合理。
   4. 默认进入画布模式；如果没有画布数据，仍能看到清楚的页面内容。
7. 在详情页切换单页、画布和文档模式，确认只有存在相应内容时才显示对应入口。
8. 在画布模式检查：
   1. 页面选择与预览内容一致。
   2. 放大、缩小、拖动画布和适应屏幕正常。
   3. 右侧“配置”和“评论”标签正常。
   4. 用户只能查看和调整当前浏览会话中的值，不能新增配置、修改项目源文件或发布。
9. 在单页模式检查：
   1. 页面目录可以切换页面。
   2. 上一页、下一页和方向键在边界处不会越界。
   3. 页面内按钮、链接和动效按发布结果正常工作。
   4. 发布时的默认配置正确显示。
10. 修改浏览端的图片或配置，刷新浏览器后确认：
    1. 如果产品规定为临时调整，刷新后恢复发布时的默认值。
    2. 不会影响创作端项目数据。
    3. 不会影响其他浏览者的默认展示。
11. 在有知识文档时打开文档模式，确认：
    1. Markdown 展示正常。
    2. 文档只读，不能出现编辑、添加或删除入口。
    3. 只显示发布的用户文档，不显示 AI 内部记忆或聊天记录。
12. 如果浏览端有 AI 入口：
    1. 入口位于左下角或产品规定的位置。
    2. 打开面板后不会遮挡全部页面，页面仍然清晰可用。
    3. 可以提问、查看流式回答、重试、选择模型和添加允许的附件。
    4. 刷新或重新进入后创建新的浏览会话；浏览历史按约定保存在当前项目和浏览器范围内。
    5. 从项目 A 切换到项目 B，不能把 A 的聊天内容或项目数据带到 B。
    6. 询问修改页面时，AI 明确拒绝写入操作。
13. 点击浏览端登录入口，确认能进入创作端登录页或产品规定的登录页面。

## 六、页面专项验收

### 6.1 设置页面

1. 在项目首页点击“设置”。
2. 确认当前账号信息显示正确。
3. 修改密码：
   1. 新密码少于 6 个字符时不能保存。
   2. 两次密码不一致时不能保存。
   3. 使用正常新密码保存后有成功提示。
   4. 退出并使用新密码登录成功。
   5. 旧密码不能继续登录。
4. 打开 AI 模型设置：
   1. 供应商名称、接口地址、密钥和模型列表字段说明清楚。
   2. 密钥默认隐藏，不能直接明文展示。
   3. 模型列表按“一行一个模型”填写时能被识别。
   4. 设置默认模型时只能选择已有模型，或给出清楚提示。
   5. 清除个人配置后，恢复平台默认配置。
   6. 输入错误配置后，页面显示可理解的保存或连接失败提示。
5. 打开外部账号授权区域，检查 Figma、钉钉等入口是否按本环境配置显示。
6. 未配置外部账号时，应明确说明暂不可用，不应出现空白按钮。
7. 关闭设置弹窗后重新打开，确认已保存内容仍在。
8. 点击退出登录，再确认登录页和会话状态正常。

### 6.2 反馈页面

1. 从创作端顶部打开“反馈”或直接访问 `/feedback`。
2. 未登录时确认可以查看公开反馈列表，或看到权限提示。
3. 检查反馈列表：
   1. 新反馈排序符合产品约定。
   2. 可以按状态、类型和严重程度筛选。
   3. 可以搜索关键词。
   4. 没有结果时有空状态。
4. 点击右下角“+”或“新增反馈”。
5. 逐项检查表单：
   1. 类型：Bug、建议、疑问、其他。
   2. 严重程度：高、中、低。
   3. 确认标题是否为选填项，并检查为空时的表现。
   4. 内容必填。
   5. 标签可以输入多个。
   6. 确认姓名是否为选填项，并检查为空时的表现。
6. 不填写内容直接提交，确认不能提交并有明确提示。
7. 填写一条正常反馈并提交，确认列表出现新反馈，内容没有乱码或丢失。
8. 在浏览端打开“意见反馈”，确认入口、提交和展示范围符合约定。
9. 使用已登录账号检查反馈操作：
   1. 可以按权限修改状态为处理中或已完成。
   2. 删除前有确认。
   3. 取消删除后内容仍在。
10. 如果 AI 支持自动上报 Bug，触发一次后确认反馈中包含页面、现象和相关描述；不要把密钥、Cookie 或完整聊天内容写入反馈。

### 6.3 嵌入页面和第三方页面展示【专项】

1. 在创作端打开项目嵌入页面 `/embed/{项目ID}`。
2. 检查页面是否展示：
   1. 嵌入代码。
   2. 预览区域。
   3. 页面或项目选择。
   4. 发布状态提示。
3. 对未发布项目确认嵌入页面提示需要先发布，不能生成可用链接。
4. 对已发布项目复制嵌入代码，粘贴到一个临时 HTML 页面中打开。
5. 检查嵌入页面：
   1. iframe 可以加载。
   2. 高度会随内容调整。
   3. 页面内按钮、动效和配置能正常工作。
   4. 嵌入页面不能读取宿主页面的敏感信息。
   5. 嵌入页面不会把编辑、删除和发布入口带给普通浏览者。
6. 切换嵌入页面或修改发布配置后，确认嵌入内容按发布结果更新。
7. 用不存在的项目 ID 或未发布项目 ID 访问，确认返回清楚的错误状态，不是空白页面。
8. 如果项目提供嵌入通信状态，检查实际支持的“准备就绪、加载完成、尺寸变化、运行错误”等状态；只需记录页面表现和提示，不必分析代码。

### 6.4 管理后台【专项】

1. 使用管理员密钥打开 `http://localhost:4200/admin?secret=管理员密钥`。
2. 访问 `/admin` 时不提供密钥，确认被拒绝或回到普通页面。
3. 使用错误密钥，确认不会进入后台，也不会泄露密钥或系统内部信息。
4. 使用正确密钥进入后台，确认布局和导航清楚：
   1. “概览”。
   2. “AI 模型管理”。
   3. “用户管理”。
5. 打开“AI 模型管理”，逐个检查标签：
   1. “后端供应商”。
   2. “模型白名单”。
   3. “识图配置”。
   4. “绘图配置”。
6. 在“后端供应商”中检查：
   1. 新增供应商时，供应商 ID、名称、接口地址、密钥和模型列表校验清楚。
   2. 模型列表一行一个模型时可以保存。
   3. 可以设置默认供应商和默认模型。
   4. 可以启用或停用供应商。
   5. 保存后数据库状态和 AI 服务同步状态分开显示，普通用户能看懂“已保存但尚未同步”的区别。
   6. 同步失败时有重试入口。
   7. 删除供应商前有确认，取消后数据仍在。
7. 在“模型白名单”中检查：
   1. 可以刷新模型列表。
   2. 可以搜索模型。
   3. 可以启用和停用模型。
   4. 可以拖动启用模型的顺序。
   5. 第一项默认模型标识清楚。
   6. 批量启用、前缀规则、名称匹配规则有明确说明。
8. 在“识图配置”和“绘图配置”中检查：
   1. 开关、模型、接口地址和密钥字段正确显示。
   2. 密钥默认隐藏。
   3. 保存成功和失败提示清楚。
   4. 没有相应服务时，用户可以知道是未配置还是连接失败。
9. 打开“用户管理”：
   1. 用户名、注册时间和操作按钮显示正常。
   2. 没有用户时显示“暂无用户”。
   3. 刷新按钮有效。
   4. 重置密码需要输入两次相同且不少于 6 个字符的密码。
   5. 重置成功后，用新密码登录测试账号。
   6. 删除用户前有明确警告，说明该用户不能再登录。
   7. 取消删除后用户仍在。
10. 使用普通账号重新打开后台地址，确认不能访问管理功能。
11. 退出管理员会话或关闭窗口后，重新访问后台，确认不会因为旧页面缓存而无权限进入。

### 6.5 Figma 插件、探索、愿望、CLI 和演示页【专项】

1. 打开 `/figma-plugin`，确认页面能加载，说明、下载或授权入口没有错位。
2. 如果配置了 Figma 授权：
   1. 点击授权后能进入授权页。
   2. 取消授权后能回到系统并有明确提示。
   3. 授权成功后不会把密钥直接显示在页面上。
3. 打开 `/explore`，检查列表、搜索、空状态和返回路径。
4. 打开 `/wish`，检查页面加载、表单必填项、提交成功和失败提示。
5. 打开 `/cli`，确认说明页和命令入口可见。
6. 在终端只执行只读检查：

   ```bash
   corepack pnpm ow --help
   corepack pnpm ow project list --json
   ```

   1. `--help` 能显示帮助。
   2. 项目列表能返回结果或清楚的空列表。
   3. 验收时不要执行删除、覆盖、发布等 CLI 命令。
7. 打开 `/demo-test`，确认演示页面能加载、预览和配置可以交互；将其记录为开发自检，不替代主流程验收。
8. 独立白板按第 6.6 节验收；手绘页面如纳入范围，按其专项说明验收。

### 6.6 Whiteboard Studio【条件专项】

> Whiteboard Studio 是独立白板工作台，不读写项目数据；它与项目内图片白板共享编辑器交互。Studio 只开放六种创建工具，但仍需检查多选、颜色、文字、组合、缩放和撤销等共享能力；项目内图片白板的回填、持久化和权限按 5.8.1 验收。

1. 按第 4.2 节启动本地服务。白板 Studio 会随 `corepack pnpm dev` 自动启动；如果 3400 端口已被占用，直接打开下面的地址，不要重复启动白板服务。
2. 打开 `http://localhost:3400`，确认：
   1. 页面能显示“Whiteboard”。
   2. 初始画布为空，没有自动出现测试图形。
   3. 页面不要求登录，不显示项目数据、聊天内容或“Dev Data”等调试数据。
3. 检查底部工具栏和白板基本操作：
   1. 可以找到“选择”“抓手”“矩形”“圆形”“文本”“图片”，并能通过悬停提示识别工具。
   2. 用“矩形”拖出图形，点击图形后确认能选中、移动、缩放、旋转或删除；放大画布后控制点大小和位置仍然稳定。
   3. 用“文本”点击画布，输入“白板测试文字”；按回车换行，点击其他位置提交，按 `Esc` 可以取消编辑。
   4. 使用“图片”工具导入一张测试图片，确认图片可以选中、移动、缩放和删除；双击图片后可以在“裁切填满”“完整显示”“拉伸填满”之间切换。
   5. 点击“放大”“缩小”“重置缩放”和“缩放到选区”，确认视图比例或位置变化合理；底部工具栏还可以撤销和重做，并能打开命令面板和快捷键帮助。
   6. 在空白处拖动可以进行矩形框选；移动对象时会出现对齐参考线并自动吸附，不显示间距线或“网格”“边缘”“中心线”等文字。按住 `Alt/Option` 拖动可以复制对象。
   7. 悬停工具按钮或键盘聚焦稍等可以看到提示，按钮本身不依赖原生 `title` 提示。
4. 选中没有内置文字的图形后，检查单选悬浮工具栏：
   1. 选中图形后出现对象上方的悬浮工具栏，并以图标显示填充、描边、层级和更多操作。
   2. 填充指示是色块，描边指示是当前颜色的空心方框；打开颜色菜单可以看到 10 列×6 行的 60 种不重复常用颜色和“其他颜色”。
   3. 将填充或描边设为“无颜色”后，对应指示变为透明/浅色并带斜杠；文字颜色菜单不应出现“无颜色”。
   4. 点击“层级”和“更多”，确认可以执行层级、删除、复制、复制样式、粘贴样式以及“位置与大小”等操作；菜单外点击或按 `Esc` 可以关闭。
5. 检查多选、对齐、分布和组合：
   1. 创建两个图形，切换“选择”，先点击第一个，再按住 `Shift` 点击第二个。确认悬浮工具栏显示“边框、颜色、对齐方式、组合、图层、更多”等图标按钮。
   2. 打开“对齐方式”，确认有左对齐、水平居中、右对齐、顶对齐、垂直居中和底对齐六项；选择一项后对象按对应边缘或中心对齐，按 `Esc` 或点击菜单外部可以关闭。
   3. 创建第三个图形，在三个对象均选中的情况下打开“更多”，确认能看到“水平分布”和“垂直分布”；执行后对象间距按对应方向均匀分布。
   4. 点击“组合”，确认工具栏切换为“解组”，选区覆盖组合内容但不出现组级缩放或旋转控制点；点击“解组”后原对象恢复为独立选择。
   5. 选中组合后拖动其中任一可见子对象，确认组合内可编辑对象一起移动且相对位置不变；组合中被锁定或隐藏的对象不应被拖动改变。
   6. 组合后普通点击组内子对象仍保持组选中；第一次双击进入组内子对象选择但不立即打开文字编辑，第二次双击带文字对象才进入文字编辑；按 `Esc` 返回组选中状态。
   7. 组合状态下打开“图层”执行置顶、上移一层、下移一层或置底，确认整个组合按一个层级单元移动，组内相对顺序不变。
   8. 同时选中一个图形和一个纯文本，打开“颜色”或“边框”选择颜色，确认只修改支持该属性的图形，纯文本的文字颜色不会被误改。
   9. 在编辑模式右键对象，确认可以打开对象菜单，右键不会误启动拖动；点击菜单外部可以关闭。
6. 检查文字工具栏：
   1. 双击矩形输入文字，确认出现包含填充、描边和文字操作的工具栏；创建纯文本后，确认出现只包含文字操作的工具栏。两者都能找到文字颜色、字号、加粗、斜体、下划线、对齐、层级和更多操作。
   2. 打开字号、文字颜色和对齐菜单并选择选项，确认菜单可以点击且文字会更新；文字颜色使用同一套 60 色常用色板和“其他颜色”，但不提供“无颜色”。
   3. 在文字编辑框中只选中部分文字，再修改颜色、加粗或下划线，确认只影响选中的文字；没有选区时修改整段文字。
   4. 把浏览器窗口缩窄，或让文字工具栏靠近左右边缘，重新打开上述菜单。确认菜单完整可见、不会被工具栏裁切，选择后文字编辑状态仍正常。
7. 检查工具范围：当前白板 Studio 只开放“选择、抓手、矩形、圆形、文本、图片”；不应显示完整草图页面中的菱形、线条、箭头、画笔、便签或橡皮等工具。
8. 刷新 `http://localhost:3400`，确认它仍作为独立工作台运行；不要求刚才的图形、文字或图片保存到项目配置中。
9. 如果 3400 服务未启动、无法打开或本次不包含独立工作台，记录“条件不满足，未验证”，不要因此判定项目内配置图片白板不通过。

## 七、通用异常和边界检查

1. 主要表单和弹窗：检查空提交、半填、空格、超长内容、连续点击、取消、关闭和浏览器返回。
2. 列表：检查 0 条、1 条、多条、长名称、重名、无结果、加载失败和重新加载。
3. 网络异常：处理中不重复提交，超时有提示，重试可以继续，失败不显示为成功。
4. 登录和权限：未登录不能访问私有页面，普通用户不能访问管理员页面，退出后返回按钮不能恢复可编辑页面，账号之间的数据不能混用。
5. 删除、恢复、发布、撤销发布和 AI 修改前，确认页面说明影响。

## 八、浏览器、尺寸和易用性检查

1. 至少使用一个主流桌面浏览器完成主流程；条件允许时再用第二个浏览器复测。
2. 在以下窗口尺寸各打开一次首页、编辑页和浏览端：
   1. 1440×900。
   2. 1280×800。
   3. 390×844 或相近手机尺寸。
3. 检查页面是否出现横向滚动条、按钮被遮挡、文字被截断或弹窗超出屏幕。
4. 使用键盘检查：
   1. `Tab` 可以按合理顺序移动。
   2. `Enter` 可以提交按钮或进入项目。
   3. `Esc` 可以关闭可关闭弹窗。
   4. 页面树和下拉菜单也能用键盘操作。
5. 浏览器放大到 125% 和 200%，确认主要按钮和错误提示仍可看到。
6. 检查颜色对比度、错误提示位置、按钮禁用状态和当前选中状态是否容易辨认。
7. 用普通用户视角阅读页面：
   1. 第一次看到按钮时，能否猜到它的作用。
   2. 出错时，能否知道下一步该做什么。
   3. 页面是否大量使用只有技术人员才懂的英文或缩写。
   4. 危险操作是否与普通操作有明显区别。

## 九、数据、安全和隐私检查

1. 用账号 A 登录，确认看不到账号 B 的项目。
2. 复制账号 A 的项目地址，用账号 B 或未登录窗口打开：
   1. 未发布项目不应被普通浏览者读取。
   2. 无权限页面应有清楚的拒绝提示。
   3. 已发布项目按公开规则展示。
3. 检查页面、聊天、反馈和错误提示中不会直接显示：
   1. AI 接口密钥（API Key）。
   2. 管理员密钥。
   3. 登录 Cookie。
   4. 其他用户的私密数据。
4. 检查浏览端只看到发布时允许公开的项目、页面、配置和用户文档。
5. 检查浏览端的临时配置调整不会写回创作端，也不会影响其他浏览者。
6. 上传包含敏感内容的文件前，先确认测试范围和保存位置；一般验收只使用虚拟数据。
7. 如果本次验收包含白板，额外确认：
   1. 未点击“回填图片”前，白板草稿不会改变配置图片。
   2. 回填失败或发生冲突时，原配置图片和已发布预览不会被半途替换。
   3. 白板编辑器、白板代码和草稿不会出现在未登录浏览端或只读页面中。

## 十二、首次验收快速路线

按本地开发模式执行；Node 版本异常时，参阅第 4.2 节启动步骤后的补充说明。

1. 确认当前代码是自己要验收的分支，并确认 `node -v` 显示 24.x。
2. 首次使用或依赖发生变化时执行 `corepack pnpm install`。
3. 执行 `corepack pnpm dev`。
4. 打开 `http://localhost:4200/login`。
5. 注册一个测试账号并进入首页。
6. 新建“人工验收主流程”空白项目。
7. 添加“首页”和“详情页”两个页面。
8. 修改页面名称或配置，等待显示已自动保存。
9. 刷新页面，确认修改还在。

> 如果本分支已开启配置图片白板，接着按第 5.8.1 节完成一次“绘制 → 检查多选/组合、颜色和文字工具栏 → 回填图片 → 重新打开”；如果开关未开启，记录“未验证”即可。

10. 保存一个命名版本，再修改内容并恢复命名版本。
11. 发布项目并复制浏览链接。
12. 打开 `http://localhost:4300`，确认项目出现在独立浏览端。
13. 在浏览端检查单页、画布、配置、文档和登录入口。
14. 回到创作端撤销发布，确认浏览端不再展示。
15. 按第五章和第六章完成专项检查。
16. 按第十章记录问题，按第十一章填写结论。
17. 验收结束后回到运行服务的终端，按 `Ctrl + C` 停止本次启动的服务。
