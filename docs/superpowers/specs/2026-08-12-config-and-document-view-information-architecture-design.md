# 配置面板与文档视图信息架构调整

## 背景

创作端的配置面板同时呈现「配置项」和「资源规范」，而资源规范已可在文档视图的「设计规范」中维护，造成重复入口。浏览端需要保留只读的折叠面板，但让资源规范先于配置项展示；其文档视图则应聚焦发布给浏览者的项目知识与设计规范。

## 目标

- 创作端的配置面板仅展示配置项，不展示或编辑资源规范。
- 浏览端的配置面板保持当前可折叠、只读的两个区块，顺序调整为「资源规范」在前、「配置项」在后。
- 浏览端文档视图仅展示「项目知识库」和「设计规范」。

## 方案

`PageConfigPanel` 增加显式的资源规范展示策略：可隐藏，或与配置项按「前置／后置」排序。默认保持现有顺序，以降低其他调用方变化风险。

创作端编辑页使用“隐藏”策略，继续将资源规范内容交由文档视图中的设计规范能力承载。浏览端 viewer 使用“前置”策略，保留既有只读渲染、折叠状态和空态。

`DocumentView` 增加面向浏览者的只读目录范围：只加载和渲染项目知识库与设计规范；不显示也不请求 AI 记忆、项目公约、页面公约与对话文件。创作端保持现状。

## 数据与交互

- 不改变资源规范的存储、Markdown 格式或配置项引用格式。
- 不改变配置项 schema、配置值写回或浏览端只作用于当前预览会话的规则。
- 浏览端设计规范仍沿用现有只读数据源与选中后展示方式；若未选择项目知识库文档，保留现有空状态语义。

## 验证

- 为 `PageConfigPanel` 覆盖隐藏资源规范及前置排序的渲染断言。
- 为 `DocumentView` 覆盖浏览模式目录仅含项目知识库和设计规范，并确认不触发被排除数据的请求。
- 运行 author-site 相关单测与类型检查（至少覆盖改动组件）。

## 范围外

- 不迁移、删除或改写已有资源规范数据。
- 不修改设计规范编辑器、配置项素材池或发布数据格式。
