# AI 对话图片附件去重展示设计

**日期：** 2026-08-12  
**状态：** 设计方向已确认，待书面审阅  
**范围：** `@workbench/ai-chat-shared` 用户消息与排队消息的附件展示

## 背景

用户在 AI 对话中发送图片时，前端会同时生成图片预览数据，并将同一图片持久化为会话级只读附件。因此一条用户消息同时包含 image part 和 file part，消息气泡会重复展示图片缩略图与文件卡片。

会话级上传仍有价值：它保留“对话文件”管理能力，并让 AI 和会话记录能够引用同一份受管附件。因此问题只在展示层，不应停止图片上传或改变服务端附件契约。

## 目标

- 图片附件在用户消息与等待队列中只展示图片预览。
- 非图片附件继续展示文件卡片及其名称、大小、类型等信息。
- 图片仍持久化为会话附件，不影响 AI 读取、附件管理或历史记录。

## 非目标

- 不修改图片上传、AI 图片直传或图片预描述流程。
- 不改变 Agent Service 的附件 API、存储格式或消息协议。
- 不删除历史会话中已保存的图片附件元数据。

## 方案选择

### 已采用：在展示附件构建时过滤图片类型文件

消息创建时，`images` 继续转换为 image part；`files` 仅转换为 MIME 类型不是 `image/*` 的 file part。排队消息复用同一个构建函数，因此自动保持一致。图片的会话附件上传不变，只是不再为消息气泡生成重复的 file part。

### 未采用：停止上传图片为会话文件

会破坏既有“对话文件”管理与会话级受管资产能力，超出本次展示修复范围。

### 未采用：仅在消息组件里隐藏文件卡片

会保留冗余展示数据，且需要分别处理普通消息、排队消息和未来其他消费者，容易产生遗漏。

## 验收与测试

- 构建一条同时含图片和其会话文件附件的用户消息时，只生成 image part，不生成该图片的 file part。
- 同一条消息含图片与 PDF/文本等非图片附件时，保留图片 image part 和非图片 file part。
- 排队消息与立即发送消息都使用相同规则。
- 运行与 AI 对话组件相关的作者站点测试，并执行 `pnpm check:author`。

## 项目文档同步

实施完成后更新 AI 对话技术文档，说明图片附件在消息流中优先采用预览展示，而会话级文件仅用于管理与读取，不在消息气泡重复呈现。
