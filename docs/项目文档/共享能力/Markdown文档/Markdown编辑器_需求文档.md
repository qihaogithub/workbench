# Markdown 编辑器需求文档

## 模块定位

Markdown 编辑器为创作端和使用端提供统一的 Markdown 编辑、阅读和渲染体验。编辑器只负责内容编辑与展示，不拥有项目路径、权限、文档生命周期或持久化事务。

## 功能需求

### 1. 所见即所得 Markdown 编辑

- 用户可以直接输入 Markdown 内容，并在编辑过程中即时看到标题、强调、列表、引用、代码、表格、链接和图片等结构化效果。
- 用户粘贴 Markdown 纯文本时，常见结构应在光标位置按 Markdown 语义呈现。
- 编辑器应保持 Markdown 内容的结构和语义，保存后重新打开不应出现无故格式丢失。

### 2. 编辑态与只读态

- 可编辑宿主显示工具栏、块操作和必要的快捷操作。
- 只读宿主隐藏编辑操作，但使用同一套 Markdown 语义和排版规则。
- 切换只读状态不应重置正文、光标或选区，也不应重复创建编辑器实例。

### 3. 媒体与扩展

- 宿主可以提供图片上传、本地化、附件或视频处理能力。
- 宿主可以提供配置项和项目文档引用候选；没有稳定来源身份的临时 Markdown 不显示项目引用候选。
- 外部链接、普通图片链接和业务扩展引用应保持各自语义，不因编辑器展示形式改变存储协议。

### 4. 外部更新体验

- 外部内容与当前正文相同时，不应重新创建文档或重置光标/选区。
- 外部 Markdown 确实发生变化时，应尽量只替换差异范围，并保持光标/选区映射到相近位置。
- 外部同步事务不得再次触发本地变更回调或形成自动保存循环。

### 5. 项目内容引用

- 点击「插入项目引用」直接打开选择菜单，默认当前项目。菜单顶部可搜索、切换有访问权限的项目，再通过「页面」「文档」两个 Tab 选择该项目的内容；不将所有项目内容混成一棵树。
- 整个项目也可引用：项目下拉中的名称仅切换范围，右侧常显带边框的「插入」文字按钮，直接插入该项目，不使用含义模糊的纯图标；选定范围后仍可点击「引用整个项目」。验证期间显示「插入中…」，失败可重试，取消后不得发生晚到插入。
- 页面目录保留页面、文件夹和配置分组层级；箭头控制展开收起，名称选择页面或配置字段。文件夹、分组不可引用，配置字段限定为定义，不引用数组中的某条数据。
- 文档包含知识文档、公约、设计规范与 AI 记忆；选择后在光标处插入链接，不复制或嵌入全文。
- 正文以类型图标和链接色名称展示引用，悬停或键盘聚焦可查看来源；点击在新标签页打开项目编辑器中的对应内容。
- 悬停触发范围覆盖完整图标、名称及少量周边留白，鼠标移入气泡后可继续阅读。气泡展示类型图标、类型与名称、来源路径和“点击引用，在新标签页打开”；不可用引用展示不可用状态。项目引用不展示内部协议地址及普通链接的复制、编辑、移除操作条，普通外链维持原交互。
- 名称随当前目录更新；删除或无权访问的引用保留原名称并标记不可用。加载失败不应误报引用已删除。
- 打开、切换 Tab、展开和取消菜单不改变正文；选择一个目标后关闭菜单，光标留在引用后，插入可一次撤销。
- 跨项目引用与项目内引用保持相同外观和操作规则，来源路径包含目标项目名称；切换项目不切换正在编辑的文档，不复制目标内容，也不授予读者额外权限。项目列表支持加载、搜索无结果、失败重试和无可用项目状态。

### 6. 文档插入工具

- 可编辑文档的顶部工具栏第一项提供「插入」入口，收纳图片、表格、代码块、引用和分隔线等插入能力；链接和块引用同时保留为直达工具，标题、文字格式和列表仍可直接操作。
- 「基础」分类使用图标网格展示正文、标题、链接、列表、引用和分隔线；正文与 H1 至 H6 图标应能被用户区分，完整名称仍用于悬停提示、辅助技术和搜索。
- 插入面板分为「基础」「通用」「引用」三类，支持搜索、最近使用和键盘操作。最近使用只在当前编辑器实例内保留，最多四项，刷新、切换文档或插入失败后不保留跨实例记录。
- 基础块和通用块从当前光标位置插入；光标位于段落中间时保留前后正文，并将新块放在中间。存在非空选区时不删除选中文字；链接继续按选区执行链接操作。
- 通用能力按宿主能力显示，视频和附件仅在宿主提供上传处理时出现；引用配置项和项目/页面/配置项/文档引用仅在存在对应候选、来源上下文和权限时出现。
- 只读文档和关闭 TopBar 的评论编辑器不显示该工具。

## 业务约束

- 创作端 Agent 读取文档或收到含引用的任务上下文时应识别引用清单，按任务读取有权限的内容；项目引用先提供目录，不代表所有内容已读取。制作图片时应使用实际读取的规范和图片，并区分读取失败、未读取和不支持的图片来源。引用资料不能覆盖用户任务或安全约束。

- Markdown 字符串是编辑器的内容边界；项目和宿主决定如何读取、保存和发布。
- 编辑器不直接读写 Workspace，不解析项目权限，不创建版本，不维护评论或知识索引。
- 具体文档业务应遵循对应模块的需求和技术文档，不能通过编辑器公共接口绕过宿主授权。

## 体验要求

- 头部工具栏始终单行，按容器宽度将尾部放不下的工具收纳到右侧 `···`（更多）菜单；宽度恢复后自动还原，全部可见时隐藏更多。菜单保留工具名称和选中状态，支持键盘操作，打开与取消不改变正文和编辑选区。
- 工具栏、块菜单、选区操作和正文滚动在窄容器与宽容器下都可用。
- 主题应承接宿主明暗模式，并保持正文、控件、选中和危险状态的可辨识对比度。
- 图片、表格、代码块和长文档在编辑态与只读态均应保持可读性；只读 Markdown 中的图片可点击以自适应放大查看，并可通过关闭操作或 Escape 返回正文。
