# Markdown 编辑器需求文档

## 模块定位

Markdown 编辑器为创作端和使用端提供统一的 Markdown 编辑、阅读和渲染体验。编辑器只负责内容编辑与展示，不拥有项目路径、权限、文档生命周期或持久化事务。

## 功能需求

### 1. 所见即所得 Markdown 编辑

- 用户可以直接输入 Markdown 内容，并在编辑过程中即时看到标题、强调、列表、引用、代码、表格、链接和图片等结构化效果。
- 用户粘贴 Markdown 纯文本时，常见结构应在光标位置按 Markdown 语义呈现。
- 编辑器应保持 Markdown 内容的结构和语义，保存后重新打开不应出现无故格式丢失。

### 2. 编辑态与只读态

- 可编辑宿主显示工具栏、块操作和必要的快捷操作。
- 只读宿主隐藏编辑操作，但使用同一套 Markdown 语义和排版规则。
- 切换只读状态不应重置正文、光标或选区，也不应重复创建编辑器实例。

### 3. 媒体与扩展

- 宿主可以提供图片上传、本地化、附件或视频处理能力。
- 宿主可以提供配置项和项目文档引用候选；没有稳定来源身份的临时 Markdown 不显示项目引用候选。
- 外部链接、普通图片链接和业务扩展引用应保持各自语义，不因编辑器展示形式改变存储协议。

### 4. 外部更新体验

- 外部内容与当前正文相同时，不应重新创建文档或重置光标/选区。
- 外部 Markdown 确实发生变化时，应尽量只替换差异范围，并保持光标/选区映射到相近位置。
- 外部同步事务不得再次触发本地变更回调或形成自动保存循环。

### 5. 编辑器浮层与正文可见性

- 选区工具栏必须避开当前选区和吸顶 TopBar；默认按下方、上方、右侧、左侧的顺序寻找安全位置，空间不足时翻转、侧移、缩小、滚动或隐藏。
- 块手柄必须位于正文左侧沟槽内；点击手柄打开插入菜单时，菜单只能出现在当前块下方或侧方，不能与当前块矩形相交。
- 列表标记、块手柄和正文文字必须保持稳定的列对齐与 8px 视觉间距；多行段落和窄窗口不能造成文字覆盖或大面积无效留白。
- 所有编辑器浮层必须绑定当前编辑器实例和当前 `EditorView`。浮层不得通过隐藏原生控件、合成事件或 DOM 观察器规避正文冲突，也不得把 `z-index` 或 `transform` 当作碰撞解决手段。

“文字可见、可编辑”是编辑器红线：任何工具栏或菜单无法找到安全位置时，优先隐藏浮层，不得覆盖正在编辑的文字。

## 业务约束

- Markdown 字符串是编辑器的内容边界；项目和宿主决定如何读取、保存和发布。
- 编辑器不直接读写 Workspace，不解析项目权限，不创建版本，不维护评论或知识索引。
- 具体文档业务应遵循对应模块的需求和技术文档，不能通过编辑器公共接口绕过宿主授权。

## 体验要求

- 工具栏、块菜单、选区操作和正文滚动在窄容器与宽容器下都可用。
- 主题应承接宿主明暗模式，并保持正文、控件、选中和危险状态的可辨识对比度。
- 图片、表格、代码块和长文档在编辑态与只读态均应保持可读性；只读 Markdown 中的图片可点击以自适应放大查看，并可通过关闭操作或 Escape 返回正文。
