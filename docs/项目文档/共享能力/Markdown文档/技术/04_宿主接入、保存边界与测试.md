# Markdown 编辑器宿主接入、保存边界与测试

## 一、公共接入契约

共享编辑器只暴露内容和行为回调。当前公共接口包括：

| 参数 | 职责 |
|:-----|:-----|
| `value` / `onChange` | 受控 Markdown 正文及本地变更通知 |
| `readOnly` / `placeholder` | 编辑状态和文档级占位提示 |
| `uploadHandler` | 图片、附件或视频的宿主资源处理 |
| `referenceCandidates` / `referenceContext` | 宿主提供的候选项和稳定来源上下文 |
| `className` | 宿主布局和外层样式接入 |

编辑器不接收 `workingDir`、绝对路径、普通 Session token 或内部授权对象。

## 二、宿主职责

宿主负责：

- 根据业务身份读取正文并决定 `value`；
- 根据角色决定 `readOnly` 和可用扩展；
- 在 `onChange` 后维护脏状态、协同草稿和保存队列；
- 在切换文档或卸载前 flush 未提交内容；
- 处理引用点击、图片上传、评论、历史和错误提示。

对于 live Workspace 保存，宿主还必须区分 Authority 的备份完整性故障。收到 `DOCUMENT_AUTHORITY_BACKUP_MISSING` 或底层 `WORKSPACE_AUTHORITY_BACKUP_MISSING` 后，应保留本地编辑值、清空待提交队列并暂停后续自动保存；不能把该错误降级为普通可重试失败，也不能在前端静默执行 reconcile-adopt。恢复由运维 status/preflight 和显式 reconcile-adopt/restore 流程负责，完成后通过刷新或重新挂载重新建立保存状态。

知识库文档使用项目子资源 API 和 `projectId + documentId` 定位；项目/页面公约、memory 等工作区文件仍由其业务入口定位。自动保存、Authority receipt、协同 flush 和资源版本分别由[知识库架构](../../../创作端/09-知识库/技术/01_知识库架构设计.md)与[实时保存与协同编辑](../../../创作端/03-项目管理/技术/11_实时保存与协同编辑.md)维护。

## 三、测试门禁

`@workbench/demo-ui` 至少覆盖：

- Markdown 往返幂等；
- `DocumentEditor` 集成渲染与受控更新；
- Crepe 异步初始化期间的受控 `value` 更新竞态；
- 中文标题选择器；
- TopBar 溢出控制器；
- Crepe Frame 主题 token、工具栏三态、滚动边界和选中状态；
- 图片远程粘贴与本地化失败降级。

author-site 因 Milkdown 为 ESM-only，使用 `jest-milkdown-mock.js` 映射 `@milkdown/*`。业务宿主另行覆盖文档切换、自动保存、协同回写、只读展示和权限边界；author-site 还需覆盖 Authority 备份缺失时的结构化错误透传、中文提示、一次性阻断自动保存、保留本地正文，以及恢复后重新保存的路径。

## 四、Milkdown 补丁与升级

`patches/@milkdown__components@7.22.0.patch` 为项目级图片尺寸编解码补丁。升级 Milkdown 或 `@milkdown/components` 时必须同时复核：

1. 图片块 Markdown 编解码和目标宽度元数据；
2. 容器最大宽度与窄屏临时缩放；
3. ImageBlock 上传回调和远程图片粘贴；
4. Crepe TopBar、表格选中和主题 token 回归。

升级完成后先运行 `corepack pnpm check:demo-ui`，再运行 `corepack pnpm check:repo` 检查文档链接和仓库契约。
