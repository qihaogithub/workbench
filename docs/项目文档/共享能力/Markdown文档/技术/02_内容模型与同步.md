# Markdown 内容模型与同步

## 一、Markdown 主线模型

编辑器内容以 Markdown 字符串作为唯一内容边界。Crepe 的 remark 与 ProseMirror transformer 负责 Markdown 与编辑器文档之间的往返，业务层不再维护一套独立的“富文本转 Markdown”序列化器。

编辑器内部的 ProseMirror 文档是编辑态投影，不能成为项目文件、知识库正文或发布快照的第二个长期来源。

## 二、受控更新

`value` 代表宿主提供的当前 Markdown，`onChange` 只报告本地正文变化。外部值变化通过 Crepe 暴露的实例执行内容替换，并使用最近一次已发送值避免双向回环。

外部值与当前正文相同的时候不执行替换；这样可以保持光标、选区、撤回栈和 IME 输入状态。外部值确实变化时，应优先计算差异范围并让 ProseMirror 事务映射当前选区，而不是无条件重建整篇文档。

受控值可能在 Crepe 异步初始化完成前到达。同步 effect 此时只记录待处理值，不调用依赖 `editorViewCtx` 的 action；实例进入 `Created` 状态后再处理最新值，确保读取 `view.state.doc` 时编辑器上下文已经就绪。

当块级结构变化导致差异起点越过新文档的共同尾部（例如删除末尾段落）时，差异范围不能组成合法的开放 Slice。此时同步逻辑改用解析后的完整文档做一次整篇替换，避免让 ProseMirror 的拟合器处理反向范围；该替换仍按外部同步事务处理，不回写本地变更。

## 三、同步来源

编辑器可能收到宿主刷新、Yjs 协同投影、资源恢复或 AI 写入后的外部 Markdown。外部同步事务必须标记为非本地编辑：

- 关闭本地引用候选菜单和粘贴替换状态；
- 不再次触发 `onChange`；
- 不直接启动自动保存；
- 由宿主决定何时重新读取服务端版本。

本地编辑才进入宿主的脏状态和保存队列。协同与 Authority 的成功边界由[实时保存与协同编辑](../../../创作端/03-项目管理/技术/11_实时保存与协同编辑.md)定义。

## 四、解析与保真

Markdown 解析需要保留标题层级、列表类型、任务状态、引用、代码语言、表格单元格、链接 destination、图片属性和转义字符。代码围栏、行内代码和 HTML 属性中的业务文本不能被误判为编辑器扩展。

解析失败或未知扩展不得删除原文。普通 Markdown 链接、外部 URL、图片链接和 legacy 配置项引用保持原有语义；`wb://` 项目引用由引用域解析器负责身份与权限投影，编辑器只承载其交互节点。

## 五、测试关注点

- Markdown 往返序列化保持幂等。
- 相同外部值不重置光标/选区。
- 初始化尚未完成时收到的外部值更新不会调用未就绪的编辑器上下文，并会在实例就绪后完成同步。
- 差异更新不会触发保存循环。
- 协同远程事务不会弹出本地菜单。
- malformed Markdown 或未知扩展保留可恢复正文。
