# Markdown 编辑器扩展与渲染适配

## 一、图片、附件与视频

Crepe ImageBlock 通过 `uploadHandler` 请求宿主处理本地文件和图片地址。编辑器不决定图片最终存储位置：知识库和创作端宿主可将外链图片交给当前 Session 的图床本地化能力；未提供处理器时才沿用浏览器临时对象地址。

网页富文本粘贴应先保留正文结构，再基于编辑器当前 Markdown 状态替换图片，避免异步处理覆盖用户刚刚粘贴的内容。图床下载、格式/大小限制、跨站展示和失败降级由[全局图床设计](../../../创作端/06-基础设施/技术/06_全局图床设计.md)维护。

BlockEdit 可以由宿主追加“上传视频/附件”等菜单项。扩展项必须通过宿主回调完成资源登记，不得让编辑器直接写入 Workspace 或绕过权限。

## 二、业务引用适配

`crepe-config.ts` 可按宿主传入的候选项追加“引用配置项”或“插入项目引用”入口。配置项引用（`@` + 名称 + 配置 key）与项目引用 `wb://` 分开识别，不能因为展示形式相似而共用解析规则。

项目引用的 canonical URI、实体目录、权限投影、backlinks 和发布索引由[项目页面文档引用与双向链接](../../../创作端/09-知识库/技术/03_项目页面文档引用与双向链接.md)维护。编辑器扩展只负责候选触发、插入、删除和点击回调，不直接解析项目文件或发起自定义协议导航。

## 三、只读渲染适配

编辑态使用 Milkdown，知识文档和页面要求的只读展示可以使用共享 Markdown renderer 或薄 adapter。Canvas、Note、Streamdown、Markdown-it 和 Viewer 各自保留宿主外壳，但都应复用同一套 Markdown 语义和安全引用转换，不把 `wb://` 交给浏览器原生导航。

只读 renderer 不加载编辑器实例、不创建保存队列，也不暴露编辑菜单。发布端只读取不可变快照，不能通过渲染器访问 live Workspace。所有只读 Markdown 容器复用图片预览层：点击已渲染图片只读取其现有 URL 与替代文本，以自适应弹层查看；关闭不影响正文或资源引用，且不改变既有的图片 URL 清洗策略。

## 四、扩展原则

- 扩展通过 typed props 和宿主回调注入。
- 没有稳定 source context 时不启用项目实体候选。
- 扩展失败时保留可恢复正文，不静默写入未经处理的受管资源地址。
- 新扩展先定义 canonical Markdown 表达，再实现编辑态与只读态 adapter。
