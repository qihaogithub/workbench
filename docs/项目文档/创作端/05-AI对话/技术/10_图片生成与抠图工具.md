# 图片生成与抠图工具（图片子 Agent）

> 版本：v1.0
> 创建日期：2026-08-08

## 一、定位

让创作端 Agent 具备“造图”能力：在主 Agent 决定页面需要新素材时，不必要求用户提供现成图片，而是由图片子 Agent 直接生成新图，或从已有图中语义抠出目标元素。这两个能力分别由 `generateImage`（文生图）和 `extractImageElement`（语义抠图）两个工具提供。

关键边界：**这两个工具只注册给图片子 Agent，主 Agent 的工具集中不包含**。主 Agent 通过 `delegateTask`（`subagentType: "image"`）启动图片子 Agent，一次性批量生成/抠图，拿到真实 imageId 后直接写进页面。

**能力开关**：图片子 Agent 的在主 Agent 眼中的可见性与绘图配置的「启用」开关绑定。未启用时，`delegateTask` 的参数定义和描述都不包含 `subagentType: "image"`，主 Agent 完全不知道存在图片子 Agent，也就不会做徒劳的绘图尝试；即使模型强行传入该参数也会被工具层拒绝（`image_subagent_disabled`）。启用后主 Agent 才看到并可使用图片子 Agent。

## 二、整体协作方式

采用“前置批量生成”的简化方案：主 Agent 在设计页面之前规划好图片素材清单，把整批任务委托给一个图片子 Agent。子 Agent 生成/抠图后把每张图的真实 imageId 返回给主 Agent，主 Agent 直接引用，全程不出现临时 URL。

可以把它理解为“主 Agent 是设计师，图片子 Agent 是外派的美工小组”：

| 角色 | 职责 |
| :--- | :--- |
| 主 Agent | 规划图片清单，委派任务，用返回的 imageId 写页面 |
| 图片子 Agent | 只做图像相关工作：生成、抠图、自我评判、重试 |
| 识图模型 | 让图片子 Agent 能“看见”自己生成的图并判断质量 |

主 Agent 通过 `delegateTask` 的 `subagentType: "image"` 参数启动图片子 Agent，并强制使用识图模型，这样子 Agent 生成一张图后可以用 `readUserImage` 回看，不满意就改 prompt 重试，满意再进入下一张。

## 三、图片子 Agent 工具集

图片子 Agent 的工具集与主 Agent 不同，只包含图像相关工具：

- `generateImage`：文生图，调用图像生成 API，结果落全局图床
- `extractImageElement`：语义抠图，从已有图抠出目标元素，输出透明 PNG
- `saveImage` / `listImages` / `readUserImage`：复用现有图片工具，用于保存外部图、查已有图、回看生成结果
- `readFile` / `writeFile`：读取页面上下文 / 写结果

这样可以避免图片子 Agent 误用页面编辑、删除等主 Agent 才该用的工具。

## 四、文生图（generateImage）

`generateImage` 接收画面描述（prompt）、输出文件名、可选尺寸和变体数，调用 OpenAI 兼容的 `/v1/images/generations` 接口生成图片，把返回的图片二进制写入全局图床，并登记到项目图片清单。生成成功后返回 imageId 和 URL，页面代码和配置里直接用 `/api/images/{imageId}` 引用。

处理流程：

1. 校验开关、API Key、prompt 长度、文件名、格式、会话配额。
2. 调用图像生成 API，优先读 `b64_json`，无则回退下载 `url`。
3. 写入全局图床，登记到项目图片清单。
4. 返回 imageId / URL / 尺寸。

失败时按配置重试若干次；每次都单独计数，受每会话最大生成数限制。

## 五、语义抠图（extractImageElement）

`extractImageElement` 使用 CLIPSeg（一个零样本文本-图像分割模型）在一张已有图中定位与语义描述匹配的像素区域，只保留该区域并输出透明背景 PNG。

处理流程：

1. 从全局图床读取来源图。
2. CLIPSeg 根据“要抠什么”的文本描述推理出一张与图片等大的前景 mask。
3. 若 mask 全黑（没找到目标），返回“未找到指定元素”。
4. 可选做边缘羽化（softEdge）或反选（invert）。
5. 把原图 RGB 通道与 mask 作为 Alpha 通道合成透明 PNG。
6. 写入全局图床并登记清单，返回 imageId / URL。

CLIPSeg 模型约 340MB，采用懒加载：首次调用时才下载并缓存，进程内复用，不拖慢服务启动。

## 六、配置

图像生成能力在**管理后台「绘图配置」标签页**配置（`/admin/models?tab=image-gen`），保存后自动推送到 agent-service 运行时并持久化到 SQLite，重建容器后由启动同步自动恢复。配置项：

| 配置项 | 作用 |
| :--- | :--- |
| 启用图像生成 | 总开关，默认关闭 |
| API Key | 图像生成接口 API Key（OpenAI 兼容） |
| Base URL | 图像生成接口 baseURL |
| 生成模型 | 图像生成模型 ID |
| 单次生成超时 | 单次生成超时（毫秒） |
| 每会话最大生成数 | 每会话最大生成数 |
| 失败重试次数 | 失败重试次数 |
| Prompt 最大字符数 | prompt 最大字符数 |

agent-service 侧对应 `src/services/image-gen-config.ts` 运行时单例，管理后台通过 `PUT /internal/image-gen` 覆盖内存配置；环境变量仅作未配置时的默认值。抠图功能的 CLIPSeg 模型独立启用，只要依赖的原生模块可用即可运行。

## 七、边界与注意事项

- 图片子 Agent 用的识图模型复用 `IMAGE_DESCRIPTION_MODEL`，见 [图片内容预描述](./05_图片内容预描述.md)。
- CLIPSeg 模型需要 `sharp` 与 `@xenova/transformers` 两个原生依赖；两者在 esbuild 构建时作为外部模块，运行时由 Docker 镜像安装。
- 生成/抠图的图片都写入全局图床并登记项目清单，`listImages` 可复查，主 Agent 可重复引用，避免重复生成。
