# 项目清单与语义索引

> 更新日期：2026-09-11

## 模块边界

项目清单把“项目有哪些可用入口、每个入口承担什么职责”拆成三层：

1. `@workbench/shared` 定义版本化 wire types、`wb://` canonical URI、native/generated/human/resolved 语义与正交状态。
2. `@workbench/project-core` 从 Authority 工作空间事实构建确定性目录，枚举页面、嵌套 Schema 字段、知识文档、治理文档和已持久化的跨项目 `wb://` 声明。
3. `knowledge-service` 在既有 `knowledge.db` 中维护独立 inventory generation、annotation、generation job 与资源 FTS；Author 在查询前绑定当前用户、项目和编辑会话。

清单只保存元数据和有限摘要，不保存 HTML、源码、配置运行值、Cookie、绝对路径或引用正文。正文继续由 `readFile`、`readProjectReference`、`readKnowledgeSource` 等原有受控读取工具按需提供。

## URI、目录和语义

一期资源类型复用 `MarkdownReferenceTarget`：`project`、`page`、`document`、`config`。项目级配置只以项目摘要和字段定义出现，不伪造 `wb://config`；字段 URI 仍然绑定页面和稳定 `fieldPath`。页面 ID 使用共享 Unicode 单路径段规则，嵌套/数组/`oneOf` Schema 使用现有字段枚举器生成稳定路径。

每个 `InventoryEntry` 包含：

- `native`：名称、别名、原生描述和非敏感元数据；名称是资源身份的一部分，只读展示。
- `generated`：AI 生成的简介草稿、`sourceFingerprint`、`contentHash`、生成版本和 evidence locator。
- `human`：唯一可编辑的 `summary`（界面称为“简介”）及系统审计字段；`null` 表示回退，`confirmedGeneratedHash` 用于确认或标记 `review_recommended`。
- `resolved`：固定优先级 `human.summary > generated.summary > native.description` 的查询投影，附带原生名称和别名。
- `sourceState`、`generationState`、`reviewState`、`refreshMode`：相互独立，不用一个状态字符串替代多个事实。

`project.inventory-overrides.json` 是 Authority 管理的项目资源，不进入发布清单。写入必须携带当前 Authority revision 和资源 hash/absent CAS；冲突返回可见错误。覆盖文件由 Resource Registry 校验，未知字段、非法 URI 和超长简介均拒绝。当前版本不迁移旧版清单覆盖数据；旧 schema 按空覆盖处理。

## Generation、查询和恢复

每次 Authority 工作空间对账先构建确定性快照，再以原子事务切换 `active generation`，旧 generation 标为 `superseded`。单条任务键绑定项目、generation、canonical URI、source fingerprint 和 generator version；任务由 knowledge-service 持有 `attemptId + leaseToken` 租约，过期后有限重试，迟到成功/失败只能被识别为 stale 或 duplicate，不能覆盖新 generation。

项目/页面生成任务保存有界 `evidenceRefs`，不保存 evidence 正文。knowledge-service 不直接调用模型，而是把一次性带租约的请求发给 agent-service 的 `/internal/inventory/generate`；agent-service 通过 Workspace Authority 按白名单引用读取当前证据，单条最多 8 KiB、总量最多 24 KiB，再使用无 AgentManager 会话、无工具、无重试的 stateless model invocation。模型只能返回固定 `{ summary }` 草稿；knowledge-service 随后生成时间、内容 hash、版本和 evidence refs，并拒绝过时 active generation 的结果。生成失败只保存分类错误码和重试状态；native 或上一版 generated 仍可用于回退。

文档和 Schema 原生语义直接进入清单，不为已有 `aiSummary` 重复调用生成器。页面 Schema evidence 的 hash 与 Authority 原文 hash 一致；人工覆盖只重算 resolved/FTS，不触发 AI。浏览器只能通过 Author 的服务端权限投影读取清单，旧的 claim/annotation/fail HTTP worker 入口已移除，生成 worker 直接操作 knowledge-service 的本地 catalog 并通过内部令牌访问 agent-service。

knowledge-service 提供资源 FTS 查询，支持资源名称、别名、简介、URI、类型和 scope 查询，再按匹配原因和 canonical URI 稳定排序。结果包含 `matchedBy`、freshness、分页游标和 `truncated`。Author 内部查询路由还会对每个 `referenced` 目标重新调用项目访问检查；无权、删除、不存在和解析失败统一返回 `targetAvailability=unavailable`，并清除名称、简介、evidence 和声明详情，不暴露具体拒绝原因。

派生库删除后从 Authority 工作空间重新构建 native 与 human overlay，再重新排队 generated，不依赖派生库恢复项目事实。现有知识正文索引仍由同一 SQLite/FTS 运维基础维护，但资源摘要 FTS 与正文 chunk FTS 分表隔离。

Author 每次读取都同时取得当前 Authority revision/rootHash。派生快照只有两者完全一致才是 `ready`；没有快照或任一值不一致时，使用当前工作空间确定性目录并标记 `stale`，GET 不隐式发布 generation；knowledge-service 无法访问时标记 `unavailable`。接口同时返回 `projectionSource`、`projectionState`、`generationActivity`、当前与快照版本以及 `reconcileRequired`，避免把目录新鲜度和后台任务活动混成一个状态。

## AI 上下文和工具

Author 的 `workspace-context` 在当前编辑会话和项目绑定后获取清单，按当前问题进行轻量相关性排序，并在客户端渲染统一 L3。投影硬上限为 12,000 字符、最多 40 条；单条摘要最多 160 字符、单条总投影最多 320 字符；当前项目和当前页面优先。投影携带 `inventoryStatus`、总数和 `truncated`，服务不可用时明确显示 `unavailable`，不静默递归扫描工作空间。

`searchProjectInventory` 是 Agent 只读能力，参数为 query、资源类型、scope、cursor 和有界 limit。它只调用 Author 的权限投影，不接受工作区路径，不返回 source body，也不改变原有读取权限。项目/页面公约仍在 `projectRules` 槽位，清单被标记为不可信资料，不能覆盖系统规则、公约或工具权限。

## Author 管理入口与观测

编辑页文档视图的「项目公约」目录始终提供虚拟子项「项目清单」。桌面端清单采用单列分组概览：项目、页面、页面下的配置项、项目文档、治理文档和外部引用分别表达层级；页面默认折叠配置项，只有搜索或展开时才查看下级资源。项目文档只包含活跃的用户知识文档，AI 记忆、项目公约、页面公约和设计规范依据 `documentKind` 进入治理文档，missing/deleted 只进入来源异常。配置项和文档默认只展示原生名称和简介等有限语义，不展示配置值或正文；用户点击资源的编辑图标后，在当前资源行内展开简介编辑区域。

行内编辑区域只维护可选的 `summary`（界面称为“简介”），并提供“恢复默认简介”和确认 AI 版本；资源原生名称、类型、来源、`refreshMode` 和状态只作为系统信息展示，不提供人工编辑控件。明确说明不会修改页面内容、配置值或文档正文。资源没有原始简介时，编辑框直接预填 AI 生成简介；已有原始简介时，AI 生成简介以折叠详情展示，用户主动展开后查看。清单顶部提供文本、类型和状态筛选，并在同一行显示自动保存状态、冲突重试和只读状态；不再展示低价值数量/freshness 统计条或保存按钮。编辑采用 `DocumentSaveCoordinator` 的 800ms debounce、3s max-wait、串行提交和失败暂停；刷新索引先 flush，失败或冲突时不执行 reconcile。CAS 冲突按字段三方合并：不同字段自动重试一次，同字段冲突保留本地草稿并要求显式重试/放弃。编辑清单期间切换左侧文档目录或离开页面会先提示，确认离开才丢弃草稿。

只有 `projectionState=ready`、`generationActivity=active` 且存在 pending 条目时，Author 才显示“生成中”并低频轮询；stale/idle 的 pending 显示“待生成”并提示刷新，unavailable 显示“索引服务不可用”，失败任务显示“生成失败”。ready/failed 终态和所有非 active 活动状态立即停止轮询。轮询只更新远端 entries 和生成状态，不能覆盖 coordinator draft，并通过请求 fencing 忽略项目切换、刷新或卸载后的旧响应。刷新失败保留明确错误，不继续维持“生成中”。只读角色可以读取清单，但只有 admin/editor 可以编辑简介或触发刷新。

入口不对应工作空间文件，也不进入 Markdown 保存、评论或引用链路。管理员和编辑者可执行覆盖保存与刷新，创建者和只读角色仅可查看。界面展示资源类型、scope、生成/复核状态、freshness、evidence locator 和 orphan 数量，但不显示被权限过滤的正文。项目设置不再提供清单入口。

`/api/inventory/status` 汇总 active projects、fresh/stale/unavailable、新鲜度积压、review 推荐积压、条目数、generation job 失败率/延迟、注解数、查询命中率/延迟和截断量，并展示完整性、reconcile、backup、最近恢复和 generation worker 状态；数据库恢复边界见[独立知识库服务整体架构](../../../独立知识库服务/技术/01_整体架构设计.md)。L3 截断率仍由 Author 侧投影调用埋点补齐，当前未持久化到 knowledge-service。
