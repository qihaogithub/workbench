# 图片内容预描述

> 更新日期：2026-09-06

用户上传图片会在发送前自动写入全局图床并保留 `imageId`、URL、原始名称、MIME、字节大小和可识别的宽高元数据；图片正文仍直接作为本轮输入交给当前模型。模型提示会明确说明无需再次调用 `readUserImage` 或 `listImages`，只有需要重新查看像素内容或检索历史素材时才调用相应工具。当前 `PiAgentBackend.sendMessage()` 尚未接入独立的 text-only 视觉预描述器，因此本次改动不宣称文本模型已经获得预描述能力；旧测试中关于 `imageDescriber` 的契约仍需单独修复或重新确认。

## 目的

当当前对话使用的文本模型不支持多模态输入时，Agent Service 先把图片交给独立的视觉模型生成简短描述，再把描述作为文本上下文交给原对话模型。支持多模态的模型仍直接接收原图，不重复预描述。

## 实现边界

- 视觉模型由 `IMAGE_DESCRIPTION_MODEL` 配置；未配置时，非多模态模型收到图片会返回明确错误，不猜测图片内容。
- 预描述结果在单次 Agent 请求内缓存，避免同一附件被重复调用视觉模型。
- 描述文本保留图片附件标识和必要的媒体上下文，但不把原始图片写入事件日志或普通文本日志。
- 预描述失败属于输入处理失败，不会伪装成模型回复成功；调用方可移除图片或改用支持视觉的模型后重试。

## 与图片工具的关系

图片预描述只负责“理解图片并转成文本上下文”；`generateImage` 和 `extractImageElement` 负责图片生成与抠图，二者使用不同的工具权限和结果回流协议。
