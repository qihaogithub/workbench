# AI 对话模块 - 需求文档

> 版本：v2.24
> 更新日期：2026-09-07
> 变更说明：聊天附件按用户与对话绑定，outbox 与账本只保存附件元数据，不保存图片 base64

---

## 一、模块定位

AI 对话模块是用户与 AI Agent 交互的核心通道，负责将用户的自然语言指令转化为代码修改操作，并实时展示 AI 的思考和执行过程。

---

## 二、功能描述

### 2.1 AI 对话功能

#### 2.1.1 发送对话消息

**用户视角**：

- 用户可在对话区输入自然语言指令，请求 AI 修改代码
- AI 响应应通过流式传输实时展示

**交互效果**：

- 支持流式响应，实时显示 AI 输出
- AI 可请求执行工具操作（如修改代码）
- AI 只有在修改已进入当前工作空间、同步到编辑状态并可被当前预览读取后，才能向用户报告修改成功
- AI 创建多个页面时，每个完整页面应在持久化后立即出现在页面树和画布预览；系统不得等待全部页面创建完成。
- 新页面出现不应自动切换用户正在查看的页面或移动其画布视口；空项目创建首个页面时除外。
- 已写入的文件不得被同一编辑页或其他协作者持有的旧状态再次覆盖；同步失败时应明确报告失败，不能误报完成
- 敏感工具调用需用户确认

#### 2.1.2 对话历史

**用户视角**：

- 用户可查看当前会话的完整对话历史
- 已获得服务端 ACK 的用户消息在刷新、断线重连和 Agent 重启后可恢复
- 尚未获得 ACK 的用户消息必须显示“正在同步”或“同步失败”，不得仅靠一条 AI 错误回复让用户猜测是否已经保存
- 对话仅 owner 可列出、读取、导出、改名和删除；共享 Workspace 不推导对话共享
- 用户取消已受理运行时，保留已 ACK 的用户消息和 `cancelled` 运行状态，不新增 assistant 取消占位
- 页面恢复后发现尚未 ACK 的旧发送命令时，应先可靠补记用户消息，但不得静默执行可能已经过时的 AI 指令；未启动的运行记为已取消，用户可明确重试
- 对话按最后活动时间保留 7 天，到期或手动删除后从活跃存储硬删除；不再存在默认 5 个对话的超限删除
- 管理员可查看不含对话正文的可靠性看板，至少包含消息持久化成功率与延迟、run 终态完整率、Agent 上下文恢复成功率和诊断数据缺口；无样本时必须显示“暂无样本”，不冒充 100%
- 对话历史应包含用户消息和 AI 响应

#### 2.1.3 系统发起任务

**用户视角**：

- 当系统自动发现可交给 AI 处理的问题时，对话区应明确展示这是系统发起的任务，而不是用户手动输入的消息
- 用户应能看到任务正在处理、处理完成或处理失败
- 用户可按需通过弹窗查看任务详情，但默认不被技术错误长文本打断

**交互效果**：

- 系统任务使用区别于用户气泡和 AI 回复的展示样式
- 自动修复类任务应展示轻量说明和状态，卡片不应被长错误详情撑开
- 查看详情应打开独立弹窗展示技术详情，并保留卡片在对话流中的紧凑布局
- 失败后应提供重新触发修复的入口
- 系统任务不应改写用户输入历史，也不应让用户误以为自己发送了该消息

#### 2.1.4 新建对话

**用户视角**：

- 用户可在编辑页面中新建对话，与 AI 开始全新交互
- 用户每次重新进入项目编辑页时，系统应自动开始一个新的 AI 对话，不直接显示上次对话内容
- 新建对话时，代码编辑器和预览区保持当前状态不变
- 新对话继承当前工作空间的文件状态
- 旧对话仍保留在项目对话历史中，用户可通过历史入口主动切回
- 用户在当前编辑页手动选择过指定模型后，新建对话应继续使用该模型，不应回到平台默认模型

**交互效果**：

- AI 对话区清空，开始新的对话
- 代码/Schema/编辑器内容不重置
- 新对话与当前对话共享同一工作空间
- 模型选择器保持用户最近一次手动选择的模型和思考深度；如果该模型在新对话中不可用，则使用新对话可用模型列表的默认选择
- 用户在同一编辑上下文内切换 tab、切换预览视图或 AI 面板重挂载后，模型选择仍应保持

#### 2.1.5 切换对话

**用户视角**：

- 用户可在对话历史列表中切换到之前的对话
- 切换对话时，代码编辑器和预览区保持当前状态不变
- 切换仅影响 AI 的上下文，不影响工作空间文件

**交互效果**：

- AI 对话区显示目标对话的历史消息
- 代码/Schema/编辑器内容不重置
- AI 恢复该对话的上下文
- 同一对话中连续追问时，AI 应能引用最近对话内容；短对话不应因为面板重挂载、流式完成或 HTTP 降级而表现为没有上下文

#### 2.1.6 跨会话记忆

**用户视角**：

- AI 能记住之前对话中了解到的项目信息、用户偏好、架构决策等上下文
- 切换对话后 AI 仍能通过阅读记忆文件了解上下文
- 用户可直接阅读和编辑记忆文件（`memory.md`）
- AI 在对话中发现重要信息时自动更新记忆文件

**交互效果**：

- 每次新对话开始时，AI 自动读取项目根目录的 `memory.md`
- 用户表达个人偏好（如"我不喜欢……"）时，AI 自动记录
- 用户做出关键决策（如"那就用……吧"）时，AI 自动记录
- 用户可手动修改 `memory.md`，AI 会保留用户手写内容

**业务规则**：

- 记忆文件位于项目根目录：`{项目路径}/memory.md`
- 记忆文件已加入 `.gitignore`，不提交到版本控制
- 建议控制在 1500 字以内，接近上限时 AI 自动压缩
- AI 不记录：一次性操作、讨论过程、代码可见信息、敏感信息

#### 2.1.7 对话历史列表

**用户视角**：

- 用户可查看当前项目下的所有对话历史
- 点击输入栏的“对话历史”按钮后，在按钮上方显示紧凑历史菜单，不使用全屏遮罩或居中弹窗
- 列表项只显示会话标题；标题缺失时显示“新对话”。首条用户消息先生成即时短标题，再由当前模型后台优化；标题生成后固定，不随后续消息变化
- 当前活跃对话有高亮标识

**交互效果**：

- 历史菜单支持新建、切换、导出和删除；新建对话以右上角紧凑文字按钮呈现，下载、删除操作仅在列表项悬浮或键盘聚焦时显示，触摸设备保持可操作
- 点击菜单外部或按 Escape 关闭；AI 流式输出期间历史按钮禁用
- 会话按最后活动时间保留 7 天，超期记录由后台删除，不在界面显示“未保存”或“已过期”等状态
- 2 小时仅表示编辑租约，用于内部鉴权和活跃编辑；AI 加载动画只显示在当前对话消息流中

#### 2.1.8 用户自定义大模型 API

**用户视角**：

- 登录用户可在账号设置中配置自己的大模型 API
- 用户可填写供应商名称、OpenAI 兼容 baseURL、API Key 和模型列表
- 用户可从供应商自动获取模型列表，再逐项选择加入自己的模型列表；也可直接手动输入模型
- 个人模型配置不提供默认模型选项
- 保存后，用户后续与 AI 对话时优先使用自己的模型配置
- 用户可清空个人配置，恢复使用平台管理员提供的默认模型配置

**交互效果**：

- API Key 输入框应以密码形式展示
- 已保存 API Key 时，再次打开设置不回显明文，只提示已保存
- 留空保存 API Key 时，应保留原有 Key
- 模型列表支持一行一个模型，不设置或保存默认模型
- 配置不完整或格式不合法时，应给出明确错误提示

**业务规则**：

- 个人模型配置只影响当前登录用户
- 个人配置优先于平台全局模型配置
- 已有活跃对话应尽量同步最新个人配置；无法同步时不影响配置保存
- 平台仍可通过管理后台配置全局可用供应商和默认模型

#### 2.1.9 图片输入边界

**用户视角**：

- 用户可在 AI 对话中上传图片，由支持图片输入的当前模型直接理解
- 当前模型不支持图片时，系统明确提示切换到支持图片的模型，不猜测图片内容

**交互效果**：

- 支持图片的模型保留多图顺序并直接接收原图
- 不支持图片的模型不发起请求，界面保留附件以便用户切换模型后重试

**业务规则**：

- 不设置独立的图片预描述 provider、模型或同步链路
- 模型是否支持图片输入由运行时模型能力决定
- 当 AI 需要把用户上传的图片用于页面代码或配置时，图片应保存为当前项目的本地资源，而不是保存到外部 OSS 或全局图床
- 保存后的图片应跟随项目工作区、预览和发布流程流转，用户不需要单独管理外部图片地址

#### 2.1.10 图像生成与抠图

**用户视角**：

- AI 在搭建页面时，可在没有现成素材的情况下直接生成所需图片，并把生成的图片用进页面
- AI 可从一张已有图中抠出指定主体（如人、车、产品、形状）单独使用
- 用户无需提供图片素材或切换模型，即可获得可用的页面图片

**交互效果**：

- 生成的图片应作为项目资源保存，AI 可直接在页面代码和配置中引用
- 语义抠图应输出透明背景图片，便于叠加到页面其他元素上

**业务规则**：

- 图像生成与抠图能力由平台侧配置开关与模型，普通用户无需理解背后的模型拆分
- 未启用图像生成能力时，AI 不应声称已生成图片，应明确告知服务未配置
- 生成的图片应保存为项目资源并登记到项目图片清单，供 AI 复用，避免重复生成

#### 2.1.11 需求确认卡片

**用户视角**：

- 当用户需求存在多个合理实现方向时，AI 可在对话中发起单选题卡片。
- 用户可直接选择一个预设选项，也可在允许时选择“其他”并输入自己的答案。
- 用户选择后，AI 应基于该选择继续处理当前任务。

**交互效果**：

- 确认卡片以内联形式出现在 AI 回复中，不应打断对话主流程。
- 卡片应展示问题、必要说明、选项和取消入口。
- 用户提交后，卡片应保留在对话历史中，并显示已选内容。

**业务规则**：

- 单选卡片只用于需求澄清，不用于敏感操作授权。
- 取消、超时或当前环境不支持卡片时，AI 应用普通文字继续说明或追问。

#### 2.1.12 执行计划审批卡片

**用户视角**：

- 当 Agent 判断任务复杂、影响范围较大或需要用户确认执行方向时，可先提交执行计划。
- 用户可在对话中的计划卡片上直接批准，也可先查看并编辑计划后再批准。
- 用户批准前，Agent 不应继续执行该计划内的代码修改、删除、验证或子 Agent 委派动作。

**交互效果**：

- 计划审批卡片以内联形式出现在对话中，展示“执行计划待确认”的状态。
- 卡片同时提供“查看计划”和“批准”入口；“批准”用于按当前计划继续执行，“查看计划”用于打开可编辑计划内容。
- 计划弹窗中仍提供取消和批准入口，取消后当前任务停止执行。
- 计划审批卡片出现后，输入区不应继续显示“停止生成”的按钮态；系统应等待用户审批，同时允许用户改问新问题。

**业务规则**：

- Agent 应自主判断是否需要计划审批；简单、低风险、目标明确的小任务不应频繁打断用户。
- 复杂、多步骤、跨文件/跨页面、需要排查后实施、需要子 Agent 或涉及关键产品决策的任务，才应提交审批计划。
- 计划审批不替代敏感操作授权；删除等高风险动作仍需使用对应确认流程。
- 用户在计划审批等待期间发送新问题时，应取消当前待审批计划并开始处理新问题，避免旧计划阻塞正常对话。
- 计划审批被取消或 AI 服务超时时，卡片应结束等待态并说明原因；旧审批不得继续阻塞输入或后续消息。

#### 2.1.13 回复期间消息排队

**用户视角**：

- AI 正在回复时，用户仍可继续输入下一条消息或添加图片、文件。
- 用户在回复期间提交的新消息应进入等待队列，不应打断当前回复。
- 当前回复结束、失败或被用户停止后，系统应自动按提交顺序发送下一条等待消息。
- 宿主检测到 AI 已不再处理而收敛流状态时，也应释放等待队列；不得只恢复视觉状态而遗留“等待发送”消息。
- 用户应能取消尚未发送的等待消息。

**交互效果**：

- 等待消息应吸附展示在输入框上方，并标记“等待发送”。
- 等待消息不应混入对话历史滚动流，避免让用户误以为 AI 已经开始处理下一条。
- 输入区有内容时，发送按钮优先提交当前输入；输入区为空且 AI 正在回复时，按钮才用于停止当前回复。

**业务规则**：

- 第一版只支持同一会话内串行发送，不并发执行多条 Agent 请求。
- 排队消息不替代权限确认、需求确认卡片、计划审批卡片或其他专用响应。
- 切换会话或组件卸载时，旧会话的等待队列不应发送到新会话。

#### 2.1.14 本地文件附件读取

**用户视角**：

- 用户可在 AI 对话中上传本地文件，让 AI 读取文件内容后回答问题或辅助修改页面。
- 图片继续保留原有图片理解体验；非图片文件作为只读参考资料进入当前 AI 对话。
- 图片和非图片文件统一从输入框的加号按钮添加；点击后通过气泡菜单选择“添加图片”或“添加附件”，不并列展示两个上传按钮。
- AI 开始处理但尚未输出正文时，创作端与使用端统一展示 5×5 点阵等待动画。
- 用户可上传文本、Markdown、JSON、CSV、常见代码文件、PDF 和 DOCX 文件。

**交互效果**：

- 已添加的文件应在输入区、用户消息气泡和等待队列中展示文件名、大小和类型提示。
- 对话历史和导出记录应保留文件附件元数据，至少包含文件名、大小和只读附件 ID，便于确认本轮消息确实携带了文件。
- 实时消息可在内存中保留图片预览，但未 ACK 命令 outbox、消息 POST 和权威账本不得复制或持久化 base64/data URL；只保存附件 ID、文件名、MIME、大小和文本提取状态。
- 文件上传失败、类型不支持或超过大小限制时，应提示用户，并且不发送不完整消息。
- AI 回复时应能按需读取用户上传文件的文本内容；扫描版 PDF、图片型 PDF 或无法提取文字的文件应明确无法读取正文。

**业务规则**：

- 文件附件只作为当前 AI 会话的只读上下文，不自动写入项目工作区，不参与项目保存、发布或版本历史。
- 文件附件不替代项目素材管理；当用户希望页面引用图片或资源时，仍按图片本地资源保存规则处理。
- 第一版不支持 XLSX；表格类内容建议先使用 CSV。
- 会话切换或组件卸载时，未发送的文件附件队列不应转移到其他会话。
- 相同用户在同一对话中重复上传内容完全相同的文件时，应复用既有附件（按内容去重）；不得跨用户或跨对话复用物理副本。
- 附件上传必须校验 Session 已获得当前用户和项目的服务端授权；发送消息时，附件引用必须与用户消息、run 和 outbox 事件在同一账本事务中提交，失败时不得只留下部分记录。
- 用户在项目编辑页左侧「代码」栏（代码 Tab）的「聊天文件」虚拟目录应能看到本人在该项目未删除对话中的聊天附件，并支持查看内容、剪切转为知识库文件、删除附件；不得列出他人、已删除对话或无归属元数据的附件。
- 用户通过对话框上传或粘贴的图片也应保存为聊天附件并展示在「聊天文件」中，可查看缩略图、打开原图、转为知识库或删除。
- 聊天附件与知识文档均支持删除：知识文档可在预览区「文档」视图目录中管理，聊天附件可在「代码」栏「聊天文件」目录中删除。
- 对话手动删除或 7 天保留期到期后，该对话的附件必须从外部 API 不可访问，并清理对应物理目录。

#### 2.1.15 消息编辑与重发

**用户视角**：

- 用户可编辑已发送的消息，修改后重新发送给 AI
- 编辑重发时，该消息之前的对话历史（用户和 AI 的完整交互）应保留为上下文
- 旧版本消息及其 AI 回复应全部作废，不得出现在 AI 的上下文中
- 编辑重发不影响该消息之前的历史，不触发之前的文件修改回滚

**交互效果**：

- 编辑后重发时，消息列表截断到该消息之前，旧消息及其回复被删除
- 编辑重发应确保服务端会话历史也同步截断，不残留旧消息在 AI 的上下文中
- 编辑重发后的 AI 回复是全新的，与旧版本无关

**业务规则**：

- 编辑重发时，截断命令必须先由服务端权威账本确认，再提交新消息；前端不得自行回灌或重播历史。
- 重新生成时，旧回复应先作废，再基于同一条已确认用户消息创建新的运行，不重复创建用户消息。
- 截断、重试或新消息提交失败时，界面不得伪装成功，也不得用本地历史覆盖服务端状态；用户可在连接恢复后重试。

---

#### 2.1.16 引用项目（跨项目读取）

**用户视角**：

- 用户可在对话中通过「引用项目」把其他项目（模板项目 + 普通项目）作为上下文，例如"把这个项目两个页面复制过来"
- 引用后，AI 应能读取被引用项目的内容（页面源码、配置、知识文档），并据此完成任务

**交互与读取**：

- 前端把消息中的引用项目（`inlineRefs` 中 project 类型 tag）解析为 `referencedProjects` 透传给 agent-service
- `knowledgeReport` 注入被引用项目的阅读地图条目，并给出读取指引与 `sourceRef`
- 读取原文统一走 `readKnowledgeSource`，按 `sourceRef` 类型分发（`knowledge://` 模板 / `ref://project/...` 普通项目受控读取）

**业务规则**：

- 知识库仍只含模板项目，普通项目引用绝不写入持久 catalog
- 跨项目原文读取必须经过受控入口，受项目权限/可见性把关；未授权引用应被拒绝
- 不得通过引用推断不可见项目的存在性

#### 2.1.17 项目清单

**用户视角**：

- 用户可在编辑页的「项目公约」目录中打开项目清单，快速理解项目、页面、配置项和项目文档之间的关系。
- 清单优先帮助用户浏览资源和补充 Agent 需要的语义，不要求用户先填写一张包含所有技术字段的表格。
- 配置项和文档默认只读浏览；需要补充简介时，用户可按需打开编辑面板，不会误改配置值、页面内容或文档正文。

**交互效果**：

- 桌面端使用单列分组概览：项目、页面、页面下配置项、项目文档和外部引用分组展示；页面下的配置项默认折叠，展开后再查看归属。
- 用户可按资源名称、别名、简介、类型和状态筛选；页面搜索命中下级配置项时，应自动展开对应页面。
- 资源显示「编辑简介」；点击后从右侧打开按需编辑面板，简介选填，资源原生名称不可在此修改。
- 保存由用户显式触发；存在未保存语义时，刷新索引和切换目录应先提示或阻止，避免草稿被覆盖或丢失。
- 并发保存发生版本冲突时，应重新载入最新清单并保留当前用户的本地修改，提示用户检查后再次保存。

**业务规则**：

- 清单是 Agent 的辅助资料，不替代项目公约、页面内容、配置值或文档正文。
- 管理员和编辑者可保存语义覆盖并刷新索引，创建者和只读角色只能查看。
- 清单不展示无权访问资源的正文、简介、证据或拒绝原因。

## 三、业务规则与约束

### 3.1 接口规范

| 方法 | 路径         | 说明         |
| :--- | :----------- | :----------- |
| POST | /api/ai/chat | 发送对话消息 |

### 3.2 安全规则

| 规则         | 说明                         |
| :----------- | :--------------------------- |
| 敏感操作确认 | 文件删除等敏感操作需用户确认 |
| 超时处理     | AI 响应超时应提示用户        |

### 3.3 对话切换规则

| 规则         | 说明                                       |
| :----------- | :----------------------------------------- |
| 切换不改代码 | 切换对话时，代码/Schema/编辑器内容保持不变 |
| 新建不改代码 | 新建对话时，代码/Schema/编辑器内容保持不变 |
| 共享工作空间 | 同一项目的多个对话共享同一个工作空间       |
| 保留模型偏好 | 新建对话时保留当前编辑页最近一次手动选择的模型；不可用时回退到新会话默认模型 |
| 友好错误提示 | 连接失败、超时、鉴权/配额、服务异常、请求取消和未知错误应显示普通用户可理解的中文提示 |
| 同轮上下文保持 | 同一对话的最近历史应稳定展示，并随下一轮请求作为上下文提供给 AI |
