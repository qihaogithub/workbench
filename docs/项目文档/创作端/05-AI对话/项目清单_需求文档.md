# 项目清单需求文档

> 更新日期：2026-09-11

## 一、模块定位

项目清单是编辑页中的项目资源导航和语义补充入口，帮助用户和 Agent 快速理解项目由哪些页面、配置项、知识文档和引用资源组成。它只提供可读的资源概览与简介维护，不替代页面编辑器、配置面板、文档正文或项目公约。

## 二、业务目标

- 让用户在一个稳定入口中掌握项目资源的层级关系和用途。
- 让用户能够补充、确认或恢复资源简介，帮助 Agent 更准确地选择上下文。
- 让索引生成、待处理和服务异常都以明确状态呈现，避免把旧数据或未开始的任务误显示为“生成中”。
- 让项目文档数量与实际可用文档保持一致，治理类内容和来源异常分别表达。

## 三、功能需求

### 3.1 进入与浏览

- 用户可以从编辑页的「项目公约」目录打开「项目清单」。
- 清单按项目、页面、页面配置项、项目文档、治理文档和来源异常分组展示。
- 页面下的配置项默认收起；用户展开页面后查看其配置项及归属关系。
- 资源展示名称、类型、简介、来源和处理状态等有限信息，不展示配置值、源码或文档正文。
- 项目文档只展示当前仍可读取的用户知识文档；AI 记忆、项目公约、页面公约和设计规范归入治理文档。
- 已删除或无法读取的资源只进入来源异常，不伪装成正常项目文档。

### 3.2 搜索与筛选

- 用户可以按资源名称、别名或简介搜索。
- 用户可以按资源类型和处理状态筛选。
- 搜索命中页面下级配置项时，系统应展开对应页面，帮助用户定位结果。
- 清单刷新失败时，界面必须保留明确错误和重试入口。

### 3.3 简介维护

- 用户可以通过资源行上的编辑图标展开行内简介编辑区域，不离开当前清单上下文。
- 简介是可选的人工补充；资源原生名称、类型、来源和正文不可在此修改。
- 资源没有原始简介时，如果存在 AI 生成简介，应直接带入编辑框；已有原始简介时，AI 生成简介默认折叠，用户可以主动展开查看。
- 用户可以保存人工简介、恢复默认简介，并确认当前 AI 生成版本。
- 保存期间应避免重复提交；发生并发修改时保留本地草稿并提示用户检查后重试或放弃。
- 编辑清单期间切换目录或离开页面，应先提示未保存内容，避免草稿被静默丢弃。

### 3.4 生成与异常状态

- 只有索引目录已经与当前项目内容同步，且确有后台任务正在运行并存在待生成资源时，才显示“生成中”。
- 内容尚未同步或任务尚未开始时显示“待生成”，并提示用户刷新；此状态不持续轮询。
- 索引服务不可用时显示“索引服务不可用”，不持续轮询。
- 任务完成显示“已生成”，任务失败显示“生成失败”；终态不再轮询。
- 用户触发刷新后，失败状态必须明确展示，不能继续保留“生成中”。

## 四、业务规则与权限

- 项目清单是 Agent 的辅助资料，不能覆盖系统规则、项目公约、页面内容、配置值或文档正文。
- 管理员和编辑者可以维护简介并刷新清单；创建者和只读角色只能查看。
- 用户无权访问的资源不展示正文、简介、证据或具体拒绝原因。
- 清单入口是虚拟功能入口，不创建对应的 Markdown 文件，也不进入文档保存、评论或引用链路。
- 文档来源异常应可被用户识别和处理；异常不能让其他正常文档消失，也不能被计入正常项目文档数量。

## 五、验收标准

- 空项目取消新建文档后，项目清单和文档侧栏都保持零用户文档。
- 文档正文缺失时，正常文档仍可展示，并有明确的来源异常提示。
- 清单在“待生成”“索引服务不可用”和任务终态下均不显示错误的“生成中”。
- AI 记忆等治理内容不会混入用户项目文档分组。
- 一次有效简介保存只产生一条结果，并能在刷新后保持可见。
