# 配置系统 - 需求文档

> 版本：v1.15 创建日期：2026-04-06 更新日期：2026-09-02

---

## 一、模块定位

配置系统是 Demo 可配置化的核心支撑模块，负责将已经确认的配置规则转换为用户可交互的表单控件，让非技术用户可以调整被明确声明为配置项的内容、样式和行为。

配置系统不负责定义页面结构，也不要求 AI 生成页面时默认把所有标题、文案、图片、颜色、按钮和布局抽成配置字段。没有明确配置诉求时，页面内容由页面源码或原型页文件承载；只有用户明确要求“添加配置项”“这个要可配置”“设为配置项”或调整已有字段时，系统才需要维护对应配置定义。

## 二、功能描述

### 2.1 Schema 解析功能

#### 2.1.1 格式识别与解析

**用户视角**：

- 系统应能自动识别并解析从设计工具导出的配置文本
- 解析结果应包含：组件代码和配置定义两部分

**交互效果**：

- 当输入文本格式不正确时，系统应提示具体的错误位置和原因
- 系统应支持自动修复常见的格式问题（如换行符不一致）

#### 2.1.2 格式验证

**用户视角**：

- 用户输入配置文本后，系统应验证其格式正确性
- 验证通过后，系统应提取出可用的代码和配置

**交互效果**：

- 验证失败时，应高亮显示错误位置
- 应提供修复建议

---

### 2.2 表单生成功能

#### 2.2.1 自动表单生成

**用户视角**：

- 系统应根据配置定义自动生成对应的表单控件
- 表单控件应与配置项一一对应

**交互效果**：

- 不同数据类型应使用不同的输入控件：
  - 文本类型：文本输入框
  - 数字类型：数字输入框或滑块
  - 布尔类型：开关或复选框
  - 枚举类型：下拉选择器
  - 颜色类型：颜色选择器
  - 数组类型：列表编辑器

#### 2.2.2 实时预览联动

**用户视角**：

- 用户修改表单中的任何配置项后，预览区应立即反映变更效果

**交互效果**：

- 配置变更应在 500ms 内反映到预览区
- 高频输入场景应支持防抖处理

#### 2.2.3 配置验证

**用户视角**：

- 用户输入的配置值应符合配置定义中的约束条件
- 不符合约束的值应被拒绝或提示

**交互效果**：

- 实时验证用户输入
- 验证失败时，应在对应字段下方显示错误提示
- 整体验证失败时，应阻止提交

#### 2.2.4 Spine 复合动画资产

- Spine 配置是一个原子字段 `format: "spine"`：用户只上传一个 Spine 压缩包（`.zip` 或 Flutter 导出的 `.zip.flutter`），不会看到或填写骨架、图集、纹理三个独立字段。
- ZIP 校验通过后，配置只保存 `{ kind: "spine", version: 1, assetId }`；未上传时字段缺失，不写空对象。
- 动画名、循环播放与音效开关是与 `spineAsset` 并列的普通配置字段；组件使用 `<SpinePlayer src={spineAsset} animation={spineAnimation} loop={spineLoop} audioEnabled={spineAudioEnabled} />`。Spine event 可播放压缩包内声明的音频。
- Spine 上传在一次受管提交中保存完整素材与页面的 `spineAsset` 引用；上传成功回执只更新本地预览，不再发起第二次相同配置保存。上传期间已有其他待保存配置时，系统必须合并最新完整配置后再落盘，不能让旧定时保存覆盖 Spine 引用。其余配置值仍按页面 500ms 防抖持久化，保存失败要保留未保存状态并向用户提示。
- Schema、AI 写入和人工编辑都必须拒绝把 Spine 声明为 `string/file/.zip` 或 `skeleton`、`atlas`、`texture` 三个用户上传字段。

### 2.3 配置导出功能

#### 2.3.1 格式化输出

**用户视角**：

- 用户完成配置后，系统应能将配置值格式化为标准格式输出
- 输出格式应便于其他系统解析和使用

**交互效果**：

- 输出应为有效的 JSON 格式
- 应保留配置项的原始类型信息

### 2.3.2 配置图片白板

用户可在创作端的单图片配置项、图片列表的某一张图片，以及对象数组内声明为图片的字段上，打开独立白板进行绘制；白板回填后以 PNG 替换当前图片，同时保留可继续编辑的绘图内容。

- Whiteboard Studio 与创作端配置图片白板使用完全相同的 `whiteboard` 工具 profile：选择、抓手、矩形、圆形、画笔分组/橡皮、文本和图片。隐藏创建入口不影响已有节点的读取、编辑、渲染和回填。

- 白板关闭、取消或回填失败均不得改变原配置图片。
- 回填结果必须包含白板中所有可见图片和其他可渲染内容；图片无论来自当前背景、上传、粘贴、拖拽、替换、项目/会话资源、图床、data URL 还是外链，都必须先归一化为受管静态 PNG，动图按回填时的静态帧处理。
- 回填失败、图片资源失效或无法解码时必须给出中文提示并保留原配置图片；不得以空白或缺失内容生成“成功”的回填结果。
- 已由白板生成的图片再次进入时恢复原绘图内容；普通本地图片可作为可删除的背景开始重新创作。
- 图片列表以当前图片值作为保护条件；删除、排序或替换后，旧入口不得覆盖其他项，而应提示用户刷新后重试。
- 存在未回填修改时，Esc、关闭和点击遮罩均须要求用户确认放弃；成功回填后焦点返回原入口。
- 普通图片添加到白板后应按原始比例完整展示，默认展示尺寸最长边不超过 600px；用户后续手动调整的尺寸应保持不变。
- 图片应支持更换、矩形裁剪和圆形裁剪；裁剪时裁剪框固定，用户可直接拖动图片内容选择显示区域，允许图片部分移出裁剪框并保留顶部等局部空白；被裁区域应显示半透明原图，点击外部或按 Esc 后保留当前裁剪结果。
- 图片、形状、线条、路径和控件应支持调整描边颜色与描边宽度；描边宽度使用 0–20px 的滑动控件，文本和分组不提供描边。
- 所有明确声明为图片的单图和多图控件均提供白板入口；普通文件、视频和未声明为图片的数组不提供该入口。
- 对象数组中的图片按当前项目位置定位；排序后仍以排序后的当前位置为准，避免将结果回填到其他项目。
- 单图处于默认值时不显示删除；替换后显示删除，删除恢复该位置的默认图片。多图仍支持逐项删除和整体恢复默认。
- 变体、视频封面及跨作用域复用不在范围内。
- 白板通过创作端功能开关灰度开放；使用端与只读配置不展示入口。

### 2.4 组件排序功能

#### 2.4.1 声明可排序子组件

**用户视角**：

- 当页面已明确需要开放子组件顺序调整时，配置定义可声明哪些子组件支持排序
- 未声明的子组件不参与排序，保持固定位置
- 支持垂直排序和水平排序两种模式

**交互效果**：

- 系统通过 Schema 中的扩展字段 `$demo.orderable` 声明**垂直排序**子组件列表
- 系统通过 Schema 中的扩展字段 `$demo.orderableHorizontal` 声明**水平排序**子组件列表
- 声明后，配置面板自动出现"组件排序"或"横向排序"区域
- 两种排序模式可同时存在，互不干扰

#### 2.4.2 排序控件交互

**用户视角**：

- 用户可通过箭头按钮或拖拽调整子组件的排列顺序
- 操作后预览区实时反映新顺序
- 可一键恢复默认顺序

**交互效果**：

- 排序控件同时支持箭头按钮（上移/下移或左移/右移）和拖拽排序两种方式
- 箭头按钮保证无障碍和精确操作，拖拽提供高效的大跨度移动体验
- 每个排序项左侧显示拖拽手柄，右侧显示方向箭头按钮
- 排序结果持久化，切换页面后不丢失
- 两种排序模式的 UI 布局不同：
  - **垂直排序**：全宽行列表布局，显示序号徽标，箭头为 ↑↓
  - **水平排序**：行内 Chip 标签布局，项间用 `→` 分隔，箭头为 ←→（hover 时显示）

#### 2.4.3 预览区顺序渲染

**用户视角**：

- 预览区中的子组件按照配置面板设定的顺序渲染
- 顺序变更后，预览区立即更新

**交互效果**：

- 垂直排序数据以 `__order` 属性注入组件 props
- 水平排序数据以 `__orderH` 属性注入组件 props
- 组件代码读取 `__order` / `__orderH` 决定子组件渲染顺序
- 排序变更不触发重新编译，仅通过配置更新消息刷新预览

### 2.5 元素定位功能

#### 2.5.1 声明可定位子组件

**用户视角**：

- 当页面已明确需要开放子组件自由定位时，配置定义可声明哪些子组件支持定位
- 声明后，用户可通过可视化画布拖拽或坐标输入来调整子组件位置

**交互效果**：

- 系统通过 Schema 中的扩展字段 `$demo.positionable` 声明可定位子组件列表，格式如下：

```json
{
  "$demo": {
    "positionable": {
      "items": ["logo", "title", "button"],
      "defaults": {
        "logo": { "x": 100, "y": 50 },
        "title": { "x": 200, "y": 100 },
        "button": { "x": 300, "y": 200 }
      },
      "size": { "width": 800, "height": 600 }
    }
  }
}
```

- 声明后，配置面板自动出现"元素定位"区域
- `$demo.positionable.items` 定义可定位的子组件列表（至少 1 项）
- `$demo.positionable.defaults` 定义每个子组件的默认位置（可选，缺省为 { x: 0, y: 0 }）
- `$demo.positionable.size` 定义容器尺寸（可选，缺省使用页面默认展示视口或 800×600）

#### 2.5.2 定位控件交互

**用户视角**：

- 用户可在缩略画布上拖拽子组件标记来调整位置
- 用户也可通过坐标输入框精确设置 X/Y 值
- 可一键恢复默认位置
- 定位编辑一次只操作一个项目；点击另一个项目时立即切换目标，已完成的位置保持不变

**交互效果**：

- 缩略画布等比例缩放容器尺寸，最大 280×200px
- 画布显示网格辅助线（100px 等间距）
- 每个子组件以可拖拽标记块显示在画布中，拖拽时高亮
- 标记块显示组件名称和移动光标
- 只有当前点击的项目显示“完成”和透明开关，其他项目仍显示“拖动”
- 数组中声明相同定位 key 的项目仍可分别编辑，切换不会导致其他项目跟随移动
- 拖动过程中活动项目不得变更，元素应连续跟随指针，松手后不回弹且不切换到相同 key 的其他项目
- 拖动中的临时位置不作为正式配置反复提交；松手时一次性保存最终坐标
- 坐标输入框限制输入范围（0 到容器尺寸）
- "恢复默认位置"按钮在位置变更后显示

#### 2.5.3 预览区位置渲染

**用户视角**：

- 预览区中的子组件按照配置面板设定的位置渲染
- 位置变更后，预览区立即更新

**交互效果**：

- 定位数据以 `__positions` 属性注入组件 props，格式为 `Record<string, { x: number; y: number }>`
- 组件代码读取 `__positions` 决定子组件的绝对定位坐标
- 定位变更不触发重新编译，仅通过配置更新消息刷新预览

## 三、业务规则与约束

### 3.0 配置项来源边界

| 规则 | 说明 |
| :-- | :-- |
| 明确配置诉求 | 只有用户明确要求添加、删除或修改配置字段时，页面级或项目级配置定义才应变化 |
| 默认空配置 | 新建页面没有明确配置诉求时，配置定义可以保持空属性集合 |
| 页面内容归属 | 标题、文案、图片、颜色、按钮和布局默认归属于页面源码或原型页文件，不因“可编辑”自动变成配置项 |
| 配置化入口 | 用户在属性面板中选择“设为配置项”后，系统才需要追加字段并刷新配置面板 |
| 项目级配置展示 | 项目级共享配置字段只有在当前页面存在可生效绑定关系时，才应出现在该页配置面板；绑定关系应覆盖静态字段和按同一命名规则选取的字段族，不能因页面采用动态取值方式而漏掉实际生效字段；未绑定到当前页的共享字段不计入该页配置数量 |
| 画布配置详情 | 画布工作台打开配置面板时应优先展示当前选中页面的配置详情，避免用户只看到页面列表和数量而看不到默认值；用户仍可返回页面列表查看其他页面；画布直接点击页面与一级列表点击共享同一进入规则，零配置页面只保留一级列表 |
| 零配置页面列表 | 页面共享配置与本页配置总数为 0 时，一级列表仅显示页面名称，不显示数量徽标和右箭头；点击仍选择页面并定位画布，但不进入配置详情 |
| 画布一级列表标题 | 画布模式的配置一级列表不显示“配置面板”标题栏；单页模式及配置详情按各自面板头部策略展示 |
| 共享配置影响范围 | 共享配置分组应显示“影响 N 个页面”，并允许展开查看受影响页面名称 |
| 默认配置保存与恢复 | 本页配置与共享配置均支持将当前配置值保存为默认值，以及一键恢复为初始默认值；恢复会丢弃当前值调整，保存会改变后续新项目、新增页面或初始预览使用的默认值 |
| 分组数量展示 | 配置字段分组标题不展示字段数量徽标；页面级和共享配置的作用范围由分组标题、影响页面列表和页面列表总数表达 |
| 空项目配置 | 项目没有页面时，配置面板应展示明确的空页面状态，而不是提示“没有匹配配置项” |
| 复杂结构边界 | 复杂列表、组件层级、布局结构、动态表达式和跨页面动作不作为普通表单字段承载 |
| 字段冲突 | 页面级配置字段不得与项目级共享配置字段重名 |

### 3.0.1 配置定义管理

创作端配置面板以单字段编辑替代“管理配置项”工作台：点击字段名称编辑该字段；新增和恢复默认统一收纳在配置面板右下角的“更多”悬浮菜单中。使用端和只读/引用页面不提供新增入口。

| 规则 | 说明 |
| :-- | :-- |
| 配置内容层级 | 配置详情直接展示共享配置与本页配置，不再额外显示“配置项”标题，也不提供整体折叠 |
| 统一操作入口 | 右下角“更多”悬浮按钮打开气泡菜单，当前收纳“添加配置项”和“恢复默认”，未来操作继续追加在同一菜单中；宿主没有提供任何可用操作时，不显示悬浮按钮 |
| 字段入口 | 即使当前页面尚无配置字段，创作者也能从“更多”菜单创建首个字段；字段名称是已有字段唯一的定义编辑入口 |
| 可管理内容 | 支持名称、字段类型、必填、分组、分类、枚举、图片上传限制及单视频上传；视频值包含视频地址和可选封面，字段 key 由系统创建且不在界面中暴露，首期不支持重命名 |
| 分组与字段层级 | 分组仅是字段元数据，用于组织日常配置表单；移走最后一个字段后分组自然消失，不提供独立的分组 CRUD |
| 未分组字段 | 未在字段中显式设置分组时，配置面板直接平铺该字段，不按类型或名称自动创建分组层级 |
| 编辑体验 | 单项编辑器使用固定头部、可滚动表单和固定底部操作；不再有跨字段暂存或“保存全部修改”步骤 |
| 字段说明归属 | 配置字段的业务说明和使用描述由设计规范维护，不作为 Schema 定义管理器中的可编辑元数据 |
| 字段状态 | 新增字段可以尚未绑定页面；未绑定是允许的预留状态，不代表保存失败 |
| 删除影响 | 删除字段时应同时清理对应运行值；若页面已经消费该字段，系统会把页面同步任务交给 AI |
| AI 交接 | 可视化属性创建字段时，HTML/React 能安全生成绑定 patch 的场景可“保存并应用”；不能安全直写时保留为明确的 AI 交接，不应表述为页面已经同步 |
| 默认值边界 | “恢复默认值”保留在日常填写面板；单项编辑器以现有 Schema 默认值初始化并复用日常配置项表单编辑。默认值区仅保留标题和直接控件，不添加说明卡片或按类型推断出的分组折叠层；保存只改写 Schema 默认值，不改写正在使用的页面配置 |
| 保存确认 | 保存前应说明字段定义影响；标题、分组、默认值和图片规则等安全变更使用“保存字段”，可视化直接绑定才使用“保存并应用” |
| 图片规则输入 | 文件类型使用预置格式下拉；宽度与高度各一条规则，按 `W/H + =、>、≥、<、≤ + 数值` 表达，新规则默认使用 `=`；留空即不限制该维度 |
| 设计规范配置摘要 | 图片字段未设置格式限制时显示“不限”；设置后显示允许格式（如 `png/jpg`），尺寸显示已配置的 W/H 规则，未设置时显示“—” |

### 3.1 支持的数据类型

| 类型    | 说明       | 对应控件        |
| :------ | :--------- | :-------------- |
| string  | 文本字符串 | 文本输入框      |
| number  | 数值       | 数字输入框/滑块 |
| integer | 整数       | 数字输入框      |
| boolean | 布尔值     | 开关/复选框     |
| array   | 数组       | 列表编辑器      |
| object  | 对象       | 嵌套表单        |
| enum    | 枚举       | 下拉选择器      |

### 3.2 支持的控件扩展

表单控件的选择遵循三层映射结构：

```
Layer 1: ui:widget 显式覆盖     → 最优先，用于非标准控件或强制指定
Layer 2: format 语义映射         → 根据 JSON Schema 标准 format 值推断
Layer 3: type 数据类型回退       → 根据基本数据类型推断
```

**设计原则**：`format` 是语义声明（「这个值是什么」），`ui:widget` 是控件覆盖（「我想用不同的控件」）。渲染层负责理解语义声明并给出合理的默认控件；只有需要偏离默认时，才需要 `ui:widget`。

| 控件 | 说明 | 触发方式 |
| :-- | :-- | :-- |
| 颜色选择器 | 可视化选择颜色 | `format: "color"`（Layer 2） |
| **图片选择器** | **选择或上传图片** | **`format: "image"`（Layer 2，推荐）** 或 `ui:widget: "file"`（Layer 1） |
| **视频选择器** | **上传 MP4/WebM 视频，可选上传封面；上传后以封面或默认占位展示，点击后在弹窗中预览** | **`format: "video"`（Layer 2）** |
| 多图选择器 | 上传多张图片 | `ui:widget: "imageList"`（Layer 1）或 `type: "array"`（Layer 3） |
| 富文本编辑器 | 编辑格式化文本 | `ui:widget: "richtext"`（Layer 1，无对应 format 标准值） |
| 代码编辑器 | 编辑代码片段 | `ui:widget` 扩展（Layer 1） |

#### 3.2.1 视频配置项展示

- 上传前区域沿用现有上传交互。
- 上传成功后，配置面板只展示视频封面；未配置封面时展示统一默认占位，不展示文件名、格式、状态、时长、分辨率和大小。
- 点击封面或默认占位后，在弹窗中播放视频；视频控制项只出现在弹窗内。
- 操作区提供“替换视频”“添加/更换封面”和“删除”。
- 删除不要求二次确认；有默认值时恢复默认视频及封面，没有默认值时清空当前值。

### 3.3 验证规则

| 规则 | 说明 |
| :-- | :-- |
| 必填验证 | 标记为 required 的字段必须填写 |
| 类型验证 | 输入值必须符合定义的数据类型 |
| 范围验证 | 数值类型可设置最小/最大值 |
| 长度验证 | 字符串类型可设置最小/最大长度 |
| 格式验证 | 可设置正则表达式验证格式 |
| 枚举验证 | 值必须在预定义的选项列表中 |
| **图片尺寸校验** | \*\*图片上传时可配置最小/最大宽高限制，详见 [3.8 图片上传验证规则](#38-图片上传验证规则) |

### 3.4 默认值规则

| 规则       | 说明                              |
| :--------- | :-------------------------------- |
| 显式默认值 | 配置定义中指定的 default 值       |
| 类型默认值 | 未指定 default 时，使用类型默认值 |
| 空值处理   | 允许为空时，默认值可为 null       |
| 图片默认值 | 单图显示默认图片时不提供删除；替换后删除恢复当前字段或当前数组位置的默认图片 |

### 3.5 排序规则

| 规则 | 说明 |
| :-- | :-- |
| 仅限声明项 | 只有配置定义在 `orderable` / `orderableHorizontal` 中声明的属性才可排序 |
| 固定项不移动 | 未声明的子组件保持原始位置 |
| 最低数量 | 至少包含 2 项，否则不显示排序功能 |
| 数据完整性 | `__order` 必须包含 `orderable` 中的所有项 |
| 双向独立 | 垂直排序 `__order` 与水平排序 `__orderH` 互不干扰，可同时存在 |
| 默认顺序 | 未修改时使用配置定义中的默认顺序，即 `orderable` 的数组顺序 |

### 3.6 定位规则

| 规则         | 说明                                                       |
| :----------- | :--------------------------------------------------------- |
| 仅限声明项   | 只有配置定义在 `positionable.items` 中声明的属性才可定位   |
| 最少一项     | `positionable.items` 至少包含 1 项，否则不显示定位功能     |
| 默认位置     | 未设置默认值时使用 `{ x: 0, y: 0 }`                        |
| 单目标编辑   | 定位编辑状态同时只包含一个字段实例；切换项目立即替换活动目标                 |
| 数组实例     | 数组定位项目按稳定实例身份区分，不能仅依赖数组下标或重复的声明式 DOM key       |
| 拖动事务     | 拖动中仅更新临时视觉位置，松手后一次提交；同一实例在完成前不重新匹配 DOM 目标 |
| 坐标边界     | X 范围 [0, containerWidth]，Y 范围 [0, containerHeight]    |
| 容器尺寸来源 | 优先级：`positionable.size` → 页面默认展示视口 → 800×600   |
| 数据完整性   | `__positions` 必须包含 `positionable.items` 中的所有项键名 |

### 3.7 配置项关联设计规范

配置项说明统一由设计规范文档承载，规范条目可绑定项目级或页面级配置项。配置 Schema 不再提供备注编辑能力。

| 规则 | 说明 |
| :-- | :-- |
| 关联展示 | 被规范条目绑定的配置项，在字段控件下方按条目展示规范标题和说明；未绑定时不显示规范卡片 |
| 空说明 | 规范条目说明为空或仅包含空白字符时，配置项下方不显示该条规范模块，包括标题、背景卡片、编辑入口和占位文案；同一配置项关联的其他非空规范仍正常展示 |
| 长说明 | 说明超过卡片默认高度时允许展开与收起，未溢出时不显示额外操作 |
| 角色区分 | 创作端规范卡片提供编辑入口，浏览端仅展示内容 |
| 编辑定位 | 创作端点击规范卡片的编辑入口后进入文档视图，选中对应规范文档并自动展开目标条目 |
| 条目排序 | 规范条目支持通过标题区的专用拖动手柄调整顺序；说明编辑器和条目名称输入内的拖动始终用于文字选择或编辑，不启动排序 |

### 3.8 图片上传验证规则

#### 3.8.1 验证类型

| 验证项   | 说明                                                              |
| :------- | :---------------------------------------------------------------- |
| 文件大小 | 创作端以 MB 输入；保存后通过 `ui:options.maxSize` 配置，默认 50MB |
| 图片尺寸 | 通过 `ui:options` 中的 `widthRule`、`heightRule` 配置（单位：px） |
| 文件类型 | 通过 `ui:options.accept` 配置，默认 `image/*`                     |

#### 3.8.2 尺寸校验策略

| 规则 | 说明 |
| :-- | :-- |
| 可选校验 | 仅当 Schema 中声明了宽度或高度规则时才触发 |
| 警告模式 | 尺寸不符合要求时弹出确认对话框，用户可选择「取消上传」或「继续上传」 |
| 非阻断性 | 尺寸校验不强制阻止上传，仅提醒用户注意 |
| 优先级 | 先校验文件大小，再校验图片尺寸；尺寸校验失败不执行上传 |

#### 3.8.3 交互流程

```
用户选择/拖拽图片
    │
    ▼
1. 文件大小校验
    ├─ 超限 → 显示错误，终止流程
    └─ 通过 ↓
    │
    ▼
2. 图片尺寸校验（仅当声明了尺寸限制）
    ├─ 未声明 → 直接上传
    ├─ 符合 → 直接上传
    └─ 不符合 ↓
    │
    ▼
3. 弹出尺寸警告对话框
    ├─ 显示：具体不合规项（如“宽度小于 100px”）
    ├─ 显示：实际尺寸（如“实际 80x60px”）
    ├─ 「取消上传」→ 终止流程
    └─ 「继续上传」→ 执行上传
```

#### 3.8.4 适用范围

| 控件                       | 支持情况              |
| :------------------------- | :-------------------- |
| FileUploadWidget（单图片） | ✅ 完整支持           |
| ImageListWidget（多图片）  | ✅ 完整支持，逐张校验 |

#### 3.8.5 Schema 配置示例

```json
{
  "type": "string",
  "format": "image",
  "title": "Banner图片",
  "ui:options": {
    "accept": "image/*",
    "maxSize": 5242880,
    "widthRule": { "operator": "≥", "value": 100 },
    "heightRule": { "operator": "≤", "value": 2048 }
  }
}
```

> **说明**：尺寸校验的完整技术实现参见 [技术/03\_表单生成器.md](./技术/03_表单生成器.md) 的 FileUploadWidget 和 ImageListWidget 章节。

### 3.9 页面配置要求

配置项备注常描述一个页面中多个配置的整体要求，而非单个配置。因此引入**页面配置要求**（Page Requirements）文档，与页面 1:1 绑定、与配置项解耦，通过软引用指向配置项。

| 规则 | 说明 |
| :-- | :-- |
| 绑定关系 | 每个页面一份配置要求文档，存储于 `demos/{pageId}/requirements.md`，随页面版本快照 |
| 文档格式 | Markdown，行内软引用 `@[名称](config_key)` 指向配置项 |
| 引用语义 | `config_key` 为 Schema 属性 key，`名称` 为写入时的 title 快照；渲染时从当前页 schema 实时解析 |
| 失效引用 | 配置项被删除/改名时，引用标记为「失效」但不阻塞文档；配置项增删改不破坏文档 |
| 反向引用 | 配置项详情可列出被哪些页面的配置要求引用（按需扫描各页 requirements） |
| 与设计规范的关系 | 页面配置要求用于页面级整体说明；字段级说明由设计规范条目承载，两者独立维护 |
| 配置面板展示 | 创作端配置面板只展示「配置项」（含共享/本页配置）；设计规范在文档视图中维护，不在配置面板重复展示 |

实现说明参见 [技术/01\_架构设计.md](./技术/01_架构设计.md) 与 [技术/06\_可视化批注与编辑机制.md](./技术/06_可视化批注与编辑机制.md)；页面配置要求与「可视化批注」（预览元素浮层）是两套独立能力，互不混淆。

### 3.10 页面设计规范自动维护

页面出现图片或动效配置项时，系统自动建立该页面的设计规范文档，并为每个符合条件的配置项创建一条规范。用户可继续补充每条规范的说明。

| 规则 | 说明 |
| :-- | :-- |
| 文档归属 | 自动文档稳定归属于页面，即使页面改名也保持同一份文档；标题随页面名更新为“页面名设计规范” |
| 条目生成 | 图片或动效配置项各生成一条规范，名称取配置项标题，说明初始为空 |
| 同步删除 | 配置项被删除，或其类型改为非图片、非动效时，对应自动条目一并删除 |
| 手工内容 | 自动同步不删除手工创建的规范条目；仍存在的自动条目保留用户补充的说明 |
| 空文档 | 页面已没有符合条件的配置项时保留设计规范文档，只移除自动条目 |
| 配置项预览 | 仅当鼠标悬浮或键盘聚焦配置项缩略图时显示预览浮窗；浮窗中的页面部分必须展示该配置项所在页面的最新真实效果图，截图缺失时明确提示，不得以示意占位图代替 |

## 四、配置定义格式规范

### 4.1 基本结构

配置定义采用 JSON Schema 格式，基本结构如下：

```json
{
  "type": "object",
  "properties": {
    "配置项名称": {
      "type": "数据类型",
      "title": "显示名称",
      "description": "配置项说明",
      "default": "默认值"
    }
  },
  "required": ["必填配置项列表"]
}
```

### 4.2 扩展字段

除标准 JSON Schema 字段外，支持以下扩展字段：

| 字段 | 说明 | 用途 |
| :-- | :-- | :-- |
| `ui:widget` | 指定使用的控件类型 | **覆盖默认控件选择**（Layer 1），用于非标准 format 场景 |
| `ui:options` | 控件配置选项 | 自定义控件行为（如 accept、maxSize 等） |
| `format` | 值语义声明 | **参与默认控件选择**（Layer 2），如 `format: "image"` → 图片上传控件 |
| `$demo.presentation` | 页面默认展示配置 | 声明固定/响应式模式、默认视口与高度行为 |
| `$demo.orderable` | 垂直可排序属性列表 | 声明哪些子组件支持垂直方向顺序调整，通过 `__order` props 注入 |
| `$demo.orderableHorizontal` | 水平可排序属性列表 | 声明哪些子组件支持水平方向顺序调整，通过 `__orderH` props 注入 |
| `$demo.positionable` | 可定位属性配置 | 声明哪些子组件支持自由定位，含 items/defaults/size，通过 `__positions` props 注入 |
| `$demo.note` | 属性级备注 | Markdown 备注内容，存储于各属性下 |
| `$demo.maxItems`（oneOf variant 级） | 模块数量上限 | 限制配置面板中该类型模块的最大添加数，达到上限后添加按钮置灰并显示 `(n/max)`；创作端与浏览端统一生效，未声明视为不限 |

> **关于 `format` vs `ui:widget`**：`format` 是 JSON Schema 标准字段，用于声明值的语义（如「这张图片的 URL」）。渲染层根据 `format` 自动选择合适的默认控件。`ui:widget` 是自定义扩展字段，用于覆盖默认选择——只有当需要使用与 format 语义不符的控件时，才需要使用。创建配置字段时，优先使用标准 `format` 字段即可。

> **关于 Schema 边界**：`config.schema.json` 只表达受控的配置与页面展示扩展，不是页面结构 DSL。`$demo.presentation`、`$demo.orderable`、`$demo.orderableHorizontal` 和 `$demo.positionable` 都不得扩展为组件层级协议；其中 presentation 只描述页面默认展示行为，不改写页面内容布局。
