# 配置图片白板实现设计

配置图片白板是配置表单的一项创作端私有能力，具体用户规则见[配置系统需求](../配置系统_需求文档.md)。它不属于页面 runtime，也不向使用端暴露 scene。

## 资源与绑定

白板内容由独立的 `WhiteboardDocument` v3 保存，包含经 Sketch 协议校验的完整 scene、`sceneFormat`、`nodeSemantics`、安全区、编辑器视图和单调的 `documentRevision`。`WhiteboardBinding` 才是配置目标与白板产物的关系：它保存配置范围、字段、图片列表原值保护条件、`documentRevisionAtOutput` 和 PNG 哈希。PNG 只是可去重资产，不保存字段归属；v1/v2 文档可读取并升级为 v3，新写入使用 v3。首次打开没有 `source-background` 的 v1/v2 文档时，会把当前配置图片迁移为整板可删除背景；V3 已保存的场景（包括用户删除背景的结果）按原样恢复。

代码是 document 的受限投影，不是第二份持久化真相。`@workbench/whiteboard-core` 提供 `html-css-v2` bridge：只允许带稳定 `data-sketch-id` 的 group、rect、ellipse、image、text、button、绝对 px 几何和白名单样式；复杂 CSS、外链资源、脚本和非 bridge 节点返回带 source range 的 diagnostics。图片节点的 `intrinsicWidth`/`intrinsicHeight` 与 `imageCrop` 会分别通过 `data-sketch-image-size`、`data-sketch-image-crop` 保留。`parse(serialize(document))` 只保证 bridge canonical fields 的稳定 round-trip。

受管资源目录将白板 document、binding 索引和图片资产纳入同一 Workspace 资源注册表；scene 不会写进普通 assets，也不会进入 HTML sandbox、execution ticket 或页面 scene。

图片资产统一走创作端的受管静态渲染管线。当前图片背景、全局图床 `/api/images/<id>`、项目图片 API `/api/projects/<projectId>/images/...`、项目/会话 workspace `assets/`、上传/粘贴/拖拽/替换图片、data URL 与外部 HTTP 图片，都会在回填前被解码并转成受管 PNG；GIF/APNG 等动图按浏览器可捕获的当前帧处理，浏览器无法安全捕获时由服务端按首帧静态化。原始宽高、透明度、适配方式、裁剪、旋转、透明度、描边和层级仍保存在完整 scene 中。持久化 image node 的 `src` 与 `nodeSemantics.assetRef` 均指向 `/api/images/<id>`，data/blob/外链不会进入白板文档。

外部 HTTP 图片由服务端按单次总超时和 10 MiB 上限处理：响应体逐块读取，超过上限立即中止，不因缺少 `Content-Length` 而先完整缓冲；重定向共享同一个总超时并逐跳重新校验。域名解析得到的公网 IP 会固定到实际 HTTP/HTTPS socket，HTTPS 仍使用原域名作为 Host/SNI，避免 DNS rebinding 在校验后把请求转入内网；localhost、回环、链路本地、保留和组播地址均拒绝。

代理网络可能把公网域名解析成 `198.18.0.0/15` Fake-IP。仅当系统解析包含这类地址且没有其他非公网地址时，白板通过固定连接 `1.1.1.1`、TLS 验证 `cloudflare-dns.com` 的 DNS-over-HTTPS 查询重新获取 A/AAAA 地址；请求只发送域名和记录类型，不发送图片路径、查询参数或登录凭据。DNS 响应限制 64 KiB、禁止重定向，并共享图片下载的 10 秒总时限。复核结果仍须全部为公网地址，随后固定实际连接 IP；字面量 Fake-IP、真实内网地址和混合内网解析均保持拒绝。加密 DNS 不可用时返回公网地址验证失败，不能回退连接 Fake-IP。

图片资产状态在 image-store 中使用 `candidate → localized → attached → output` 生命周期：本地化后先以白板草稿 ID 租约登记，成功提交后转为白板文档的 durable reference；取消、失败、超时由租约释放和 GC 清理，已被项目或白板引用的资源不回收。服务端读取白板时对缺失资源 fail-closed，不创建空白替代物。

## 提交路径

表单组件只产生无 IO 的图片目标，宿主以 capability 打开 `WhiteboardDialog`。对话框维持私有完整 V3 草稿，提交时只上传 scene 与目标，不接受客户端提供的最终 `pngBase64` 作为可信结果。服务端先校验原生完整场景和所有图片资源，再使用 `sketch-core` 同一套 SVG 场景规则栅格化 PNG，生成渲染清单，确认所有可见图片节点均参与合成后才进入 `WhiteboardCommit`。live Workspace 先把服务端生成的二进制 PNG 放入 Authority staging，再用同一 mutation 写入 PNG、V3 document、binding 和相应的页面或项目配置值；页面级 `demos/<pageId>/config.values.json` 是与 Schema 并列的受管运行时资源，并由 project-core 的资源注册表统一校验，`whiteboards/bindings.json` 使用专用 binding 校验。non-live Workspace 使用 project-core 的可恢复白板事务：写入前比较所有文件哈希、以排他锁串行化，并用可恢复 journal 在中断后回滚 prepared 事务或完成已提交事务。任一校验、资源读取、渲染或写入失败，都不修改配置、binding 或 document revision，草稿保留并可重试；receipt 成功后编辑页才更新预览投影。

这像把图片、画稿和配置装进同一个密封包裹：任一校验或写入失败，原配置和已发布预览都不会被半途替换。目标字段以受限的规范路径表示，例如 `blanks[0].image` 或 `modules[0].image`；服务端逐段验证 Schema，递归解析 `oneOf` 分支，拒绝危险键和无法确认图片语义的分支。页面目标 ID 必须是工作区中已存在的安全单路径段，可保留 Unicode 页面目录名，但拒绝路径分隔符、点目录和控制字符。提交的并发基线按目标路径解析：持久化值存在时优先使用持久化值，缺失时只补足当前目标所需的 Schema 默认分支，不把无关默认值物化到运行值文件；Schema 默认值或持久化值发生变化仍会触发冲突。图片列表提交额外校验当前项仍与启动时的 URL 一致，避免排序或删除后的静默覆盖。

白板 PNG 的配置值统一保存为 workspace-relative 的 `assets/whiteboards/<sha>.png`。`demo-ui` 的 widget、iframe 配置投影和预览资源预热会把该 canonical path 解析为当前 session 的 workspace 资源 URL；原型预览的 `data-bind-src`/`href` 绑定和 HTML/CSS 初始资源也通过同一规则转换，避免绑定图片在 Shadow DOM 内按页面相对路径丢失。不满足受管 `assets/` 图片路径约束的字符串保持原有解析规则，不会扩大可访问范围。

服务端回填渲染固定使用完整画布尺寸和白色背景，只输出可见节点；隐藏节点不输出，锁定节点仍输出，不包含选区框、工具栏、控制点和评论标记。非法 scene、缺失/非 PNG 受管资源、输出尺寸不一致、空输出或未渲染的可见节点均直接报中文错误，不回退到默认空白场景。React 编辑与预览入口也沿用 fail-closed 语义：遇到无法渲染的场景显示中文错误并停止渲染，不过滤问题节点后继续展示局部内容。

## 输入与交互边界

服务端接受 Schema 明确标记的单图、图片列表及对象数组中的同类字段，并验证完整目标路径。`format: image`、`ui:widget: image`、明确的图片列表和嵌套 `oneOf` 对象数组图片均可进入白板；普通文件、视频、变体、视频封面及跨作用域复用不提供该入口。共享表单按当前数组索引取得父级默认值：默认单图隐藏删除，替换后显示删除并可恢复该位置的默认图片；多图仍支持逐项删除和整体恢复默认。

PNG 需满足签名和大小限制；scene、bridge profile、受管 image assetRef 与 binding 均在受管写入前校验。持久化 image `src` 不接受 `data:`、`blob:` 或外链；资产身份使用 `nodeSemantics.assetRef`，render-time URL 只在受控渲染阶段解析。白板 bridge 的诊断保留稳定错误码供日志和指标使用，但用户界面只展示中文可读文案；未知诊断也回退为中文通用提示，避免将英文内部错误直接透传给创作者。对话框导出失败会保留完整 document 草稿并允许重试。
回填请求携带完整 `WhiteboardDocumentV3` 与 `baseDocumentRevision`；V1/V2 文档只作为读取兼容格式，新提交统一升级为 V3。图片资产 API 负责解析项目图片 API、`assets/...`、会话资源、`/api/images/...`、data URL 和外部 HTTP，并在进入文档前统一落成静态 PNG；无法解码、资源失效、跨域捕获失败且服务端也无法安全解码时阻止回填。持久化 image `src` 不接受 `data:`、`blob:` 或外链；资产身份使用 `nodeSemantics.assetRef`，render-time URL 只在受控服务端渲染阶段解析。白板 bridge 的诊断保留稳定错误码供日志和指标使用，但用户界面只展示中文可读文案；代码 bridge 的限制只影响代码导入/导出，不影响人工编辑和 PNG 回填。对话框导出失败会保留完整 document 草稿并允许重试。

Dialog 拦截脏稿状态下的 Esc、遮罩和关闭动作，并在确认后才丢弃本地稿。白板内部命令面板和快捷键帮助先消费自己的 Esc 并停止冒泡；只有内部浮层关闭后再次按 Esc，才交由外层 Dialog 执行脏稿确认或关闭。创作端编辑页始终向可编辑图片字段注入白板启动能力；共享表单仍由宿主回调决定是否展示入口，因此使用端和只读配置不会获得创作端存储能力。

白板主工具栏的“图片”是一次性上传动作，不会把 controller 切换到持续图片绘图态。点击按钮或命令面板动作后，`SketchEditorCanvas` 通过宿主 ref 打开自身的本地文件选择器；选中的图片默认插入当前视口中心并自动选中，取消或无有效文件不产生 scene patch。空白拖拽保留为矩形框选；图片文件拖入空白处、粘贴图片、拖入既有图片替换和属性面板替换仍沿用原有落点/目标语义。Studio、`WhiteboardDialog` 和页面编辑宿主均接入同一能力，创作端不复制图片解析逻辑。

## 图片尺寸、裁剪与描边

普通图片由 `SketchEditorSurface` 在浏览器解码完成后读取 `naturalWidth`/`naturalHeight`。新建或替换图片的默认 frame 使用原始比例，并按 `min(1, 600 / max(width, height))` 缩放；因此最长边不超过 600px，用户后续通过拖拽或位置与大小面板修改的 frame 不会被原始尺寸逻辑覆盖。新建图片默认 `imageFit: contain` 且无描边；替换图片重新计算默认 frame，同时保留位置、样式、绑定和图层，清除旧裁剪。`source-background` 始终保留整板 frame，并继续使用背景的 cover 语义。

图片裁剪写在 scene 节点的 `imageCrop` 中，不修改源图：`sourceRect` 是原图归一化坐标，节点 `x/y/width/height` 是当前裁剪结果边界，`originalFrame` 与 `originalImageFit` 用于重复裁剪和重置。`sourceRect.x/y` 可以为有限负数或超过 1，只要源区域仍与原图有交集；`width/height` 仍为正数且不超过 1。矩形裁剪从当前 frame 开始；圆形裁剪沿用当前 frame，正方形渲染为正圆，非正方形渲染为对应椭圆。编辑器在裁剪期间隐藏普通工具栏和选择柄，固定裁剪框，用 50% 黑色遮罩标出当前图片内容在裁剪框外的部分；裁剪态渲染完整图片内容而不套 clip path，拖动裁剪框内部或当前图片内容区域会反向更新 `sourceRect.x/y`，允许顶部等局部空白保留，拖动柄只更新裁剪 frame 和 `sourceRect`。每次连续平移或缩放共用一个撤销检查点。点击外部或按 Esc 提交当前结果并退出，重置回到首次裁剪前的 frame/适配状态。共享的图片内容 frame 计算同时用于编辑态预览与提交态 SVG；提交态只在裁剪区域内使用矩形、圆形或椭圆 clip path，原图范围外不绘制图片。不带背景的 SVG 在圆形节点外及图片移出区域保持透明，`WhiteboardDialog` 导出 PNG 时仍使用现有整画布白底策略。core 和 React 编辑/预览入口遇到未解析的可见图片绑定都会 fail-closed，直接显示中文错误并停止渲染，不过滤问题节点后继续展示局部内容。

可描边的图片、形状、线条、路径和控件统一提供 `0–20px`、步进 `1px` 的描边宽度滑杆；属性面板和悬浮描边面板同时保留精确数值输入。描边宽度控件使用白板统一的浅色面板、浅灰边框和深色文字，滑轨、进度和滑块均显式使用浅色主题，避免继承宿主的深色原生控件样式。悬浮面板中宽度模块与颜色区保持独立间距，标题和值使用与“其他颜色”入口一致的轻量文字层级。悬浮工具条的填充色块与描边指示器共用 `16×16px` 视觉盒，保持独立 Studio 与创作端 Dialog 的图标尺寸对齐。文本与分组不提供描边控件。图片默认无描边，矩形/圆形裁剪分别使用对应的矩形/圆形描边几何。

## 独立开发边界

共享画笔设置浮层也由 `sketch-react` 唯一维护。它虽然通过 Portal 脱离工具栏挂载，但会显式恢复自身的指针事件能力，以兼容创作端 Dialog 的 Modal 外部事件隔离；Dialog 不复制画笔工具、状态或浮层。绘制中的临时节点仅作为共享预览层渲染在现有节点之上，不写入持久化 scene；提交时仍由 `sketch-core` 的新增操作统一分配层级。

白板编辑能力在 `@workbench/sketch-core` 与 `@workbench/sketch-react` 中维护；创作端只保留打开、持久化和图片回填的适配层。`@workbench/sketch-playground` 作为独立的 Whiteboard Studio，可用 `pnpm dev:whiteboard` 单独启动，不读取项目、登录、AI 或截图服务。

Studio 与 `WhiteboardDialog` 都将 scene 交给 `SketchEditorSurface`。这个共享工作区统一创建编辑 controller，并固定组合画布、快捷键作用域、画布内按需面板入口和底部浮动主工具栏；图片按钮的直接上传能力也在该共享工作区内实现。它不读取项目、会话或配置回填 API。宿主负责的只是工作区外层：Studio 提供独立开发环境，Dialog 管理草稿、关闭保护、PNG 导出与原子提交。页面编辑继续使用自己的 `SketchPageEditor` 固定检查器布局，不作为配置图片白板的兼容入口。

Whiteboard Studio 与创作端 Dialog 的主工具栏均由 `SketchEditorSurface profile="whiteboard"` 提供选择、抓手、矩形、圆形、画笔分组/橡皮、文本和图片入口。`whiteboard` profile 集中维护可见工具和可激活工具，两个集合共享同一份工具元组；profile 只控制创建入口与工具激活，不过滤 scene 节点，也不影响已有节点的选择、编辑、渲染、提交和回填。菱形、线条、箭头、便签和路径等没有创建入口的节点仍由完整 V3 scene 保存、恢复和服务端渲染，不因代码 bridge 或共享节点注册表自动新增入口。新建创作端白板保留确认过的“手绘页面”标题和当前图片背景，不注入共享工厂的教学便签；Studio 继续使用空白 fixture。

新增白板编辑能力先在 `SketchEditorSurface` 实现并在 Whiteboard Studio 验证，再以创作端对话框覆盖实际宿主尺寸和回填契约。这使白板可以独立演进，同时不会把创作端的存储与权限规则复制进编辑器内核。

图片配置入口统一由 `ImageInputActions` 承载，缩略图或上传占位块悬浮时只显示上传和白板绘图两个动作。`format:image`、`ui:widget:image`、明确的图片列表及嵌套对象数组图片均经同一入口能力传给宿主；普通文件和视频不注入白板动作。AI 绘图能力只在白板内部提供，不在配置图片控件、author-site 代理接口或独立候选面板中重复实现。图片列表白板回填只替换当前索引；聊天附件、文档编辑器和白板内部素材上传不复用该入口。

agent-service 的白板工具默认关闭，显式设置 `PI_AGENT_WHITEBOARD_TOOLS_ENABLED=true` 后才注册。`readWhiteboardContext`、`planWhiteboardComposition` 和 `applyWhiteboardActions` 使用 `whiteboard-context-v1`、`whiteboard-plan-v1`、`whiteboard-action-v2` schema 版本；上下文/计划可携带选区边界与安全区约束，reducer 拒绝把受保护角色放到安全区外。动作 schema 只允许字段级 patch，图片只能由受管 `placeAsset` 绑定，不能用普通节点 patch 替换 `src`；`setImageCrop` 可在校验后的图片节点上写入或清除非破坏裁剪及可选 frame。`applyWhiteboardActions` 面向完整原生 V3 文档执行，使用原生校验和 canonicalizer 保留 scene metadata、assets、bindings；`html-css-v2` bridge 校验仅用于代码导入/导出。AI 的 action 与代码导入当前只返回可审计的私有 draft 提案，不会单独写 document；宿主必须将该 draft 渲染为 PNG 并经 WhiteboardCommit 一次提交 document、binding 和配置值。计划与候选资产工具均不写 binding 或配置值，候选以 workspace、会话和 whiteboard 隔离；撤销由宿主 draft 控制，避免把 document revision 推进到与输出 PNG 不一致的状态。bridge profile 当前为 `html-css-v2`。

白板质量指标沿用编辑页诊断链路，不在 document 中写统计字段。`WhiteboardDialog` 记录 `whiteboard.code_import.completed/failed`、`whiteboard.asset_localization.completed/failed` 与 `whiteboard.commit.completed/failed`，携带规范化耗时、节点/资产数量、document revision 和脱敏错误码；其中首次可用图片耗时取资产本地化阶段耗时。AI 撤销率由 `ai.tool_call_finished` 中 `toolName=undoWhiteboardEdit` 的调用结果统计。固定 Chromium 字体下的 Studio 用例使用 Playwright PNG golden，并以像素容差而非图像哈希验收。

## 生命周期与清理

再次打开同一配置目标时，读取 API 只沿 binding 恢复对应 document，不会根据可复用 PNG 反向猜测所有权。单图、图片列表和嵌套对象图片提交均带有启动时的值保护；发生并发替换或 `baseDocumentRevision` 过期时服务端拒绝提交，对话框保留草稿并提供刷新远端版本的恢复入口。读取到损坏的 bound document 会返回错误并阻断回填，不会静默创建新稿；白板目录缺失绑定索引、索引损坏或任一 document 无法验证时 GC 均 fail-closed。GC 同时保护 binding 输出、配置值和有效 document 仍附着的白板 PNG；image-store 另行保护项目引用、白板 durable reference 和未过期草稿租约，只有经过宽限期且无任何引用的临时 PNG 才会清理。

复制页面会在同一 Workspace revision 中派生 document 与 binding；删除页面会先移除其 binding，保留 document 供延迟清理和删除快照恢复。每次成功回填都会生成一份保守的七天 GC 计划：仅删除未绑定且已过宽限期的 document，并且仅在没有 live binding 或任何配置值引用时删除白板专属 PNG。这样既不会把内容哈希复用的图片当作字段所有物，也不会因瞬时失败清掉用户可恢复的画稿。
