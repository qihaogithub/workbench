# 配置图片白板实现设计

配置图片白板是配置表单的一项创作端私有能力，具体用户规则见[配置系统需求](../配置系统_需求文档.md)。它不属于页面 runtime，也不向使用端暴露 scene。

## 资源与绑定

白板内容由独立的 `WhiteboardDocument` v2 保存，包含经 Sketch 协议校验的 scene、`nodeSemantics`、安全区、编辑器视图和单调的 `documentRevision`。`WhiteboardBinding` 才是配置目标与白板产物的关系：它保存配置范围、字段、图片列表原值保护条件、`documentRevisionAtOutput` 和 PNG 哈希。PNG 只是可去重资产，不保存字段归属；旧 v1 文档仅用于读取归一化，新写入一律为 v2。

代码是 document 的受限投影，不是第二份持久化真相。`@workbench/whiteboard-core` 提供 `html-css-v1` bridge：只允许带稳定 `data-sketch-id` 的 group、rect、ellipse、image、text、button、绝对 px 几何和白名单样式；复杂 CSS、外链资源、脚本和非 bridge 节点返回带 source range 的 diagnostics。`parse(serialize(document))` 只保证 bridge canonical fields 的稳定 round-trip。

受管资源目录将白板 document、binding 索引和图片资产纳入同一 Workspace 资源注册表；scene 不会写进普通 assets，也不会进入 HTML sandbox、execution ticket 或页面 scene。

资产引用在 `@workbench/whiteboard-core` 中使用 `candidate → localized → attached → output` 单向状态机。`transitionWhiteboardAsset` 只允许安全的本地或同源受管 workspace asset 路径（包括 `/api/images/<id>` 与会话 workspace 资源），`resolveWhiteboardAssetRefs` 在预览/提交前拒绝缺失、候选或未附着的 asset，并把已确认记录投影到 image node 的 `src`；对话框会在提交前将编辑器产生的临时 data URL 上传到受管图床，再写入 `assetRef`，不会把临时 URL 持久化。

## 提交路径

表单组件只产生无 IO 的图片目标，宿主以 capability 打开 `WhiteboardDialog`。对话框维持私有草稿，导出 PNG 后调用专用 WhiteboardCommit。live Workspace 先把二进制 PNG 放入 Authority staging，再用同一 mutation 写入 PNG、document、binding 和相应的页面或项目配置值。non-live Workspace 使用 project-core 的受限白板事务：写入前比较所有文件哈希、以排他锁串行化，并用可恢复 journal 在中断后回滚 prepared 事务或完成已提交事务。receipt 成功后编辑页才更新预览投影。

这像把图片、画稿和配置装进同一个密封包裹：任一校验或写入失败，原配置和已发布预览都不会被半途替换。目标字段以受限的规范路径表示，例如 `blanks[0].image`；服务端逐段验证 Schema、拒绝危险键和无法确认图片语义的分支。图片列表提交额外校验当前项仍与启动时的 URL 一致，避免排序或删除后的静默覆盖；写入前以 Schema 默认值补足缺失配置，默认图片也能安全回填。

## 输入与交互边界

服务端接受 Schema 明确标记的单图、图片列表及对象数组中的同类字段，并验证完整目标路径。共享表单按当前数组索引取得父级默认值：默认单图隐藏删除，替换后删除恢复该位置的默认值；多图逐项删除规则不变。PNG 需满足签名和大小限制；scene、bridge profile、受管 image assetRef 与 binding 均在受管写入前校验。持久化 image `src` 不接受 `data:`、`blob:` 或外链；资产身份使用 `nodeSemantics.assetRef`，render-time URL 只在受控渲染阶段解析。对话框导出失败会保留完整 document 草稿并允许重试。

Dialog 拦截脏稿状态下的 Esc、遮罩和关闭动作，并在确认后才丢弃本地稿。白板功能由 `NEXT_PUBLIC_WHITEBOARD_AUTHORING_ENABLED` 控制，避免未启用时向共享表单或使用端泄露创作端存储能力。

## 独立开发边界

白板编辑能力在 `@workbench/sketch-core` 与 `@workbench/sketch-react` 中维护；创作端只保留打开、持久化和图片回填的适配层。`@workbench/sketch-playground` 作为独立的 Whiteboard Studio，可用 `pnpm dev:whiteboard` 单独启动，不读取项目、登录、AI 或截图服务。

Studio 与 `WhiteboardDialog` 都将 scene 交给 `SketchEditorSurface`。这个共享工作区统一创建编辑 controller，并固定组合画布、快捷键作用域、画布内按需面板入口和底部浮动主工具栏；它不读取项目、会话或配置回填 API。宿主负责的只是工作区外层：Studio 提供独立开发环境，Dialog 管理草稿、关闭保护、PNG 导出与原子提交。页面编辑继续使用自己的 `SketchPageEditor` 固定检查器布局，不作为配置图片白板的兼容入口。

新增白板编辑能力先在 `SketchEditorSurface` 实现并在 Whiteboard Studio 验证，再以创作端对话框覆盖实际宿主尺寸和回填契约。这使白板可以独立演进，同时不会把创作端的存储与权限规则复制进编辑器内核。

图片配置入口统一由 `ImageInputActions` 承载，缩略图或上传占位块悬浮时只显示上传和白板绘图两个动作。`format:image`、`ui:widget:image`、明确的图片列表及嵌套对象数组图片均经同一入口能力传给宿主；普通文件和视频不注入白板动作。AI 绘图能力只在白板内部提供，不在配置图片控件、author-site 代理接口或独立候选面板中重复实现。图片列表白板回填只替换当前索引；聊天附件、文档编辑器和白板内部素材上传不复用该入口。

agent-service 的白板工具默认关闭，显式设置 `PI_AGENT_WHITEBOARD_TOOLS_ENABLED=true` 后才注册。`readWhiteboardContext`、`planWhiteboardComposition` 和 `applyWhiteboardActions` 使用 `whiteboard-context-v1`、`whiteboard-plan-v1`、`whiteboard-action-v1` schema 版本；上下文/计划可携带选区边界与安全区约束，reducer 拒绝把受保护角色放到安全区外。动作 schema 只允许字段级 patch，图片只能由受管 `placeAsset` 绑定，不能用普通节点 patch 替换 `src`。AI 的 action 与代码导入当前只返回可审计的私有 draft 提案，不会单独写 document；宿主必须将该 draft 渲染为 PNG 并经 WhiteboardCommit 一次提交 document、binding 和配置值。计划与候选资产工具均不写 binding 或配置值，候选以 workspace、会话和 whiteboard 隔离；撤销由宿主 draft 控制，避免把 document revision 推进到与输出 PNG 不一致的状态。

白板质量指标沿用编辑页诊断链路，不在 document 中写统计字段。`WhiteboardDialog` 记录 `whiteboard.code_import.completed/failed`、`whiteboard.asset_localization.completed/failed` 与 `whiteboard.commit.completed/failed`，携带规范化耗时、节点/资产数量、document revision 和脱敏错误码；其中首次可用图片耗时取资产本地化阶段耗时。AI 撤销率由 `ai.tool_call_finished` 中 `toolName=undoWhiteboardEdit` 的调用结果统计。固定 Chromium 字体下的 Studio 用例使用 Playwright PNG golden，并以像素容差而非图像哈希验收。


## 生命周期与清理

再次打开同一配置目标时，读取 API 只沿 binding 恢复对应 document，不会根据可复用 PNG 反向猜测所有权。单图和图片列表提交均带有启动时的值保护；发生并发替换或 `baseDocumentRevision` 过期时服务端拒绝提交，对话框保留草稿并提供刷新远端版本的恢复入口。读取到损坏的 bound document 会返回错误并阻断回填，不会静默创建新稿；白板目录缺失绑定索引、索引损坏或任一 document 无法验证时 GC 均 fail-closed。GC 同时保护 binding 输出、配置值和有效 document 仍附着的白板 PNG，只有经过宽限期且没有任何上述引用的 PNG 才会清理。

复制页面会在同一 Workspace revision 中派生 document 与 binding；删除页面会先移除其 binding，保留 document 供延迟清理和删除快照恢复。每次成功回填都会生成一份保守的七天 GC 计划：仅删除未绑定且已过宽限期的 document，并且仅在没有 live binding 或任何配置值引用时删除白板专属 PNG。这样既不会把内容哈希复用的图片当作字段所有物，也不会因瞬时失败清掉用户可恢复的画稿。
