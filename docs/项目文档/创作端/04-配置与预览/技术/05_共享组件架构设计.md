# 共享组件架构设计

> 版本：v1.6
> 更新日期：2026-08-13

## 一、包边界

`@workbench/demo-ui` 是创作端与使用端共同使用的前端组件包，负责配置控件、预览 renderer、单页预览外壳和画布工作台。`@workbench/shared` 只承载跨运行环境的类型、协议和纯契约；后端与领域包不得依赖 `demo-ui`。

共享的目标是让相同技术决策只有一份实现，而不是让所有入口拥有完全相同的产品行为。两类职责按以下边界拆分：

| 层级 | 职责 |
| :--- | :--- |
| `demo-ui` | 页面数据协议、尺寸解析、renderer 选择、单页滚动容器、模式切换骨架、画布组件 |
| 宿主页面 | 数据加载、配置状态、文档目标、草图编辑、视觉编辑、诊断、历史、权限与模式切换副作用 |

共享包内部只使用自身相对导入，不依赖宿主的路径别名。公共组件和类型统一由 `packages/demo-ui/src/index.ts` 导出；author-site 与 viewer-site 的本地 `components/demo` 文件只作为薄转导层。

## 二、预览舞台

### 2.1 页面规范化

`PreviewStagePage` 在既有 `CanvasPageData` 上补充 Schema 和 fallback 尺寸。宿主把自己的页面元数据、代码、原型、草图、配置和发布 URL 整理成该模型，并以稳定数组同时交给单页和画布。

页面 adapter 必须遵守运行时边界：

- 高保真 React 页携带源码、编译模块 URL 或发布 iframe URL；
- HTML/CSS 原型页携带原型 HTML、CSS 和 meta；
- 草图页携带序列化后的 scene 与 meta；
- 不用其它运行时的残留文件伪装当前页面类型。

创作端 adapter 从多个页面级 map 合并数据；独立使用端从发布清单和发布路径生成数据；嵌入 viewer 从 viewer data API 返回值生成数据。adapter 使用 memo 保持引用稳定，避免无意义地重挂载 iframe 或画布。

### 2.2 尺寸单一规则

`resolvePreviewStageSize` 是单页和画布的共同尺寸入口，优先级固定为：

1. 页面 Schema 中的 `$demo.previewSize`；
2. 页面已解析或发布的 `previewSize`；
3. `prototype.meta.json` 中的原型尺寸；
4. 仅供当前创作页使用的 `fallbackPreviewSize`。

`PreviewStage` 在把页面交给 `SinglePagePreview` 和 `PreviewCanvas` 前完成规范化。非活动页不得继承活动页的 fallback 尺寸，避免多页面画布串用尺寸。

### 2.3 renderer 单一规则

`resolvePagePreviewRenderer` 统一单页与画布的页面类型判断，顺序为发布 iframe、HTML/CSS 原型、草图、已编译模块、创作源码、空内容。

`SinglePagePreview` 根据该结果分发到 `IframePreviewFrame`、`PrototypePagePreview`、`SketchPagePreview` 或 `PreviewPanel`。`CanvasPageItem` 复用同一判断，但继续保留截图占位、iframe 预算、休眠、内容高度回写和不可直接操作页面内容等画布生命周期。

发布 iframe 的优先级不会改变发布协议。发布清单同时存在 iframe 与编译模块时优先 iframe；只有缺少 iframe 路径时才使用编译模块。

### 2.4 组合关系

| 组件 | 职责 |
| :--- | :--- |
| `SinglePagePreview` | 单页滚动容器、空状态和默认 runtime 分发 |
| `PreviewStageToolbar` | 默认页面选择器、居中插槽和宿主插槽（不再包含模式切换按钮） |
| `PreviewModeSwitcher` | 单页/画布/文档 受控视图切换，由宿主放在 Header 栏中间 |
| `PreviewStage` | 组合工具栏、默认单页和既有 `PreviewCanvas` |
| `PreviewPanel` | 高保真源码编译或已编译模块执行 |
| `PreviewCanvas` | 多页面布局、视口、资源调度和画布交互 |

`PreviewStage` 是受控组件，不自行修改活动页、模式或画布状态。宿主可通过页面选择插槽、工具栏居中插槽、工具栏尾部插槽、单页内容覆盖和 renderer 精确 props 保留专有能力。视图模式切换已从预览区工具栏迁移到 Header 栏中间，由宿主通过 `PreviewModeSwitcher` 触发，创作端支持 单页/画布/文档，浏览端提供 单页/画布。

创作端编辑页把单页预览的页面目录选择器收拢到工具栏居中插槽：中间显示当前页面名称，左右各一个箭头按钮用于在有序条目（先页面后文档）间快速切换上一页/下一页，点击中间名称展开目录下拉菜单（按“页面/文档”分组）。右侧插槽继续承载手绘编辑、历史等页面级操作按钮。

创作端编辑页仅在文档目标和草图编辑态覆盖默认单页内容；普通原型、草图只读态和高保真页继续走 `SinglePagePreview`。视觉编辑、自动修复、预览投影确认和诊断回调通过现有 renderer props 传入，没有在共享包中复制新的简化协议。

### 2.5 渲染传播优化

`SinglePagePreview` 和 `PreviewPanel` 使用 `React.memo` 加自定义比较器阻断无效重渲染。`PreviewStage` 不加 memo，因为其 props 中 `singlePageProps` 等 JSX 对象每次渲染都是新引用，memo 难以生效；重渲染级联在 `SinglePagePreview` 和 `PreviewPanel` 两层拦截。

| 组件 | 比较策略 | 不 memo 的场景 |
| :--- | :--- | :--- |
| `SinglePagePreview` | `page.id`、`page.code`、`page.compiledJsUrl`、`page.prototypeHtml/Css`、`page.configData`、`page.previewSize`、`page.runtimeType` 字段级浅比较 | — |
| `PreviewPanel` | `code`、`compiledJsUrl`、`previewSize`、`configData`、`demoId`、`sessionId`、`activityState`、`visualEditMode`、`visualAnnotationMode`、`isAutoRepairing` 浅比较 | `fillContainer` 模式（由内部 ResizeObserver 驱动） |

`SinglePagePreview` 内部对 `resolvePreviewStageSize(page)` 加 `useMemo`（依赖 `page?.schema`、`page?.previewSize`、`page?.prototypeMeta`、`page?.fallbackPreviewSize`），稳定 `previewSize` 返回值引用，使下游 `React.memo` 能正确比较。

## 三、配置组件

`ConfigForm` 根据 Schema 生成表单，`PageConfigPanel` 负责项目级与页面级配置的分层展示。图片、颜色、富文本、排序和元素定位控件均由共享包提供。

配置数据仍由宿主管理。共享预览组件只消费页面对应的 `configData`，不负责持久化，也不改变“配置更新无需重新编译”的预览运行时语义。

## 四、Markdown 编辑器（DocumentEditor）

`DocumentEditor` 是共享包中的 Markdown 富文本编辑器，被创作端配置表单、页面公约、知识库文档、AI 计划编辑和使用端文档浏览等多处复用。它基于 **Milkdown Crepe v7** 实现「Markdown 实时渲染输入」：直接书写 Markdown 语法，输入时在光标处实时折叠为渲染效果（如 `# ` 立即成标题、`**` 立即加粗）。所有入口使用同一组件和交互能力，不再维护按宿主分叉的编辑器实现。

### 4.1 模型与存储

- **Markdown 是主线模型**：编辑器内容即 Markdown 字符串，不再经过「富文本 → Markdown」的手写序列化，往返保真由 Milkdown 的官方 transformer（remark + ProseMirror）保证，避免旧 TipTap 方案下的格式丢失。
- **受控组件**：`onChange` 在 Markdown 变化时回调，外部 `value` 变化通过 Crepe 暴露的 Milkdown 实例执行 `replaceAll`，用 `lastEmittedRef` 防止双向回环。
- **只读态与生命周期**：通过 `crepe.setReadonly` 动态切换；组件卸载时销毁实例，避免监听与编辑状态泄漏。

### 4.2 能力

- **标准能力**：启用 Crepe 的 Cursor、ListItem、LinkTooltip、ImageBlock、BlockEdit、Placeholder、Toolbar、CodeMirror 和 Table，覆盖标题、粗/斜/删除线、行内代码、代码块、有序/无序/任务列表、引用、表格、链接、图片、分隔线、选区工具条和块拖拽。块菜单、TopBar 标题选择器与选区工具条首项均使用“正文、一级标题至六级标题”的中文名称；选区标题选择器复用 Milkdown 的块类型命令，不改变原有格式化按钮。菜单使用紧凑尺寸以适应创作端多栏布局。
- **能力边界**：Latex 和 Crepe AI 明确关闭；原生 TopBar 固定进入 Crepe 功能图，只在可编辑状态展示，只读切换不重建编辑器实例。标题样式下拉菜单使用独立于正文与“更多”浮层的交互层，保持完整按钮热区和选项命中，避免窄容器内菜单被后续内容遮挡。TopBar 以编辑器容器的实际宽度决定可见工具数量，超出空间的工具按既有顺序收纳到“更多”浮层，并在容器变宽时自动还原；该适配不改变格式化命令或消费方接口。迁移不扩张现有内容协议。
- **滚动边界**：编辑器高度受宿主面板约束时，Milkdown 内容层承担纵向滚动，正文超过可视区域仍可完整浏览；TopBar 继续贴在该滚动容器顶部，滚动正文时不离开可见区。
- **图片拖拽/粘贴上传**：Crepe ImageBlock 复用 `uploadHandler`。本地文件继续交给宿主上传；粘贴到编辑器的远程图片会先识别 URL，再交给宿主的上传处理器完成本地化，避免把外链地址直接写进工作区。未提供上传处理器时沿用浏览器临时对象地址。
- **业务集成**：`markdown/crepe-config.ts` 通过 `BlockEdit.buildMenu` 按 props 追加可搜索的「引用配置项」以及「上传视频/附件」。引用仍插入 `@[label](key)`，视频与附件仍保存现有 Markdown/HTML 表达。
- **占位**：Crepe Placeholder 使用文档级模式，只在空文档且可编辑时显示。

### 4.2.1 自适应宿主主题

编辑器只导入 Crepe common 结构样式，不直接套用固定浅色或暗色主题。`markdown/crepe-theme.css` 以官方 Frame 主题的“正文背景—控件表面—弱表面—描边—交互色”层级为基线，再由宿主的背景、前景和危险色推导完整 Crepe token；因此暗色工作台与浅色弹窗使用同一套关系，而不是各维护一份皮肤。正文使用比宿主底色略抬高的背景，TopBar、浮动工具条和菜单使用更深/更浅一层的控件表面，默认、悬停与选中状态分别使用可区分的前景色和不透明底色。标题与正文统一使用中文系统无衬线字体栈，避免西文衬线标题和中文正文混排时产生断裂感；代码仍使用等宽字体。

表格边框、单元格选中遮罩、节点选中和图片选中继续使用 Crepe common 中各自的组件规则。项目主题只提高这些规则依赖的 `outline`、`primary` 与 `selected` token 对比度，不对 `.ProseMirror-selectednode` 或 `.selectedCell` 增加全局覆盖，避免表格单元格出现双层描边。编辑正文不再额外嵌套固定宽度的居中“纸张”，而是直接使用宿主可用宽度和紧凑内边距，并遵守 `prefers-reduced-motion`。

### 4.3 接入与依赖

- **接口**：`value` / `onChange` / `readOnly` / `placeholder` / `uploadHandler` / `referenceCandidates` / `className`。旧版 `format`（markdown/html）与 `htmlSanitizer` 已移除，全部消费方统一以 Markdown 存储。编辑器为所见即所得实时渲染，不提供源码/预览切换。
- **宿主 UI**：共享组件不再依赖宿主 shadcn 控件；Crepe 结构样式与项目 token 主题在共享包内闭环。
- **依赖**：`@milkdown/crepe` 与 `@milkdown/kit` 为直接生产依赖；React 仍由宿主提供。TipTap、`prosemirror-markdown`、`@milkdown/react` 和 `@prosemirror-adapter/react` 已从该组件边界移除。

### 4.4 测试

`demo-ui` 用 Vitest 覆盖：Markdown 往返幂等（`markdown/__tests__/roundtrip.test.ts`）、编辑器集成渲染（`DocumentEditor.test.tsx`）、标题选择器（`markdown/heading-style-toolbar.test.ts`）、TopBar 溢出控制器（`markdown/top-bar-overflow.test.ts`）和 Frame 主题契约（`markdown/crepe-theme.test.ts`）。主题契约锁定完整 token、中文系统字体、可编辑 TopBar、标题下拉菜单的层级与点击热区、正文区滚动边界、工具栏三态、紧凑块手柄，并禁止重新引入覆盖表格选中的全局节点描边。author-site 的 Jest 因 Milkdown 为 ESM-only，通过 `jest-milkdown-mock.js` 全局映射 `@milkdown/*`。

## 五、运行环境与依赖

`demo-ui` 把 React 和 React DOM 声明为 peer dependency，由宿主提供。拖拽、编辑器和清洗能力属于共享组件的生产依赖。

author-site 和 viewer-site 的 Tailwind 配置必须扫描 `demo-ui` 源文件，否则共享组件中的工具类不会进入最终 CSS。`demo-ui` 不能引入新的 UI 框架，基础交互继续使用现有 Tailwind、Radix/shadcn 和 lucide 体系。

预览 iframe 模板属于运行时生成边界，不由 `PreviewStage` 生成。编辑态 fixed shell、发布 `iframe.html`、`cssImports` 和 cache bust 规则见 [动态编译方案](./01_动态编译方案.md)。

## 六、入口接入

| 入口 | 接入方式 | 保留在宿主的能力 |
| :--- | :--- | :--- |
| 创作端编辑页 | 完整 `PreviewStage` | 文档、草图编辑、视觉编辑、历史、诊断、转换与切换确认、单页居中目录导航 |
| 创作端项目级嵌入 viewer | 完整 `PreviewStage` | URL 参数、postMessage、配置面板显隐 |
| 创作端单页嵌入 viewer | `SinglePagePreview` | 应用图动作、路由参数、运行时状态 |
| 独立 viewer-site | 完整 `PreviewStage` | 发布数据加载、目录、配置面板、页面管理和 AI 问答 |

四个入口共享页面尺寸和 renderer 判断，但交互权限分别使用 `readonly`、`viewer` 或 `editor` 语义，不能把它们压缩成统一的布尔开关。

### 6.2 创作端编辑页代码分割

创作端编辑页使用 `next/dynamic({ ssr: false })` 惰性加载重组件，减小首次加载 JS 体积。被动态加载的组件分为三类：

| 类别 | 组件 | 分割理由 |
| :--- | :--- | :--- |
| 预览/配置 | `PreviewStage`、`PageConfigPanel` | iframe 编译 + 画布 + 表单 widgets，browser-only |
| AI 对话 | `AIChat` | 流式 SSE + Markdown + 工具 UI，browser-only |
| 条件渲染 | `VisualPropertyPanel`、`SketchEditorEngine*`、`DemoPageTree`、`WorkspaceFileTree`、`KnowledgePanel`、5 个 Dialog | 仅在特定 Tab/弹窗/运行时下渲染 |

`useSketchEditorEngineHost` 等 hook 保持静态 import（hook 不能动态加载），仅对展示组件做 `dynamic()`。type import 也保持静态，仅对组件值做 `dynamic()`。所有动态组件使用 `loading: () => null` 避免闪烁。

## 七、测试门禁

`demo-ui` 使用 Vitest、jsdom 和 Testing Library 验证尺寸优先级、renderer 选择、单页分发、受控模式切换、插槽、内容覆盖、空活动页和三种画布交互模式。根 `check:demo-ui` 同时运行类型检查与包内测试。

宿主继续负责集成与发布回归，重点锁定：

- 创作端模式切换确认、首次画布适配、页面/文档选择和草图编辑覆盖；
- 嵌入 viewer 的消息通信与应用图动作；
- 使用端发布 iframe 优先、编译模块回退和配置联动；
- 发布 `iframe.html`、`cssImports` 与 cache bust 不变。
