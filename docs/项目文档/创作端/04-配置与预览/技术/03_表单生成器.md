# 配置系统 - 表单生成器

## 一、职责边界

`ConfigForm` 根据页面或项目 `config.schema.json` 生成运行时配置表单，`PageConfigPanel` 负责共享配置与页面配置的分层展示。表单只维护当前会话中的临时值，配置持久化和预览投影仍由宿主负责。

### 1.1 业务与资源分区

字段语义由 Schema 元数据标识：标记为业务配置的字段进入“业务配置”区，其余字段（包括历史未标记字段）进入“资源配置”区。`PageConfigPanel` 将项目级和页面级字段合并到对应语义区，而不是先按作用域拆出两套面板；当两个语义区同时存在时，仅用弱标题和细分隔线建立阅读节奏，避免卡片或嵌套标题造成额外层级。

`ConfigForm` 接收可选语义筛选，并将它与现有的展示分类筛选共同应用。筛选只影响当前表单的可见字段，不改变 Schema、运行值、字段权限、保存队列或预览投影。项目级字段仍先受页面绑定范围限制，再进行语义和分类筛选；因此页面不会看到其未消费的共享字段。`PageConfigPanel` 在语义区内隐藏 Schema 字段分组标题，避免形成第三层视觉结构。项目级表单可选择为顶层字段传入来源提示：字段标题行仅在悬停或键盘聚焦时显示低强调图标，并通过 Tooltip 说明“项目共享配置”；页面级字段和数组嵌套字段不继承该提示。

## 二、控件映射

字段映射按 `ui:widget`、`format`、基础类型三层解析。颜色相关字段优先按显式 `format` 映射到共享 `@workbench/color-picker`：`color` 写入 `#RRGGBB | null`，`opacity` 写入 `0–100 | null`，`color-opacity` 写入规范化 `rgba(r, g, b, a) | null`。颜色选择器的交互核心直接采用 [shadcn.io Color Picker](https://www.shadcn.io/components/color-picker) 的公开组件源，保留 shadcn 的源码可见、可组合方式；本地适配层只负责三种 schema `format` 的值转换、空值和预设语义。没有控件覆盖时使用下拉选择器。单值枚举可通过 `ui:widget` 选择 `radio` 或 `segmented`，两者只改变展示，不改变枚举值、默认值和校验行为。

选项展示优先使用 `enumNames`，否则显示枚举值。表单把枚举项映射为稳定的内部选项索引，提交时再还原为 Schema 中的原始值，因此字符串、数字枚举都能使用同一套交互。

## 三、共享选项组

`OptionGroup` 是 `demo-ui` 内的共享展示组件，使用原生 `input[type=radio]` 作为交互基础：

- `radio` 以纵向选项组呈现，适合需要同时比较的少量或较长文案；
- `segmented` 以填满可用宽度的横向分段呈现，固定 30px 高度并使用均匀留白和更强的选中对比，适合桌面端 2–4 个短标签和频繁切换；触控优先场景应使用 `radio`；
- 两种变体都提供 `radiogroup` 名称、可见焦点、禁用态和浏览器原生方向键行为；
- 标签过长、选项较多或容器狭窄时，产品层应选择 `radio` 或下拉，而不是强行压缩分段控件。

创作端和使用端都通过 `demo-ui` 的 `FieldRenderer` 消费同一实现。创作端视觉属性面板已有的专用分段交互不改变配置表单契约；后续若需要统一视觉，可在共享组件层复用样式。

## 四、配置定义编辑

配置定义编辑器仍以 `enum` 作为唯一的枚举字段类型，并额外保存 `enumWidget` 展示偏好。写入 Schema 时，`radio` / `segmented` 转换为 `ui:widget`；`select` 删除这两个覆盖值，回到默认下拉。读取旧 Schema 时没有覆盖值的枚举字段回填为 `select`。

默认值编辑器会复制同一控件覆盖，避免编辑默认值时出现与日常配置面板不同的交互。控件偏好属于字段元数据，不参与运行值清理计划，也不会触发字段类型变更。

字段标题编辑入口覆盖根字段、显式分组字段以及对象数组/`oneOf` 分支中的嵌套字段。`FieldRenderer` 点击标题时同时传递字段 key 和稳定的 Schema 字段路径，例如 `modules[type=image].image`；面板按该路径定位原始属性并只更新目标节点，避免把嵌套字段误当成根字段。嵌套字段的默认值属于新建数组条目的局部默认，不写入根配置值对象。

## 五、其它控件

普通文本、数字、开关、图片、视频、MP3 音频、富文本、数组和定位字段继续沿用现有 `FieldRenderer` 分支。颜色字段统一由共享 `ColorPicker` 渲染，组件包含色板、色相、Hex/RGB/HSL 输入切换（`color-opacity` 增加 RGBA）、浏览器支持时的吸管取色、透明度、预设和清除能力；输入格式切换不改变 schema 业务 `format`。预设从 `ui:options.colorPresets` 读取，只替换颜色并保留透明度。空值保持为 `null` 并显示无色/未设置，透明度 0 不被当作空值。图片与文件由 `FileUploadWidget`、`ImageListWidget` 负责上传和尺寸规则；单图、多图和音频等上传占位控件统一使用 10% 不透明度的黑色填充（`bg-black/10`），上传中、禁用和悬停状态仍使用各自的状态反馈；`format: "file"` 字段的 `accept` 包含 `audio/mpeg` 或 `.mp3` 时自动切换为音频模式，默认大小上限为 1 MiB，上传后展示音频状态卡片，不自动播放且不渲染图片。排序、定位和复杂对象数组仍由专用控件承载，不通过枚举选项组表达。

对象数组由 `ArrayFieldGroup` 递归渲染。每个数组层级独立读取 `FieldConfig.sortable`：Schema 必须显式声明 `$demo.sortable`，`true` 显示拖拽手柄并启用 dnd-kit 排序，`false` 隐藏拖拽手柄并禁用顺序写回，缺失或非法值按不可排序处理。无论是否排序，展开、添加、删除、详情 Sheet 和子数组都保持可用；新增对象时，未显式提供默认值的数组/对象子字段分别初始化为 `[]` / `{}`，避免新增父项后嵌套列表拿到字符串空值。`visibleWhen` 由共享纯函数按当前对象的兄弟字段与默认值求值，普通对象数组、`oneOf` 变体、内联折叠和详情 Sheet 行为一致；每个数组项独立判断，隐藏只影响渲染，不删除字段当前值。条目头部将标题/箭头按钮与左侧容器设为 `flex-1`，使热区覆盖拖拽手柄（如有）和右侧删除入口之间的行内剩余宽度；删除按钮所在操作容器默认使用 `opacity-0` 与 `pointer-events-none`，通过 `group-hover` 显示并恢复指针事件，同时保留 `group-focus-within` 键盘可达回退；拖拽手柄和删除按钮仍是独立控件，不共享标题点击事件。

## 六、配置项能力与标题批注气泡

`PageConfigPanel` 按当前实际页面计算项目级、页面级的 `ConfigItemCapabilities`，再由 `ConfigForm` 传给每个 `FieldRenderer`。能力拆成四个维度：定义是否可编辑、值是否可编辑、是否可添加批注和不可编辑原因。引用页使用 `canEditDefinition=false`、`canEditValue=true`：定义入口、配置要求、设计规范编辑和白板入口关闭，普通值与资源上传控件仍可用；值只由宿主保留在当前会话，不触发源项目、目标项目或数据库写入。

字段标题按权限渲染为直接编辑按钮或普通文本：创作端具备定义编辑权限时，点击、Enter 或 Space 标题直接打开配置项编辑 Dialog；浏览端、只读字段和无定义编辑权限时不渲染按钮。标题悬浮或聚焦不会打开操作菜单。规范 Tag（蓝色）和批注 Tag 紧跟标题排列；创作端无匹配线程时批注 Tag 仅在鼠标悬停标题所在行或该行获得键盘焦点时以中性色弱化显示，有任意线程（包括已解决线程）时常驻并以琥珀色高亮；浏览端无匹配线程时不渲染，有任意线程时常驻并高亮。文案固定为“批注”且不显示数字。创作端空批注状态不接收鼠标事件，避免遮挡标题行的其它交互。

`ConfigCommentPopover` 以 `scope + pageId + fieldKey` 精确筛选线程，沿用规范气泡的 portal、定位、箭头、最大高度和移动端全宽回退；桌面端气泡的理想垂直中心与触发标签中心重合，实际顶部按上下各 16px 的视口安全边距钳制，内容过高时只让正文区域滚动；配置栏滚动、窗口尺寸变化或内容尺寸变化后重新对齐。正文按最新在前顺序展示，线程列表独立滚动。创作端主批注和回复默认安全渲染为只读 Markdown，只有点击图标才切换当前卡片编辑；主批注使用 `CommentMarkdownEditor` 在输入停止 800ms 后自动保存，失焦或关闭前 flush，空正文恢复最近保存值。新增批注编辑器固定在气泡底部，默认单行并自动增高，失焦或 Cmd/Ctrl+Enter 提交，不显示保存按钮；回复编辑不自动保存，通过发送/确认图标或 Cmd/Ctrl+Enter 显式提交。编辑器隐藏固定 TopBar，但保留选中文本后的浮动 Toolbar，正文区达到约 8 行后内部滚动。浏览端只传入线程数据并隐藏新增编辑区和全部写入控件。配置项评论不回写 Schema，也不复用 `$demo.note`。宿主接入评论控制器时，表单通过布尔 `hasConfigComment` resolver 判断标签是否高亮，并将能力、resolver 和字段路径继续透传给嵌套对象数组的子 `FieldRenderer`；未接入评论能力的通用表单不渲染不可用入口。

### 6.1 值编辑能力的控件覆盖

`canEditValue=false` 时，文本、长文本、数字、整数、滑块、开关、颜色、枚举选择、单选/分段、图片、文件、音频、视频、富文本、数组、级联、多选、定位和白板入口均不得产生配置变更；数组的新增、删除、排序操作也一并隐藏。引用页的 `canEditValue=true` 允许上述普通值和上传、替换、删除操作，但白板入口仍由宿主专属能力控制。可编辑但 `$demo.sortable: false` 的数组仍显示新增/删除/展开，不显示拖拽手柄；缺失声明的对象数组也按不可排序处理。该规则只影响配置栏交互，评论和只读设计规范入口仍按各自能力工作。

## 七、三级关卡设置 Sheet

对象数组详情采用显式能力开关，不根据嵌套深度自动改变所有数组的展示方式。Schema 在数组字段的 `ui:options` 中设置 `detailPresentation: "sheet"` 后，`ArrayFieldGroup` 仍负责列表、添加、删除，并按该数组的 `$demo.sortable` 能力决定是否排序；条目主体会向 `PageConfigPanel` 发出稳定条目 ID、字段路径、面包屑和字段回写回调；未设置该选项的数组保持原有折叠卡片。详情 Sheet 与不可排序数组可以同时使用；排序能力不得从父数组继承，也不得依赖 `ui:options.sortable`。

`PageConfigPanel` 只维护一个 `ConfigDetailSheet` 实例。进入详情时保存父级滚动位置和触发元素，父级配置栏通过 `inert` 与 `aria-hidden` 暂停交互；Sheet 关闭、遮罩、Esc 或返回按钮会恢复父级滚动和焦点。路由可以保留完整祖先路径供返回历史使用，但 Sheet 顶部只展示当前条目（例如 `关卡 01`）；“关卡模块 / 关卡列表”属于 Sheet 外的父级配置栏，不渲染在 Sheet 面包屑中。更深层对象继续替换同一个 Sheet 路由，不创建 Sheet 套 Sheet。

Sheet 内直接复用 `FieldRenderer`，所以图片/文件、枚举、坐标、批注、设计规范、白板、定位编辑和条件显隐仍沿用日常配置表单的值语义与权限矩阵。字段编辑后先更新 Sheet 的乐观本地条目，使兄弟条件立即重算；宿主配置回投后再按稳定实例同步最新条目，避免旧 getter 覆盖本地开关状态。定位字段由 Sheet 自身的 `PositionConfigContext` 注册，提交仍通过原有 `onChange` 透传到宿主；数组条目使用组件内稳定 ephemeral ID，不把 UI 身份写回业务配置。

创作端的 Sheet 以容器模式挂载在右侧配置栏根节点内，而不是挂到文档根层：外层蒙层只覆盖配置栏内部，Sheet 本体保留约 8px 内缩、最大宽度 500px，并使用配置栏剩余高度独立滚动。进入时面板保持不透明，只使用显式 `transform` 做约 300ms 的无过冲缓进缓出，蒙层单独使用约 320ms 淡入，避免底层 underlay 透出形成残影；underlay 不做额外的 `translate` 或 `scale`，保持底层页面几何稳定。组件以内联过渡时长锁定这两个值，避免 Tailwind 任意时长工具类在运行时回退到默认 150ms。不使用 `animate-in/slide-in-from-right` 关键帧组合，`prefers-reduced-motion` 仍关闭过渡。嵌入模式不锁定 `body`，因此中间预览区、左侧对话区和其他右侧栏外页面仍可继续交互；配置栏列表 underlay 仍由 `inert`/`aria-hidden` 暂停，避免 Sheet 打开时误改父级字段。

关卡列表的推荐声明如下：`detailPresentation: "sheet"`、`detailBreadcrumbTitle: "关卡列表"`、`itemTitleTemplate: "关卡 {index}"`，并在数组字段的 `$demo` 中显式设置 `sortable:false`。其中 `{index}` 是从 1 开始的两位序号，生成“关卡 01”这类稳定展示标题；这样一级页面和二级模块继续内联，点击具体关卡才打开三级 Sheet。

实现入口：[`ConfigDetailSheet.tsx`](../../../../../packages/demo-ui/src/ConfigDetailSheet.tsx)、[`PageConfigPanel.tsx`](../../../../../packages/demo-ui/src/PageConfigPanel.tsx)、[`ArrayFieldGroup.tsx`](../../../../../packages/demo-ui/src/ArrayFieldGroup.tsx)。

## 八、验证与测试

- Schema 定义 mutation 覆盖 `select`、`radio`、`segmented` 的读写回环；

- `PageConfigPanel.test.tsx` 覆盖跨作用域合并后的业务/资源区块、无作用域大标题和共享来源提示；`ConfigForm.test.tsx` 与 `config-categories.test.ts` 覆盖语义筛选、分类筛选交集、项目级绑定计数和嵌套字段不继承来源提示。
