# 配置系统 - 表单生成器

## 一、职责边界

`ConfigForm` 根据页面或项目 `config.schema.json` 生成运行时配置表单，`PageConfigPanel` 负责共享配置与页面配置的分层展示。表单只维护当前会话中的临时值，配置持久化和预览投影仍由宿主负责。

## 二、控件映射

字段映射按 `ui:widget`、`format`、基础类型三层解析。`enum` 是值语义和校验约束；没有控件覆盖时使用下拉选择器。单值枚举可通过 `ui:widget` 选择 `radio` 或 `segmented`，两者只改变展示，不改变枚举值、默认值和校验行为。

选项展示优先使用 `enumNames`，否则显示枚举值。表单把枚举项映射为稳定的内部选项索引，提交时再还原为 Schema 中的原始值，因此字符串、数字枚举都能使用同一套交互。

## 三、共享选项组

`OptionGroup` 是 `demo-ui` 内的共享展示组件，使用原生 `input[type=radio]` 作为交互基础：

- `radio` 以纵向选项组呈现，适合需要同时比较的少量或较长文案；
- `segmented` 以填满可用宽度的横向分段呈现，固定 30px 高度并使用均匀留白和更强的选中对比，适合桌面端 2–4 个短标签和频繁切换；触控优先场景应使用 `radio`；
- 两种变体都提供 `radiogroup` 名称、可见焦点、禁用态和浏览器原生方向键行为；
- 标签过长、选项较多或容器狭窄时，产品层应选择 `radio` 或下拉，而不是强行压缩分段控件。

创作端和使用端都通过 `demo-ui` 的 `FieldRenderer` 消费同一实现。创作端视觉属性面板已有的专用分段交互不改变配置表单契约；后续若需要统一视觉，可在共享组件层复用样式。

## 四、配置定义编辑

配置定义编辑器仍以 `enum` 作为唯一的枚举字段类型，并额外保存 `enumWidget` 展示偏好。写入 Schema 时，`radio` / `segmented` 转换为 `ui:widget`；`select` 删除这两个覆盖值，回到默认下拉。读取旧 Schema 时没有覆盖值的枚举字段回填为 `select`。

默认值编辑器会复制同一控件覆盖，避免编辑默认值时出现与日常配置面板不同的交互。控件偏好属于字段元数据，不参与运行值清理计划，也不会触发字段类型变更。

## 五、其它控件

普通文本、数字、开关、颜色、图片、视频、MP3 音频、富文本、数组和定位字段继续沿用现有 `FieldRenderer` 分支。图片与文件由 `FileUploadWidget`、`ImageListWidget` 负责上传和尺寸规则；`format: "file"` 字段的 `accept` 包含 `audio/mpeg` 或 `.mp3` 时自动切换为音频模式，默认大小上限为 1 MiB，上传后展示音频状态卡片，不自动播放且不渲染图片。颜色输入保持紧凑高度，容器使用 `w-full min-w-[132px] max-w-[180px]` 自适应宽度，并对 Hex 文本进行溢出处理。排序、定位和复杂对象数组仍由专用控件承载，不通过枚举选项组表达。

## 六、验证与测试

- Schema 定义 mutation 覆盖 `select`、`radio`、`segmented` 的读写回环；
- `ConfigForm` 覆盖默认值回显、`enumNames` 标签和选项切换后的原始枚举值回调；
- 共享组件使用语义化 `radiogroup` / `radio`，并检查键盘可达性所需的原生表单结构；
- `FileUploadWidget` 覆盖 MP3 accept 自动识别、1 MiB 客户端拦截、音频状态卡片和替换/删除操作；颜色输入覆盖自适应宽度与完整 Hex 值展示；
- `pnpm --filter @workbench/demo-ui typecheck` 与 `pnpm --filter @workbench/demo-ui test` 作为改动后的基础门禁。
