# 10 评论批注机制

评论批注的产品规则见[预览系统需求](../预览系统_需求文档.md)中的页面批注部分。本文件说明双端如何复用同一套输入、存储和展示机制。

## 输入与提及

共享评论输入器把普通文字与提及标签放在同一个可编辑区域。标签是不可拆分的结构化对象，显示为带身份色的短标签；删除键落在标签边缘时会移除整个对象，并同步清理提及列表。

输入器从光标向前寻找最近的 `@`，不要求它前方有空格。候选列表在打开时固定首项为活动项，方向键切换、回车或 Tab 确认、Escape 关闭。最终提交时，标签会被还原为正文中的 `@名称`，并与独立的 `mentions` 列表一同提交，因此已存评论和评论展示仍可使用同一份数据契约。

## 编辑与同步

主评论和回复都可进入编辑态，编辑态复用相同输入器并将修改后的正文、提及列表提交给各自更新接口。服务端先按既有作者权限验证，再原子更新对应对象及线程更新时间；匿名用户仍不能提及其他普通用户。

更新完成后服务端广播完整线程更新事件，订阅方以该线程替换本地副本，避免主评论和回复的局部更新产生不一致。编辑中首次加入 AI 提及会沿用创建评论时的入队规则；移除提及不会回滚已经开始的 AI 任务。

## 预览标记边界

`CommentLayer` 负责计算标记位置，但标记是否渲染由宿主提供的可见性开关决定。创作端和使用端在右侧「评论」页签激活时开启该开关；切换到其他页签只隐藏预览覆盖层，不清除线程数据、评论模式或当前选择。

这种分工让评论功能的状态保持在页面级，而展示范围始终与用户当前的工作上下文一致。

## 未解决提示范围

`useComments` 的 `target` 可省略：省略时 REST 与 WebSocket 都维护项目内全部评论线程；传入页面或文档 target 时继续只维护对应目标。共享筛选工具将页面线程、文档线程和未解决计数的规则集中在 `demo-ui`，避免宿主各自解释同一份数据。

作者编辑页统一省略 `target`，通过一次项目级 REST/WS 订阅维护全部评论线程；单页和画布模式都从这份线程集合派生当前页面线程、页面标签数量和配置项目标线程。右侧评论列表使用完整页面线程分组，预览标记和线程弹窗仍只接收当前聚焦页面线程，不能把项目级结果直接映射到其他页面坐标。文档评论不参与项目级红点统计。

`CommentUnreadDot` 只在存在未解决评论时渲染红色圆点，绝对定位且不显示数字。页签本身通过 `title` 和 `aria-label` 提供“有 N 条未解决评论”的文字提示，圆点保持 `aria-hidden`。

## 配置项评论目标

配置项评论与页面、文档评论共用 `CommentThread`，但目标身份不同。配置目标由 `kind: "config"`、`scope`、页面级时的 `pageId` 和 `fieldKey` 组成，`fieldTitleSnapshot` 只用于展示；它不携带 `anchor`、`pin` 或 `documentAnchor`。项目级配置不传页面 ID，页面级配置必须传当前引用页/普通页面 ID。

评论列表查询采用显式的配置范围、页面和字段条件，服务端拒绝 scope 与 pageId 不匹配、缺少 fieldKey 或混入页面/文档锚点的请求。配置项评论写入当前项目 comments store：引用页不会把评论写入源项目。字段删除或改名后线程仍保留，前端用字段快照或“配置项已不存在”状态继续展示。

作者编辑页订阅项目内全部评论，再用统一筛选函数把页面线程和当前配置目标线程分发到右侧栏。字段标题的操作 Popover 触发 `ConfigCommentPopover`，气泡与设计规范共用 portal、定位和外部点击机制；目标下的全部线程按最新在前顺序滚动展示，主评论在当前卡片内原位编辑，新增和编辑正文经过统一 Markdown 清洗，回复继续走 `MentionTextarea` 和既有提及协议。解决、恢复、删除和 WS 更新沿用现有线程接口，因此配置项评论不会进入页面评论未处理数量。viewer 本期不传入配置批注入口，保持现有只读配置面板语义。

### 与相邻语义的边界

| 能力 | 语义 | 存储/消费 |
| :-- | :-- | :-- |
| 设计规范 | 设计指导信息，可复用到页面或配置项 | 设计规范文档与规范面板 |
| 页面需求 | 页面级 Markdown 需求，可软引用多个配置 | 页面需求文档 |
| 配置项批注 | 字段级评论线程，面向业务说明和协作跟进 | comments store、评论面板和 WS |
| `$demo.note` | 历史兼容字段，仅保留读取能力 | 配置 Schema 读取链路 |

## 画布侧栏边界

画布工作台复用右侧的评论列表与线程选择能力，并与配置面板通过页签切换。用户在画布评论模式点击页面卡片时，透明选择层优先接收点击；点击的屏幕坐标由外层评论层换算后，复用与单页相同的浮动输入框。提交时保存为页面级锚点与卡片内归一化位置，不切换到单页预览。这样评论能稳定归属页面，又不会绑定到会随画布缩放与拖拽变化的自由坐标。

画布页面标题旁的“评论 X”标签由项目级线程派生，X 只计算 `resolved=false` 的页面线程；标签点击先同步页面选择，再打开评论页签，不触动画布视口重定位。评论列表先执行“全部 / @我的 / 未解决”筛选，再按页面顺序分组；分组标题显示页面名称及该组未处理数量，“全部”筛选仍可查看已处理线程。画布当前页面变化时，侧栏通过页面分组锚点滚动定位并短暂高亮；选择其他页面线程时，宿主先切换聚焦页面，确保 `CommentLayer` 的页面线程与活动线程一致。滚动动画遵循 `prefers-reduced-motion`。
