# HTML 资源 Bundle 与受控本地化

本设计扩展 [HTML 导入需求](../HTML导入_需求文档.md) 的单文件能力。它把本地 bundle 和远程资源本地化视为两条独立、明确授权的流程，避免“上传一个网页”隐含地变成“替用户访问互联网”。

## 本地 Bundle

ZIP 与文件夹上传先在导入边界逐项读取，再交给 project-core 的同一规范化规则。入口必须唯一且为 `index.html`；目录穿越、绝对路径、重复文件、加密条目、超出条目数或解压体积上限的 bundle 均直接拒绝。解析过程不把 ZIP 解压到临时目录，避免残留和路径覆盖。

相对资源仅能指向 bundle 内文件。规范化阶段将可识别资源替换为受控数据引用，并为每份内容生成 SHA-256 引用；同一字节内容在一个 bundle 中只有一个身份。外部脚本、模块 import、iframe、Worker 与网络请求不随 bundle 获得任何额外权限，仍由 sandbox 能力策略阻断。

## 远程静态资源的显式本地化

远程图片、样式、字体与媒体不会在 prepare、preview 或 commit 时自动下载。用户必须在兼容性详情中逐项选择本地化，系统才创建独立作业。作业只允许 HTTP(S)，并在每次重定向后重新校验目标：拒绝私网、回环、链路本地、文件协议与非标准端口；限制重定向次数、响应 MIME、单文件和总字节数、下载耗时与并发数。

下载结果必须先经过内容哈希、类型嗅探与可执行内容门禁，再作为私有项目资产写入；失败、取消或许可信息缺失不会保留半成品。诊断只记录域名类别、哈希、大小桶、策略版本和错误码，不记录完整 URL、授权 token 或响应体。用户负责确认自己拥有下载、保留和发布该资源的权限。

## 内容寻址与生命周期

资源引用的稳定身份是内容哈希，不是原始 URL 或文件名。页面元数据只保存资源引用和策略摘要；原始路径用于导入期映射，提交后不作为公开资源地址。引用计数或一次扫描得出的可达集合负责回收未被 draft、页面版本或发布版本使用的内容；回收必须延后到没有活动 execution ticket 和发布版本引用后。

## 外部 JavaScript

外部 JavaScript 永远不进入静态资源本地化队列。即使用户授权下载，脚本也不能因而获得同源、网络、表单、下载或宿主通信能力。若未来需要支持外部脚本，必须单独定义新的 runtime、权限模型、来源许可、版本锁定、完整性校验和浏览器回归；在此之前分析结果保持部分兼容或不可导入，不能提供“继续下载脚本”的快捷路径。
