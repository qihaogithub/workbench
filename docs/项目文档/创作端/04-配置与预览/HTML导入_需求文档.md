# HTML 导入需求

> 版本：v1.1  
> 更新日期：2026-08-20

## 一、模块定位

HTML 导入用于把单个、自包含的 `.html` 或 `.htm` 文件转为创作端页面。系统负责自动判断页面是静态原型还是交互页，用户不选择运行模式。

## 二、功能需求

- 用户可一次选择一个或多个 HTML 文件，每个文件创建一个页面。
- 页面初始名称使用文件基础名；可识别标题和视口尺寸时，应保留到导入结果。
- 无可执行脚本的页面自动创建为 HTML/CSS 原型页，继续使用现有静态预览、配置、批注和视觉编辑能力。
- 含可执行 script、事件属性或 `javascript:` 链接的页面必须判定为交互页，不得删除脚本后伪装成静态成功。
- 含可执行内容的页面在隔离交互运行时中运行；用户可以看到脚本、事件、定时器和画布等页面行为，同时应看到明确的加载、运行时错误或超时状态。
- 交互页不得获得创作端会话、Cookie、父页面敏感数据或默认的跨源通信能力；系统应以明确的安全提示说明可用能力和限制。
- 交互页可以在创作端单页预览、截图、发布后的使用端和嵌入场景中展示；发布与嵌入失败时应返回可理解的原因，不把源码 URL 暴露给浏览器。
- 旧版 Workbench Export Markdown 继续可导入 React 页；现有 Figma HTML 中的标题和设计稿尺寸继续保留。

## 三、业务规则与约束

- 首期只支持单页面、自包含内容；不支持站点路由、ZIP 资源包、相对资源或远程资源。
- iframe、embed、object、真实表单提交、弹窗、下载、Worker 与敏感权限不属于导入支持范围；页面不得依赖这些能力才能完成首屏展示。
- 隔离运行时用于降低页面与宿主的权限边界，但不承诺绝对断网、CPU/内存硬隔离或对任意脚本行为的业务等价还原。
- 输入或内联 data URL 超出限制时，整个导入失败，不局部丢弃资源。
- 导入的分析、校验和提交是一个完整操作；任一步失败都不应留下页面目录或页面树记录。
- 所有失败使用稳定原因码和可理解提示，不要求用户理解内部运行时名称。
