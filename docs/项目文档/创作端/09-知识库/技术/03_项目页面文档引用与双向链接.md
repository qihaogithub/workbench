# 项目内容引用与双向链接实现

## 协议

项目内与跨项目 Markdown 引用均使用普通 Markdown 链接承载 `wb://` URI：

- `[项目](wb://project/{projectId})`
- `[页面](wb://page/{projectId}/{pageId})`
- `[文档](wb://document/{projectId}/{docId})`
- `[配置字段](wb://config/{projectId}/{pageId}/{encodedFieldPath})`
- 治理文档使用 `wb://document/{projectId}/{documentKind}/{docId}`，文档类别限定为 memory、project-convention、page-convention、design-spec；知识文档保持上述短形式。

URI 中只保存稳定身份；标签是插入时的快照，编辑器展示时用当前目录名称覆盖而不改写正文。配置字段身份沿用 Schema catalog 的定义路径，支持嵌套对象、数组定义和 oneOf，不包含数组数据索引。memory 和 project-convention 分别使用固定 ID memory、convention；页面公约使用 pageId，设计规范使用 specId。原有配置项 `@[名称]` + `(config_key)` 语法仍由共享解析器独立识别，不混入新入口。解析器会跳过 fenced code、行内代码和 HTML 属性，并返回源位置与 malformed URI 诊断。

## 共享领域层

`@workbench/shared/markdown-reference` 提供目标/source discriminated union、URI 编解码、规范 Markdown 序列化和纯语法解析。它不读取文件系统，也不判断权限。

`@workbench/project-core` 的 `ResourceDirectory` 从当前项目、workspace tree、Schema catalog 和文档元数据生成候选目录；`buildCandidateDirectoryEntries` 产生具有稳定祖先 ID 的页面与配置字段层级。Author 补齐存在的公约、记忆及设计规范文档，并排除缺失文件和越界路径；文件系统地址不进入候选响应。候选入口提供整项目目标，供独立整项目入口使用，不混入页面/文档树。`EntityResolver` 在同项目策略下把目标解析为 active/missing/forbidden，并把客户端状态投影为 resolved/unavailable。索引同时提供内存实现和 `<DATA_DIR>/derived/markdown-links.sqlite` 持久实现：SQLite 按 `projectId + workspaceId` 隔离，使用 generation 事务切换，支持全量 rebuild、source 级增量更新、Authority revision/root hash 防旧 receipt 覆盖和损坏缓存轮换。`MarkdownReferenceProjector` 是 committed mutation receipt 的统一投影入口，正文和 manifest 不写入链接索引。

索引来源适配器已覆盖知识文档、页面需求、memory、项目/页面公约、DesignSpec entry、配置备注和 richtext 字段；配置字段通过 schema/value 的受限 JSON pointer 定位。画布知识文档继续复用 knowledge source，画布本地 Markdown 仍保持独立 locator，不会冒充知识文档。

当前生产保存流程尚未接线 `MarkdownReferenceProjector`，持久出链/反链仍依赖管理员显式 rebuild；目标删除或恢复后也需完整重建才能刷新未修改来源的索引状态。派生索引能力版本为 `markdown-reference-v2`，旧 generation 标记 stale，不允许以增量更新冒充能力升级。该限制不影响编辑器直接读取当前目录、插入引用和导航。

## 编辑器接入

共享 `DocumentEditor` 的引用候选、插入、删除、点击回调和外部同步行为见[编辑器扩展与渲染适配](../../../共享能力/Markdown文档/技术/03_扩展与渲染适配.md)与[内容模型与同步](../../../共享能力/Markdown文档/技术/02_内容模型与同步.md)。本模块只定义项目实体目录、`wb://` canonical URI、权限投影、索引和发布快照；知识文档、页面需求、公约、memory 和 DesignSpec 通过各自 source context 接入，不把任意 Workspace 路径暴露给编辑器。

知识文档、页面需求、公约、memory 和 DesignSpec 编辑均使用稳定 source context；richtext 字段在配置表单中派生 `richtext-field` locator。没有 source context 的临时 Markdown 不启用实体候选。编辑器的 BlockEdit 菜单有显式「插入项目引用」入口，`wb://` 链接标记支持整段 Backspace/Delete，点击交由宿主导航。

## Author API

Author 提供以下同项目、鉴权后的查询入口：

- `GET /api/projects/{projectId}/markdown-references/candidates`
- `GET /api/projects/{projectId}/markdown-references/outgoing`
- `GET /api/projects/{projectId}/markdown-references/backlinks`
- `POST /api/projects/{projectId}/markdown-references/rebuild`（管理员）
- `GET /api/projects/{projectId}/markdown-references/mentions`

跨项目选择复用 `GET /api/demos` 的当前操作者可访问项目列表，再请求目标项目的 candidates，不新增跨项目聚合扫描接口。候选入口先通过 `getCurrentProjectActor` 与 `ProjectAdminService.getProject` 执行既有项目访问校验，再解析 workspace 和读取目录。`createAuthorReferenceProvider` 仅对来源项目携带当前 sessionId；读取其他项目时使用其服务端解析的项目 workspace，不复用来源项目 session，也不读取他人私有草稿。不修改角色或授予访问权限。

路由从 project/session 解析 workspace，不接受客户端任意路径。候选只返回已授权实体及 label、displayPath、hierarchy、documentGroup；空查询返回完整目录，避免大项目页面或字段被截断。outgoing/backlinks 返回 `resolved` 或统一投影后的 `unavailable`，并附带观测 workspace、Authority revision/root hash 与索引状态。新增复合目标可通过 canonical URI 作为 targetId 查询反链。普通链接查询使用 SQLite active generation；显式 rebuild 才重建已持久化 Markdown 索引。“提及但未链接”查询使用共享 parser 排除代码和已有链接，并排除当前知识文档或页面公约对应的自身 document/page target；用户仍需再次确认后才能转为 canonical 链接。

目录快照包含完整扩展实体及其 missing 状态。已登记资源的 ENOENT 视为缺失；其他 IO 错误、无效 JSON 或路径越界使候选请求返回 503，前端保留已知目录并展示加载失败/重试，不把失败响应解释为资源删除。

## Agent 受控读取

`POST /api/internal/markdown-references/read` 仅接受内部服务令牌。Agent 传递服务端绑定的 ownerUserId、sourceProjectId、原 sessionId 和 canonical uri；Author 重新读取用户、校验来源会话及过期状态，并用同一项目领域服务分别校验来源与目标访问权限。跨项目读取绝不向目标传入来源 session；不接受客户端磁盘路径或新的角色声明。响应统一 no-store，失败不包含文件系统地址或原始异常。

content 模式按目标读取概述/目录、页面说明与配置、Schema 字段定义及可定位值、知识或治理文档。响应附来源、内容哈希、分页状态、引用与图片清单；目录不递归读取正文，单文件读取前检查 1 MiB 限制，正文按 16000 字符分页。未能安全定位的配置值明确报告，不以其他字段的值代替。

image 模式要求 uri 与该来源中的 assetId，重新验证内容关联。全局图床还要求目标项目归属；Workspace 素材通过 realpath 限制在受管 assets 下。只返回不超过 10 MiB 的受支持栅格图片像素；远程 URL 不由此接口抓取，SVG 与未支持资源需要明确报告。工具使用及参考图生成流程见[Agent 核心模块](../../../独立Agent服务层/03-核心模块设计.md#markdown-引用读取与图片输入)。

## 渲染与导航

整项目深链使用同一 canonical reference 参数，目标端通过候选目录重验后保留正常项目编辑入口，不选择任意子页面来代替项目目标。

页面需求、备注和画布文档只读渲染会把 `wb://` 转成带 `data-reference-uri` 与类型图标的安全行内链接，通过点击回调导航；静态只读渲染使用标签快照，不查询当前目录。legacy 配置项引用仍使用 `data-ref-key`。Milkdown 会清洗非标准协议的 href，点击适配必须读取 decoration 的 canonical URI，而不是依赖渲染后的 href。

Author 的文档视图和知识文档弹窗使用共享底部链接托盘：折叠态只显示出链、反向链接、提及三项统计和展开控件；展开后以带数量徽标的 Tab 切换“此文档链接到”“链接到此文档”和“提及但未链接”。托盘展开不参与编辑区布局，长列表在限定高度内滚动。提及条目只展示名称，提供独立跳转和转为链接按钮，不显示行号；跳转定位对应出现位置，转为链接仍需确认后写回 canonical 链接。

Author 行内点击打开目标项目的新浏览器标签页，地址只携带目标项目 ID 和 canonical reference，不传播来源 session/workspace 路径。新页签等待正常登录和编辑器初始化，从目标项目当前候选目录验证精确目标后选择页面或文档；URL 项目与引用项目不一致时拒绝定位。文档通过稳定目标参数等待目录加载并消费一次，不依赖可能在组件挂载前丢失的一次性事件。配置引用沿用既有配置定义定位入口，保持宿主原有角色权限；不将字段定义路径转换为任意数组实例。Canvas、Note、Streamdown、Markdown-it 和 Milkdown 各自保留薄 adapter，不把 `wb://` 交给浏览器原生导航。

跨项目扩展覆盖候选、插入、名称/来源刷新和新页签定位；派生出链/反链仍保留上述项目隔离与显式重建约束，不新增跨项目反链聚合。发布规则不变，跨项目目标继续降级为纯文本。

发布管理器从同一 canonical snapshot 生成 `markdownReferences` 目标目录、`documentPaths`（`docId → publishedPath`）和精简边索引；知识文档、页面需求及 DesignSpec JSON 内嵌 Markdown 中未发布或跨项目目标均在发布正文中降级为纯文本，避免通过源码恢复不可见 ID。本次新增配置定义与治理文档目标未开放到发布端，发布时同样降级为文字。Viewer 只读取发布快照，不能访问 live workspace。

页面需求的 `demos/{pageId}/requirements.md` 已纳入 shared/project-core 的受管资源策略，live workspace 写入继续通过 Workspace Mutation Authority 返回 receipt；链接索引只消费已提交快照，不在页面保存 handler 中直接改写正文。
