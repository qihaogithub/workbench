# 项目、页面与知识文档引用实现

## 协议

项目内 Markdown 引用使用普通 Markdown 链接承载 `wb://` URI：

- `[项目](wb://project/{projectId})`
- `[页面](wb://page/{projectId}/{pageId})`
- `[文档](wb://document/{projectId}/{docId})`

URI 中只保存稳定 ID；标签是插入时的显示快照。页面配置项仍使用 `@[名称]` + `(config_key)` 的 legacy 语法，两者由共享解析器分开识别。解析器会跳过 fenced code、行内代码和 HTML 属性，并返回源位置与 malformed URI 诊断。

## 共享领域层

`@workbench/shared/markdown-reference` 提供目标/source discriminated union、URI 编解码、规范 Markdown 序列化和纯语法解析。它不读取文件系统，也不判断权限。

`@workbench/project-core` 的 `ResourceDirectory` 从当前项目、workspace tree 页面和知识库 manifest 生成候选目录；`EntityResolver` 在同项目策略下把目标解析为 active/missing/forbidden，并把客户端状态投影为 resolved/unavailable。索引同时提供内存实现和 `<DATA_DIR>/derived/markdown-links.sqlite` 持久实现：SQLite 按 `projectId + workspaceId` 隔离，使用 generation 事务切换，支持全量 rebuild、source 级增量更新、Authority revision/root hash 防旧 receipt 覆盖和损坏缓存轮换。`MarkdownReferenceProjector` 是 committed mutation receipt 的统一投影入口，正文和 manifest 不写入链接索引。

索引来源适配器已覆盖知识文档、页面需求、memory、项目/页面公约、DesignSpec entry、配置备注和 richtext 字段；配置字段通过 schema/value 的受限 JSON pointer 定位。画布知识文档继续复用 knowledge source，画布本地 Markdown 仍保持独立 locator，不会冒充知识文档。

## 编辑器接入

共享 `DocumentEditor` 的引用候选、插入、删除、点击回调和外部同步行为见[编辑器扩展与渲染适配](../../../共享能力/Markdown文档/技术/03_扩展与渲染适配.md)与[内容模型与同步](../../../共享能力/Markdown文档/技术/02_内容模型与同步.md)。本模块只定义项目实体目录、`wb://` canonical URI、权限投影、索引和发布快照；知识文档、页面需求、公约、memory 和 DesignSpec 通过各自 source context 接入，不把任意 Workspace 路径暴露给编辑器。

知识文档、页面需求、公约、memory 和 DesignSpec 编辑均使用稳定 source context；richtext 字段在配置表单中派生 `richtext-field` locator。没有 source context 的临时 Markdown 不启用实体候选。编辑器的文档块操作菜单有显式「插入项目引用」入口，`wb://` 链接标记支持整段 Backspace/Delete，点击交由宿主导航。

## Author API

Author 提供以下同项目、鉴权后的查询入口：

- `GET /api/projects/{projectId}/markdown-references/candidates`
- `GET /api/projects/{projectId}/markdown-references/outgoing`
- `GET /api/projects/{projectId}/markdown-references/backlinks`
- `POST /api/projects/{projectId}/markdown-references/rebuild`（管理员）
- `GET /api/projects/{projectId}/markdown-references/mentions`

路由从 project/session 解析 workspace，不接受客户端任意路径。候选只返回已授权实体；outgoing/backlinks 返回 `resolved` 或统一投影后的 `unavailable`，并附带观测 workspace、Authority revision/root hash 与索引状态。普通查询只读取 SQLite active generation；显式 rebuild 才扫描已持久化 Markdown。“提及但未链接”查询使用共享 parser 排除代码和已有链接，并排除当前知识文档或页面公约对应的自身 document/page target；用户仍需再次确认后才能转为 canonical 链接。

## 渲染与导航

页面需求、备注和画布文档只读渲染会把 `wb://` 转成带 `data-reference-uri` 的安全 chip，并通过点击回调导航；配置项引用仍使用 `data-ref-key`。Author 的文档视图和知识文档弹窗使用共享的底部链接托盘：折叠态只显示出链、反向链接、提及三项统计和展开控件，不显示额外标题；展开后以 Tab 切换“此文档链接到”“链接到此文档”和“提及但未链接”，各 Tab 显示数量徽标；面板展开不参与编辑区布局，长列表在限定高度内滚动。提及条目只展示名称，并提供独立的“跳转”和“转为链接”文字按钮，不显示行号；跳转会定位正文中的对应出现位置，转为链接仍需确认后写回 canonical 引用。宿主按目标类型切换页面配置或知识文档视图，并在打开前重新校验当前项目权限。Canvas、Note、Streamdown、Markdown-it 和 Milkdown 各自使用薄 adapter，不把 `wb://` 交给浏览器原生导航。

发布管理器从同一 canonical snapshot 生成 `markdownReferences` 目标目录、`documentPaths`（`docId → publishedPath`）和精简边索引；知识文档、页面需求及 DesignSpec JSON 内嵌 Markdown 中未发布或跨项目目标均在发布正文中降级为纯文本，避免通过源码恢复不可见 ID。Viewer 只读取发布快照，支持知识文档和 DesignSpec 的只读点击，不能访问 live workspace。

页面需求的 `demos/{pageId}/requirements.md` 已纳入 shared/project-core 的受管资源策略，live workspace 写入继续通过 Workspace Mutation Authority 返回 receipt；链接索引只消费已提交快照，不在页面保存 handler 中直接改写正文。
