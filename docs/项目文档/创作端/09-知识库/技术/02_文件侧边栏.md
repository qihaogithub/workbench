# 文件侧边栏与文档视图

> 更新日期：2026-09-04

项目编辑页左侧的「代码」栏是用户在编辑页浏览和管理项目文件的入口。它只保留代码视图（`WorkspaceFileTree`），不再拆分「文档 / 代码」子视图。

原「文档」栏中的知识库文档列表（`KnowledgePanel`）迁移到预览区新增的「文档」视图下，作为中间栏左侧的目录使用。

## 一、代码栏

`WorkspaceFileTree` 递归渲染工作空间文件树，支持懒加载子目录、展开/折叠。根目录由 `/api/sessions/:sessionId/workspace/files` 返回。

当项目存在聊天附件时，根目录会注入一个名为「聊天文件」的虚拟目录（`.ai-attachments/`），其子项为各附件。点击文本附件走附件读取接口查看内容；点击图片附件会打开原始图片。

## 二、文档视图

「文档」视图是预览区的一种视图模式（单页 / 画布 / 文档），通过 Header 栏中间的视图切换进入。`DocumentView` 组件自上而下包含：

- **目录区（左 1/4）**：复刻原左侧栏 `KnowledgePanel` 的文档列表结构，自顶向下为：
  - **AI 记忆**：列表项（Brain 图标），点击在右侧编辑器内打开并编辑 `memory.md`。
  - **项目公约**（可折叠文件夹，amber FolderOpen 图标）：只展示已创建的项目公约（根，`convention.md`）与页面公约（`demos/{pageId}/convention.md`），不会在项目初始化或读取时创建文件。管理员可以新建、编辑和删除；编辑者只读查看，界面不显示新建与删除操作，接口也拒绝写入。
  - **项目知识库**：可折叠列表，列出用户文档（`knowledge/manifest.json` 中 `source !== "system"` 的条目），支持切换文档；每项右侧只显示统一的「更多」菜单，菜单提供资源历史和删除，不再显示眼睛或编辑快捷图标。文件夹加号打开「新建 / 上传」气泡菜单：新建立刻生成空的「未命名文档」、在右侧打开，并让左侧标题进入行内重命名；回车或失焦提交名称，Esc 放弃名称修改但保留文档。上传仅接收 `.md`、`.markdown`、`.txt`，使用文件名作为标题并直接在右侧打开。可编辑 Markdown 入口统一复用当前 Session 的外链图片本地化回调；无 Session 或只读入口不启用。
  - **设计规范**（可折叠文件夹，cyan FolderOpen 图标）：内含多份设计规范文档（`design-spec/spec-{id}.json` + `design-spec/manifest.json` 索引）。管理员可新建、编辑和删除；编辑者可读取但以只读编辑器展示，界面与 API 均不提供写入入口。新建顶层文档先打开应用内命名 Dialog，标题自动取第一个未占用的「设计规范 N」，提交前去除首尾空格并禁止空标题；取消不会创建请求或目录项。
- **文档编辑区（右 3/4）**：加载当前目标（知识库文档 / AI 记忆 / 项目公约 / 页面公约）的 Markdown 内容，使用共享 `DocumentEditor` 就地编辑。编辑器公共工具、主题、TopBar 和外部同步规则见[Markdown 文档与编辑器专题](../../../共享能力/Markdown文档/)。本视图只负责文档目标切换、角色感知的 `readOnly`、保存调度和导航：知识库文档使用项目子资源 API `/api/projects/:projectId/documents/:documentId`，AI 记忆和项目/页面公约继续使用 workspace files 接口；生产编辑页不把 `workingDir` 或 `fileName` 作为文档业务身份。`markdownUpdated` 后由宿主执行 800ms 防抖写回，并在切换文档或卸载时 flush，避免切换/刷新丢改动。选中「设计规范」文档时改用 `DesignSpecEditor`，不渲染 Markdown 编辑区。

编辑器外部值相同与差异同步的公共规则见[内容模型与同步](../../../共享能力/Markdown文档/技术/02_内容模型与同步.md)。本视图只负责在服务端/协同内容更新后重新读取当前文档，不重复实现编辑器同步逻辑。

AI 记忆与项目公约不再弹窗，由文档视图内部直接读写 workspace 文件。目录加载与正文加载保持分离：公约目录通过一次 workspace 文件 API 的批量元数据读取获取，避免按页面展开请求；同一轮文档视图中已成功读取的正文会暂存在内存，以便来回切换时立即复用。缓存只作用于当前工作空间和会话；收到知识库刷新事件时清空知识文档正文缓存，设计规范事件只刷新设计规范目录，不把两组目录同时置为阻塞加载态。读取失败的正文不会写入缓存。

### 数据刷新机制

- 知识库变动：`knowledge-updated` 窗口事件 → 文档视图后台刷新知识库列表；已有目录行、滚动位置和当前选中目标保持不变。
- 设计规范变动：`design-spec-updated` 窗口事件 → 文档视图仅后台刷新设计规范列表；保存或素材池刷新不会重新应用旧的自动定位请求。
- 首次加载与后台刷新分离：首次加载可显示加载状态，后台刷新保留已有目录；列表请求按作用域和递增请求序号保护，旧响应不能覆盖最新响应。工作空间或项目切换时清空旧目录状态并重新加载。
- 配置项入口传入的设计规范定位是一次性请求：文档/条目定位成功或确认文档不存在后立即消费；用户手动选择任意文档后清除待定位条目并以手动选择的 `docId` 为准。
- 聊天附件变动：`chat-attachments-updated` 窗口事件 → 代码栏重新加载根目录；文档视图不请求或展示聊天附件。
- 事件由 `chat-input.tsx` 在上传成功后、以及相关批量操作后广播。

原 `KnowledgePanel` 的「AI 记忆」「项目公约」「批量删除」等能力随文档列表一并迁移；对话文件仅在代码栏的「聊天文件」虚拟目录中查看和管理。

### 设计规范编辑器（DesignSpecEditor）

选中「设计规范」文件夹下的某份文档后，右侧编辑区切换为 `DesignSpecEditor`（三区布局）：

  - **中栏（规范卡片列表）**：每条目一张卡片，可展开/折叠、重命名、删除；页面规范展开后先展示已绑定页面名称摘要，页面行悬停或聚焦时可解绑，再展示说明；配置项规范展开后展示已绑定配置项表格（缩略图 + 名称 + 类型 + 来源，行末提供“编辑配置项”和“解绑”）。点击“编辑配置项”时保持当前设计规范文档视图，直接打开现有字段定义编辑器；页面级引用在后台准备所属页面 Schema，项目级引用沿用当前活动页面上下文；失效引用不显示编辑入口，只能解绑。保存期间对话框保留并禁止重复提交：页面级字段以绑定的页面 ID 写入，即使该页不是当前活动页；只有工作区及项目同步成功后，绑定行和配置面板才同时显示新 Schema。失败时保留草稿重试，两个位置均不显示未提交数据。说明编辑复用共享 Markdown 编辑器，图片和内容扩展遵循[编辑器扩展与渲染适配](../../../共享能力/Markdown文档/技术/03_扩展与渲染适配.md)。点击右下角 `＋` 先打开应用内命名 Dialog，默认使用第一个未占用的「新页面规范 N」；确认标题后才创建空白条目，取消不修改文档，不能回退到浏览器原生 prompt。卡片使用 dnd-kit sortable 排序：排序只能从专用手柄开始，拖到另一张卡片后优先使用当前鼠标位置与卡片垂直中线决定插入前后（键盘拖拽回退到拖拽卡片中心），目标卡片以浅色高亮作为落点反馈；拖动中的卡片使用轻量位移动画和拖拽浮层，支持键盘排序。右栏页面/配置项仍使用原生 copy 拖拽，二者事件边界相互隔离。中栏不设标题栏与保存按钮——改动自动保存（`DesignSpecWorkspace` 脏数据出现后 800ms 防抖，并按文档快照串行写入，旧响应不能覆盖后续编辑）。
- **配置项预览**：右栏素材项和中栏已绑定配置项表的每一项均支持悬停或键盘聚焦预览其所在页面示意图；图片项同时显示默认图片。预览不重复展示配置项或页面名称，鼠标离开或焦点离开即关闭。图片仍可点击进入全屏查看。
  - **配置项素材池一致性**：仅在 Schema 已提交至工作区并同步项目后，`config-schema-updated` 才携带变更后的 Schema、作用域和提交标记。`DesignSpecWorkspace` 可立即投影该已提交结果，随后无缓存刷新服务端素材池；服务端结果是长期真值，不保留无限期的本地覆盖层，因此切换视图后规范表格与配置面板始终读取同一份 Schema。
- **右栏（配置项页签）**：右侧栏为「配置项」与「评论」两个页签，选中设计规范文档时自动切到「配置项」。配置项页签聚合项目级 + 各页面级 schema 的配置项，顶部搜索框与「全部/已绑定/未绑定」过滤按钮并列，下方类型过滤 chips（色值/文字/图片/数值/动效），按来源（项目级/各页面）分组；每项展示 swatch（颜色块/文字缩写/图片缩略），可拖拽进卡片绑定。
- **数据模型**：只存“条目结构 + 说明文字 + 对配置项的引用”，不存配置值；配置值实时从 `project.config.schema.json` / 页面 `config.schema.json` 投影，规范永不过期。页面级引用按 `pageId + fieldKey`，页面删除后显示“已失效引用”灰条。

设计规范数据走 `/api/design-specs`（列表/新建/单文档/配置项池），live workspace 写入经 workspace mutation authority 提交。详见 `docs/plans/进行中/创作端-设计规范文档录入与维护-实施计划.md`。

### Markdown 图片尺寸

图片块的通用拖拽尺寸、Markdown 元数据和 `@milkdown/components` 补丁见[编辑器扩展与渲染适配](../../../共享能力/Markdown文档/技术/03_扩展与渲染适配.md)以及[宿主接入、保存边界与测试](../../../共享能力/Markdown文档/技术/04_宿主接入、保存边界与测试.md)。知识库文档视图额外使用 560px 的历史比例图片阅读上限；该上限属于本视图排版，不改变编辑器保存的目标宽度。

### Markdown 阅读排版

桌面端 Markdown 采用统一的阅读标尺：正文为 15px、行高 1.75，标题沿用 H1 2em、H2 1.55em、H3 1.25em 的层级。`DocumentEditor` 将包含左右编辑沟槽的正文盒限制为 880px，实际文本列约为 752px；设计规范说明使用的 `PageRequirements` 直接限制为居中的 760px 阅读列。与说明对应的已绑定配置项表格也处于同一列内，保证表格、说明标签和正文共享左右边缘。这样宽屏保留足够留白，窄容器仍会自然收缩为容器宽度。移动端编辑器维持 14px 的响应式字号。

独立浏览端发布时会携带设计规范目录及其索引；浏览端文档视图只读展示「项目知识库」和「设计规范」，不呈现创作态的 AI 记忆、公约或对话文件。

### 文档评论

文档视图使用独立于页面 pin 的评论目标。目标以工作区相对路径标识；设计规范条目使用 `design-spec/<docId>#<entryId>` 标识。整篇评论只绑定资源，选区评论额外保存引用原文、前后文与创建位置，用于正文变更后的重新定位。右侧评论栏只加载当前文档资源的线程；选择线程时应回到对应文档并突出其有效引用。文档被删除时，关联线程同时删除并通过评论 WebSocket 广播。页面预览仍使用 DOM anchor 和归一化 pin，不与文档评论混用。

文档评论中的 `@AI` 是用户对当前资源的明确修改授权。评论任务会持久化触发者的服务端角色并按角色隔离批次：管理员可按既有范围写入，编辑者只能写入普通页面、AI 记忆和用户项目知识库；公约、设计规范和模板页的写入会被拒绝，匿名或失效授权任务只可回复线程。
