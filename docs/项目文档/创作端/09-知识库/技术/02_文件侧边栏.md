# 文件侧边栏与文档视图

项目编辑页左侧的「代码」栏是用户在编辑页浏览和管理项目文件的入口。它只保留代码视图（`WorkspaceFileTree`），不再拆分「文档 / 代码」子视图。

原「文档」栏中的知识库文档列表（`KnowledgePanel`）迁移到预览区新增的「文档」视图下，作为中间栏左侧的目录使用。

## 一、代码栏

`WorkspaceFileTree` 递归渲染工作空间文件树，支持懒加载子目录、展开/折叠。根目录由 `/api/sessions/:sessionId/workspace/files` 返回。

当项目存在聊天附件时，根目录会注入一个名为「聊天文件」的虚拟目录（`.ai-attachments/`），其子项为各附件。点击文本附件走附件读取接口查看内容；点击图片附件会打开原始图片。

## 二、文档视图

「文档」视图是预览区的一种视图模式（单页 / 画布 / 文档），通过 Header 栏中间的视图切换进入。`DocumentView` 组件自上而下包含：

- **目录区（左 1/4）**：复刻原左侧栏 `KnowledgePanel` 的文档列表结构，自顶向下为：
  - **AI 记忆**：列表项（Brain 图标），点击在右侧编辑器内打开并编辑 `memory.md`。
  - **项目公约**（可折叠文件夹，amber FolderOpen 图标）：只展示已创建的项目公约（根，`convention.md`）与页面公约（`demos/{pageId}/convention.md`），不会在项目初始化或读取时创建文件。管理员可以新建、编辑和删除；编辑者只读查看，界面不显示新建与删除操作，接口也拒绝写入。
  - **项目知识库**：可折叠列表，列出用户文档（`knowledge/manifest.json` 中 `source !== "system"` 的条目），支持切换文档；每项右侧只显示统一的「更多」菜单，菜单提供资源历史和删除，不再显示眼睛或编辑快捷图标。文件夹加号打开「新建 / 上传」气泡菜单：新建立刻生成空的「未命名文档」、在右侧打开，并让左侧标题进入行内重命名；回车或失焦提交名称，Esc 放弃名称修改但保留文档。上传仅接收 `.md`、`.markdown`、`.txt`，使用文件名作为标题并直接在右侧打开。
  - **设计规范**（可折叠文件夹，cyan FolderOpen 图标）：内含多份设计规范文档（`design-spec/spec-{id}.json` + `design-spec/manifest.json` 索引）。管理员可新建、编辑和删除；编辑者可读取但以只读编辑器展示，界面与 API 均不提供写入入口。
- **文档编辑区（右 3/4）**：加载当前目标（知识库文档 / AI 记忆 / 项目公约 / 页面公约）的 Markdown 内容，使用 `DocumentEditor` 就地编辑。编辑区不另设业务标题栏与保存按钮——当前选中文档由左侧目录标示；编辑器在可编辑状态显示 Crepe 原生吸顶 TopBar，集中提供 `正文`、`H1`–`H6` 标题、文字格式、列表、引用、代码、表格等完整编辑操作，只读时隐藏 TopBar。TopBar 必须相对 `.milkdown` 正文滚动容器吸顶，而非随正文上划；工具栏右侧固定保留“更多”入口，窄容器下将超出项收纳到菜单，宽容器下菜单仍展示完整工具集合。该入口由 React 编辑器外层宿主承载，与 Crepe 的 `.crepe` 滚动容器平级，且层级必须高于原生 TopBar。适配器不保存一次性的 Vue DOM 引用，而是持续核对当前 `.top-bar-inner` 的节点身份；Crepe 替换 TopBar DOM 后立即重新绑定。被收纳项通过 `hidden` 退出布局，主题层不得用按钮 `display` 规则覆盖该语义。恢复菜单处于 `.milkdown` 之外，其克隆 SVG 必须显式承接原 TopBar 的默认与悬停图标色，不能依赖原工具栏选择器的隐式继承。主题沿用 Crepe Frame 的正文与控件表面层级并自适应宿主明暗模式；选区工具条的标题触发器与原生按钮对齐，菜单允许越过工具条边界保持可见、可命中；选区工具条同时使用明确的默认、悬停和选中底色，表格边框与单元格选中由 Crepe 原生规则按校准后的主题 token 渲染。块手柄保留 Crepe 原生的“添加 + 拖拽”两个入口，并统一使用紧凑尺寸。自动保存在 `markdownUpdated` 触发 `onChange` 时捕获目标与内容、调度一次 800ms 防抖写回，并在切换文档与组件卸载时冲刷未落盘编辑，避免切换/刷新丢改动。知识库文档统一使用项目子资源 API `/api/projects/:projectId/documents/:documentId`（列表、正文与变更均以 `projectId + documentId` 定位）；AI 记忆和项目/页面公约继续使用 workspace files 接口的 `memory.md` / `convention.md` / `demos/{pageId}/convention.md`。旧 `/api/knowledge` 仅保留给尚未迁移的非编辑页调用方，生产编辑页不再传 `workingDir` 或 `fileName` 作为文档身份。选中「设计规范」文档时，改用 `DesignSpecEditor`（卡片列表 + 配置项素材池），不渲染 Markdown 编辑区。

AI 记忆与项目公约不再弹窗，由文档视图内部直接读写 workspace 文件。目录加载与正文加载保持分离：公约目录通过一次 workspace 文件 API 的批量元数据读取获取，避免按页面展开请求；同一轮文档视图中已成功读取的正文会暂存在内存，以便来回切换时立即复用。缓存只作用于当前工作空间和会话；两者任一切换、或收到知识库、设计规范刷新事件后都会清空，下一次打开重新获取服务端版本。读取失败的正文不会写入缓存。

### 数据刷新机制

- 知识库变动：`knowledge-updated` 窗口事件 → 文档视图 `fetchItems()`。
- 聊天附件变动：`chat-attachments-updated` 窗口事件 → 代码栏重新加载根目录；文档视图不请求或展示聊天附件。
- 事件由 `chat-input.tsx` 在上传成功后、以及相关批量操作后广播。

原 `KnowledgePanel` 的「AI 记忆」「项目公约」「批量删除」等能力随文档列表一并迁移；对话文件仅在代码栏的「聊天文件」虚拟目录中查看和管理。

### 设计规范编辑器（DesignSpecEditor）

选中「设计规范」文件夹下的某份文档后，右侧编辑区切换为 `DesignSpecEditor`（三区布局）：

  - **中栏（规范卡片列表）**：每条目一张卡片，可展开/折叠、重命名、删除；展开后展示已绑定配置项表格（缩略图 + 名称 + 类型 + 来源，行末解绑）与共享 `DocumentEditor` 的 Markdown 说明编辑区。说明编辑直接使用 Crepe 的标题、格式、列表、表格等能力，不再维护独立的文本框、编辑/预览切换或局部快捷按钮。用户从网页快捷键粘贴包含多张外网图片的 Markdown 时，编辑器保留整段文字并逐一通过当前 Session 保存到全局图床后再写入稳定地址，具体存储约束见[全局图床设计](../../06-基础设施/技术/06_全局图床设计.md)。`＋` 新建条目，卡片可拖拽排序，可从右栏拖入配置项绑定。中栏不设标题栏与保存按钮——改动自动保存（`DesignSpecWorkspace` 在脏数据出现后 800ms 防抖落盘）。
- **配置项预览**：右栏素材项和中栏已绑定配置项表的每一项均支持悬停或键盘聚焦预览其所在页面示意图；图片项同时显示默认图片。预览不重复展示配置项或页面名称，鼠标离开或焦点离开即关闭。图片仍可点击进入全屏查看。
- **右栏（配置项页签）**：右侧栏为「配置项」与「评论」两个页签，选中设计规范文档时自动切到「配置项」。配置项页签聚合项目级 + 各页面级 schema 的配置项，顶部搜索框与「全部/已绑定/未绑定」过滤按钮并列，下方类型过滤 chips（色值/文字/图片/数值/动效），按来源（项目级/各页面）分组；每项展示 swatch（颜色块/文字缩写/图片缩略），可拖拽进卡片绑定。
- **数据模型**：只存“条目结构 + 说明文字 + 对配置项的引用”，不存配置值；配置值实时从 `project.config.schema.json` / 页面 `config.schema.json` 投影，规范永不过期。页面级引用按 `pageId + fieldKey`，页面删除后显示“已失效引用”灰条。

设计规范数据走 `/api/design-specs`（列表/新建/单文档/配置项池），live workspace 写入经 workspace mutation authority 提交。详见 `docs/plans/进行中/创作端-设计规范文档录入与维护-实施计划.md`。

### Markdown 图片尺寸

`DocumentEditor` 的图片块将用户拖拽后的宽度作为目标 CSS 像素宽度保存；编辑区和只读文档视图都以该值为优先尺寸。图片外层同时以当前正文容器为上限，因此宽屏不会把图片放大，窄屏只作临时视觉缩小，也不会回写或改变用户保存的目标值。设计规范说明的轻量只读渲染也会读取同一元数据；历史比例型图片没有目标宽度时，使用 560px 的通用阅读上限，避免在宽屏内容区铺满。

图片元数据继续随 Markdown 文本保存，不需要用户书写新的编辑语法。历史的比例型图片仍按原行为读取；用户再次调整其尺寸时，编辑器会自动写入稳定宽度。该能力由 `@milkdown/components` 的项目级补丁提供，补丁文件为 `patches/@milkdown__components@7.22.0.patch`，升级该依赖时必须复核图片块的 Markdown 编解码与容器上限行为。

### Markdown 阅读排版

桌面端 Markdown 采用统一的阅读标尺：正文为 15px、行高 1.75，标题沿用 H1 2em、H2 1.55em、H3 1.25em 的层级。`DocumentEditor` 将包含左右编辑沟槽的正文盒限制为 880px，实际文本列约为 752px；设计规范说明使用的 `PageRequirements` 直接限制为居中的 760px 阅读列。与说明对应的已绑定配置项表格也处于同一列内，保证表格、说明标签和正文共享左右边缘。这样宽屏保留足够留白，窄容器仍会自然收缩为容器宽度。移动端编辑器维持 14px 的响应式字号。

独立浏览端发布时会携带设计规范目录及其索引；浏览端文档视图只读展示「项目知识库」和「设计规范」，不呈现创作态的 AI 记忆、公约或对话文件。

### 文档评论

文档视图使用独立于页面 pin 的评论目标。目标以工作区相对路径标识；设计规范条目使用 `design-spec/<docId>#<entryId>` 标识。整篇评论只绑定资源，选区评论额外保存引用原文、前后文与创建位置，用于正文变更后的重新定位。右侧评论栏只加载当前文档资源的线程；选择线程时应回到对应文档并突出其有效引用。文档被删除时，关联线程同时删除并通过评论 WebSocket 广播。页面预览仍使用 DOM anchor 和归一化 pin，不与文档评论混用。

文档评论中的 `@AI` 是用户对当前资源的明确修改授权。评论任务会持久化触发者的服务端角色并按角色隔离批次：管理员可按既有范围写入，编辑者只能写入普通页面、AI 记忆和用户项目知识库；公约、设计规范和模板页的写入会被拒绝，匿名或失效授权任务只可回复线程。
