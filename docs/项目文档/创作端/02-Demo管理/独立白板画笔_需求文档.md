# 独立白板画笔功能需求文档

> 状态：方案 1 已确认，研发实现与独立白板专项回归已完成
> 更新日期：2026-09-05
> 所属模块：创作端 / Demo 管理 / Whiteboard Studio 与配置图片白板

## 1. 一句话定义

让用户可以在 Whiteboard Studio 和创作端配置图片白板中快速自由手绘，并把每一笔保留为可单独选择、修改、移动、撤销和删除的白板对象，用于勾勒结构、圈选重点和记录临时想法。

## 2. 背景与价值

Whiteboard Studio 和创作端配置图片白板当前开放选择、抓手、矩形、圆形、文本和图片，缺少最直接的自由表达入口。现有白板编辑体验（详见[草图绘图 SDK](./技术/05_草图绘图SDK.md)）已经具备对象选择、撤销/重做、缩放/平移和路径对象的可复用基础，但画笔尚未通过共享 profile 成为两个白板宿主的一致用户入口。

画笔的首要价值不是提供专业绘画，而是让用户在搭建线框、整理页面结构或评审内容时，能够用最低成本完成“画一下、圈一下、标一下”。因此本需求优先保证笔划可控、可编辑、可撤销，并保持与现有白板对象模型一致。

## 4. 产品定位与设计原则

1. **结构化笔划优先**：一笔是一个可管理的白板对象，而不是只存在于屏幕上的临时涂层。
2. **快速表达优先**：首期只解决实线自由手绘和必要的纠错，不引入专业笔刷、绘画纹理或手写识别。
3. **不破坏既有对象**：画在形状、文本或图片上方时，笔划保持独立，不自动改变、裁剪或绑定被覆盖对象。
4. **行为可预测**：绘制中的草稿不提前进入白板内容；释放指针后一次提交一笔；普通点击不生成不可见的小点。
5. **白板宿主优先**：本需求只开放 Whiteboard Studio 和[创作端配置图片白板](../04-配置与预览/技术/14_配置图片白板实现设计.md)的共享 `whiteboard` profile；页面编辑入口、AI 工具、协同和服务端持久化不随本需求自动开放。

## 5. 目标用户与使用场景

### 5.1 目标用户

- 需要快速搭建页面结构和交互草图的产品、设计和研发人员。
- 在白板中整理信息、圈重点或临时记录想法的项目成员。
- 需要通过简单线条表达关系、范围或修改意见的评审者。

### 5.2 典型场景

1. 用户在页面线框旁画一条手绘连线，说明两个区域之间的关系。
2. 用户圈出一个卡片或图片区域，标记下一步要修改的地方。
3. 用户连续写下几个草稿符号，随后只删除其中一笔，不影响其他对象。
4. 用户画完后发现线条太粗或颜色不合适，选中该笔划进行调整。

## 7. 功能需求

### 7.1 入口与工具状态

- 底部主工具栏在 Whiteboard Studio 和创作端配置图片白板中都只展示一个“画笔”分组入口，由画笔图标和下拉箭头组成，放在圆形之后、文本之前，保持现有工具的阅读顺序；两端均由 `SketchEditorSurface profile="whiteboard"` 提供。
- 点击画笔图标区域直接进入画笔并开始绘制；点击下拉箭头展开二级操作栏。二级操作栏包含画笔、橡皮擦、颜色和粗细，且不替换主工具栏中的其他工具。
- 画笔入口和二级操作栏必须有清晰的选中态、悬浮提示和可访问名称；选中态与其他主工具保持同一套视觉语言。
- 推荐画笔保持连续激活：完成一笔后仍可继续绘制；选择其他工具或按 Esc 后退出到选择状态。
- 画笔绘制期间不显示会遮挡落笔区域的选区上下文工具栏；二级操作栏点击画布后收起，但不阻断当前画笔或橡皮擦操作。
- Space 临时抓手、滚轮缩放、现有选择和抓手行为保持不变；画笔不能吞掉这些既有视口操作。

### 7.2 绘制行为

- 支持鼠标、触控板和浏览器可识别的指针输入完成自由绘制；本期不承诺笔压随压力变化。
- 指针按下开始一笔，移动时显示实时预览，释放时提交该笔划。
- 笔划只记录在当前白板页面范围内；不借此把当前固定页面改造成无限画布。
- 笔划使用实线外观，默认沿用现有白板的基础线条视觉；不得出现填充色块或封闭形状填充。
- 一次有效拖动只生成一个独立笔划；普通点击、移动距离不足、指针取消和离开后未完成的草稿都不生成对象。
- 画在已有对象上方时，笔划仍是独立对象；它不会自动进入形状、图片或文本，也不会改变这些对象的尺寸和内容。
- 新笔划默认位于当前可见内容的上层；用户可通过既有图层操作调整顺序。

### 7.3 颜色与粗细

首期提供“细 / 中 / 粗”三个快速档位，对应 2px、3px、5px；默认颜色为 `#111827`，默认粗细为 3px。颜色设置提供现有白板色板中的常用颜色和自定义颜色入口。

- 绘制前修改颜色或粗细，只影响之后创建的新笔划。
- 选中已有笔划后修改颜色或粗细，只影响当前选择，并进入既有撤销历史。
- 颜色设置沿用现有白板颜色体系，提供常用颜色和自定义颜色入口，不另造一套持久化颜色配置。
- 画笔设置属于当前编辑会话中的临时设置，不写入白板对象；切换颜色或粗细不会回写已有笔划。
- 画笔不提供“无颜色”；无效或不可见的线宽值不得作为可选的默认档位。
- 多选笔划时，若用户执行颜色或粗细调整，应一次性作用于所有可编辑笔划；混合状态要能被识别，不得静默改写非笔划对象。

### 7.4 选择与编辑

- 切换到选择工具后，用户可以点选单个笔划；命中范围应围绕实际笔迹，而不是把整个空白包围盒都当作笔划。
- 选中笔划后，复用现有对象选区边界、移动、缩放、旋转、复制、删除、锁定、显隐、图层和成组行为。
- 笔划被移动、缩放或旋转后，笔迹形状和其他对象的相对关系应符合用户操作，不得出现跳回原位或误选其他对象。
- 选中多个对象时，画笔作为普通可编辑对象参与现有选择和成组规则；不新增画笔专属的组合模型。
- 本期不提供逐点编辑、节点拉拽或专业路径控制柄；如未来需要，应另立需求评估。

### 7.5 橡皮擦

- 橡皮擦只面向画笔笔划，不删除形状、文本、图片或其他非笔划对象。
- 单击命中笔划时删除整笔；拖动经过多笔时删除经过的整笔。
- 橡皮擦不做局部切割，不把一笔拆成多段；误擦后使用撤销恢复。
- 锁定、隐藏或当前不可编辑的笔划不应被橡皮擦删除。
- 橡皮擦应与画笔一样支持清晰的激活态和 Esc 退出，不改变选择工具的默认状态。

### 7.6 撤销、重做与失败处理

- 每一笔完成的绘制、每次整笔擦除和每次外观调整都应作为可理解的历史动作。
- 绘制期间的实时预览不进入历史；用户取消绘制后，撤销按钮状态不应发生变化。
- 绘制发生异常时，应保留已有白板内容，不生成半截笔划或不可选择的残留对象。
- 画笔功能不得改变既有矩形、圆形、文本、图片、选择、抓手、缩放和平移的结果。

## 8. 主流程与异常流程

### 8.1 首次绘制

1. 用户点击工具栏中的“画笔”。
2. 用户按需选择颜色和粗细。
3. 用户在画布内按下并拖动。
4. 画布实时显示笔迹预览。
5. 用户释放指针后，白板保留一笔独立笔划；按推荐方案，画笔继续保持激活。

### 8.2 绘制后修正

1. 用户切换到选择工具并点选笔划。
2. 用户调整颜色、粗细、位置、尺寸或角度。
3. 每次调整都可以通过既有撤销操作恢复。

### 8.3 橡皮擦除

1. 用户选择橡皮擦。
2. 用户点击一笔或拖过多笔。
3. 命中的完整笔划被移除，形状、文本和图片保持不变。
4. 用户按 Esc 或切换工具退出橡皮擦。

### 8.4 异常与边界

- 只点击不移动：不创建笔划。
- 绘制中按 Esc 或触发指针取消：取消当前草稿，不写入白板和历史。
- 在缩放、平移后的画布上绘制：最终笔划位置以用户看到的落点为准，不因视口比例产生偏移。
- 笔划与其他对象重叠：选择和擦除优先命中实际笔划，不误操作底层对象。
- 锁定笔划：可以查看，但不能被移动、改样式或擦除。
- 超出页面边界：不产生页面外的持久内容；不改变当前页面尺寸。

## 9. 非功能与体验要求

- 工具栏和画笔设置面板沿用独立白板现有浅色视觉、圆角、阴影、间距和 Tooltip 规范。
- 颜色、粗细、橡皮等入口应能通过键盘获得焦点，并提供明确的中文无障碍名称。
- 绘制预览应连续、稳定，不因普通移动出现明显跳点、闪烁或拖尾；释放后笔划与预览结果一致。
- 画笔状态不能把画布锁死：用户始终能通过选择工具、抓手、Space 或 Esc 返回普通编辑。
- 本期不把笔迹数量、点数、输入设备或性能统计写入用户可见白板内容。

## 10. 验收标准

### 10.1 正向验收

- Whiteboard Studio 和创作端配置图片白板工具栏均显示并可使用“画笔”，且入口、分组设置、键盘和无障碍名称一致。
- 用户可连续绘制至少两笔，每笔都能独立选中和删除。
- 一笔绘制完成后可以撤销；撤销后可以重做；绘制草稿期间不会提前影响撤销状态。
- 在不同缩放和拖动画布后，画笔落点与用户操作位置一致。
- 选中笔划后可以按确认的范围修改颜色和粗细，已有笔划不会被新默认样式悄悄改变。
- 若纳入橡皮擦，点击或拖动只删除画笔笔划，不删除形状、文本和图片。
- 既有选择、抓手、矩形、圆形、文本和图片主流程均保持可用。
- 页面重新渲染后，当前会话中的笔划仍能正确显示、命中和参与现有对象操作。

### 10.2 反向验收

- 不出现荧光笔、Washi tape、激光笔、笔压、手写识别、自动图形识别或套索擦除入口。
- 不把白板画笔入口自动扩展到页面编辑器、使用端或 AI 工具；Studio 与配置图片白板必须继续共享同一 profile。
- 不新增 AI 画笔指令、多人协同、云端保存、移动端专属交互或独立导出流程。
- 不允许普通点击产生零长度、不可见或无法删除的笔划。
- 不允许橡皮擦误删非笔划对象。

## 11. 待用户确认的决策

以下决策已由用户确认，并作为本次实现的范围基线：

1. **首期范围**：采用“画笔＋颜色 / 粗细＋橡皮擦”。
2. **连续模式**：采用连续画笔；完成一笔后保持画笔激活。
3. **直线辅助**：本期不纳入 Shift 直线，保留自由曲线。
4. **设备边界**：按浏览器统一指针行为验收，不承诺笔压变化；移动端和主动笔适配另立需求。
5. **粗细设置**：本期提供 2px、3px、5px 三档，不增加精确线宽输入。

当前实现由 `@workbench/sketch-react` 的唯一 `whiteboard` profile 同时供 Whiteboard Studio 和 `WhiteboardDialog` 使用，两个宿主均开启画笔分组入口；`SketchPageEditor` 不接入该 profile，继续保留画笔和橡皮的独立工具栏展示。

## 12. 确认后的协作与交接

方案 1 确认后，按以下协作边界推进：

1. **乔布斯**：冻结范围账本，记录用户对上述决策的选择。
2. **毕加索**：补充工具栏、设置面板、连续模式、橡皮擦反馈和窄屏布局的交互规格。
3. **图灵**：在共享白板编辑能力中实现并由 `whiteboard` profile 同时接入 Studio 与创作端配置图片白板；不得顺带开放页面编辑器、使用端或 AI 工具。
4. **福特**：只有在用户明确要求交付或发布时，评估交付范围与环境影响；本需求本身不授权发布。
