# 会话与版本管理 - 生命周期设计

> 版本：v3.2
> 更新日期：2026-09-01
> 变更说明：拆分 2 小时编辑租约与 7 天历史保留，清理按最后活动时间删除。

---

## 一、会话生命周期概述

### 1.1 状态定义

| 状态 | 说明 |
|:-----|:-----|
| 创建中 | 会话正在初始化 |
| 编辑中 (editing) | 会话正常使用中 |
| 已归档 (archived) | 用户切换到其他对话，该对话被归档 |
| 已保存 (saved) | 用户已保存，会话结束 |
| 已放弃 (discarded) | 用户已放弃，会话结束 |
| 编辑租约失效 | `expiresAt` 超时，仅阻止继续编辑或鉴权；历史仍由 `lastActivityAt` 决定 |

### 1.2 状态流转

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   用户打开项目编辑                                              │
│        │                                                        │
│        ▼                                                        │
│   ┌─────────────┐                                               │
│   │   编辑中    │◄────────────────────────┐                    │
│   │  (editing)  │                          │                    │
│   └──────┬──────┘                          │                    │
│          │                                 │                    │
│          ├──── 用户活动（编辑/配置）───────┘                    │
│          │                                                      │
│          ├──── 命名版本 ─────► 创建快照 ─────► 继续编辑          │
│          │                                                      │
│          ├──── 用户放弃 ─────► 归档会话上下文 ─────► 已放弃     │
│          │                                                      │
│          ├──── 用户切换对话 ─────► 已归档 (archived)            │
│          │                                                      │
│          └──── 最后活动超过 7 天 ─────► 删除历史与临时文件     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、会话元数据

### 2.1 数据结构

```typescript
interface EditSession {
  sessionId: string             // 会话唯一标识
  projectId: string             // 关联的项目 ID
  workspaceId: string           // 关联的工作空间 ID
  username: string              // 当前编辑者用户名
  basedOnVersion: string        // 基于的版本号
  status: 'editing' | 'archived' | 'saved' | 'discarded'
  workbenchSessionId: string | null  // workbench Agent 会话 ID
  createdAt: number             // 创建时间戳
  expiresAt: number             // 2 小时编辑租约截止时间
  lastActivityAt: number        // 7 天历史保留依据，每次会话活动更新
}
```

### 2.2 存储位置

会话元数据存储在 Session 目录的 `.session.json` 文件中：

```
sessions/
└── {userId}/{projectId}/
    └── session-{timestamp}-{random}/
        └── .session.json    ← 会话元数据（含 workspaceId）
```

代码文件存储在关联的 Workspace 目录中，Session 不直接持有文件。普通编辑页绑定项目级 live Workspace；显式事务或旧链路才可能绑定 branch/legacy Workspace。

## 三、会话创建

### 3.1 创建流程

```
用户打开项目编辑
        │
        ▼
检查项目是否存在
        │
        ├── 不存在 → 返回错误
        │
        ▼ 存在
生成 Session ID
格式：session-{timestamp}-{random}
        │
        ▼
绑定项目工作区
（显式传入 workspaceId 时可绑定分支/legacy Workspace）
        │
        ▼
创建会话元数据（关联 workspaceId）
        │
        ▼
同步用户模型配置与外部授权到 Agent（非阻断）
        │
        ▼
返回会话信息
```

### 3.2 Agent 配置同步边界

编辑页打开项目时，Session 与 Workspace 创建是进入编辑器的主链路；用户模型配置、外部工具授权等 Agent 侧配置同步是附属链路。附属链路失败时只能记录 warning，不能让 `/api/sessions` 创建请求失败，也不能让页面列表、预览和编辑区变为空。

这条边界的原因是：创作端编辑项目首先依赖本地工作空间文件，Agent 配置只影响后续 AI 对话能力。即使 agent-service 暂时不可用、用户外部授权刷新失败或模型配置读取异常，用户仍应能打开项目、查看页面、编辑和保存。

### 3.3 Session ID 生成规则

```
session-{timestamp}-{random}

示例：session-1712345678-abc123def
```

| 部分 | 说明 |
|:-----|:-----|
| `session-` | 固定前缀 |
| `{timestamp}` | 毫秒级时间戳 |
| `{random}` | 随机字符串 |

## 四、会话保持

### 4.1 活跃度检测

| 检测方式 | 说明 |
|:---------|:-----|
| 文件更新 | 更新会话文件时刷新 `lastActivityAt`，必要时续期 `expiresAt` |
| API 调用 | 创建、发送消息、更新标题、续期和恢复会话时刷新 `lastActivityAt` |
| 心跳 | 可选的定期心跳检测 |

### 4.2 过期时间计算

```typescript
const SESSION_LEASE_MS = 2 * 60 * 60 * 1000  // 2 小时编辑租约

function calculateExpiryTime(): number {
  return Date.now() + SESSION_EXPIRY_MS
}
```

## 五、编辑租约

### 5.1 过期检测

```typescript
function isSessionExpired(session: EditSession): boolean {
  return Date.now() > session.expiresAt
}
```

### 5.2 租约策略

| 配置项 | 默认值 | 说明 |
|:-------|:-------|:-----|
| 编辑租约 (`expiresAt`) | 2 小时 | 仅用于内部鉴权和活跃编辑 |
| 历史保留 (`lastActivityAt`) | 7 天 | 从最后活动时间滑动计算，决定历史是否删除 |
| 历史清理频率 | 30 分钟 | 定时任务运行；历史列表请求前对当前项目轻量清理 |

## 六、会话清理

### 6.1 清理触发

| 触发方式 | 说明 |
|:---------|:-----|
| 命名版本后 | 只创建快照，不结束会话，不删除 live Workspace |
| 放弃后 | 用户确认放弃后归档 Session；只允许清理 branch/legacy Workspace |
| 定时任务 | 每 30 分钟清理最后活动超过 7 天的历史会话 |
| 页面加载 | 项目列表加载时触发清理 |

### 6.2 清理逻辑

定时任务和历史列表请求前的轻量清理遍历当前范围的 Session 元数据，使用 `lastActivityAt`（兼容旧记录时回退到最近消息时间或创建时间）判断是否超过 7 天。超期时删除 Session 元数据、消息和关联的非 live Workspace 临时文件；项目级 live Workspace 永不因历史清理删除。近期活动会话不会因为 2 小时编辑租约失效而从历史中消失。

清理结果使用幂等语义：仅返回本轮真正删除的 Session。删除操作需同时移除元数据和消息文件，目标已不存在时不重复报告；live Workspace 由项目生命周期独立管理。

孤儿 Workspace 扫描同时保护编辑租约仍有效或仍处于 7 天历史保留窗口内的会话引用，避免 2 小时租约失效后提前删除可恢复的 non-live Workspace。
