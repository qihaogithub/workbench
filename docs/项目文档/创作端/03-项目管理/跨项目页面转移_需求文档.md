# 跨项目页面转移 - 需求文档

> 版本：v1.0
>
> 更新日期：2026-09-11

## 模块定位

跨项目页面转移是项目管理的一等能力。人工画布和 Agent 通过同一领域命令，把其他项目的页面复制为独立副本，或创建持续跟随源页面已提交版本的引用；剪贴板只负责传递页面身份和布局快照，不承载页面源码。

## 用户能力

- 用户可以从有权访问的源项目选择一个或多个页面，选择“复制”或“引用”后转入当前项目。
- 复制生成可独立运行和修改的完整副本；源页面后续变化不影响副本。
- 引用保留目标项目中的名称、routeKey、文件夹、画布布局、导航和评论，页面内容与运行依赖跟随源页面最新已提交版本。
- 同一批次内成功页面立即可用；失败页面不会留下空目录、空页面或孤立 tree 条目，重试不会重复创建成功页面。
- 默认保留成功页面集合内部的相对布局、页面组、完整 Section 和页面导航；指向未选择或失败页面的关系不扩大复制范围，并给出告警。
- 普通无冲突操作可直接完成；配置、routeKey、外部关系、动态配置依赖或并发版本冲突必须返回可定位的冲突，不能静默覆盖。

## 权限与安全规则

- 复制要求调用者具备目标项目编辑权和源页面读取权；引用要求同时具备目标项目编辑权以及源项目编辑或管理权。
- 引用授权精确绑定一个源页面和一个目标引用页，不授予源项目列表、其他页面、评论、诊断或历史版本的读取权。
- Agent 只能使用服务端绑定的用户、目标项目和会话身份，不能通过工具参数声明角色。
- 引用被撤销，或源页面、源项目被删除后，编辑态和公开访问立即按下一次解析 fail-closed；已有产物不能绕过授权继续使用。
- “查看源项目”只在当前用户另有源项目访问权时提供。

## 页面与依赖规则

- 支持 `prototype-html-css`、`high-fidelity-react`、`sandboxed-html` 和 `sketch-scene` 四种 runtime。
- 页面包包含 Workspace Resource Registry 识别的页面资源，以及页面实际使用的项目配置、局部资产、白板绑定、DesignSpec 和 visibility 规则依赖。
- 无法静态确定的动态配置访问阻断转移；配置定义或值不一致时必须由用户显式选择复用目标值、覆盖目标值或可验证映射。
- React 页面在目标 Preview Dependency Policy 下重新验证；`lockedDependencies` 不作为页面转移或运行时依赖解析依据。
- 复制引用页和创建引用都会先解析到终端源页面并固定预检版本，不建立引用链。

## 发布规则

- 引用页首次发布前必须存在通过校验的 materialization，否则阻断发布。
- 目标发布清单只记录稳定 `referenceId`，不公开源项目 ID。
- 源页面产生新提交后，引用解析器重建内容寻址产物；当前实现由编辑或公开访问触发幂等 reconcile，无需重新发布目标项目。
- 新版本构建失败时保留最近可用版本并记录引用 head 错误；撤销与删除不允许使用最近可用版本兜底。
- sandbox 引用使用目标项目作用域的短期 execution ticket，不返回源码，也不复用源项目 ticket。

## 不在转移范围内

- 评论、诊断记录、历史版本和源画布选择集合之外的关系不复制。
- CLI 可以复用 project-core 服务，但不维护独立的页面复制实现。

## 验收标准

- 人工粘贴和 Agent 转移对同一输入生成相同页面包、依赖映射和画布关系结果。
- 四种 runtime 均覆盖复制、引用、编辑预览和发布读取。
- 单页 Authority 提交具备原子性；批量任务允许部分成功、幂等重试和拓扑补偿。
- 权限不足、伪造项目 ID、授权撤销、源删除、版本漂移和 sandbox ticket 越权均 fail-closed。
