# 01 反馈存储与工具实现

## 技术架构

反馈系统采用「共享类型 + Agent 工具 + 创作端存储 API + 双端页面」的分层架构：
- `packages/shared` 定义反馈数据模型和类型
- `packages/agent-service` 提供 `submit_feedback` 工具和预装 Skill，让 AI 能主动生成报告
- `packages/author-site` 提供反馈存储读写层和 REST API，以及反馈列表页和提交表单
- `packages/viewer-site` 提供跨域 API 客户端和反馈列表页

## 数据模型

反馈条目（`FeedbackItem`）核心字段：
- `category`：bug / suggestion / question / other
- `severity`：high / medium / low
- `report`：结构化问题报告（仅 bug 类使用），含背景、现象、期望行为、复现步骤、AI 判断依据、排查线索
- `author`：提交者身份（登录用户 / 匿名用户 / AI 助手）
- `channel`：chat（AI 上报）/ manual（手动提交）
- `source`：author-site / viewer-site / agent
- `status`：open → in_progress → done，状态变更记录在 `history` 中

## 数据存储

所有反馈以单文件 `data/feedback/feedback.json` 存储，结构为 `{ items: [...] }`。创作端和 Agent 服务通过共享 `DATA_DIR` 实现对同一文件的读取。

存储层使用 read-modify-write 模式，类似评论存储。单机低并发场景足够，后续如量大可迁移至 SQLite。

## Agent 工具

### submit_feedback

位于 `packages/agent-service/src/backends/pi-tools/feedback-tool.ts`。注册在 workbench 和 viewer-readonly 两套工具集中。

参数：`category`、`severity`、`title`、`content`、`report`（结构化报告）、`tags`、`contact`。

工具执行时自动推断来源（workbench → author-site，viewer-readonly → viewer-site），写入 `data/feedback/feedback.json`。

### feedback-collection Skill

位于 `packages/agent-service/src/preinstalled-skills/feedback-collection/SKILL.md`。通过目录扫描自动注入为「预装 Skill」。定义了系统 bug 判断规则、上报流程、报告模板和严重程度判断标准。

## API 路由

### GET /api/feedback

公开接口，返回时间倒序的反馈列表。支持 `status`、`category`、`severity` 查询参数过滤。

### POST /api/feedback

公开接口，创建反馈。支持 Cookie 和 `X-Auth-Token` 两种身份来源（创作端和浏览端跨域）。`source` 字段从 body 获取（默认 author-site，viewer-site 端传 viewer-site）。

### PATCH /api/feedback/[id]

需登录。修改反馈状态，追加 `history` 记录。

### DELETE /api/feedback/[id]

需登录。删除反馈。

## 页面结构

### 创作端反馈页

`/feedback` 路径，位于 `packages/author-site/src/components/feedback/feedback-page.tsx`。使用 SWR 获取数据，支持筛选和搜索，登录用户可改状态和删除。

### 浏览端反馈页

`/feedback` 路径，位于 `packages/viewer-site/src/components/FeedbackPage.tsx`。通过 `packages/viewer-site/src/lib/feedback-api.ts` 跨域调用创作端 API。使用 useState + useEffect 获取数据（静态导出环境不依赖 SWR）。

浏览端开启 `trailingSlash`，`/feedback` 会 308 重定向到 `/feedback/`，因此 `ViewerApp.tsx` 的路由判断需同时匹配 `"/feedback"` 与 `"/feedback/"`，否则会误落入项目视图。匿名显示名（默认「匿名用户」）通过 `x-anonymous-name` header 传递，HTTP header 仅允许 ISO-8859-1，客户端需 `encodeURIComponent` 编码、服务端 `decodeURIComponent` 解码，否则含中文时报 `Failed to read the 'headers' property from 'RequestInit'`。

### 首页入口

- 创作端：home-page.tsx header 右侧「反馈」按钮（MessageSquareText 图标）
- 浏览端：ViewerApp.tsx ProjectListPage header 右侧「反馈」按钮（Bug 图标）

## 系统提示词

创作端系统提示词和浏览端系统提示词均添加了「意见反馈」小节，引导 AI 在遇到系统问题时调用 `submit_feedback` 工具。
