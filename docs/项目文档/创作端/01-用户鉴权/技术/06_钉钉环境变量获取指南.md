## 一、需要准备的环境变量

普通浏览器 OAuth 和钉钉内部 H5 免登共用企业应用凭证。浏览器 OAuth 还必须配置回调地址：

| 环境变量 | 必填 | 来源 | 说明 |
| :--- | :--- | :--- | :--- |
| `DINGTALK_LOGIN_ENABLED` | 是 | 本系统配置 | 设置为 `true` 启用 |
| `DINGTALK_CORP_ID` | 是 | 钉钉企业信息 | 企业 CorpId，不是应用 App ID 或 AgentId |
| `DINGTALK_APP_KEY` | 是 | 应用凭证 | 截图中“Client ID（原 AppKey 和 SuiteKey）” |
| `DINGTALK_APP_SECRET` | 是 | 应用凭证 | 截图中“Client Secret（原 AppSecret 和 SuiteSecret）”，只能放服务端 |
| `DINGTALK_LOGIN_REDIRECT_URI` | 浏览器 OAuth 必填 | 本系统 + 钉钉后台 | 例如 `http://10.130.33.34:4200/api/auth/dingtalk/callback`，必须完全一致 |
| `DINGTALK_LOGIN_SCOPE` | 否 | 本系统配置 | 默认 `openid` |
| `DINGTALK_LOGIN_PROMPT` | 否 | 本系统配置 | 默认 `consent` |
| `DINGTALK_LOGIN_AUTH_URL` | 否 | 兼容旧配置 | 仅在新 OAuth 配置不完整时作为手工跳转回退 |

示例：

```bash
DINGTALK_LOGIN_ENABLED=true
DINGTALK_CORP_ID=dingxxxxxxxxxxxxxxxx
DINGTALK_APP_KEY=dingxxxxxxxxxxxxxx
DINGTALK_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
DINGTALK_LOGIN_REDIRECT_URI=http://10.130.33.34:4200/api/auth/dingtalk/callback
DINGTALK_LOGIN_SCOPE=openid
DINGTALK_LOGIN_PROMPT=consent
```

## 二、截图中的几个 ID 怎么区分

应用凭证页面通常同时出现三类值：

| 页面名称 | 用途 | 对应配置 |
| :--- | :--- | :--- |
| `App ID` | 开发者平台应用对象的 UUID | 本次 OAuth 不使用 |
| `原企业内部应用 AgentId` | 钉钉工作台内部应用入口标识 | 本次 OAuth 不填到 `DINGTALK_APP_KEY` |
| `Client ID（原 AppKey 和 SuiteKey）` | OAuth 客户端 ID | `DINGTALK_APP_KEY` |
| `Client Secret（原 AppSecret 和 SuiteSecret）` | OAuth 客户端密钥 | `DINGTALK_APP_SECRET` |

`DINGTALK_CORP_ID` 不在这张应用凭证截图中，需要从钉钉开发者后台的企业信息处复制。不要把 App ID 或 AgentId 当作 CorpId。

## 三、获取企业 CorpId

1. 打开[钉钉开放平台](https://open.dingtalk.com/)，进入开发者后台。
2. 选择目标企业，在企业基本信息或企业开发信息中查找 `CorpId`。
3. 将该值写入服务端环境变量。

如果当前账号只有开发者权限但看不到企业信息，请让企业管理员提供 CorpId；CorpId 本身不是 Client Secret，可以通过安全的配置渠道传递。

参考：[获取企业 CorpId](https://open.dingtalk.com/document/development/obtain-enterprise-corpid)。

## 四、获取 Client ID 和 Client Secret

1. 进入“应用开发 → 企业内部应用”，打开目标 H5 微应用。
2. 进入“凭证与基础信息”。
3. 复制“Client ID（原 AppKey 和 SuiteKey）”到 `DINGTALK_APP_KEY`。
4. 复制“Client Secret（原 AppSecret 和 SuiteSecret）”到 `DINGTALK_APP_SECRET`。

安全要求：

- Client Secret 只能放在 author-site 服务端环境变量中。
- 不要提交到 Git、前端代码、浏览器控制台或日志。
- 如果密钥曾出现在截图、聊天或公开日志中，应在钉钉后台刷新密钥，并同步更新 `.env`。

## 五、登记浏览器 OAuth 回调地址

普通浏览器登录需要在钉钉后台“钉钉登录与分享”中登记回调地址。登记的是完整地址，不是只填域名：

```text
http://10.130.33.34:4200/api/auth/dingtalk/callback
```

然后在 `.env` 中设置同一个值：

```bash
DINGTALK_LOGIN_REDIRECT_URI=http://10.130.33.34:4200/api/auth/dingtalk/callback
```

协议、主机、端口、路径必须逐字一致，不能一边使用 `localhost`、另一边使用局域网 IP。若平台不接受局域网 IP，需要申请内网穿透地址，例如 `https://xxx.example-tunnel.com/api/auth/dingtalk/callback`，并用该域名访问整个登录流程。

## 六、配置应用首页地址（可选）

如果还要从钉钉工作台打开应用，在网页应用配置中把 PC 端首页地址设置为 author-site 可访问地址，例如：

```text
http://10.130.33.34:4200/login
```

这个首页地址和浏览器 OAuth 的回调地址不是同一个字段：前者是用户打开应用的入口，后者是 OAuth 授权完成后钉钉回跳的接口。

## 七、重启与验证

修改 `.env` 后必须重启 author-site。先访问登录页并点击“使用钉钉企业账号登录”，普通浏览器应按以下顺序跳转：

1. `/api/auth/dingtalk/start`。
2. `https://login.dingtalk.com/oauth2/auth` 钉钉授权页。
3. `/api/auth/dingtalk/callback?authCode=...&state=...`。
4. 登录成功后回到 `/workbench`。

返回登录页并提示“授权状态已失效”通常表示 state Cookie 丢失或回调使用了不同的域名。提示“未配置”则检查 `DINGTALK_LOGIN_REDIRECT_URI`、Client ID 和 Client Secret 是否已加载。

从钉钉工作台打开应用时，前端仍会优先走 H5 免登接口；普通浏览器则走上述 OAuth 路径。

## 八、上线前检查清单

- [ ] CorpId 已从企业信息处获取，未误填 App ID 或 AgentId。
- [ ] Client ID 已填入 `DINGTALK_APP_KEY`。
- [ ] Client Secret 已填入 `DINGTALK_APP_SECRET`，且只存在于服务端。
- [ ] 钉钉后台“钉钉登录与分享”已登记完整回调地址。
- [ ] `DINGTALK_LOGIN_REDIRECT_URI` 与后台登记值逐字一致。
- [ ] 局域网 IP 被平台接受，或已准备内网穿透地址。
- [ ] 修改 `.env` 后已重启 author-site。
- [ ] 普通浏览器授权后能回到 `/workbench`。
- [ ] 从钉钉工作台打开时 H5 免登仍可用。
