# 运行时配置与漂移门禁

## 配置边界

运行时配置按职责拆分，不建立包含全部业务配置的单一文件：

- `@workbench/runtime-config/topology` 是 browser-safe 的 local/Docker 端口、服务 URL 与 CDN 默认值来源。
- `@workbench/runtime-config/env` 只用于 Node 启动入口，优先级固定为现有进程环境、服务 `.env`、根 `.env`。
- `@workbench/runtime-config/paths` 统一定位 workspace 根目录并把 `DATA_DIR` 解析成绝对路径；显式绝对路径可在不包含 workspace 清单的容器运行时直接使用。
- `@workbench/runtime-config/model` 保存模型策略、绘图配置类型、严格校验器和不含密钥的默认值。
- `@workbench/runtime-config/secrets` 只在服务端读取密钥；生产环境按当前服务职责 fail-fast。

固定拓扑如下：

| Profile | Author | Agent | Screenshot | Knowledge | Viewer | Sketch |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| local | 4200 | 4201 | 4202 | 4203 | 4300 | 3400 |
| docker | 3200 | 3201 | 3202 | 3203 | 3300 | - |

Docker 内部 DNS 地址和浏览器公开地址是不同投影，不得互相替代。`NEXT_PUBLIC_*` 只参与 Next 构建；服务端运行变量由 Compose 的 environment 注入。

## 数据与环境文件

根 `.env` 和服务 `.env` 是本地开发输入。Docker 使用未跟踪的 `.env.docker`，仓库只提交无凭据的 `.env.docker.example`。启动脚本在私有文件缺失时给出复制模板提示。

`DATA_DIR` 的默认值始终是 workspace 根目录下的 `data/`。Docker 显式注入 `/app/data`，并通过 Compose 公共 anchor 复用挂载。Knowledge 数据库、各服务数据库和 Viewer 只读发布目录保持独立职责，不因路径统一而合并。

## 密钥职责

以下密钥不得互相回退：

- `JWT_SECRET`：登录 JWT 签名。
- `MODEL_CONFIG_ENCRYPTION_KEY`：用户及全局模型、绘图 API Key。
- `EXTERNAL_AUTH_ENCRYPTION_KEY`：Figma、钉钉等外部授权凭据。
- `INTERNAL_API_TOKEN`：服务间内部 API。
- `ADMIN_SECRET`：管理后台鉴权。

全局和用户模型 Key、绘图 Key、外部授权凭据只以 AES-256-GCM 密文持久化。管理 API 只返回 `hasApiKey`；提交空 Key 表示保留现有密文。历史明文或旧密钥数据不会进入长期兼容分支，需先 dry-run 统计、备份数据库，再经人工确认清空凭据并重新配置。

## 工具链基线

TypeScript 配置分为 base、Node、browser bundler 和 Next 四层；NodeNext 与 bundler 不混用。Vitest 按 Node/browser 两类复用基线，Tailwind 使用根 preset，Next ESLint 使用规则工厂。包级 alias、测试环境、include 和 ignore 仍由包配置负责。

固定版本为 TypeScript 5.9.3、Playwright 1.59.1、Vitest 2.1.9。ESLint 8/9 并存和 Author Jest 是已登记边界。

## 漂移检查

`pnpm check:config-drift` 在 `check:all` 前段执行，检查依赖 override、工具版本、端口和 URL、E2E 入口、旧模型字段、敏感模板、重复配置及绕过统一入口的直接使用。错误包含文件和行号，且不会输出环境变量值。

确有必要的环境或包级差异必须精确登记在 `scripts/config-drift-allowlist.json`。登记表示该文件承担明确职责，不表示允许任意新增重复配置。
