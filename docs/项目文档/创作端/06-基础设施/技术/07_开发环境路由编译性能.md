# 开发环境路由编译性能

> 更新日期：2026-08-14

## 1. 优化目标

创作端开发模式保留 Next.js 按需编译和 Fast Refresh，但首页、根布局和编辑页的同步依赖图应只包含当前首屏必需的能力。聊天渲染、Markdown 高亮、编辑器、评论面板和截图补生等重型能力不应因聚合导出而进入无关路由。

## 2. 包导出边界

`@workbench/ai-chat-shared` 和 `@workbench/demo-ui` 的根入口用于需要整组功能的消费方。跨路由公共布局、基础 Provider 和编辑页首屏应优先使用 package exports 公开的具体子路径。

根布局的 Toast Provider 直接使用 `@workbench/ai-chat-shared/ui/toast-provider`，不经过会同时导出 AI Chat、Streamdown 和 Shiki 的根入口。编辑页对预览舞台、配置面板、画布内核和类型的依赖也使用具体子路径，避免二次经过创作端兼容聚合入口。

编辑页加载 AI Chat 时使用创作端专用宿主入口：该入口只负责注入工作台集成配置，并从共享包的 `ai-chat` 子路径导出主组件。编辑页依赖的消息、流服务、活动视图和元素选择类型分别使用类型子路径，不再解析共享包全量索引。聊天消息列表继续把用户消息与助手富文本渲染器作为动态边界；当会话为空时不下载 Streamdown、Shiki、Mermaid 等消息展示依赖，已有消息或开始流式输出时再加载。

编辑页同步调用的画布工作区、视觉编辑状态、运行时配置合并、原型视觉编辑与评论 API 只允许引用 `types`、`iframe-types`、`validator`、`canvas-utils`、`LayerTreeMenu`、`comment` 等精确子路径。类型位置也不能使用根入口的内联 `import()`；在 Next.js 开发编译中，这类写法仍会解析完整导出图。该边界用于阻止 DocumentEditor、Milkdown、Markdown 解析器和完整预览组件进入编辑页主体开发 chunk。

新增共享能力时，如果它会被根布局或轻量页面消费，需同时提供独立子路径，不得要求消费方从全量索引中取一个轻量符号。

编辑路由当前还必须遵守四条静态边界：校验器分别从 `@workbench/demo-ui/validator` 与 `@workbench/demo-ui/types` 取值，AI Chat 注入配置从 `@workbench/ai-chat-shared/config` 取值，知识文档编辑器从 `@workbench/demo-ui/DocumentEditor` 取值，中文日期 locale 从 `date-fns/locale/zh-CN` 取值。对应静态测试会扫描高频入口，禁止这些依赖重新经过 package 根入口或 locale 桶入口。

author-site 的校验适配器还必须从 `@workbench/shared/validator` 精确子路径重导出校验类型与函数，不得回退到 `@workbench/shared` 根入口。这条边界避免编辑页因一个校验函数而继续解析 Workspace、Agent、知识库、诊断与评论等无关共享导出。

`extractCodeConfigBindingKeys` 和 `extractPrototypeConfigBindingKeys` 位于 `@workbench/demo-ui/config-binding-utils` 纯 TypeScript 子路径。编辑页不得为了调用这两个函数同步导入 `PageConfigPanel`。手绘编辑的 state hook、画布、工具栏、图层和属性面板统一位于动态子树，只在手绘页进入编辑态后挂载。共享预览内部的文档编辑器和手绘预览也使用懒加载边界，分别在用户打开画布文档编辑器或实际渲染手绘页时初始化。

共享 `PreviewStage` 对单页与画布模式保持真正的代码分割：初始单页模式不解析 `PreviewCanvas` 及其自由节点、文档 Markdown 和几何依赖；只在用户切换到画布模式时异步加载该子树。加载占位保留原容器尺寸，不改变单页、文档或画布交互契约。

## 3. 编辑页初始数据链路

`POST /api/sessions` 返回轻量编辑器 Bootstrap：Session 与 Workspace 标识、项目摘要、页面/文件夹目录、项目级配置和选定的当前页 ID。新建 Session 与复用活跃 Session 使用同一响应结构，不读取、不序列化页面源文件字典。

客户端收到 Bootstrap 后即解除整页加载态，再通过 `GET /api/sessions/{sessionId}/files/{pageId}` 读取当前页文件。当前页未就绪时只覆盖预览区；其他页面在用户切换或画布调度需要时使用同一单页接口加载。用户创作偏好与 Bootstrap 并发读取，偏好失败不阻塞编辑器。

Session 完成建立或复用后，模型配置与外部授权配置会并发推送到 agent-service。Bootstrap 仍必须等两者都结束后才返回，以保证用户首条 AI 消息不会读到缺失配置；两条独立链路不得再串行累加到编辑器 shell-ready 门禁。

页面评论链路只在活动页 ID 就绪后启动。页面评论 target 必须使用稳定引用，不得在每次 React 渲染时新建对象；否则初始状态提交会重复触发评论 REST 刷新与 WebSocket 重连，并可能发出空 `pageId` 请求。

Workspace Authority 的首次拉取、轮询、刷新和确认只有在 `projectId`、`workspaceId`、`sessionId` 三者全部就绪后才允许启动。浏览器 client 还会在构造 URL 前执行同一完整性检查；任何空标识都返回 `WORKSPACE_AUTHORITY_NOT_READY`，不得发出包含双斜线路径或空 `sessionId` 的请求。该双层门禁避免无效请求在开发冷状态下额外触发 `/not-found` 编译。

## 4. 首页后台任务

首页会读取已有截图用于项目卡片，但元数据不再由每张卡片逐页查询。首页在空闲延迟后把当前最多 500 个项目/页面标识提交给一次 `POST /api/screenshots/metadata`；接口只读取 author-site 与 screenshot-service 共享的 `DATA_DIR`，返回 hash、variant、renderBox 和带 hash 的图片 URL，不触发截图生成、补生或重试。

卡片只消费首页批量结果，图片文件仍在卡片进入视口或近视口后插入 DOM。路由离开会中止尚未完成的批量请求。screenshot-service 离线时，已有共享磁盘截图仍可读取，缺失项保持占位；批量接口限制条目数并校验项目与页面标识，禁止路径穿越和无界扫描。

缺失截图的自动补生不是首屏前置条件。页面稳定后再延迟启动补生，项目之间串行执行；离开首页时取消未启动的调度。这使路由编译、React 水合和可见缩略图读取优先获得 CPU、磁盘与服务并发配额。

在开发环境，截图元数据读取与补生使用更长的空闲延迟。用户点击项目卡片开始导航时，首页立即阻止尚未开始的截图工作；这避免动态截图 API 的首次开发编译与编辑页路由竞争。生产环境维持即时的可见缩略图读取和原有补生延迟。

## 5. 开发运行时基线与路由保活

根目录 `.nvmrc`、`package.json` engines 与各服务 Dockerfile 统一使用 Node 24 LTS。切换 Node 主版本后，含原生扩展的本地依赖必须在 Node 24 下重建；Docker 镜像在构建阶段自行生成与容器运行时匹配的原生产物。

author-site 的开发服务器会把已编译路由保留五分钟，并保留十二个并存页面。该设置只调节开发期内存和重复编译的平衡；生产构建和运行时不受影响。

日常开发统一运行 Next.js 16.2.12 与 React 19.2.3。author-site 的 `dev` 与 `dev:turbo` 等价，默认使用 Turbopack；`dev:webpack` 保留为诊断与紧急回退入口。生产 `build` 与 `build:webpack` 仍继续使用 Webpack，`build:turbo` 只用于专项验证。开发和生产 bundler 独立准入，避免开发性能收益被尚未稳定的 Turbopack 生产构建阻断。viewer-site 和 sketch-playground 仍保持 Webpack 默认值。

author-site 的 Turbopack 配置以仓库根目录为 workspace root，并维护两条与 Webpack 等价的窄规则：Markdown prompt 在 Webpack 中使用 `asset/source`，在 Turbopack 中转为 ESM 文本模块；仅 NodeNext 源码包（`knowledge-*`、`preview-contract`、`project-*`）中的相对 `.js` 引用按存在的文件重写到 `.ts` 或 `.tsx`。该规则不能覆盖共享包的全部源码，否则会让 Turbopack 将正常的导出图按 loader 输出处理，造成客户端导出解析失败。两套站点的 Tailwind 配置也只能通过 ESM import 引入插件，不能在 Next 16 的 ESM 配置加载期调用 CommonJS `require()`。`better-sqlite3`、TypeScript、Mermaid 解析器等 Node 侧依赖继续由 `serverExternalPackages` 保持在服务器边界；Proxy 取代旧 Middleware 约定，但鉴权和 CORS 语义不变。

sketch-playground 的 Playwright 基址固定为 `127.0.0.1:3400`，因此其 Next 配置必须显式允许该开发来源。否则 Next 16 会拦截来自该主机的 HMR 资源，表面上页面仍可打开，但真实画布指针交互可能停在未水合状态。该约束与 production 输出无关，只保证本地浏览器回归使用与开发服务器一致的安全边界。

2026-08-14 在同一代码、Node 24、相同项目数据和受控系统负载下完成 author-site 开发态 A/B。编辑页三轮冷响应中位数由 Webpack 的 29.815s 降至 Turbopack 的 12.507s，改善 58.1%；Next 编译日志中位数由 28.4s 降至 12.5s，改善 56.0%；热响应由 208ms 降至 65ms。登录页和首页冷响应也分别改善 40.9% 和 30.3%。完整五服务拓扑下，Turbopack 编辑页连续三次都到达 `editor-ready`，用时 4.089s、3.976s 和 3.280s；Fast Refresh 前后页面保持 ready，没有新增运行时异常。因此 author-site 开发默认值切换为 Turbopack。

在默认 Turbopack 基线上继续收窄首屏依赖与启动串行链后，完整五服务拓扑的三次热导航到可用状态为 1.118s、1.923s 和 2.040s，中位数 1.923s；相对上述 3.976s 中位数改善约 51.6%。同轮 `/api/sessions` 资源耗时为 431ms、382ms 和 845ms，三轮均无运行时异常。首页模式不挂载画布，手动切换到画布后能异步挂载画布工作区，且编辑器保持 ready、无运行时异常。该复测使用已存在的开发服务和热缓存，用于验证客户端启动改善，不替代清空 `.next` 的冷编译基线。

Turbopack 生产构建的独立稳定性门禁仍未完成：历史重复构建曾在优化阶段长时间无进展。这不影响开发态准入，但生产 `build` 必须继续使用 Webpack，不能因开发态收益顺带切换。

## 6. 全服务本地预览

创作端的日常开发不以 Docker 作为页面反馈路径。`pnpm dev` 会在本机常驻启动 author-site、agent-service、knowledge-service、viewer-site、screenshot-service 与 sketch-playground，并启用编辑页主动发起的自动截图生成，保留 AI 对话、协同落盘、知识检索、使用端、Agent 截图工具和草图 SDK 预览之间的完整真实关系。

当日常开发不需要生成截图时，使用 `pnpm dev:lite`。它保持相同的六服务拓扑、实时 iframe 预览、Agent 截图能力和服务健康检查，只暂停编辑页主动发起的自动截图任务，降低 Puppeteer 与路由编译的资源竞争。对应的 `:repair` 后缀会一并清理三套 Next.js 开发缓存。两个档位启动前都会释放六个本地开发端口（3400、4200–4203、4300），避免旧进程使某一服务静默缺席。发布前的生产行为仍由 `pnpm preview:local` 验收。

## 7. 验证方式

代码级验证要覆盖 Toast 子路径可用性、编辑 bootstrap 标识门禁、首页批量元数据读取、首页补生的延时与串行顺序、Session Bootstrap 不包含页面源文件、模型与授权配置并发且共同完成的契约、评论 target 稳定性、shared validator 精确子路径、PreviewCanvas 按模式加载、当前页单页加载，author-site 和 demo-ui 类型检查。性能验证使用清理 `.next` 后的冷启动编译日志与浏览器 Navigation Timing，同时检查 `app/layout.js`、首页和编辑页开发产物体积。浏览器口径应至少区分 shell-ready、当前页文件应用完成和预览内容就绪，不得用单一 `editor-ready` 标识代替完整可用性。

2026-08-12 在 Node 24.10.0、Next.js 14.1.0、Webpack dev bundler 下，对固定编辑路由进行了三次清理 `.next` 的独立采样：编译时间为 24.0s、23.0s、22.4s，均为 8,605 modules；浏览器 `responseStart` 中位数为 25.0s，`load` 中位数为 28.5s。相对治理前 78.6–165s、约 10,300 modules 的样本，编译时间中位数约下降 81%，模块数约下降 16%。已热编译后的编辑页返回首页 UI 就绪采样为 111ms；浏览器未出现空 Authority 请求，首页元数据为单个批量请求且 screenshot-service 离线时仍可读取共享磁盘缩略图。

性能基线采集必须先检查系统负载和内存。冷样本采集期间不得并行运行其他构建或测试；指向 author-site 的旧浏览器标签会自动重连并触发首页/API 编译，必须关闭或改用空闲端口。本次已作废 load average 达 40–102 的污染样本，正式样本均在一分钟 load 不超过 15 时串行采集。
