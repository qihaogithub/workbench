# 页面高保真快照导出实现设计

> 更新日期：2026-08-20

## 技术定位

该实现由浏览器插件和纯函数核心包组成。插件负责读取当前标签、维持任务状态、传输大页面和触发下载；核心包负责把忠实 HTML 拆成 Editable Snapshot Bundle v1。核心包不读取文件系统，也不调用浏览器扩展接口，因此同一契约可以被后续命令行工具或静态原型派生器复用。

现有静态页面导出工具仍面向创作端安全原型，不与高保真保留策略共用净化流程。两条链路只在未来显式派生步骤相遇，原始高保真快照不会被静态规则覆盖。

## 浏览器任务流

弹窗收集路由标识、来源项目和页面状态备注。Side Panel 提供显式多标签选择、捕获 profile、精确到 origin 的 profile 站点规则、非内容导出历史和审核入口。列出标签前由用户手势申请可选 `tabs` 权限，批量开始前再申请选中标签的 host 权限；Chrome match pattern 不能限定端口，因此授权不会扩大 scheme 或 host，但会覆盖该 host 的所有端口。profile 规则仍以完整 origin 匹配。没有默认全选、自动切换标签或 history 读取。后台按队列串行处理，只有用户已切换到目标标签时才继续，以保证可见截图对应正确页面。

采集脚本在页面隔离世界运行 SingleFile 采集核心。主页面 hook 尽量读取 frame、Shadow DOM、延迟资源和样式运行态；画布在采集前额外保存当前像素回退，完成后恢复原页面样式。由于首版只在用户点击后获得权限，早于点击发生且必须依赖文档启动期 hook 的状态会进入采集警告。

页面 HTML 不通过单条消息返回。采集脚本按固定大小切块，每块带顺序号和校验值。后台 worker 串行转发，offscreen 文档按捕获标识聚合并校验。这样后台 worker 被回收后，offscreen 中的大数据不会跟着普通消息处理栈消失。

用户取消时，后台先等待页面采集端确认停止，再断开 port 和清理 offscreen；超时时明确要求刷新后重试。SingleFile Core 与主世界 hook 在同一页内只初始化一次，避免大页取消后重试重复注入并占用大量内存。

## Bundle 构建

`@workbench/editable-snapshot-core` 接收捕获元数据、HTML、截图和哈希适配器，输出内存中的虚拟文件列表。

忠实层保存采集原文和当前标签截图。工作区通过 HTML parser 稳定序列化节点，抽取内联样式和脚本，保留脚本位置、顺序、模块类型、异步属性、完整性和跨域属性。iframe 的 `srcdoc` 或内联 HTML 会形成独立 frame 目录，跨域 frame 则保留属性、地址和缺失原因。

内联图片、字体、媒体和可读取画布按内容哈希落入资产目录；相同内容只保存一次。依赖图记录页面到样式、脚本、frame 和资产的关系。执行路径继续使用原始字节，Prettier 只在 `workspace/readable/` 生成 HTML/CSS/JavaScript 阅读副本。采集端在 SingleFile 内联外部脚本前标记其原始绝对 URL，使 source map 可相对原脚本而非快照页面解析；source map 同时支持内联 map、授权后外部 map、`sourcesContent` 和可下载的缺失 source。offscreen 构建器不自行扩大权限：它向 Service Worker 请求资源，后者校验目标 scheme-and-host 权限后才使用无凭证 GET 拉取，并拒绝重定向。Chrome 的端口匹配限制会被记录为权限边界的一部分。失败、部分恢复与缺失内容均进入清单，不伪造源码。

ZIP 使用确定性的 store-only 写入器在浏览器内生成，不依赖原生压缩模块。offscreen 文档生成 ZIP 后先进入 `review_required`，把敏感项计数、外部/缺失资源和视觉状态交给 UI；只有用户确认风险后才调用下载权限。取消、失败、批准下载后都会撤销 Blob 地址和清理捕获缓存。

Bundle 生成初始 `workspace-history.json`。Agent 修改后可运行无外部依赖的 `runner/repack.mjs`，重新计算 workspace 内容哈希、追加说明并生成新 ZIP。该历史只追踪包内文件版本，不记录浏览器内容；扩展侧 `storage.local` 也只保存 captureId、URL、route、时间、文件名和终态。

## 任务状态与失败处理

任务状态依次经过准备、采集、解析、工作区构建、source map 恢复、离线视觉检查、打包、用户审核和下载发起。状态、进度、错误以及批量队列/profile 写入会话存储，弹窗重新打开或 Service Worker 重启后可以恢复排队项；正在传输且端口已丢失的单项不会伪称续传，而是清理队列并要求重试。待审核 Blob 最长保留 30 分钟，超时自动撤销并进入失败态。

分块损坏、重复序号内容冲突、缺块、解析失败、打包失败和下载失败都会进入失败终态。用户取消时，采集端停止发送，后台断开端口，offscreen 清空对应分块。

## 安全边界

插件默认声明当前标签、脚本注入、下载、存储、offscreen 和 Side Panel 能力。`tabs` 与跨域站点访问都是用户手势触发的可选权限；站点访问按 scheme 和 host 请求，端口不属于 Chrome 可表达的 host match pattern。实现不声明 `cookies` 或 `history`，也不导出 Cookie 或浏览器 storage 数据库。

Bundle 的统一清单强制标记为可执行内容。安全报告提示脚本、内联事件、表单目标、疑似令牌、URL 凭证、私钥材料、密码字段和 DOM 邮箱，不静默删除业务内容。随包 preview runner 默认离线；`read-only` 模式只通过本地代理执行不带凭证的 GET/HEAD，其他方法被拒绝；`original` 模式必须由使用者显式开启并承担真实后端风险。路径解析使用相对边界校验，不能穿越 workspace 根目录。

视觉检查在 script-disabled、外部网络阻断的隐藏 iframe 中回放 faithful/workspace。资源先改写为本地 data URL，再由 html2canvas 的 DOM/CSS 渲染器生成 PNG，避免 SVG `foreignObject` 污染 canvas。报告提供像素变化率、平均通道误差、阈值和限制说明；它是稳定的离线近似比较，不证明脚本交互等价。

## 许可与构建

构建脚本锁定仓库已有的 `single-file-cli@2.0.83`，在构建期展开其中由 `single-file-core@1.5.68` 生成的静态浏览器脚本。运行时不使用动态求值，满足 Manifest V3 的扩展页面策略。

构建产物附带 SingleFile 的 AGPL-3.0 文本、html2canvas MIT 文本、第三方说明、隐私草案、对应源码说明和 SPDX 2.3 SBOM。包元数据当前标记 AGPL-3.0-or-later，但项目尚未完成组合版权与最终分发方式评审，因此产物只作为内部技术原型，不进入商店发布流程。

每次扩展检查在构建完成后还会校验 unpacked 产物的最低权限、隐私说明、SPDX 文件、对应源码说明与 AGPL/MIT 许可证文本。它像出库前的封条，能阻止构建遗漏材料或意外增加 Cookie、history、永久站点权限；但不能替代对外分发前的许可决定。

## 验证边界

核心契约测试覆盖可执行结构保留、脚本顺序、资源去重、iframe 拆分、内联/外部 source map、阅读副本、runner 网络边界、workspace 历史重打包与 manifest 哈希更新、安全报告和 ZIP。扩展单测覆盖 10MB/50MB 分块、损坏与缺块拒绝、权限/生命周期、批量选择、profile/站点规则/历史、资源改写和 RGBA 指标。`build:fidelity-harness` 可重建浏览器夹具；真实 Chrome 已验证离线 fidelity 渲染能生成 faithful/workspace PNG，并据此修复了 `foreignObject` canvas 污染问题。

持久 Chromium profile 的加载未打包扩展 E2E 已覆盖 Popup 配置表单和审核确认按钮、公开夹具的表单运行值、Shadow DOM、canvas、同源 CSS/JS/懒加载图片、嵌套 frame，以及按原脚本 URL 恢复的外部 source map/source。它还验证审核前零下载、审核后 ZIP/历史、50MB 取消后重试与 Service Worker 强制回收。下载后的 bundle 烟测会编辑 workspace，实际启动其离线预览并确认它不暴露 faithful，再运行自带重打包器；faithful 字节不变、workspace 历史与 ZIP 都更新。Side Panel 烟测确认标签初始不选中、只能显式选入单项、队列提示用户激活目标标签且不会自动切换或下载。额外的无权限覆盖运行已通过 Chromium 扩展菜单真实点击授予 `activeTab`，并完成后续链路；Playwright 的下载接管使 Save As 系统对话框未停留。已登录 author-site 与 Save As 对话框仍需人工验收。许可评审和商店发布也未完成；在这些验收完成前，不得把内部原型标记为可外部分发版本。
