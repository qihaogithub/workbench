# OneFlow 工作台上线宣讲稿（v2.0）

> 文档版本：v2.0
>
> 主题：让活动系统更容易被使用、被维护、被扩展。
>
> 说明：本文沿用现有产品命名。产品演进顺序是“资源预览平台前身 → OneFlow 工作台 2.0 MVP → 当前 OneFlow 工作台 1.0 正式版”，版本数字是产品名称，不代表时间先后。

> v1.0 历史版本：[OneFlow 全员上线宣讲 PPT 逐页规划](./workbench上线宣讲-v1.0.md)

## 演讲稿正文

OneFlow 工作台是一个协作平台，专注于营销活动业务，提高大家的协作效率
今天我想用一个生活中的比喻，介绍 OneFlow 工作台到底要解决什么问题。

### 一、活动系统：一家已经建好的“叫叫大酒店”

酒店里预先规划了几类不同用途的房间，分别对应活动系统里预设的活动类型：

- 闯关活动；
- 拍摄活动；
- 抽奖活动；
- 以及其他已经建设好的活动类型。

每个房间里面，都有已经安装好的家具和设备。它们对应活动类型中的页面、流程和功能。

比如，闯关活动这个房间里，可能已经有题目、答题、进度、奖励等功能；抽奖活动这个房间里，可能已经有抽奖规则、奖品和结果展示等功能。

这些活动类型不是每次都要重新开发。我们可以通过配置项，把同一个活动类型包装成不同的具体活动。

例如，选择“闯关活动”这个房间，再配置活动名称、题目、图片、规则、奖励和视觉资源，就可以做成一次“英语单词挑战赛”。

这就像同一个宴会厅，换一套布置可以办婚宴、年会，也可以办行业峰会。房间本身没有变，变的是里面的布置和使用方式。

所以，活动系统的价值，就是提前把常见的活动能力建设好。后续面对不同活动需求时，我们可以优先选择合适的活动类型，再通过配置快速组合，而不是每次从零开发一套业务系统。

### 二、活动系统的建设方式：产品经理是建筑师，UI设计负责装修规则

在这家酒店里，产品经理负责规划房间：

- 酒店有哪些活动类型；
- 每种活动类型能完成什么业务目标；
- 一个活动需要哪些页面和流程；
- 哪些内容可以通过配置修改；
- 哪些能力暂时不能修改，必须重新建设。

UI 设计师负责制定装修规则：

- 图片、视频和动效应该使用什么尺寸；
- logo 放在什么位置；
- 文案有多大空间；
- 哪些区域可以替换，替换后怎样才能正常显示。

运营设计师则像客户自己的现场布置团队。他们根据一次具体活动的目标，为页面设计图片、视频、动效和其他资源，再按照规范把这些资源放进活动里。

比如：

- 沙发可以换沙发套，对应某些图片或视觉资源可以替换；
- 墙纸可以重新贴，对应页面背景和装饰可以调整；
- 瓷砖本身不能更换，但可以铺地毯，对应底层功能不变时，可以通过其他配置改变整体效果。

### 三、真正的痛点：客户每次都要来问“酒店怎么用”

现在的问题不是酒店没有房间，而是客户还不能方便地知道：有哪些房间、每个房间能做什么、哪些家具可以更换、具体应该怎么更换。

活动策划要做一次“英语单词挑战赛”，可能需要反复确认：

“闯关活动能不能满足这次需求？”

“哪些页面可以直接使用？”

“题目、奖励和视觉资源分别在哪里配置？”

运营设计师还要继续确认：

“这张图应该做多大？”

“这个 logo 放在哪里？”

“我做好的资源放进真实页面后，最终效果是什么样？”

于是，产品经理和 UI 设计师一边要继续建设和升级活动系统，一边还要反复充当“酒店前台”和“装修顾问”。

他们需要一次次解释活动类型、配置边界和设计规范；客户则需要在聊天记录、会议结论和多个文档之间来回寻找答案。

一个活动可能涉及几十个页面，每个页面又有很多配置项。只要有一个尺寸、比例或理解出现偏差，就可能在后面产生返工。

这不是某个岗位不够努力，而是活动系统的能力、规则和真实效果，没有被放在一个方便大家共同查看和协作的地方。

### 四、OneFlow 的前身：资源预览平台

我们最早的解决方案，是先做一个资源预览平台，把活动系统中的一部分页面做成线上样板间：

[资源预览平台](https://jojo-preview.netlify.app/)

它可以按学习页、广场页、弹窗、伴读页等类型浏览页面样例。运营设计师不必只看静态设计稿，而是可以直接打开页面，查看资源放进真实页面后的效果。

这一步主要解决“设计资源无法及时验证”的问题：设计师可以更早发现尺寸、比例、位置和视觉效果问题，减少做完之后才发现不能用的返工。

但它的定位更接近“样板间展示平台”，还不是完整的协作平台。每增加一个新的页面样例，都需要单独建模、配置交互和维护，数量一多，维护成本就很高，也不利于多人共同建设。

### 五、OneFlow 工作台 MVP：把协作工作台搭起来

在资源预览平台的基础上，我们进一步做了 OneFlow 工作台  MVP。

MVP 解决的核心问题是：活动系统的新页面和新能力，建设速度太慢，参与建设的人也太少。

过去，新增一个页面往往需要从设计、开发到交互配置全部手工完成，一个页面可能要花 300 分钟甚至更久。现在，设计师可以在 Figma 中完成设计稿，通过插件把设计稿直接导出为代码，再粘贴到 OneFlow 工作台中，快速生成可交互的页面。

图片、视频、动效等常见能力，也可以沉淀成通用 SDK，供开发者和 AI 复用。团队成员可以通过代码仓库和在线工作台共同维护，不再把所有建设工作集中在一个人身上。

这样，常见页面的初版建设可以缩短到半小时甚至更短。活动系统扩展新活动类型、补充新页面的速度变快了，OneFlow 也从“看效果的样板间”变成了“共同建设活动系统的协作工作台”。

但 2MVP 主要解决的是“建设和协作效率”，还没有彻底解决“客户如何自助使用”的问题。

客户依然可能不知道应该选哪种活动类型，运营设计师依然可能要翻找规范，产品经理和 UI 设计师依然要花很多时间重复解释。

### 六、当前 OneFlow 工作台 1.0 正式版：在协作平台里加入 AI 管家

所以，当前 OneFlow 工作台 1.0 正式版的核心想法，是在这个协作平台里加入一位 AI 管家。

这里要特别说明：AI 管家属于 OneFlow，不是把 AI 直接塞进活动系统里替代活动系统。它的工作，是帮助大家更好地使用和建设活动系统。

这位 AI 管家了解活动系统中的各种“房间”：

- 知道有哪些活动类型；
- 知道每种类型适合什么需求；
- 知道有哪些页面和配置项；
- 知道哪些资源可以替换；
- 知道每项资源的尺寸和设计规范；
- 也知道哪些需求超出了现有能力。

活动策划可以直接描述自己的目标：

“我们想做一场英语单词挑战赛，面向什么用户，希望用户完成什么动作，希望活动呈现什么氛围。”

AI 管家会根据活动目标，匹配合适的活动类型和页面，整理出配置清单、资源清单和设计要求，并生成一份可以讨论、可以修改的活动原型。

运营设计师拿到原型后，能够清楚知道：这次活动需要哪些页面，每个页面有哪些资源需要设计，每项资源的尺寸和规范是什么。设计完成后，直接上传到 OneFlow 中，就可以查看它在页面中的实际效果。

如果资源尺寸不对、比例不对，或者与页面要求不匹配，系统可以尽早提示。大家讨论的也不再只是“我觉得应该可以”，而是直接围绕同一个页面、同一份配置和同一个实际效果做判断。

在这个过程中，AI 管家承担的是标准化的工作：查询能力、解释规则、匹配活动类型、整理方案、生成原型和进行初步检查。

产品经理和 UI 设计师并不是被替代，而是可以减少重复接待，把更多精力放回活动系统本身：

- 建设新的活动类型和页面能力；
- 完善配置边界和设计规范；
- 处理复杂需求和例外情况；
- 让活动系统的基础能力持续升级。

### 七、OneFlow 和活动系统如何配合

可以把两者的关系概括成一句话：

> 活动系统负责承载业务，OneFlow 负责协作交付。

一次活动的理想流程是：

> 在 OneFlow 中输入活动目标 → AI 匹配活动类型和能力 → 生成可讨论的活动原型 → 团队在线协作 → 上传资源并实时预览 → 必要时由开发补充活动系统能力 → 在活动系统中配置并上线 → 将规范和经验沉淀回 OneFlow。

OneFlow 不会取代活动系统，也不是再造一个活动系统。它更像是连接活动策划、产品、设计、运营设计和开发的共同工作台，让大家围绕同一份活动上下文协作。

### 八、我们最终想解决的业务痛点

OneFlow 想解决的，不只是“页面做得更快”，而是活动交付中的三个长期问题：

1. **重复沟通太多**：把活动类型、能力边界、配置项和设计规范整理出来，让客户可以先自助了解。
2. **设计返工太多**：让资源尽早进入真实页面预览，及时发现尺寸、比例和效果问题。
3. **每次活动都像重新开始**：把页面、配置、规范和经验沉淀下来，下一次活动可以直接复用。

最终，希望形成这样的分工：

- 活动策划负责提出目标和判断方案；
- 产品经理负责建设活动系统的能力和规则；
- 设计师负责制定视觉规范；
- 运营设计师负责制作和验证活动资源；
- 开发负责把通用能力变成稳定的基础设施；
- OneFlow 和 AI 负责把信息、方案、资源和协作串联起来。

### 九、最后用一句话总结

如果说活动系统是一家真正承载业务的酒店，那么 OneFlow 就是酒店旁边的协作中心：

它让客户更容易找到合适的房间，让设计师更容易完成装修，让产品和开发更容易扩建酒店，也让每一次活动留下的经验，都能成为下一次活动可以直接使用的资产。

这就是 OneFlow 工作台想解决的业务痛点：让活动系统更容易被使用、被维护、被扩展，让大家把时间从反复解释和反复返工，重新投入到更有价值的活动创新和产品建设中。
