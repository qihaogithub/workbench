# OneFlow 全员上线宣讲 PPT 逐页规划（v1.0）

> 文档版本：v1.0（从 Git 提交 `cf0ff71f` 恢复）
>
> 当前版本：[OneFlow 工作台上线宣讲稿（v2.0）](./workbench上线宣讲.md)

> 用途：全员上线宣讲 PPT 制作 brief。每页统一包含“目的、文案、画面”，不附现场讲稿。
> 宣讲对象：全体业务与技术同事，重点覆盖活动策划、产品、设计、运营设计和开发相关角色。
> 建议时长：20–25 分钟，10 页。

## 第 1 页：OneFlow 解决什么问题

### 目的

用全员都能理解的语言建立共识：OneFlow 要解决的是活动交付中的重复劳动、信息分散和协作等待。

### 文案

- 标题：**每个活动，都不该从零开始**
- 副标题：OneFlow 是面向运营活动的 AI 协作平台。
- 三个问题：重复整理方案与原型；规范和经验散落在不同地方；跨角色协作不断补上下文。
- 结论：OneFlow 把活动从目标推进到原型、配置、预览、开发接入和经验复用。

### 画面

左侧用三个真实工作场景呈现“重复、分散、等待”，右侧用一条连续工作流连接“目标 → 原型 → 配置 → 预览 → 上线 → 复用”。

## 第 2 页：OneFlow 是一种新的协作方式

### 目的

让听众理解 OneFlow 不只是新增工具，而是把 Agent 能力变成所有岗位都能参与的在线项目协作能力。

### 文案

- 标题：**不用安装编程工具，也能参与 AI 创作和协作**
- 过去：工具、文档、对话和产物分散在个人环境与不同团队中。
- 现在：项目统一承载活动目标、对话、页面、配置、资源、预览和版本。
- 结论：同一份项目上下文，让不同角色在线协作。

### 画面

用“分散的个人工具”与“统一的 OneFlow 项目”做左右对比；突出浏览器、共享上下文和协作产物。

## 第 3 页：过去与现在的活动交付

### 目的

用一张对比图讲清楚工作方式变化，避免陷入角色和功能细节。

### 文案

- 标题：**从临时拼接，变成连续交付**
- 过去：提出目标 → 人工整理方案 → 反复确认能力 → 补规范和资源 → 开发重新理解 → 上线。
- 现在：输入目标 → AI 整合知识并生成原型 → 项目内协作配置 → 上传资源并预览 → 必要时开发精准接入 → 复盘沉淀。
- 结论：AI 承接可规则化的执行，人保留判断、标准和例外。

### 画面

上下两条流程对比；上方标出“沟通、等待、返工”，下方突出“共享上下文、实时验证、经验复用”。

## 第 4 页：每个角色都会得到什么

### 目的

消除“AI 替代角色”的担忧，让全员看到自己的参与方式和价值变化。

### 文案

- 标题：**不是替代谁，而是减少重复工作**
- 策划：更快得到可讨论、可调整的活动方案和原型。
- 产品：把能力边界、模板和验收规则沉淀为可复用知识。
- 设计与运营设计：围绕真实页面组织规范、制作资源并在线验证效果。
- 开发：直接读取页面、协议、配置和资源上下文，减少重新理解和返工。
- 共同变化：人负责判断和标准，AI 负责执行、整合和自助答疑。

### 画面

用五个角色沿同一条项目上下文带排列，每个角色只保留一句“输入 → 收益”；避免复杂职责矩阵。

## 第 5 页：OneFlow 的中心产物

### 目的

明确大家最终协作的对象是可交互活动原型，而不是聊天记录或静态文档。

### 文案

- 标题：**一个可交互原型，成为团队共同语言**
- 原型承载：页面、正式文案、功能状态、配置项、资源规范、使用说明和真实预览。
- 它连接：活动目标、产品能力、视觉规则、运营资源和开发上下文。
- 结论：一次生成页面与上下文，减少跨文档同步和人工补齐。

### 画面

优先展示真实原型截图；周围仅保留“策划、产品、设计、运营、开发”五个连接标签。

## 第 6 页：从资源交付到在线验证

### 目的

用一个具体场景展示 OneFlow 的可感知收益，让抽象能力落到页面使用。

### 文案

- 标题：**上传资源，就能看到它在真实页面中的效果**
- 流程：查看配置项 → 阅读项目内规范 → 上传图片/动效/音效 → 实时预览 → 调整并验收。
- 结果：设计交付不止于素材文件，而是直接验证素材在页面中的可用性。
- 延伸：必要时可生成高保真页面代码，为开发提供更准确的视觉上下文。

### 画面

使用真实产品界面或录屏截图：左侧配置项，中间资源上传，右侧实时预览；用 1–5 标出操作顺序。

## 第 7 页：AI 在活动交付中的作用

### 目的

用最少概念解释 AI 的价值，避免听众把 OneFlow 理解成普通聊天入口。

### 文案

- 标题：**AI 不只回答问题，还参与完成活动**
- 执行：生成方案、原型、配置清单和资源清单。
- 整合：结合产品能力、视觉规范、历史经验和开发边界。
- 自助答疑：回答“能不能做、怎么配置、资源怎么准备、如何接入”。
- 结论：AI 有依据地执行、整合和答疑，人负责最终判断。

### 画面

用三个递进层级“执行 → 整合 → 自助答疑”，每层配一个活动场景，不使用复杂技术架构图。

## 第 8 页：一次活动如何跑通闭环

### 目的

把前面内容收束成一条全员可复述的活动工作流，并建立对试点的期待。

### 文案

- 标题：**从活动目标，到上线复盘，一条链路完成**
- 流程：模板与知识 → 活动目标 → AI 方案 → 可交互原型 → 配置与资源 → 在线协作 → 上传预览 → 开发接入 → 验收上线 → 经验回流。
- 结论：一次活动不仅完成交付，还会为下一次活动留下可复用资产。

### 画面

用一条横向闭环流程；中心或末端突出“经验回流到模板与知识库”。如果条件允许，替换为一个真实活动案例。

## 第 9 页：上线边界与试点方式

### 目的

建立合理预期，并明确大家如何用真实活动验证 OneFlow，而不是停留在概念讨论。

### 文案

- 标题：**先用一个真实活动，验证完整闭环**
- 当前重点：活动模板、项目内规范、AI 原型、配置与资源上传、实时预览、在线协作和开发接入。
- 试点标准：真实业务、范围可控、多角色参与、有明确上线时间，并具备复用价值。
- 三个验收问题：能否生成可用原型？能否减少沟通与返工？能否完成资源预览到上线验收？
- 说明：逐项操作教程和技术实现细节放到后续培训，不在本次全员宣讲展开。

### 画面

左侧为“当前可用能力”，右侧为“试点选择标准”，底部突出三个验收问题；避免展示过长的功能清单。

## 第 10 页：现在开始做什么

### 目的

把全员宣讲转化为明确行动，让听众知道下一步、参与方式和成功标准。

### 文案

- 标题：**选择一个真实活动，跑完第一条 OneFlow 工作流**
- 第一步：确定试点活动和负责人。
- 第二步：由策划输入目标，产品、设计、运营设计和开发按需补充上下文。
- 第三步：完成原型、资源预览、开发评审和上线复盘。
- 复盘关注：节省了哪些体力活，减少了哪些沟通和返工，沉淀了哪些可复用资产。
- 行动号召：**先跑通一个闭环，再把有效方法扩展到更多活动。**

### 画面

以“试点活动 → 负责人 → 参与角色 → 复盘产出”的四步行动图收束；明确试点入口、联系人和时间点（待补充）。
