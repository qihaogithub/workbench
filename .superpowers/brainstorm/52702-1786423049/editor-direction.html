Markdown 编辑器优化方向

我已对比当前项目实现与 Milkdown 官方 Playground。请选择更接近你预期的方向；它决定我们是做视觉打磨，还是切换上层编辑器能力。

项目设计说明
像官方 Playground 一样，直接采用 Milkdown Crepe：成熟的块菜单、图片工具、链接编辑、代码块与表格交互。
＋ 块菜单 拖拽 图片操作

A · Crepe 优先（推荐）

最接近官方演示，删除大部分自研原生 UI 适配层；保留项目特有的上传和配置引用能力。体验上限最高，迁移与回归成本中等。

项目设计说明
保留现有 Milkdown Kit 架构，补齐版式、悬浮菜单、键盘行为、选区与块操作。

B · 现有架构深度打磨

继续维护自定义 slash / tooltip / block provider，逐项追平官方体验。改动更局部，但长期维护量最大，容易继续出现细节差异。

项目设计说明
只修正内容宽度、字体层级、间距、焦点和菜单样式，让阅读与书写更舒服。

C · 轻量视觉优化

不改编辑器能力，只调整 typography、留白、颜色和浮层外观。风险最低、见效最快，但不会解决菜单能力与复杂块交互差距。

初步审计结论

当前实现并不是官方 Playground 使用的 Crepe，而是 Milkdown Kit 加自研 slash、选区工具条和块手柄。正文只设置了 text-sm / px-3 / py-2 / min-height，缺少系统化排版主题；斜杠菜单无搜索与键盘高亮，链接仍用浏览器 prompt，表格按钮是字符图标，块手柄也只有拖拽而没有块级操作。这些共同造成“能编辑，但不像完整产品”的感受。
